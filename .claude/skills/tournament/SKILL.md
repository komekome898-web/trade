# トーナメント(定期ブラッシュアップ)

第8回(第13報、`scripts/research_tournament.py`)から抽出した反復可能な手順。目的は**候補生成**であり採用ではない — 採用は常に`research-protocol`の事前登録基準を経由する。

## 1. 開催条件

- 新しい30日データ窓が回った時(月次目安)
- 新レポートが`docs/KNOWLEDGE.md`に実測法則を追加した時
- **対象外**: ライブ資金投入・`config/risk_limits.yaml`の上限変更 — これらはオーナー承認領域であり、トーナメントの勝敗では動かせない

## 2. チャンピオンの定義

現在ペーパーで走る構成(現状 `xborder_momentum` k=30/thr_pct=0.8)。開始前に**再現ゲート**必須:直近の監査行(既存レポートの基準線)をtrade-for-tradeで再現できなければ中断し原因を解消してから進める。

## 3. 挑戦者の資格

- `KNOWLEDGE.md`の実測法則に立脚した**弱点攻撃のみ**。根拠なき新規シグナルの持ち込みは禁止
- 最大**3ファミリー**、ファミリー内チューニング(パラメータ候補)は事前に列挙し後から足さない
- 過去に「機構不成立」で棄却された挑戦(例: 第13報のC1 maker TP出口)は**再挑戦不可**。「コスト負け」棄却のみ条件を変えて再挑戦可(`research-protocol` sec.5の線引きに従う)

## 4. 対戦規則(固定)

- データ: 30日実データ、時系列**60/40分割**(探索/判定)
- 探索区間でファミリー内の変体を選択(採用基準はresearch-protocolの型に従う)
- 判定区間は**一度だけ**実行しそのまま報告
- 勝利条件: 判定区間で**期待値とmaxDDの両方**でチャンピオンに勝ち、かつ **n≥20**
- 勝った要素は「チャンピオンv2」に吸収し、残る挑戦者と**再戦(最大1回)** — 再選択なし、新規変体なし
- 敗者側の成果物は**敗因の機構分析**(コスト分解・出口構成比・チャンピオンとの取引重複)

## 5. 結果の行き先

- 勝者要素 → `CompositeStrategy`のゲート付きモジュール化(fail-closed枠組み、`config/composite.yaml`)
- 開錠条件: **ペーパー部分集合判定 + オーナー承認**(全体基準からの逸脱がある場合はレポートと同時に逸脱ごと承認を得る、第13報C2/C3の先例)
- 明記事項: **トーナメントは候補生成であり採用ではない**。採用は常に`KNOWLEDGE.md` sec.5の事前登録済みペーパー基準(主戦略: 30取引以上・+0.15%/取引以上・最大DD10%未満)を経由する

## 6. 批評ループ

実装(エンジン拡張・モジュール追加)を伴う場合は`/loop`で戦略批評家⇔コード批評家を交互投入し、**ブロッキングゼロが2連続**+フルテスト緑+`scripts/validate_composite.py`全PASSまで回す。
参考実績: 第8回(第13報)は6巡で6件のブロッキング(fail-open復旧不能ループ・後付け基準など)を摘出し収束した。

## 7. 記録

- `docs/RESEARCH_REPORT_<date><suffix>.md`に1本(必須セクションは`research-protocol` sec.7に従う: 事前登録/探索区間/判定区間/逆選択反実仮想/アブレーション/サニティ/限界)
- `docs/KNOWLEDGE.md`の索引(検証済み仮説数・棄却数・生存候補、係属仮説セクション)を更新
- アーティファクト(config・エンジン拡張)を更新。**下位エージェントはコミットしない**(`delegated-study` sec.1) — 検収とコミットはリード
