# 引き継ぎ文の型(分析を新しい会話で始めるとき。L-705・L-711)

新しい会話(会話を消した後・別の実行環境)で分析を始めるときに、最初のメッセージとして渡す文の型。`〈 〉` の所だけを埋める。埋める所以外は書き換えない(書き換えたら、その会話の分析は仕組みの外で行ったことになる)。
出所: 2026-10-04 の引き継ぎ文 `docs/DISCUSSIONS/2026-10-04_analysis_skill/HANDOFF_REDO2.md` と、2026-10-05〜06 の 2 人作業で起きたこと(`docs/DISCUSSIONS/2026-10-05_analysis_mechanism/PROPOSAL.md` §1・§2・§6)。

---

あなたはこのリポジトリのリードです。作業ブランチは `〈ブランチ〉`。

## やること

〈分析する単位(カード名・候補の K 番号・問い)と、その順番〉

- 完了の形(オーナーの逐語): 「〈オーナーの逐語〉」
- 上限: 〈周か時間〉。上限に達したら止めて、残りを持ち越しとして状態板に書く。

## 最初にすること(この順で。飛ばさない)

1. `sh scripts/install_git_hooks.sh` を打つ(この実行環境で押し出しの門を効かせる。打つまでは効かない。2026-10-05 に、打っていない環境で押し出しを続けていた)。`git config --get core.hooksPath` が `githooks` と出ることを確かめる。
2. CLAUDE.md・`docs/OWNER_STATUS.md` を読む。CLAUDE.md §0.1 の 2 列の表(やろうとすること × オーナーの原文の該当語)を出してから着手する。
3. 今の会話の道具の一覧に advisor の道具があるかを確かめ、結果を 1 行で書く(ある / 無い)。無ければ、相方は `analysis-partner`(Agent の道具)になる。

## 分析の進め方(1 単位ごと)

1. 単位ごとに、分析のスキル `analysis-lens` を **Skill の道具で呼び直す**(読み込むだけでは手順は当たらない。L-685)。1 回の呼び出しで 1 単位。
2. 新しい単位は `python3 scripts/analysis/diag_skeleton.py --unit <単位>` で骨組みを作る。既にある分析の文書に書き足すときは、先に `python3 scripts/analysis/diag_skeleton.py --refresh <文書>` を通す(スキルが変わった後は、通すまで書き込みがフックで止まる)。
3. 手順は文書の上から 1 つずつ。各節の引用を読み直してから「当てたこと」を書く。
4. **相方の検め(手順 R)**: 少なくとも D9b の後と D10 の前に、`python3 scripts/analysis/partner_brief.py --doc <文書> --at <時点> --done "<完了の形>"` で渡し書きを作り、advisor の道具があれば渡し書きを Read してから呼ぶ。無ければ `analysis-partner` に渡し書きのパスを渡す。相方の出力は返答に逐語で出し、`docs/RESEARCH/partner/<文書>/` の記録ファイルにも写して、1 件ずつ応答を書く。R 節の表に 1 行足す。
5. D9b の候補は `python3 scripts/analysis/ledger_rows.py <行の定義ファイル>` で台帳に足す(手で台帳を書かない)。
6. コミットは次の形(引用符の中で実際に改行する。`\n` と書いても sh では改行にならず、門の「`Claude-Session: ` で始まる行」の検めで止まる)。台帳の検査と仮置きが 0 でなければコミットしない。

       sh scripts/analysis/commit_gate.sh "<英語のメッセージ>

       Claude-Session: <この会話の URL>"
押し出しは `git push -u origin <ブランチ>`(押し出しの門が、指紋の照合・台帳の検査・仮置き・相方の記録を検める)。
7. 候補を確かめるときは、なぜと予言のスキル `why-predict` を Skill の道具で呼ぶ(1 候補 1 呼び出し)。
