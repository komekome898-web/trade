# 研究プロトコル(事前登録型検証)

報告12本を出して過学習採用ゼロを保った規律。**走らせる前に**このチェックリストを埋める。

## 1. 事前登録 — 実行前に固定する

スクリプトのdocstring冒頭に以下を書き切ってから1行も実行しない。

- 対象データ(パス・期間・行数)
- 分割(探索/判定の境界日時)
- 構成ファミリー: **列挙する。後から追加しない**
- 採用基準(数値バー)と選択規則(どの指標でどう1つ選ぶか)
- 判定区間は**一度だけ実行し、そのまま報告**

例: `scripts/research_calm_range.py` / `scripts/research_exit_surface.py` のヘッダ。

## 2. 分割規約

- 時系列 60/40(探索/判定)。イベント研究はイベント開始時刻でソートして前半/後半
- 判定を見た後の構成変更は**禁止**
- 探索の勝者と判定の勝者が入れ替わる=「構成の乗り換わり」= **過学習兆候として不採用**

## 3. コスト・執行モデル(**定数は持たない。単位ごとに測る**)

2026-09-08 の全捨てで、この節にあった実測定数(taker 片道・スプレッド・逆選択の水準)は**すべて失効**した。
理由は CLAUDE.md §5.2 — 摩擦の見積りが 3〜20 倍過大で、それが全棄却の判定バーになっていた。

- **各単位は自分でコストを測り、事前登録にその測定方法と値を書く。** 他単位の値を流用しない。
- 制度の事実(手数料率・呼値・売買単位)だけは `config/constants.yaml` の
  `primary_document` 由来の項目を使ってよい。`status: discarded_2026-09-08` が付いた値は使えない。
- **摩擦の見積りにはバイアスの向きを書く。** 高めに見積もることは「安全」ではない —
  棄却方向のバイアスであり、採用方向のバイアスと同じだけ有害である。
- maker 約定判定は保守則(print 単位の traded-through、反対側の約定が指値を叩き抜けた時のみ約定)を既定とするが、
  **保守則を使ったこと自体を結果の解釈に明記する**(どちら向きにどれだけ歪むか)。
- **逆選択の反実仮想を必ず報告**: 「取り逃したシグナルを taker で入っていたら」vs「実際に約定した分」。
  水準は単位ごとに測る。

## 4. 採用基準の型

判定区間で以下を**すべて**満たすこと。

1. 最低取引数 **≥100**(イベント系は **≥30イベント**)
2. ネット期待値バー(単位ごとに事前登録する)
3. 日次 or イベントクラスタ **t ≥ 2.0**(ブートストラップCIがゼロを除外)
4. グリッド勝者は **台地条件**: 隣接構成(各軸±1ステップ)が候補から大きく劣化しない

### 4.1 検出力を先に書く(**必須**。これが無い事前登録は実行しない)

- 事前登録に **MDE**(この n・この分散で検出できる最小効果)を**走らせる前に**書く。
- **欲しい効果 < MDE なら、その単位は実行しない。** データを増やすか、設計を変える。
- 実行後、効果が MDE 未満だった場合の結論は「**不明**」であって「効かない」ではない。
- **MDE を書いていない測定を、陰性として引用してはならない。**

## 5. 結果の三分類(**「再監査不可」という区分は廃止した**)

旧版には「機構不成立 = 再監査不可」という永久に扉を閉じる区分があった。**廃止する。**
それが偽陰性を蓄積させた装置だったため(CLAUDE.md §5.2)。結果は次の 3 つに分類する。

- **陰性**: 欲しい効果 > MDE の検定で、効果の不在を測った。**射程を必ず併記する**
  (何を測ったか / 何を測っていないか)。射程の外へ一般化して引用してはならない。
- **不明**: 測ったが検出力が足りなかった。**扉は開いたまま**。必要な n を書く。
- **陽性**: 次段(フレッシュデータ・ペーパー)へ。

どの分類でも、報告には **「なぜそうなるのか」** の節を置く。**判定だけの報告は不合格**(CLAUDE.md §5.2)。

## 6. 必須サニティ(全部通してから結果を読む)

- ルックアヘッド **ゼロ**(特徴量の窓が判定対象の窓と重ならないこと)
  - トートロジー検出: 過去の報告、嵐の定義窓(30分リターン)の内側を読んでいただけ。**定義窓を完全に外して再測**すると56%(コイントス)
- ポジション重複 **ゼロ**、クールダウン厳守
- 取引数の妥当性(指値設置数に対する約定率が桁で異常でないか)
- **再実行決定性**(ブートストラップはseed固定、ネットワークアクセスなし)
- **pandas datetime64 単位トラップ**: 秒への変換は必ず

  ```python
  EPOCH = pd.Timestamp("1970-01-01", tz="UTC")
  t = ((idx - EPOCH) / pd.Timedelta("1s")).to_numpy(dtype=float)
  ```

  `.astype("int64")` や `.view()` は us/ns/s を取り違える。過去にこれで**美しく間違った結果**が出た。変換直後にクロスチェック行を1本printする。
- 既存結果の再現ゲート: 新スクリプトの基準線(E0等)が既存結果を**trade-for-trade再現**することを検算してから差分を語る

## 7. 報告様式

- **陰性結果も第一級の成果**。`docs/RESEARCH_REPORT_<date><suffix>.md` に記録する
- 必須セクション: 事前登録 / 探索区間の表 / 判定区間の結果 / 逆選択の反実仮想 / アブレーション(要素別寄与) / サニティ / 注意点・限界
- 数値は「n・ネットbps/取引・t or CI」を必ず併記。単独の平均は書かない
- 結果は報告本文に測定として書く(引用可能な「確立知識」の索引はもう作らない)
- 採用に至らなくても、機構の発見(例「指値が約定する0.86%は突き抜ける瞬間である」)は本文に残す

## 8. 禁止事項

1. **自己汚染**: 判定区間から仮説を生成 → 同じデータで検証。新鮮データが貯まるまで待ち、係属仮説として事前登録だけしておく(過去の報告)
2. 事前登録外の**診断結果を採用に格上げ**する(診断は診断のまま報告)
3. **掘り出し(fishing)**: 27候補をスクリーニングした後に3条件を通過する構成は**偶然でも出る**。候補数を明記し、台地条件とペア比較CIで潰す
4. in-sample選択構成の採用(過去の報告)
5. 「最良だから採用」ではなく「これより良いと言える構成が存在しないから維持」と書く(過去の報告)

## 9. 判断の型

エッジ採用と**分散改善**を分ける。過去の報告、中央値・勝率・sd・損失有界性で現行を支配したため「分散改善」として切替え、事前登録カウントは切替時点から**リスタート**した。基準未達のものをエッジとして採用しない。

## 10. 探索の深さ(2026-08-25 オーナー指示で追加)

事前登録の凍結が縛るのは**判定**(新鮮データ・一発勝負)であって、**探索の深さではない**。
「やってみた→ダメでした→次へ」は戦略候補の消費であり研究ではない。

- **汚染済みデータ上の探索は、点ではなく面を測る。** 単一構成の可否ではなく、
  パラメータ面(閾値×窓×遅延×地平)上のドリフト/損益の地図を作り、
  「エッジがどこに住み、どこで死ぬか」を機構として言えるまで掘る。
  旧botの開発が実際にそうであったように、試行錯誤はここで行う。
- **棄却レポートは棄却の水準を明記する**:
  - **機構水準の死**(符号法則・コスト床>ドリフト天井・頻度の壁など、
    どのパラメータでも越えられない算術)— その算術を明示して初めて主張できる
  - **点水準の死**(検証したセルが死んだだけ)— 「機構が死んだ」と書いてはならない。
    探索した方向と未探索の方向を列挙する
- **スケール規約**: 旧環境由来のパラメータは絶対値(円・BTC・秒)で持ち込まず、
  現行データの分布から相対的に再導出する(分位・ティック・中央値比)。
  時間スケールの転写も原典と一致させるか、差を適用範囲として明記する(過去の報告)。
- 深い探索は候補数を爆発させる。**掘った面の広さ(セル数)を必ず報告し**、
  そこから凍結するのは最大1〜2構成、採用判断は変わらず新鮮データの一発判定のみ。

## 11. 分母と反証者(2026-09-04 ポストモーテムで追加。`docs/POSTMORTEM_2026-09-04_tp_precursor.md`)

- **分母宣言**: 報告する全ての率(適合率・再現率・勝率・AUC・IC・t)に分母(母集団)を一文で明記する。
  分母が運用時に部品が動く母集団と異なるなら、その差を数字で示す。
- **整合性テスト**: 同じ効果を測る2指標(例: AUC と状態内 recall@閾値)が食い違ったら、報告せずにまず
  母集団・定義の差を探す。原因を特定するまで結論を書かない。
- **対照は仮説の反事実**: 対照を替える提案は「同じ問いへの答えか」を先に確かめる。全時刻無作為と状態内無作為の
  両方を計算して併記する。
- **撤回の手順**: 結論を動かすときは「前 → 後 → 誤りの型 → 変わったもの/変わらないもの」を1表で示す。
- **反証者レビュー(必須)**: 判定結果をオーナーへ報告する前に、リードの説明文を渡さない独立サブエージェントに
  PREREG・コード・数表だけを渡し、ポストモーテム §4 の10問(分母・対照・翻訳・相対/絶対・定義の副作用・
  データ妥当性・選択の汚染・ベンチマーク・一貫性・反証条件)に数値つきで答えさせる。致命が1つでもあれば保留。
- **標準手続き(2026-09-05 採用、既知正解テスト第 1 世代で 3 名とも判定 6/6・罠 4/4)**: 判定を「確定」と
  書けるのは、(削除済み文書) に従う**盲検再実装 2 名(下位 1 + 上位 1)**が判定クラスで一致した
  ときのみ。不一致なら**裁定 1 名**(両報告を読む)が決める。単独監査・未監査の判定は必ず「暫定」と表示し、
  実弾判断に使わない。maker 約定モデル(待ち行列・再クオート・上限 taker 決済)を含む判定は、その型の既知正解
  テストに合格するまで 2 名一致でも「暫定」。既知正解テストの合格基準は 感度・特異度・罠検出 ≥ 0.9
  ((削除済み文書))。手続き自体の改訂は、改訂後に既知正解テストを再実施してから有効。
