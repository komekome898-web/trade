# /owner-options — 空欄が出たら、案を出して止まる

**オーナー逐語(L-168)**:
「**「着手前の対応表に右が空の行があるとき、規則とゴールに則り案をいくつか提示し、
オーナーが選択するまで次の道具を呼べないようにする。」なら検討の価値はあります**」

**オーナーの選択(L-169)**: 「**→A**」= **全面停止。**
リードが提案した部分停止(案 B =「その行に依存しない部分は続行する」)は**採らない。**

## いつ使うか

1. **自己申告系**: §0.1 の対応表を書いたら、右が空の行があった。
2. **行動系**: `owner_options_gate.sh` が止めた
   (オーナーの発言以降、ゴールと逐語を一度も開かずに書き始めようとした)。

**2 の方が本体である。**1 は表を書かなければ発火しない — Compliance Gap の Theorem 2 が
「テキストからは検出できない」と言う channel そのもの。
2026-09-14 の失敗は、**1 が検出していたのに止まるところが無かった**という形だった。

## 手順(read-do。1 項目ずつ実行する)

1. **空欄の行を、そのまま引く。**リードの言い換えを混ぜない。
2. **`docs/PROJECT_GOAL.md` を開く。**(Read で。開いたことがログに残る)
3. **`docs/AUDITOR/OWNER_MODEL_SOURCE.md` で、関係する逐語を探す。**
   見つかったら、それは空欄ではない — 表の右に入れて、この手順を終える。
4. **見つからなければ、案を 2〜4 個作る。**各案に次を必ず付ける。
   - 何をするか(1 行)
   - **根拠**: `CLAUDE.md` の条項 か `PROJECT_GOAL.md` の記述(どちらか必須)
   - **代償**: この案を採ると何が悪くなるか
   - **リードに有利な案を推さない。**自分の停止を緩める側・自分の作業を楽にする側は、
     推奨を書かずに並べるだけにする(2026-09-14 の 33 本目の監査の指摘)。
5. **`docs/OWNER_STATUS.md` の「判断が要る項目」に積む(最大 3 件)。新しいファイルを作らない。**
6. **`.claude/state/awaiting_owner_choice` に、聞いていることを 1〜20 行で書く。**
   これが待ち状態の印である。`owner_options_gate.sh` がこれを見て**すべての道具を拒否する**。
7. **オーナーに、選択肢だけを見せる。**仕様を書き下ろしてもらわない(§0.1)。
8. **待つ。**オーナーが発言すると `owner_options_gate.sh` が印を消す。
   **リードが自分で消さない。**

## やってはいけないこと

- **「依存しない部分は続行する」**— 案 B であり、オーナーが採らなかった。
- **`.claude/state/awaiting_owner_choice` を自分で消す** — 待ちの解除はオーナーの発言だけが行う。
- **yes と言わせるための質問**(O-9)。案には必ず代償を書く。
- **案を 1 個だけ出して「これでよいですか」と聞く** — それは擦り合わせではなく承認の要求である。
