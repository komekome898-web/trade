# /owner-options — 空欄が出たら、その件だけ案を出して止める

**経緯**: L-168 でオーナーが「**「着手前の対応表に右が空の行があるとき、規則とゴールに則り案をいくつか提示し、オーナーが選択するまで次の道具を呼べないようにする。」なら検討の価値はあります**」、L-169 で A(全面停止)を選択。その機械 `owner_options_gate.sh` は L-468「**対策3.のフックはもう捨てましょう。薄々感じてましたが意味ないわ**」/ L-469「**両方消せ**」で削除。**2026-10-01、L-488 4(b) でオーナーが B(空行の件だけ聞き、依存しない作業は続ける)を選んだ。**

## いつ使うか

§0.1 の対応表を書いたら、右が空の行があった。

## 手順

1. **空欄の行を、そのまま引く。**リードの言い換えを混ぜない。
2. **`docs/PROJECT_GOAL.md` を開く。**
3. **`docs/AUDITOR/OWNER_MODEL_SOURCE.md` で、関係する逐語を探す。**
   見つかったら、それは空欄ではない — 表の右に入れて、この手順を終える。
4. **見つからなければ、案を 2〜4 個作る。**各案に次を必ず付ける。
   - 何をするか(1 行)
   - **根拠**: `CLAUDE.md` の条項 か `PROJECT_GOAL.md` の記述(どちらか必須)
   - **代償**: この案を採ると何が悪くなるか
   - **リードに有利な案を推さない。**自分の停止を緩める側・自分の作業を楽にする側は、
     推奨を書かずに並べるだけにする。
5. **`docs/OWNER_STATUS.md` の「判断が要る項目」に積む(最大 3 件)。新しいファイルを作らない。**
6. **オーナーに、選択肢だけを見せる。**仕様を書き下ろしてもらわない(§0.1)。
7. **待つ間、その件に依存する道具は呼ばない。依存しない作業は続ける**(L-488 4(b))。
   どの作業が依存するかは、空欄の行の答えで前提が変わるかどうかで決め、状態板に 1 行で書く。

## やってはいけないこと

- **yes と言わせるための質問**(O-9)。案には必ず代償を書く。
- **案を 1 個だけ出して「これでよいですか」と聞く** — それは擦り合わせではなく承認の要求である。
- **空欄の件に依存する作業を、答えを待たずに進める。**
