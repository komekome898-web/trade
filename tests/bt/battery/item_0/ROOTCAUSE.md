指摘の逐語は `docs/DISCUSSIONS/2026-09-23_backtest_env/item_0/battery/AUDIT.md`(4 回目の起動の監査 0#1〜0#5)。リードの処置は `docs/AUDITOR/VERDICTS/2026-09-23_backtest_env_run4_item0.md` の「リードの処置」4 項。
この回は場面集を作り直した(規則 1〜9 に合わせる。委任文 §3「項目 0 のやり直し」「規則に合わないものは流用しない」)。下の「直し」は、作り直したあとの今の形で、その指摘が再び起きない理由を書く。**機械で止める仕組みがあるものは、その試験の名前を書く。**

## 0#5-1 [止める] DEFINITIONS.md が scenes.py と食い違った(0#1 の b1-1 の再発)

- **根本原因**: DEFINITIONS.md の再生成が人の手順で、scenes.py を直したあとに走らせるのを忘れても何も止めなかった。前回の「2 回繰り返して差分が出ないことを確かめた」はその時点の確認で、その後の編集を見張るものではなかった。
- **直し**: `test_battery_item0.py::test_definitions_in_sync_with_scenes` を毎回の pytest に入れた(`gen_definitions.render()` が scenes.py から作る文と DEFINITIONS.md が 1 文字でも違えば落ちる。`python3 gen_definitions.py --check` も同じ突き合わせ)。場面の定義に道具の名前は書かない(`gen_definitions.py` の見出しの共通の規則)。

## 0#5-2 [止める] 能力の場面 v6・v7 が `hasattr`・`inspect.signature` で作りの形を数えていた

- **根本原因**: 能力の場面の期待を「その口があるか」で決めていた。口の有無は名前を置くだけで満たせるので、場面集の規則 1(呼んだ結果を正解と突き合わせる)・規則 2(振る舞いを試す)に反していた。v1・v4・v5 だけを直し、同じ形の v6・v7 に直しを広げなかった。
- **直し**: 場面集を観点 P0-1〜P0-7 ごとに作り直し、能力の場面は全部「その能力を使うと出るはずの観測値」を期待にした。P0-6 は発注→未決の数→取消→未決の数(p6-place-then-cancel、期待 1 → 0)・取消の知らせ・約定の数量、P0-7 は差し込んだ模型が返す値がそのまま出るか(約定の値段 12345.0・約定の時刻 T0 + 7 ms・費用 0.5・0・口座が記録した数量 [1.0])。名前や引数の有無を数える場面は 1 つも無い。`test_battery_item0.py::test_every_viewpoint_has_a_value_scene_and_every_scene_an_expected` と `test_grading_uses_expected_not_the_adapters_word` が場面の形と採点を見る。
- **変異体**: 前の `_fake_cap_claim`(観点 4 だけ)はやめ、`mutant.py` は新実装の中身を変えずに包んで 1 つの誤り(入力の流れの「受け取れる時刻」を「取引所の時刻」に差し替える)を入れる形にした。`mutant.py --check` と `test_battery_item0.py::test_mutant_core_delivers_early_and_nothing_else` が、変わるのが p4-received-time だけであることを見る。口の名前だけを偽る実装は、能力の場面で観測値が出ないので「正解と一致」にならない。

## 0#5-3 [聞く] barter-rs の再現が時刻をマイクロ秒止まりの `datetime` で持っていた

- **答え**: その型は一次資料から一意に決まるものではなく、場面係の実装の都合だった(一次資料は chrono の `DateTime<Utc>` でナノ秒を持てる)。委任文 §3「弱めもしない」に当たる弱めだった。
- **根本原因**: 再現の型を一次資料の型から写さず、手近な標準の型で書いた。
- **直し**: 旧 `opponents/barter_rs_repro.py` は消した。今の候補の集まり(`pool.tsv`)で barter-rs(61)は P0-1 と P0-3 にだけ入り、どちらも Basana が観点の場面を全部正解と一致させたので「上位互換」でスキップした(`opponents/CONSIDERED.md`、能力を 1 つずつ対にした)。今回の再現 `opponents/repro_33_execution_simulator.py` は、一次資料の `Timestamp`(int64 のナノ秒)を Python の int のまま持つ(型を弱めていない)。

- **根本原因**: 委任文 §3 の (b)「一次資料を読みに行く(読むだけで、取ってきたコードは実行しない)」を「構築して動かす」と読み違え、構築の手間を (b) の不足の理由にした。

## 0#5-5 [止める] 旧「観点 2-ティック」の 14 行が、未確認のまま無条件に「上位互換」と書いていた

- **根本原因**: 「上位互換」を、スキップする候補の能力を行ごとに挙げずに、相手の候補が持つ能力だけで言い切っていた。確かめきれていないという注記と、表のセルの断定が別々に置かれていた。
