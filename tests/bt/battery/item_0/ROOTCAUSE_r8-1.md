## i0-r7-03 [直す](LEAN の再現が、利用者の作れない購読の組を持つ)

### なぜ起きたか(根本原因)

1. **再現の範囲の始まりを、利用者の入口ではなく「購読ができた後」に置いた。**第 r6-3 回の再現は LEAN の「データの道」(購読・frontier・同期・Slice・OnData)を書き直し、購読を作る所(利用者の `AddCryptoFuture` から `LookupSubscriptionConfigDataTypes` まで)は場面集の側が場面の事象の型から組んだ。第 r7-1 回の i0-r6-04 の直しは「書き直した文を囲む条件も含めて 1 対 1」にしたが、その対象は**再現が引いていた範囲**(TimeSliceFactory・Sync・frontier・AlgorithmManager)の中の条件だけで、範囲の外(購読を作る道)に同じ問いを当てていない。第 r7-1 回に `data_manager_add` の注釈を書いたとき、626 行と 768 行を引いていながら、型が解像度から決まることを再現の組み方に照らさなかった。**同じ根の探しの空間を、自分が引いた行の一覧から作っていた**(LEAD_DESIGN.md §2 の「扱う場合の一覧」と同じ形)。
2. **「対象の型」を、設定の違う実行の和で決める規則にしていた。**第 r7-1 回の規則(DEFINITIONS.md 12 行)は「対象の型 = 同じ実行の p3-<型> の場面で、対象がその型の事象を戦略に届けた型」で、p3 の 6 場面が**同じ設定で**走ったかを問わない。p3-trade は約定だけ、p3-bar は足だけを入れるので、解像度で型が決まる対象(LEAN)でも各 p3 は通る。その和を型を測らない観点の場面(1 回の実行に複数の型を入れる)に使うと、1 つの設定では作れない組を要求し、adapter・再現がそれを組めば「対象の振る舞い」として採点される。VnPy では adapter の試しがそれを止めたが、止めたのは規則ではなく adapter の出来だった。
3. **帰属の定義(第 r6-3 回、DEFINITIONS.md 23 行)が「物」だけを見て「設定」を見ていなかった。**(b) は「場面の入力を adapter が対象の class で組んで対象に渡し、対象が届けた物は数える」と書き、入力と設定を組む自由に制限を置いていない。br6-1-1・br6-2-1・br6-3-2 は物の出所の穴だったので、直しは物の検め(型・届いた道)に集まり、**物が届く前に決まる設定**を誰が作ったかは検めの外に残った。

### この指摘の族に対する正の定義(定義 A = 監査役に先に通す段落)

**対象の振る舞いと数える物**: 場面の結果として対象に帰すのは、次の 3 つが全部成り立つ実行で出た物だけである。**(1) 設定**: その実行で対象が事象を届ける前に決まっている全部(入力の口と購読・型の組・同時刻の並びの引数・解像度・差し込んだ模型と口座)が、利用者が対象の公開の手段だけで作れる **1 つの設定**であること。場面集の側がその設定を作るときは、要素ごとに「利用者のどの公開の呼び出しがそれを作るか」を対象の配布物(再現なら一次資料)の行で示す。別々の設定でならそれぞれ作れる要素を 1 つの実行に寄せ集めたものは、1 つの設定ではない。**(2) 仕事**: 場面が測る仕事(事象に型を付ける・時刻を変換する・並べる・過去を読ませる・通知を作る・模型を呼ぶ)を、対象の配布物のコードが行ったこと。再現では、利用者の公開の入口から戦略の呼び出しまでの道の全部を一次資料の行に 1 対 1 で書き直した物(書き直した文を囲む条件を含む。書き直さない条件は、場面で成り立たない理由を行で示す)が行ったこと。場面集の側が行ってよいのは、場面の入力の値を対象の公開の入口の形に写すこと、公開の手段を呼ぶこと、公開の差し込み口に利用者の実装を渡すこと、返ってきた物を場面の語に写すことだけである。**(3) 届き方**: 戦略が受けた物は、戦略の 1 回の呼び出しが始まってから戻るまで(コルーチンなら最初に入ってから終わるまで)の間に、対象のコードが戦略に引数として渡した物、その中にあった物、母語のコードが渡した物、または戦略がその間に対象の関数を呼んで返ってきた物であること。**数えない物**: adapter・再現の外側が組んだ物(`dict`・関数・対象の class の実体)、公開の手段で作れない設定か設定の寄せ集めの下で出た結果、戦略の呼び出しの外で対象の関数を呼んで得た物、戦略が自分で貯めた値、場面集の側が呼んだ変換の値、一次資料の行に対応しない再現の工夫(条件の落とし・範囲の外を場面集の側で組んだこと)で決まった結果。これらで決まった場面は採点しない(結果なし、理由を残す)。**型を測らない観点の場面が使う「対象の型」は、この 1 つの設定の下で対象が届けた型の組であり、設定の違う p3 の結果の和ではない。**設定が複数ある対象(解像度など、公開の引数で型の組が変わるもの)は、設定ごとに p3 と型を測らない観点の場面を走らせ、どの設定で走らせたかを materials に記録し、表には場面ごとに最も良い結果を寄せる(委任文 §3「取りうる値を 2 つ以上走らせて全部の結果を記録」・場面集の規則 5)。この定義は新実装・当方の現状・調査結果の側・再現のすべてに同じく当てる。

## i0-r7-05 [直す](「受け取れた時刻 ≤ 今」を注文の通知について測る場面が無い)

### なぜ起きたか(根本原因)

1. **観点の場面の入力を、場面の入力の列(市場の事象)から作った。**P0-4 の 3 場面は、場面の入力に書ける物 = 市場の事象の列で「未来」と「受け取りの遅れ」を作った。注文の通知は対象が内部で作る事象で、入力の列に書けないため、場面係の頭の中の「事象」から抜けた。固定した要件 §1 の行は事象の型に「注文の受付/拒否/約定の通知」を含み、観点 P0-4 の文(「戦略が『受け取れた時刻 ≤ 今』の事象しか見えないこと」)は事象を型で限っていない。**観点の範囲を要件の名詞から列べる手順が無かった**(上の表のとおり、時計と通知は P0-3 と P0-6 にしか出ない)。
2. **「見る」の道を、事象の配達だけで考えていた。**通知が遅れるとき、未来が漏れる道は通知の事象そのものではなく、戦略が公開の手段で読む注文の状態(約定済みの数量・未決の数・状態)である(probe の 4 秒目の呼び出しで未決 1・約定 0.0 と読める = 新実装は漏らしていない。漏らす対象はここで 1.0 を読ませる)。P0-4 の p4-visible-at-step・p4-future-read-attempt は過去の市場の事象の読み出しだけを試し、注文の状態の読み出しを見る道に入れていない。
3. P0-6 は同じ読み出しを遅れ 0 の既定で測るので、受け取りの時刻と取引所の時刻が一致し、この欠陥は構造上そこで出ない。

### この指摘の族に対する正の定義(定義 C)

**観点の場面が覆う範囲**: 観点の場面が覆うべき範囲は、固定した要件の §1 の行と §2 のその観点の文に出る名詞の全部の組から列べた物である。事象 = §1 の型 8 種(約定・板の写真・板の差分・足・資金調達・清算・時計・注文の受付/拒否/約定の通知)、見る道 = 戦略の呼び出しに届く事象・発注と取消の呼び出しがその場で返す物・公開の手段で読む状態(過去の事象・注文の状態・約定済みの数量・未決の数)。観点の文が事象か道を限っていなければ、その全部がその観点の範囲に入る。場面係は、観点ごとに全部の組を列べ、場面にした組と、場面にしなかった組とその理由(固定した測り方より厳しくなる・その組では観点の性質が起こりえない、など)を DEFINITIONS.md の「場面にしていない観点・側面」に全部書く(書く表は定義から機械で作り、組の抜けを試験が落とす)。場面は、その組について観点の性質(例: 受け取れた時刻 ≤ 今)だけで結果が決まり、ほかの観点が測るもので決まらない形にする: 遅れは公開の設定の値でも差し込み口でもよい(P0-7 の差し込み口を持つかで決めない)。組に要る型が対象に無いときは、第 r7-1 回の型の規則(型が最低の数に足りない対象は対応なし、理由に p3 の結果)に従う。
