# BitMEX XBTUSD 1 分足 2017-01-01 〜 2021-12-31(1 秒足から作成。作成日 2026-10-02)

カード `c2_owner_xvenue_wick` の変種 (c) のシグナルの足として作った(`docs/RESEARCH/cards/c2_owner_xvenue_wick/CARD.md` の「変種と測る順」)。
`scripts/check_card.py` の市場の表では `bitmex:XBTUSD`(型 `backtest_data/bitmex_XBTUSD_1m_from1s_*/*`)に当たる。

## 出所

- 入力: `backtest_data/bitmex_trade_1s_XBTUSD/<年>/<YYYYMMDD>.csv.gz`(1,826 日分、2017-01-01〜2021-12-31)。
  その置き場は `scripts/fetch_bitmex_archive.py` が BitMEX の公開の約定アーカイブ
  (`https://s3-eu-west-1.amazonaws.com/public.bitmex.com/data/trade/`)から作った 1 秒足(同じ置き場の `MANIFEST.json`)。
- 入力の時刻 `ts` は秒の始まり、UTC、オフセット無し【事実: `scripts/fetch_bitmex_archive.py` 96 行
  `sec = row["timestamp"][:19].replace("D", "T")`。BitMEX の約定の timestamp の秒までを切り出したもの】。
  BitMEX の約定の timestamp が UTC であることは、BitMEX の資料では確かめていない【推定】。
- 入力の欠け: 入力の `progress.json` は 1,826 日すべてが `absent: false`(BitMEX が出していない日は 0 日)。
  日ごとの 1 秒足の行数は `progress.json` の `bars` と全日で一致した(年ごとの数は下の表。合計 78,744,359 = 入力の
  `MANIFEST.json` の `bars`)。

## 中身

| ファイル | 中身 |
|---|---|
| `bitmex_XBTUSD_1m_YYYY.csv.gz` | 年ごとの 1 分足(2017・2018・2019・2020・2021)。gzip の mtime は 0(同じ入力なら同じ md5) |
| `MANIFEST.json` | 年ごとの行数・最初と最後の時刻・md5・バイト数・検め(`checks`)・入力の数(`input`) |
| `MD5SUMS` | この置き場の全ファイル(MD5SUMS 自身を除く)の md5。`md5sum -c MD5SUMS` で照合できる |

### 列(列の名前と時刻の形は現物の置き場 `backtest_data/binance_BTCUSDT_1m_20170801_20231231/` と同じ)

`open_time,open,high,low,close,volume`

- `open_time`: 分の始まり。ISO-8601、UTC(`2017-01-01 00:00:00+00:00` の形)。その分の 1 秒足の `ts` の先頭 16 文字(分まで)。
- `open`: その分の最初の 1 秒足の `o`。`high`: その分の 1 秒足の `h` の最大。`low`: `l` の最小。`close`: 最後の 1 秒足の `c`。
  単位は USD(XBTUSD の値段)。
- `volume`: その分の 1 秒足の `vol` の和。**単位は XBTUSD の契約の枚数(1 枚 = 1 USD)であって BTC ではない【推定】**。
  現物の置き場の `volume` は BTC なので、名前は同じでも単位が違う。推定の根拠: 入力の最初の行
  `2017-01-01T00:00:36,968.49,...,vol=2000.0,...,n=4,max_size=1303.0` は、BTC なら 1 秒に 4 件で約 2,000 BTC(約 194 万 USD)に
  なり、1 件 1,303 BTC の約定を含むことになる。USD の枚数なら 2,000 USD で、こちらの方がありそうという読み。BitMEX の資料では確かめていない。
- 現物の置き場にある `quote_volume`・`n_trades`・`taker_buy_base` は作っていない(委任文で指定された 6 列だけ)。

### 取引の無かった分の扱い

**行を作らない(値を埋めない)。** その分に 1 秒足が 1 本も無ければ、その分の行は無い。直前の終値で埋めた行・出来高 0 の行は作らない
(出来高 0 の行は 0 行。下の表)。読む側は、行の無い分を「約定が無かった分」として扱う。
現物・先物の Binance の置き場は約定の無い分も行がある(`n_trades=0` の行)ので、この点は Binance の置き場と違う。

抜け(隣の行との差が 60 秒でない所)は下の表。抜けの原因(約定が無かったのか、取引所の停止・保守か)は調べていない【未確認】。

## 作り方

```
python3 scripts/build_bitmex_xbtusd_1m.py    # 年ごとの csv.gz と MANIFEST.json を書く(入力は読むだけ)
```

日ごとに読み、年ごとに書く(作った時の記憶の最大 約 382MB、所要 約 8 分)。`MANIFEST.json` は書き直されるので、その後に手で足した `load_check`・`seal_check` は消える。また `MANIFEST.json` は作った時刻 `built_utc` を持つので、作り直すと md5 が変わり、`MD5SUMS` の MANIFEST の行が合わなくなる(csv.gz は gzip の時刻を 0 にしているので変わらない)。作り直したら `MD5SUMS` も作り直す。
MD5SUMS は最後に `find . -type f ! -name MD5SUMS | sed 's|^\./||' | sort | xargs md5sum > MD5SUMS` で作った。

## `bot.bt.data.load_reference` で読めること(2026-10-02)

`load_reference(".", {"name": "bitmex_close", "paths": ["backtest_data/bitmex_XBTUSD_1m_from1s_20261002/bitmex_XBTUSD_1m_2017.csv.gz"], "range_ns": [2017-03-01T00:00Z, 2017-04-01T00:00Z], "spec": {"format": "csv", "header": true, "delimiter": ",", "compression": "gzip", "time": {"columns": ["open_time"], "unit": "iso"}, "value": "close"}}, declarations={"bitmex_close": {"lag_ns": 60000000000, ...}})`

使えるようになる時刻 − 行の時刻 = 60 秒(全行)。`MANIFEST.json` の `load_check` に同じ値を手で足した。
