# bitFlyer FX_BTC_JPY 約定、統一 UTC μs スキーマ, 2026-07-23 .. 2026-09-06(P2-08b 主系列)

`scripts/normalize_bitflyer_executions.py` により、本リポジトリが保持する 2 つの生ソースを
1 つの UTC マイクロ秒スキーマ・日次 csv.gz に統合したもの。P2-08b の主系列(bitFlyer 側)。

## 入力ソース
1. **REST 31日スナップショット** `backtest_data/executions_FX_BTC_JPY_31d_20260823.csv.gz`
   (`/v1/getexecutions` の凍結コピー、取引所刻印 ms、id 有り)。実測範囲
   2026-07-23T12:09:27 〜 2026-08-23T12:25:34 UTC、982,000 行。
2. **WS テープ** `paper_logs/tape/executions_YYYYMMDD.csv.gz`
   (`scripts/extract_tape.py` による WS `lightning_executions_FX_BTC_JPY` 抽出、取引所刻印を
   サブミリ秒精度で保持、**id は含まれない**)。

## 主系列の切替規則(PREREG.md の暦封印境界 2026-08-23 00:00 UTC と同一)
- **2026-07-23 〜 08-22**: REST を採用(`source=rest`、`id` は実際の約定ID)
- **2026-08-23 〜 09-06**: WS を採用(`source=ws`、`id` は空欄 — WS 抽出には約定IDが無いため)

日ごとの一括切替であり、行単位の重複排除ではない(下記「REST/WS 重なりの確認」は別の診断)。

## ファイル
- `executions_YYYYMMDD.csv.gz`(46 日分、合計 **1,562,833 行**)。列: `id, ts_us, side, price, size, source`
- `overlap_check.csv` — REST と WS が両方存在する 4 日間(2026-08-20〜08-23)の突合診断
- `gaps.csv` — 採用系列(上記切替規則後)を通した 5 分超の無約定ギャップ、88 件

## REST/WS 重なりの確認(2026-08-20〜08-23、overlap_check.csv)

| date | 重なり窓(UTC) | REST 件数 | WS 件数 | 差 | WS 欠け率 |
|---|---|---|---|---|---|
| 2026-08-20 | 06:13:26.885〜23:59:58.449(WS 開始が日中のため部分日) | 56,727 | 55,134 | 1,593 | **2.808%** |
| 2026-08-21 | ほぼ全日 | 102,962 | 101,051 | 1,911 | **1.856%** |
| 2026-08-22 | ほぼ全日 | 45,692 | 45,431 | 261 | **0.571%** |
| 2026-08-23 | 00:00:03〜12:25:34(REST 側がこの日で終了するため部分日) | 24,338 | 24,201 | 137 | **0.563%** |

→ **WS 欠け率は概ね 0.6〜2.8%**(タスク指示の「0.6〜1.9%」の実測値とほぼ一致。08-20 の 2.8% は
WS 記録開始直後の部分日で、既知の記録開始タイミングの影響を含む可能性がある)。

**手法上の注記(重要)**: 当初、`(取引所刻印をミリ秒に丸めた値, side, price, size)` の複合キーで
1件ずつ突合を試みたが、一致率が 20〜30% 程度しか出ず(見かけ上 70% 超の「欠け」)、原因は
bitFlyer の REST `/v1/getexecutions` と WS `lightning_executions` が**同一の約定でも部分約定の
分割単位が異なる**ため(1件の REST 行が WS では複数行に分かれる、またはその逆)と判明した。
WS は約定IDを持たないため真の1対1突合は不可能であり、上表は**重なり時間窓内の単純な件数比較**
(`docs/PHASE2/P2-08b/PROCUREMENT.md` の実測値と同じ手法)に切り替えた結果である。

## 既知欠陥(gaps.csv より)
- 88 件の 5 分超ギャップのうち、**43 件はメンテナンス窓(UTC 18:59〜19:12、±20分の遊び込み)と一致**
  (`is_maintenance_window=True`)。
- **2 件は 8〜10 時間規模の実際の記録断絶**(`is_maintenance_window=False`、`duration_s` > 30,000秒):
  - 2026-08-25T18:29:29 〜 08-26T02:55:00(8.42 時間)
  - 2026-08-27T17:57:09 〜 08-28T04:18:56(10.36 時間)
  これらは自宅PC側の WS 記録プロセス停止(推定、`docs/PHASE2/P2-08b/PROCUREMENT.md` に既出)。
  WS 由来区間(08-23 以降)にのみ影響し、REST 由来区間(07-23〜08-22)は影響を受けない。
- 残る**43件の非メンテナンスギャップ**は数分〜十数分規模の短い無約定区間(自然な閑散、または
  WS の短時間断続)— `gaps.csv` に全件記録。

## id 列の注意
- `source=rest` の日: `id` は実際の bitFlyer 約定ID(整数)。
- `source=ws` の日: `id` は**空欄**(WS 抽出に約定IDが含まれないため)。ユニークキーとして
  `id` を使う処理は WS 日には機能しない(`(ts_us, price, size, side)` を近似キーとして使うこと、
  ただし上記の部分約定分割の問題により厳密な一意性は保証されない)。
