## 1. 形

- すべての価格・数量・率・金額は `fractions.Fraction`(正確な有理数)。浮動小数の丸めの差が答え合わせに混ざらないようにするため。受け取る型は int・str・Fraction・float(float は 2 進の値のまま `Fraction(float)` で変換)。bool は拒む。
- 時刻は int のナノ秒だけ(float・bool・str は拒む。int64 の範囲外も拒む)。
- **挙動を変える選択のうち、要件の文が決めていないものは、全部「既定値の無い必須の引数」にした。**呼ぶ側が選ばないと動かない(試験 `test_required_parameters_have_no_defaults` が 2 つの入口の全引数について確かめる)。参照実装が勝手に 1 つを選んで、それを正解のように見せないため。
- 入口は 2 つ: 事象の参照実装 `event_sim.simulate`(約定・板の写真・資金調達・足・時計の事象)と、足の参照実装 `bar_sim.run_bars(bars, signals, options)`(足のバックテスト。2026-09-26 に場面集の規則の文 R-T〜R-O だけから書き直した = §3・§7・§10)。

## 7. 入口の形(項目 4 の作業者が第 2 段で新エンジンと全格子で突き合わせる口)

```python
from bot.bt.reference.bar_sim import run_bars, RefusedConfig
run = run_bars(bars, signals, options)      # 3 つとも位置引数、既定値なし
```

- `bars`: 足の列。各足は `(始値, 高値, 安値, 終値)` の 4 つ組か `{"open", "high", "low", "close"}` の dict。値は int・str(10 進)・`Fraction`・float(`repr` の 10 進として読む)。時刻は受けない(規則は足の番号と `bar_seconds` だけで決まる)。
- `signals`: `{足の番号: "BUY" | "SELL" | "CLOSE"}` の dict、または足と同じ長さの列(`None` / `"HOLD"` = 何もしない)。足 i の合図は足 i の終値の時点のもの。
- `options`: 次の鍵が**全部**要る(欠け・余りは `RefusedConfig`):

| 鍵 | 型 | 意味(規則) |
|---|---|---|
| `capital` | 数 | 元本(R-A4) |
| `order_amount` | 数 > 0 | 発注額(R-A1) |
| `bar_seconds` | int > 0 | 足の秒(R-S1) |
| `costs` | dict: `taker_fee_pct`・`maker_fee_pct`・`slippage_pct`・`spread_pct`(4 つとも必須、%) | R-A2・R-C1 |
| `execution` | `"taker"` / `"maker"` | 建てと合図の決済の執行(R-T1 / R-M1) |
| `maker_timeout_bars` | `None` / int ≥ 1(maker なら必須) | 指値の寿命(R-M2) |
| `allow_short` | bool | R-T3・R-T4 |
| `swap_daily_pct` | 数 | 日率 %(R-S1)。0 で持ち越しなし |
| `stop_loss_pct` | `None` / 数 > 0 | 率の逆指値(R-P1・R-P3) |
| `take_profit_pct` | `None` / 数 > 0 | 利確(R-P1・R-P4) |
| `max_hold_bars` | `None` / int ≥ 1 | 保有の上限(R-H1) |
| `exit_execution` | `"signal"` / `"maker_tp"` | maker の利確を足すか(R-X1) |
| `maker_tp_pct` | 数 > 0(`maker_tp` のとき必須。`signal` のときは見ない) | R-X1・R-X3 |
| `entry_mask` | `None` / 足と同じ長さの bool の列 | R-E2 |
| `entry_sides` | `"both"` / `"long"` / `"short"` | R-E1 |
| `stop_mode` | `"fixed"` / `"wick_invalidation"` | R-W1(`wick_invalidation` なら `stop_loss_pct` は `None`、R-W4) |
| `stop_window_bars` | `None` / int ≥ 1(`wick_invalidation` なら必須) | R-W1 の N |
| `undecided` | dict: `wick_short_history` ∈ {`refuse`, `use_available`, `no_stop`}・`same_side_exit_signal` ∈ {`keep`, `replace`}(2 つとも必須) | §4 の U1・U2 |

- 返り値 `BarRun`:
  - `fills`: 約定の列(起きた順)。各 `Fill` = `bar`(約定の足)・`side`(`OPEN_LONG` / `OPEN_SHORT` / `CLOSE_LONG` / `CLOSE_SHORT`)・`price`・`size`・`fee`(`Fraction`)・`liquidity`(`taker` / `maker`)・`reason`(`signal` / `entry_limit` / `exit_limit` / `stop_loss` / `take_profit` / `maker_tp` / `wick_invalidation` / `max_hold`。読むための欄で、規則ではない)。
  - `pnls`: 往復ごとの実現損益(決済の順、`Fraction`、R-A3)。
  - `equity`: 各足の終値の時点の資産(足と同じ長さ、`Fraction`、R-A4)。
  - `missed_fills`: 取り逃しの数(int、R-M5)。
  - `trades`(閉じた往復の詳細)・`open_trade`(終わりに開いている建玉、無ければ `None`)。
  - `to_dict()`(分数を文字列に)・`to_floats()`(fills の 足・向き・値・数量と pnls・equity・missed_fills を float に。浮動小数の新エンジンと幅で比べるため)。
- 場面集の入力の形(`config`)との対応: 場面集の `config` の鍵の名は `costs`・`execution`・`maker_timeout_bars`・`allow_short`・`swap_daily_pct`・`stop_loss_pct`・`take_profit_pct`・`max_hold_bars`・`exit_execution`・`maker_tp_pct`・`entry_mask`・`entry_sides`・`stop_mode`・`stop_window_bars` と同じ名にした(DEFINITIONS.md の「入力の形」と場面の config に書かれた名。元本・発注額の鍵の名は DEFINITIONS.md に書かれていないので `capital`・`order_amount` と置いた)。場面集の「使わない」の値(0 など)をこの口の `None` に写すのは呼ぶ側。
- 突き合わせの使い方: 新エンジンと同じ入力を渡し、`to_floats()` と新エンジンの出力を場面集の判定の決まり(|a − b| ≤ 1e-9 × max(1, |a|, |b|)、足と向きは完全一致)で比べる。**違いが出たら新エンジンの欠陥として扱う(参照を新エンジンに合わせない)**(仕上げの委任文 §1 の条件 2)。`undecided` の 2 つは、新エンジンの振る舞いに合わせて選ぶのではなく、リードが決めた値を渡す(§8 の問い 1)。
