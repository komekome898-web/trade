## 1. 形

- すべての価格・数量・率・金額は `fractions.Fraction`(正確な有理数)。浮動小数の丸めの差が答え合わせに混ざらないようにするため。受け取る型は int・str・Fraction・float(float は 2 進の値のまま `Fraction(float)` で変換)。bool は拒む。
- 時刻は int のナノ秒だけ(float・bool・str は拒む。int64 の範囲外も拒む)。
- **挙動を変える選択のうち、要件の文が決めていないものは、全部「既定値の無い必須の引数」にした。**呼ぶ側が選ばないと動かない(試験 `test_required_parameters_have_no_defaults` が 2 つの入口の全引数について確かめる)。参照実装が勝手に 1 つを選んで、それを正解のように見せないため。
- 入口は 2 つ: 事象の参照実装 `event_sim.simulate`(約定・板の写真・資金調達・足・時計の事象)と、足の参照実装 `bar_sim.run_bars`(足のバックテスト、旧エンジン由来の挙動の要件 I4-8〜I4-14 のうち文が決めている部分)。

### 3.3 参照実装が決めたもの(要件の文に無い。§8 でリードに聞く)

- 建玉は同時に 1 つ。建玉中・建ての待ち中・最後の足の合図は無視して `ignored_signals` に理由(`in_position` / `entry_pending` / `no_next_bar` / `side_filtered` / `mask_at_signal_bar` / `mask_at_fill_bar`)を残す。
- 損切り・利確の値は、合図に書いた「距離」(`sl_dist`・`tp_dist`、値の単位)を約定の値から足し引きして決める(割合の約束は要件に無いため、単位の読み違いを避けて絶対の距離にした)。
- 指値の建てが有効な足を過ぎて埋まらなければ `missed_fills` に 1 を足す。有効な足の途中でデータが尽きたら数えず `window_cut_by_end` と記録する。**旧エンジンの `missed_fills` と同じ数え方かは確かめていない**(要件 I4-16 の文だけでは決まらない)。
- 評価額(足ごと)= 初期資金 + 閉じた取引の損益 + 開いた建玉の終値での評価 − その建ての手数料。
