# 委譲研究ラウンド2 統合報告(2026-08-20 第7報)

リード(Fable 5)が仮説設計と審査、サブエージェント(Sonnet/Opus)が実行した第2ラウンドの総括。

## 1. アンカー乖離逆張り — 2回の事前登録検証を経て棄却・退役

- v1(21日): イベントスタディはw=60分でのみ仮説どおり(乖離+2.5σ→60分で-19.5bps)だが、戦略はストップ0.5%(エッジの10倍)と決済設計の不整合で失敗
- v2(30日、7月の未使用9日を含む・60分時間決済・ストップなし・事前登録): **Train+Val全構成マイナス**(残余≒往復コスト)。OOSのプラスは既知期間との重複であり証拠にならない(エージェント自身が指摘)
- 結論: 生のフェード効果はコスト6.3bpsを超えない。**退役**。副産物としてエンジンに `max_hold_bars`(時間決済)が正式追加(テスト7件)

## 2. 30日拡大サンプルでの候補再検定(追加9日は全選択に未使用)

- **フレッシュデータ追試に失敗した候補は落とす**原則により棄却。21日の「合格」は偶然と判断

## 3. 板不均衡 — 単独戦略としては不成立、フィルタ用途は係属

4時間の板記録(14,454秒)による初回本判定:
- 効果は実在・符号も理論どおり(買い板優勢→上昇、1秒先相関+0.14、6分スモークの逆符号はアーティファクトと確定)
- **条件付きドリフト(+0.29〜+1.35bps)が実測スプレッド2.22bpsを全ホライズン(≤30秒)で下回る** → 単独タカー戦略は経済的に死亡
- 係属: ①バーストスキャルの方向フィルタ用途、②30秒超ホライズン — 自宅の板記録が1〜2週間分に達した時点で判定

## 4. データ基盤の到達点と発見

- **bitFlyer公開約定履歴は直近31日まで**というAPI制限を発見(90日バックフィルは不可能)。フェッチャーは制限到達で優雅に打ち切るよう修正済み。長期履歴は自宅の15分毎増分収集が日々延伸する(すでに稼働中)

## 5. 実運転由来の改善(オーナー観察起点)

オーナーの3つの所感(成行が勿体ない・30秒固定への疑問・頻度不足)を実気配データで検証し、3つとも採用: スキャルパーは**指値エントリー(10秒タイムアウト)・保有60秒・閾値10bps**へ更新済み(詳細は該当コミットとresearch_scalp_opt.py)。期待改善: -2.8bps/イベント → +0.7〜+1.4bps、頻度+25%。加えてWindows固有のクラッシュ(状態ファイル書き込み競合が取引プロセスを道連れ)を修正 — 監視は本体を殺さない設計へ。
