# 委任表(オーナー承認 2026-09-06、L-009)。オーナーの関与を「週 1 回 30 分 + 月 1 回 1 時間」に固定する。

## 1. 判断の 4 種と決め方
| 種類 | 例 | 決め方 |
|---|---|---|
| 取り返しがつかない | 実弾の開始・増額、口座・資金の操作、新市場への参入、リスク上限の変更 | **オーナーのみ**。`docs/OWNER_STATUS.md` の判断が要る項目に載せ、明示の yes を待つ |
| 研究の判定 | 採用候補 / 棄却 / 保留 / 判定不能 | **自動確定**: 事前登録のバー・反証文・保留区分をそのまま適用。リードは判定案でなく「確定」を書く。オーナーは `docs/OWNER_STATUS.md` の判断が要る項目で拒否権(2 週間以内に異議が無ければ確定) |
| 問いの設定 | 次の単位の選択、封印の開封、反復の継続・停止、最終評価の実施 | **オーナーと相談**: 着手順は 暗号資産 → FX → 株(CLAUDE.md §5.3)。停止規則・開封規則は事前登録どおり自動。**枠組み(問いの立て方・族の切り方)は自動化しない** — 2026-09-08 の全捨てで、枠組みの誤りが最も高くついたと判明したため |
| 事実の訂正 | データの見落とし、古い前提 | 仕組みで減らす(§3)。残りはインシデントとして記録し費用として受け入れる |

## 2. 委任の範囲(この外に出たくなったら止まり、`docs/OWNER_STATUS.md` の判断が要る項目に載せる = 問いを変えない規則)
- 研究: フェーズ 2 仕様・雛形・格子の順序の範囲内は自動。新しい仮説の追加は資源登録簿からのみ、月次で提示。
- データ: 無料・公開・利用条件に反しない範囲の取得は自動。有料・ライセンス要のものは要約に載せる。
- 予算: 週間トークン 70%(全モデル・Fable とも)以内は自動。超過見込みなら作業を止めて要約に載せる。
- 実装: 研究基盤・監査・データ基盤は自動。発注系コードは dry-run までは自動、実弾の三重ゲート解除はオーナー。
- PC 側の手作業: 月 1 回にまとめる(`docs/OWNER_PROCEDURES.md`)。share_logs は定期実行に移す。

## 3. 事実の扱い
- 報告の各主張に **事実**(観測・出典あり)/ **推定**(計算・推論)/ **仮定**(未確認)の印を付ける。オーナーは裏を取らない。
- 「無い・できない」という否定的事実は `docs/NEGATIVE_FACTS.md` に日付・方法・賞味期限つきで登録し、期限切れは再確認なしに引用しない。
- 単位の着手前に「調達票」(必要データ → 入手経路 3 つ以上 → 到達確認の日付 → 欠け)を事前登録に含め、設計監査の前に
  **リード盲点監査**(盲検の監査者が「リードが探さなかったもの」だけを探す)を置く。

## 4. 週次要約((削除済み文書)、毎週月曜 日本時間 08:00 に自動作成)
1 ページ。項目: (1) 規則で確定した判定、(2) 進行中の単位と次の自動行動、(3) インシデントと事実の訂正、(4) 予算消費、
(5) **人間の判断が要る項目(最大 3 件、yes / no で答えられる形)**、(6) 自動停止基準への接近。

## 5. 月次見直し(1 時間): 範囲(残り単位の絞り込み)、予算、優先順位、委任表そのものの改訂。

## 6. 自動停止基準(該当したら `docs/OWNER_STATUS.md` の判断が要る項目の 1 件目に「休止提案」を出す)
- 3 か月連続で採用候補ゼロ。
- 週間予算超過 2 回。
- インシデント(事実の訂正)が月 3 件。
- オーナーが 4 週連続で要約に反応しない(委任の再確認)。
