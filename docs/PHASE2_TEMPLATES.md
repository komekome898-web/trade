# フェーズ 2 の雛形(事前登録・反復台帳・判定案)— 2026-09-05

`docs/PHASE2_SPEC.md` に基づく。研究単位ごとに `docs/PHASE2/<P2-nn>/` を作り、以下 3 文書を置く。
研究サブエージェントが読めるのは `PREREG.md` と `docs/PHASE2_TRIAGE.md` §4(仮説の転記)だけ。

## 1. `PREREG.md`(事前登録。実行前に凍結、設計監査を通す)

```

## データ
| ファイル(スナップショット名) | schema | 期間 | 封印(SEALED.json の seal_from_ts) | 既知欠陥(schema から) |

## コスト定数(constants.yaml のキーと source_type。assumed は不可)

## 停止規則
直近 3 反復の val 改善 < MDE、または反復 8 回。延長は理由付きでオーナー申請。
```

## 2. `ITER.md`(反復台帳。反復のたびに追記、削除禁止)

```
| 反復 | 日付 | 変更点(何を・なぜ) | 追加構成数 | 累計 N | train 主指標 | val 主指標 | val 改善 | 判断(続行/停止) | 実行ログ |
```
- 「val 改善」は前反復比。3 回連続で MDE 未満なら停止。
- 監査で指摘を受けた再テストも 1 反復として数える。

## 4. 設計監査のチェック(監査者に渡す 10 問の設計版)

1. 仮説文に数値・過去判定が混入していないか。
2. 分母と n の見込み、MDE が書かれているか。効果の見込みが MDE を下回るなら着手前に棄却候補。
3. 封印が SEALED.json と一致し、開発セットと重なっていないか。
4. コスト定数が全て measured / primary_document か。
5. 対照 3 種が仮説の反事実になっているか。
6. 探索面 N0 が数えられているか。
7. 停止規則と反復予算が書かれているか。
8. 既知欠陥(schema)への対処が書かれているか(除外は印付けのみ)。
9. 執行様式の既知正解テストに合格しているか。
10. 反証文が具体的か。
