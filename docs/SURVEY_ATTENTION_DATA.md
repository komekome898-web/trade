# 机上調査: BTC「大衆注目度・加熱度」日次系列の入手性と、日次スケール注目効果の事前分布

日付: 2026-08-31。担当: 調査エージェント(机上のみ。発注・取引・コミット・バックテストなし)。
目的: 「注目ショック → 短期リターン」を後日**事前登録付きで**検証するための前段として、
(a) 日次粒度・長期履歴・無料/安価で取れる注目系列の台帳、(b) 日次〜週次スケールの学術的事前分布、
(c) 我々のプロトコル(Train/Val/OOS 一度きり・イベントクラスタ t≥2)で判定可能な n に届くかの見積り
を作る。

**本文書は推奨に留まる。go/no-go の決定はリードが行う。**

**汚染管理の宣言**: 本調査では**価格リターンとの突合せを一切行っていない**。§3 のイベント頻度は
注目系列**単独**の記述統計(自己の過去分位に対する Z スコア/比率)であり、リターンは一度も参照していない。
§3 の検出力計算は σ を**仮定値のまま**параメトリックに置いており、実データの σ は事前登録時に確定すること。

数値には全て出典 URL を付す。取得日は特記なき限り 2026-08-30〜31(UTC)。
見つからなかった数値は「**不明**」と書き、埋めない。実測は「実測」と明記する。

## 0. 結論(先出し)

> **(1) データは十分にある。無料・APIキー不要・単一リクエストで10年級の日次履歴が取れる系列が3本ある**
> (Wikipedia ページビュー 4,078日 / GDELT ニュース量 3,503日 / Fear&Greed 3,129日 — いずれも本調査で実測取得)。
> 収集は障害ではない。
>
> **(2) 束縛するのは統計的分解能である。**「注目ショック」をクラスタとして数えると、
> 定義を問わず **年3〜7クラスタ**にしかならない(実測)。10年で n=33〜80。
> Train/Val/OOS 3分割後の OOS は n≈10〜25 になり、我々の判定バー(クラスタ t≥2)に対して
> **必要効果サイズが 0.7〜1.4%/日**になる。これは文献が報告する最大の効果(§2、0.03〜0.3%/日相当)の
> **2〜10倍**であり、**離散イベント設計は事前に検出力で閉じている**。
>
> **(3) 文献の事前分布は、我々自身の既存法則と一致して否定的である。**
> 本調査で最も設計が近い2本 —— Bleher & Dimpfl (2019、日次/時間足/週次、複数暗号資産、
> 一貫SVI構築) と F&G 2026論文 (2018-2025 日次 VAR) —— はともに
> **「リターンは予測できない / ボラティリティと出来高は予測できる」**と報告する。
> これは本プロジェクトが第25報(z)で独自に到達した法則
> **「規模については成立し、方向については成立しない」**の外部追認である。
>
> **(4) Fear & Greed 指数は「注目」系列ではない。** alternative.me 自身の公表する構成比は
> ボラ25% + モメンタム/出来高25% + BTCドミナンス10% = **60%が価格・出来高の変換**である。
> 外部注目に由来するのは SNS 15% + Google Trends 10% だけで、アンケート15%は**現在停止中**。
> 「リターンが ΔFGI をグレンジャー因果し、逆は成立しない」(2026年論文)は、
> **指数の設計からの必然**であって発見ではない。注目研究の入力に使ってはならない。
>
> **(5) 日次スケールでは、本プロジェクトを一貫して支配してきた「コストの壁」が初めて束縛しない。**
> bitFlyer CFD 往復 taker 5.8bps = 0.058% に対し BTC の日次変動は 2〜4%。
> つまり**この市場・この時間スケールは、過去34報とは別の判定基準で審査しなければならない**。
> 落ちる理由がコストから**検出力**に移る。

### 1.2 Wikipedia ページビュー(推奨筆頭)

**エンドポイント(実測で成功)**:

```
GET https://wikimedia.org/api/rest_v1/metrics/pageviews/per-article/
    {project}/all-access/user/{article}/daily/{YYYYMMDD}/{YYYYMMDD}
```

- 例(全履歴を**1リクエスト**): `.../en.wikipedia/all-access/user/Bitcoin/daily/20150701/20260829`
  → **4,078 行**、`{"timestamp":"2015070100","views":12957}` 形式。実測取得済み。
- `agent=user` を必ず指定(`all-agents` はボット/スパイダーを含む)。
- 日本語: `ja.wikipedia` / 記事名 `ビットコイン`(URLエンコード)→ 実測 4,078 行。

**開始日**: 2015-07-01。これは API の仕様であって記事の歴史ではない
([Wikimedia Analytics API](https://doc.wikimedia.org/generated-data-platform/aqs/analytics-api/reference/page-views.html)、
[Diff 告知 2015-12-14](https://diff.wikimedia.org/2015/12/14/pageview-data-easily-accessible/))。

**レート制限(2026年に新設)**: 準拠 User-Agent なしの匿名リクエストは **10 req/min**、
連絡先入りの準拠 UA を付ければ **200 req/min**
([Wikimedia APIs/Rate limits](https://www.mediawiki.org/wiki/Wikimedia_APIs/Rate_limits))。
実測: UA なしで 429、連絡先入り UA + 数秒待機で 200。全履歴が1リクエストなので実務上は非問題。

**遅延(実測・重要)**: 2026-08-31 00:10 UTC 時点で取得できる最新日は **2026-08-29**。
つまり **D-2**。**「当日の注目ショックを見て当日/翌日に建てる」戦略は Wikipedia では機構的に不可能**。
使えるのは D-2 の注目を D で使う設計(= 効果が2日以上持続することが前提)のみ。

**落とし穴(実測)**:

1. **恒常的減衰**。EN "Bitcoin" の年次中央値は
   2015: 8,319 → 2017: 27,578 → 2021: 16,310 → 2023: 5,266 → **2026: 3,082**。
   JA は 478 → 2,194 → 982 → **163**。
   サイクルの山と、検索エンジンの回答ボックス化による**構造的なウィキペディア離れ**が重畳している
   (現象の一般的記述: [The great decline in Wikipedia pageviews](https://vipulnaik.com/blog/the-great-decline-in-wikipedia-pageviews-full-version/))。
   → **水準で扱ってはならない。ローリング窓 Z スコアか比率でしか使えない**。
2. **JA は計数ノイズの床に近い**。2026年中央値 163 views/日 → ポアソン sd ≈ 12.8、CV ≈ 8%。
   「Z>2」の一部は純粋な計数揺らぎで発生しうる。
3. **記事名とリダイレクト**。`Bitcoin` / `Cryptocurrency` / `Bitcoin_Cash` は別系列。
   リダイレクト経由の閲覧は転送先に計上されない場合がある(要検証)。
   事前登録では**記事名を凍結**すること。
4. **ライセンス**: pageview データの正確な再配布ライセンスは本調査で**確認できず(不明)**。
   社内研究利用は問題ないが、公開配布前に要確認。

**2015年以前(2008-2015)の代替**:

| 手段 | 状態(実測) | 備考 |
|---|---|---|
| stats.grok.se | **死亡(HTTP 403)** | 2016年頃にソフト変更で破損。原典 Kristoufek 2013 のデータ源 |
| wikishark.com | 到達可(HTTP 200) | 後継を名乗るが**データ品質・出典は未検証(不明)** |
| **`dumps.wikimedia.org/other/pagecounts-raw/`** | **到達可。2007〜2016 年ディレクトリ実測** | **時間毎の生ダンプ**。自前集計が必要。**デスクトップのみ・モバイル除外**(2015年6月まで) |
| `dumps.wikimedia.org/other/pageviews/` | 到達可。2015〜2026 実測 | API と同じ定義の生ダンプ |

→ **2015年以前を接ぎ木すると定義が変わる**(モバイル除外 → 含む)。
本プロジェクトの再現性規律からは、**2015-07-01 を起点として接ぎ木しない**のが正しい。
(10.2年 = 十分に長い。§3 の結論は接ぎ木しても変わらない。)

### 1.4 Fear & Greed Index(注目系列としては**不適格**)

**エンドポイント(実測で成功)**: `GET https://api.alternative.me/fng/?limit=0&format=json`
→ **3,129 行、2018-02-01 〜 2026-08-30、単一リクエストで全履歴**。
欠測は 2件のみ(2日ギャップ×1、4日ギャップ×1)。極めて扱いやすい。

**利用条件**([alternative.me/crypto/fear-and-greed-index](https://alternative.me/crypto/fear-and-greed-index/))
: 出典の明示的な帰属表示が必須(データ表示のすぐ隣)。商用利用は帰属があれば可。
なりすまし・混同を招くサービス化は禁止。

**構成比(同ページの公表値、実測抜粋)**:

| 要素 | 重み | 由来 |
|---|---|---|
| Volatility(30/90日平均比のボラ・DD) | 25% | **価格** |
| Market Momentum / Volume(30/90日平均比) | 25% | **価格・出来高** |
| Social Media(Twitter ハッシュタグ相互作用率) | 15% | 外部注目 |
| Surveys(strawpoll 週次) | 15% | **現在停止中(currently paused)** |
| Dominance(BTC 時価総額シェア) | 10% | **価格** |
| Trends(Google Trends 関連クエリ) | 10% | 外部注目 |

→ **公称で 60%、停止中のアンケートを除いて再正規化すると約 70.6% が価格・出来高の変換**。
これは「注目の代理」ではなく「価格のスムージング済み変換」である。

この構成から、2026年の実証論文の結論は**設計上の必然**として読める:
2018-2025 日次 VAR で **ΔFGI はリターンをグレンジャー因果せず、OOS 予測改善もゼロ。
逆にリターンが ΔFGI をグレンジャー因果する**。週次集約・VIX/EPU 追加・2021年前後分割・
高低VIX日・符号非対称のいずれにも頑健
([Do bitcoin returns move sentiment? Evidence from the crypto fear & greed index, ScienceDirect S305070062600006X, 2026-01](https://www.sciencedirect.com/science/article/pii/S305070062600006X))。

**判定: F&G は §4 の注目研究の入力候補から外す。** ただし §5 のダッシュボード計器としては
「人間が読む温度計」として有用(自作の Z スコアより一般に通じる)。

### 1.5 Google Trends(**推奨しない**)

3つの独立した障害が重なっている。

1. **日次データは9ヶ月窓限定**。9ヶ月〜5年は週次、5年超は月次。
   窓ごとに 0-100 に再スケールされるため、長期日次系列は**重複窓の接合**で作るしかない
   ([Eichenauer, Indergand, Martínez & Sax (2022), *Obtaining consistent time series from Google Trends*, Economic Inquiry 60(2):694-705](https://onlinelibrary.wiley.com/doi/full/10.1111/ecin.13049)
   / R パッケージ [trendecon](https://trendecon.github.io/trendecon/))。
2. **同一クエリでも取得のたびに値が変わる**(Google は標本を返す)。上記論文の主眼はこの
   **サンプリングノイズ**と周波数不整合の同時解決である。→ **本プロジェクトの再現性規律
   (同じスクリプトが同じ数を出す)と正面衝突する**。
3. **近年データ品質が劣化している**。プライバシー閾値による低ボリュームのゼロ化、
   日次サンプリングの揺らぎ、アルゴリズム更新による水準変化。
   「以前は安定していたクエリでも、ゼロとノイズが増えている」
   ([Djorno et al. (2025), *Restoring the Forecasting Power of Google Trends with Statistical Preprocessing*, arXiv:2504.07032](https://arxiv.org/abs/2504.07032))。
   同論文は**生の Google Trends を投入すると統計モデルの予測精度がむしろ悪化する**と報告。

**ツールの現状(2026年8月)**:
- `pytrends`: **2025-04-17 にリポジトリがアーカイブ**、初回コールで 429。実質死亡。
- **公式 Google Trends API**: 2025-07-24 にアルファ発表
  ([Google Search Central Blog](https://developers.google.com/search/blog/2025/07/trends-api))。
  **1年経った現在も申請制アルファ**で一般開放されていない。履歴は 1,800日(約5年)。
  ただし**リクエスト間で一貫したスケーリング**を謳っており、開放されれば §1.5 の (1) と (2) は解消する。
  → **監視項目**: 一般開放されたら Google Trends の評価をやり直す価値がある。
- 代替: `trendspy`(維持されている) / SerpApi・DataForSEO・Bright Data(有料)。
  いずれも**非公式スクレイピング**で、(2)(3) の問題は解決しない。

**さらに悪い性質: クラスタが年に集中している。** WP-EN 365日窓 Z≥2 の33クラスタの年別内訳は
`{2016:2, 2017:9, 2019:1, 2020:7, 2021:1, 2023:4, 2024:7, 2025:1, 2026:1}` ——
**3つの年(2017/2020/2024)が全体の 70%(23/33)を占める**。

**90日窓に短くすると年別分布は大きく平坦化する**
(`{2015:2, 2016:6, 2017:9, 2018:2, 2019:7, 2020:9, 2021:4, 2022:4, 2023:8, 2024:7, 2025:4, 2026:3}`)
—— これは「サイクルの山」ではなく「局所的な注目の跳ね」を拾っているため。
**判定可能性の観点では 90日窓が明確に優れている**(n が2倍、年間分散が良い)。

### 3.2 検出力: 必要効果サイズ

イベント平均リターンをクラスタロバスト t で検定する設計での最小検出効果:

> δ_min = 2 · σ_h / √n 、 σ_h = σ_1d · √h (h = 保有日数)

σ_1d(BTC 日次対数リターンの標準偏差)は**本調査では価格に触れないため仮定値**。
事前登録時に実データで確定すること。

**h = 1(翌日)、単位 = %/日**:

| n | σ=2.0% | σ=3.0% | σ=4.0% |
|---|---|---|---|
| 20 | 0.89 | 1.34 | 1.79 |
| 30 | 0.73 | 1.10 | 1.46 |
| 50 | 0.57 | 0.85 | 1.13 |
| 65 | 0.50 | 0.74 | 0.99 |
| 100 | 0.40 | 0.60 | 0.80 |
| 500 | 0.18 | 0.27 | 0.36 |
| 4,000(全日) | 0.063 | 0.095 | 0.126 |

**文献の事前分布と突き合わせる**:

- Da et al.: +30bps / 2週 = **約 0.03%/日**(しかも断面、単一資産には移植不可)
- Kristoufek GT: 検索10%ショック → 2週で 0.8% = **約 0.08%/日**(週次・in-sample・n=113)
- Kristoufek WP日次: **効果なし**(無条件)

| 設計 | 到達 n | 必要 δ (σ=3%, h=1) | 文献の最大事前分布 | 判定 |
|---|---|---|---|---|
| 離散ショック(365日窓 Z≥2、単系列) | **33** | **1.05%/日** | 0.08%/日 | **13倍不足。閉じている** |
| 離散ショック(90日窓 Z≥2、単系列) | **65** | **0.74%/日** | 0.08%/日 | **9倍不足。閉じている** |
| 離散ショック(90日窓、WP-EN+WP-JA+GDELT 合算、重複除去後を仮に 120 と見積り) | ~120 | **0.55%/日** | 0.08%/日 | **7倍不足。閉じている** |
| **連続回帰(全4,078日、注目Zを連続説明変数)** | **~4,000** | **0.095%/日** | 0.08%/日 | **同桁。ここだけが測れる領域** |

### 3.3 プロトコル適用時の実際

本プロジェクトの規律(`.claude/skills/research-protocol`)は Train+Val で選択 → **OOS 一度だけ** → フレッシュデータ追試。
時系列3分割(例 50/25/25)を離散ショック設計に適用すると:

| 設計 | 全体 n | Train+Val | **OOS** | OOS でのクラスタ t≥2 の可否 |
|---|---|---|---|---|
| 365日窓 Z≥2(WP-EN) | 33 | 25 | **8** | **不可能**(n=8 では σ の推定すら不安定) |
| 90日窓 Z≥2(WP-EN) | 65 | 49 | **16** | **事実上不可能**(必要 δ = 1.5%/日) |
| 3系列合算・90日窓 | ~120 | 90 | **30** | 必要 δ = 1.1%/日 —— 文献値の14倍。**不可能** |

**加えてフレッシュデータ追試が不可能である。** 90日窓 Z≥2 は年6クラスタ = **2ヶ月に1回**。
n≥30 のフレッシュ標本を集めるには **5年**かかる。
S12(1.44回/日 → 約21日で n≥30)と比べると**判定の時定数が桁で違う**。

> **結論(§3): 離散「注目ショック」イベント設計は、データを集める前に検出力で閉じている。**
> これは効果が存在しないという主張ではなく、**我々の判定バーで判定できないという主張**である。
> 唯一開いているのは**全日パネルの連続回帰**(n≈4,000)であり、そこでも必要 δ は文献値と同桁 =
> 「測れるかどうかの境界線上」である。

### 4.2 探索を**始めるべきでない**理由(反対側の材料)

1. **§3 が閉じている**。離散設計は検出力で不可能、連続設計は境界線上。
   本プロジェクトが 34報で確立した「バーを下げない」規律に照らすと、
   **事前登録の時点で「判定できない」と分かっている仮説**を係属登録すべきではない。
2. **文献の事前分布が否定的**。しかも最も設計が近い2本(Bleher & Dimpfl 2019 / F&G 2026)が
   周波数を揃えて否定している。
3. **フレッシュデータ追試に5年かかる**(§3.3)。汚染管理された再検証の経路がない。
4. **方向の否定は自前でも証明済み**。第25報(z)の3,008セル面で
   「方向は推定可能な n で全特徴 lift 0.93〜1.16 に潰れる」。
   注目は新しい特徴ではあるが、**面の外に出る理由がない**。
5. **日次スケールでコストは束縛しない**が、それは「勝てる」を意味しない。
   コストの壁が消えると**検出力の壁**が現れるだけである(§0-(5))。

### 4.3 もし着手するなら、最小コストの順序

コストの小さい順に3段。**各段で落ちたら止める**。

1. **第0段(半日、汚染なし)**: WP-EN / WP-JA / GDELT の3系列を取得し、
   **系列間の相互相関のみ**を測る(価格には触れない)。
   3系列が実質1系列(相関 >0.9)なら「合算で n を増やす」経路が消え、§3.3 の最良ケースも閉じる。
   → **この1点だけで go/no-go が決まる可能性がある。最優先。**
2. **第1段(事前登録が必要)**: 連続回帰で **注目 Z → 実現ボラ**(方向ではない)。
   期待は「肯定」。肯定してもそれは既知法則の再確認であり、**採用にはならない**。
   価値はゲートとしての順序安定性(第25報の「順序だけが不変」則を注目軸で試す)。
3. **第2段**: 第1段でゲートとして順序が安定した場合にのみ、
   既存の係属候補(S12 等)に注目ゲートを重ねる形で評価。**単独戦略としては評価しない**。
