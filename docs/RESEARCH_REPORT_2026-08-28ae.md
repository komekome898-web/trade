## 2. 訂正(リードの誤り)

PREREG §0 に書いた「利益単位 = (2.0−0.8)×vola」は**誤り**。原典の `exit_setting=0.8` は
**参照されない死にコード**で、実際に使われるのは `step_exit=0.8` — TPは中心からではなく
**建値から** 0.8×vola/k(按分)。凍結した族は原典の忠実移植(実測 width/vola が設計値
0.8/k と一致)なので**検定自体は有効**だが、§0 の動機文は誤っていた。ここに記録して訂正する。

## 3. 機構の発見

### 3.1 按分TPの恒等式(本報の芯)

往復の粗利は width×k = **0.8×vola で在庫段数によらず一定**(実測中央値 0.80〜1.05×vola)。
一方、損失は k 単位すべてに乗る。実測: 勝ち90.5%×+5.31 rt-bps(平均k 2.20)/
負け9.5%×**−85.7 rt-bps(平均k 5.03)** → 期待値 −3.36 rt-bps(表と一致)。
**「収益性を平滑化する」按分装置は、取ったリスクと無関係に勝ちを固定する装置と同一物**。
在庫が深いほど勝ちは薄く、負けは重い — v37 の中核的な設計トレードオフ。

### 3.2 符号反転(ブレイクモード)は稼がない

ブレイク建て往復 −2.18 vs レンジ建て −1.21 bps/unit。ON は両ラダーで OFF より悪い。
最大損失源は forced-flip(逆向きブレイクによるレンジ在庫の成行解消、64往復・−6,500 unit-bps)。
「3段までTP抑制で勝ちを走らせる」は実在するが +598 unit-bps = 損失の15%どまり。
継続則との整合は方向として正しかったが、**フェード在庫を抱えたままブレイクを迎える構造**が
それを上回って食う。

### 3.3 「緩和=taker」は5秒スケール固有だった(第29報の法則のスコープ訂正)

40分スケールでは緩和決済の92〜97%が**maker で約定する**(中心が市場から遠いため
置き直しが突き抜けない)。それでも−10〜−29 bps/unit を失う — 死因は手数料ではなく
**逆行の大きさそのもの**。ad の法則は「短スケールでは緩和=taker、長スケールでは
緩和=makerだが逆行値幅で同じだけ失う」に精密化される。

### 3.4 史上最接近 — 損益均衡まで 1.13〜1.48倍

M2 は負けバケットを11.5〜64倍縮める必要があった。**M3 は 1.13〜1.48倍**。
平均化寄与も +5.4〜5.5 bps/unit と M2(+2.4〜3.5)を上回る(ただし notional 2.4倍)。
逆選択・capture は第26報を再現(cap+adv −0.87〜−0.97)。
maker建てでコスト床は払っていない — **本族はコスト負けではなく、按分恒等式(§3.1)と
負け尾(逆行継続)の「差」で死んでいる**。

## 4. 棄却の水準(§10)

- **機構水準**: 按分TPの勝ち固定恒等式(§3.1)— この装置を持つ限り、勝ちは在庫リスクに
  比例しない。ブレイク符号反転のレンジ在庫との構造的干渉(§3.2)。
- **点水準(未掃引)**: **按分の除去**(TP幅を 0.8×vola 固定 = 勝ちも k に比例)、
  band幅・段数・グリッド間隔、ブレイク単独機(レンジ在庫なしで符号反転のみ)。
  §3.4 の「1.13〜1.48倍」という距離は、按分除去という**1ノブ**が恒等式を直接攻撃する
  ことを考えると、機構的根拠のある追試候補である(登録判断はリードとオーナー)。
