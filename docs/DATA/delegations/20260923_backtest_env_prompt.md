## 3. 回し方(Workflow)
1. 項目 0 を「作る → 批評 → 盲検」の周回で先に仕上げる。
2. 項目 1〜12 を並列で回す。各項目: 要件を固定する → 資料係が比較資料を作る → 作る → 批評 → 盲検(組ごとに別の 3 体)→ 未達なら指摘を渡して作り直す。
3. 項目 13 を同じ周回で回す。最後に「欠けているものは何か」の批評家 1 体。出たものは新しい項目として同じ周回に入れる。

**完了の条件**: 1 項目の完了 = 圧倒の判定(§0 の最後の行)を満たした、または周回の上限か同じ未達理由 3 周で「未達」として止めた(未達は理由つきで報告する。完了と書かない)。全体の完了 = 項目 0〜13 がすべて完了 + 「欠けているもの」の批評家が新しい項目を 0 件返した + `PYTHONPATH=src python -m pytest` が全件通る。**「データ待ち」の層(例: JPX の板・ティック)は完了の報告に別立てで全部書き、その層は「データが届いたら同じ周回で検証する」とする。完了と混ぜない。****作業者 1 体の完了 = §6 の報告を返したとき。**

**根本的解決(L-407 C)**: 2 周目以降の作業者は、前の周の未解消の指摘 1 件ごとに「なぜ起きたか(根本原因)」と「どの構造を変えるか」を先に書いてから直す。**場当たりの直し(試験だけを特別扱いする・閾値や既定値をずらして通す・指摘の文言だけに合わせる・機能を外して要件から逃げる)は批評家が [止める] にする。**前の周から変わった構造が無い周(周回を稼ぐだけの周)は周回に数えず [止める]。同じ未達理由が 3 周続いたら、作業を止めて根本原因の分析をリードに返す。リードは設計で解けるものは設計を変えて新しい周回を起こし、この環境で解けないもの(データが無い・オーナーの判断が要る)だけを、理由と必要なものつきで「未達」として報告する。

**要件と判定の固定**: 1 周目の前に、その項目の要件(§2 の行 + 調査結果の該当行から引いた比較の観点)を 1 つのファイルに書いて固定する。**周回の途中で要件・観点・圧倒の判定を緩めない、後から厳しくもしない**(A-6 と同じ)。変えるのはリードだけで、変えたら記録を残し、その項目の盲検をやり直す。

**調査結果の側の選び方(弱い相手を選べないようにする)**: 調査結果の側の資料は 1 つの道具ではなく、**その項目の要素の印を持つ台帳の候補すべて**から、観点ごとに**段(機構)が最も高い機構**を寄せ集めたもの(1 つの道具より強い合成の相手)。候補は `docs/DATA/tools_catalog.tsv` の要素の列に印がある行を**機械で全部**抜き出す(人が足し引きしない)。選ぶのは資料係(作業者ではない)。候補の番号と `SCAN_2026-09-21_tools.md` の行を観点ごとに全部書き、要件のファイルと一緒に 1 周目の前に固定する。
**資料係(作業者とは別の者。項目ごと・周ごとに新しい者を起こす)**: 比較資料を作る。作業者は自分の資料を作らない(O-10)。**資料はすべて同じ雛形で作る**: 固定した観点ごとに 1 節、各節は「何ができるか / 既定で何が起きるか / 根拠(ファイル:行、SCAN の行、実行したコマンドと出力)」の 3 行以内。根拠の強さも揃える: 新実装に実行の記録を付けるなら、当方の現状にも同じ場面の実行の記録を付け、調査結果の側は調査班の実測の記録(SCAN の行)を使う。道具の名前・パス・当方の語彙を消す。**実データから出た数値は入れない**(§4)。

**批評家(項目ごと・周ごとに新しい者を起こす。前の周の指摘の一覧は渡すが、前の周で「直った」とされた点も自分で確かめ直す)**: 固定した要件と調査結果の該当行を手元に置き、**自分で試験を書いて壊しにいく**。出力は [止める] / [直す] / [示唆] つきの指摘と根拠(ファイル:行 か 実行したコマンドと出力)。「良さそう」で通さない。
