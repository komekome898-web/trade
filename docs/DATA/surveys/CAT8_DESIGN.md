## 4. 尺度

**段(順序のある目盛り)は 1 回目の前に決める**(オーナーの選択 L-502「**(3)案B**」。案 B の代償として、まだ道具を 1 つも見ていないので当方の位置を基準にした目盛りになりやすいことを示したうえでの選択)。

### 4.1 段(自動化と汎用性の段。**要素ごとに**付ける)

**段は、`印` を付けた要素ごとに 1 つ付ける**(8 列それぞれに段の列を持つ。`なし` の要素には付けない)。同じ道具でも、データ品質は段 4 でルックアヘッドは段 2、のように要素ごとに違いうるため。
**段は下から積み上げで決める**: その要素について、段 1 から順に条件を満たすかを見て、**条件を満たす一番上の段**を付ける。上の段の条件の一部だけを満たしても、その段は付けない(満たした部分は §4.2 の軸に原文で残す)。

| 段 | 名前 | 条件(その要素の機能について、一次資料に書いてあること) |
|---|---|---|
| 1 | 文書だけ | 手順・点検表・注意書き・例のコードとして書いてあるが、**道具の機能として呼べない** |
| 2 | 呼べる・判定は人 | 呼ぶと結果(差分・異常の一覧・再生の出力など)を出すが、**合否や検出を自分で判定しない**(人が読んで決める) |
| 3 | 自動で判定・枠の中 | 合否・検出・再生を**自動で**行うが、**その要素の対象**(下の表)は、その道具の枠組みの中のもの(その道具で書いた戦略・その道具のデータ形式・その道具のエンジン)に限る |
| 4 | 自動で判定・枠の外にも | 段 3 に加えて、**その要素の対象のすべて**(下の表)を、その道具の外から持ち込んでも(一般の Python の関数・CSV など広く使われる形式)掛けられる。対象の一部だけが外から持ち込めるものは段 3 とし、どれが持ち込めるかを §4.2 に書く |
| 5 | 基準を指定・結果を固定 | 段 4 に加えて、**次の 2 つの両方**を満たす: (ア) 判定の基準(許容誤差・閾値・検出の条件)を使う人が指定できる (イ) 結果を保存して次の実行と比べられる(回帰の検査として固定できる)。片方だけのものは段 4 とし、(ア)(イ) は段と別に §4.2 に記録する |

**要素ごとの対象**(段 3・4 の「対象」): E1a = 突き合わせる 2 つの出力 / E1b = 同じ種類の出力を出す計算に入れる入力(データと戦略・計算のコード)/ E2 = 検査するデータ / E3a = 検出する相手の計算・特徴量・戦略のコードと、それに入れるデータ / E3b = 混入を防ぐ仕組みを掛ける先のデータの流れ(結合・分割・特徴量の計算)と、それを使う戦略・計算のコード / E4 = 再生する記録データと、再生を受ける戦略・計算のコード / E5 = 固定・比較する実験(コード・データ・設定)/ E6 = その機能の原文が名指す対象。

- **段は道具の側の記述だけで決める**(当方が何を持っているかで決めない)。当方の位置は索引(§7)で、区分 8 の結果と並べて別に書く。
- **E6 の段の一貫性**: E6 の対象は開いた定義なので、リードは毎回の検収で E6 に段を付けた行を全部読み、対象の原文と段の根拠を並べて、同じ種類の対象に違う段が付いていないかを見る。
- 条件を決めるのに要る一次資料に届いていなければ `未判別`。段の列の値は `1`〜`5` / `未判別` / `-`。**`-` はその要素が `なし` のときだけ**。要素が `未判別` のときの段は `未判別`(確かめて無かったのか、まだ確かめていないのかを段の列でも分けるため。監査 8 回目の指摘 4)。
- 段の順序の根拠: 段 1→2 は機能として呼べるか、2→3 は判定を機械が出すか、3→4 はその道具の外のもの(道具の作者が用意していない関数・データ)に掛かるか、4→5 は使う人が基準を決め結果を固定して繰り返し使えるか。**どの境目も道具の側の性質で、当方が今何を持っているか(当方の位置)は入れていない。**順序の向き(上ほど良い側)は、プロジェクトの目標の文書の「人が決めるもの…と自動化できるもの…を分けて記録する」「② の資産は…手順と道具(…データ検査、再現ゲート…)」から取った: 上ほど、検証を人の手を介さずに回せる。**これは当方の目標(向き)であって当方の位置(基準点)ではない**が、目標に合わせて順序を決めていることは事実なので書いておく(監査 6 回目の指摘 2)。**外部の既存の枠組み(検証や試験の自動化の成熟度の段など)を調べて決めたものではない**(未確認)。**先に調べずに見せる理由と、その穴の塞ぎ方**: そうした枠組みを探すこと自体が区分 8(検証の道具)の調査の中身なので、1 回目の起動文の検索計画に「検証・試験の自動化の段・成熟度の枠組み」を入れて調査班に探させる。1 回目の検収でリードがこの段と突き合わせ、合わなければ段の変更として全行に当て直し、監査役に通し、オーナーに見せる。1 回目の時点では台帳の行が少ないので、当て直しの手間は最も小さい(推定)。
