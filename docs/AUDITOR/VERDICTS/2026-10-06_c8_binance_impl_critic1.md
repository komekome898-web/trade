## 問 1: bitFlyer の道具と Binance の口は同じか

- **[情報] 決定・約定・日の割り当て・損益の式は同じ**【事実: コードを読んだ】。
  - どちらも `SessionMeanRevert` → `run_card` → `run_v2.concat` → `pnl`(P = e × (次の次の足の始値 ÷ 次の足の始値 − 1) × 10,000。空の足は飛ばす)→ `daily_rows(p, "Asia/Tokyo")` → `light_b2.measure`(`diag_c8` を含む)。
  - venue は名札だけです(`run.py` 177–179・212)。
  - 年ごとに区切ってつないでも持ち高が同じことは、試験 `test_run_outputs_carry_and_mid` が確かめています。`run_v2.boundaries` の年の境は読んでいません(未確認)。
- **違う所(どれも意図したもので、報告に書かれている)**
  - 取引の無い分: bitFlyer は値段の空の行を落とし、Binance は `n_trades="0"` の行を落とします。落とした後は同じ意味です。
  - ずれた行: Binance だけの扱いで、落とします。
  - 足したもの: 中ほどの値の損益 `daily_mid.csv`、取引の記録 `trades.json.gz`、またぎの日の一覧 `boundary_carry_days.csv`。
- **[直すとよい・走らせる前に決める] 値段 = 平均のときの持ち高が bitFlyer と違う**【事実】
  - カードは「平均ちょうどなら 0」です(`c8_session_mean_revert.py` 21 行)。1 円単位の値段なら和が正確なので 0 になります。0.01 USDT 単位の値段では、浮動小数の和の丸めで ±1 になります。
  - 作り物の足で確かめました(最初の 60 本を同じ値段にした):
    ```
    close 35698.72  nonzero exposures among 60 flat bars: 51 values [-1.0, -0.0]
    close 11868.04  nonzero exposures among 60 flat bars: 48 values [-1.0, -0.0, 1.0]
    close 3569872.0 nonzero exposures among 60 flat bars: 0 values [-0.0]
    ```
  - このため `bn_bars.py` 20–21 行の「単位は持ち高にも損益の bp にも効かない」と、試験 `test_unit_does_not_change_exposure_or_pnl` は、同値の無い作り物の上でしか成り立ちません。`diag_c8` の書き直しの確かめ(`np.cumsum`)も同じ丸めをするので、この違いを見つけません。
  - 本物の足でどれだけ起きるかは未確認です。たぶん少ない【推定】。
  - 直し方は 2 つあり、走らせる前にどちらかを決めて事前登録に書きます。
    - (a) 値段を整数のセントに丸めて渡す。
    - (b) 走らせた後に `run.npz` の close と持ち高から整数のセントで同値の数と P の和を数え、診断として並べる。(b) なら走らせは止めなくてよいです。
  - どちらでも、docstring の主張は直し、平らな区間を入れた試験を足します。

## 問 0 の答え(逐語)

この測りは、オーナーの目的の逐語 L-714「yes」・L-715「Binance の 1 分足(推し)」「A と B の両方(推し)」に答えている。戦略のロジックは写さずに `SessionMeanRevert` を import し、bitFlyer のときと同じ `run_card`・`pnl`・`daily_rows`・`light_b2.measure` にそのまま通しており、年で区切ってつないでも持ち高が同じことを試験が確かめている【事実】。ただし 1 か所、値段がセッションの平均とちょうど等しいとき、0.01 USDT 単位の値段では浮動小数の丸めで持ち高が 0 でなく ±1 になり、1 円単位の bitFlyer と決定が違う(作り物の足で確かめた。本物の足での頻度は未確認)。「限界」の語は対象の文書・コードに 0 件、「近似」は PREREG.md 55 行の「2.8 … 正規近似」だけだった(grep の出力による)。代わりや近似で測っている所ごとの答えは次のとおり。(1) 門を、門なしの 1 本の日ごとの損益の上で後から当てる形は、セッションが日本時間の日と一致し、区切りの足で持ち高を 0 にし、損益が決定の日に乗るので、経費の前では門つきのカードを回すのと同じになる【推定: コードを読んだ理由による】。省いたのではない。(2) 中ほどの値 = (高値 + 安値) ÷ 2 は気配の中値の代わりである。手元の `backtest_data` に 2019〜2023 年の Binance 現物の気配の置き場が無いことは ls で見た事実だが、外部に取れるデータがあるかは調べていない。オーナーに見せた枠組みにある並べ方である。(3) 2018 年を測らないのは、2017 年の量のある日が 124 日で、同じ定義の区分が作れないという調べた事実による。ただし、オーナーに見せた「2018-01-01〜・2,177 日」と違い、オーナーはまだ知らない。(4) ずれた行を落とすのは、データが無いからではなく選んだ扱いで、効くのは 2019 年の境だけである(委任先の報告では 1 日。私は確かめていない)。(5) 走らせる前の MDE は bitFlyer のばらつきを借りた仮定で、PREREG が仮定と明記し、走らせた後に出し直すとしている。
