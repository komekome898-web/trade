# 事前登録 — JEV-EVAL-001: Jev を監査の前段・行動記録の分類器として使えるか(Phase 1 影 + Phase 2 前段)

- 作成 2026-09-19。出所: L-209「添付ファイルを参考にjevの導入を検討してください」/ L-210「案 1」。
- 判断文書: `docs/DISCUSSIONS/2026-09-19_jev_adoption_review.md`。資料: オーナー提供 `jev_trade_integration_decision_for_fable_v2.md`。
- **これは取引戦略の研究ではない**が、`research-protocol` の型(実行前に固定・判定は一度・射程を書く)に従う。
- **監査の省略(Phase 3)は本単位に含まない。**本単位の結論は「前段として使うか / 使わないか」まで。

## 1. 問い(固定)
Q1(Phase 2・前段): Jev の原則ごとの確率が、監査役(`owner-auditor`、Sonnet)がこれまで見逃した欠陥を含めて**正解ラベルの「該当あり」を拾えるか**。指標 = 原則ごとの見逃し率(偽陰性 / 該当あり)と誤検出率(偽陽性 / 該当なし)。
Q2(Phase 2・前段): 同じ問いを **Haiku**(比較群 D)に投げたときと比べて、見逃し率が低いか。**単価は比べない**(どちらも 1 日 $1 未満で決め手にならない — 判断文書 §4)。
Q3(Phase 1・影): 行動記録(会話の記録を秘密情報を落として道具呼び出しの列にしたもの)に対する 6 問(`trace_review`)が、事故 I-010〜I-012 の起きた手を「該当あり」と返すか、正常な手を「該当なし」と返すか。**評価集合は 3 件しか無い**ので、Q3 は結論を出さず観測の記録にとどめる(射程)。

## 2. 評価集合(固定。数は 2026-09-19 の実測)
| 材料 | 件数 | 使い方 |
|---|---|---|
| `docs/AUDITOR/before/*.md` | 23 | 入力(訂正前の成果物) |
| `docs/AUDITOR/answers/*.md` | 22 | 正解(オーナーの訂正・指摘)。対応の付け方は `scripts/jev_eval.py build` の `manifest.json` に記録 |
| `docs/AUDITOR/KNOWN_ANSWERS.md` | 16 件 | ラベル付けの参照(どの原則に当たるか) |
| `docs/INCIDENTS.md` | 12 件 | Q3 の該当あり(会話の記録が残るのは I-010〜I-012 の 3 件) |
| 対照 | `IMPROVEMENT.md` 手順 3 と同じ対照 3 節 | 誤検出の測定 |

**ラベル**: `docs/AUDITOR/JEV/labels_2026-09-19.csv`(列 `file, has_answer, P1..P16`、0/1。**リポジトリに入れる** — ラベルは当方の記録から作った正解であり、ベンダーの性能情報ではない。実送信のときに `data/jev/eval/labels.csv` へ複写する)。**リードが `answers/` を読んで 1 回だけ付けた(2026-09-19、同日のうちに固定。付けたあとに変えない)。**付ける前に予測を見ていない(実送信は 1 件も行っていない)。根拠は `docs/AUDITOR/JEV/LABELS_NOTES_2026-09-19.md`。一次ラベル = `PRINCIPLES.md` の「対応 KA」、二次ラベル = 本文を読んで明らかに当たる原則。

## 3. 比較群(固定)
| 群 | 中身 | 目的 |
|---|---|---|
| A | 現行の監査役の結果(`VERDICTS/` と `EVAL_2026-09-11b` の捕捉 / 部分 / 見逃し) | 基準 |
| C(本命) | Jev(版付き ID を固定)の原則ごとの確率、しきい値 0.5 | Q1 |
| D | 同じ質問文を Haiku に投げて 0/1 を返させたもの(この環境に Anthropic の鍵が無ければ**未実施と書く**。実施できたら同じラベルで採点) | Q2 |
資料 §12.1 の B(Jev → 全件監査役)は、本単位では **A と C を同じ集合で採点することで代える**(監査役をもう一度全件回す費用を掛けない。L-204「監査をとめろ」の後なので、監査役の新規実行は本単位に含めない)。

## 4. 判定の規則(固定。判定は一度)
- 主指標: **原則ごとの見逃し率(C)**と、**全原則をまとめた見逃し率(C)**。比較対象は同じ集合での A の見逃し率(2026-09-11 の全体値 32.1%)。
- 「前段として使う」の条件(資料 §13 の式を本単位の量で): `Miss_C ≤ Miss_A` **かつ** 誤検出率 ≤ 0.5(それ以上なら絞り込みにならない)。**両方を満たさなければ「使わない」。**
- **MDE**: 集合は 23 件。全原則まとめの該当あり件数 n は ラベル後に決まる。n に対して、見逃し率の 95% 信頼区間(Wilson)の幅を事前に出し(`scripts/jev_eval.py score` が出す)、**区間が 32.1% をまたぐなら「不明」と書き、陰性にしない**(`CLAUDE.md` §5.2)。
- しきい値 0.5 は事前固定。**開封後に動かさない**(A-6)。感度として 0.3 / 0.7 の表も出すが判定には使わない。
- Q3 は判定しない(観測 3 件)。

## 5. 手順(固定)
1. 実装(委任、`scripts/jev/` + `jev_prescreen.py` + `jev_trace_export.py` + `jev_eval.py` + テスト)。実送信なし。
2. `jev_eval.py build` → `labels_template.csv`。**リードがラベルを付ける(手順 2 で固定)。**
3. 鍵をこの環境の環境変数に置く(オーナー)。`list_models` で版付き ID を取り、`config` ではなく本書に書く: **使う ID = `jev-1.13.0`**(2026-09-19 記入)。なお `list_models` が返すのは別名 `jev-latest` / `jev-preview` の 2 つだけで、版付き ID は一覧に出ない。両別名とも応答の `model` 欄が `jev-1.13.0` を返し、`jev-1.13.0` を直接指定した要求も通る(`jev-1.13` / `jev-9.99.9` は 400 `Unknown model` で弾かれるので、別名の素通しではなく実在の版)。本単位は別名ではなくこの版付き ID を指定して送る。
4. `jev_eval.py run --model <ID>`(C)。D は鍵があれば同日に。
5. `jev_eval.py score` → 表。**表の数値は `data/jev/eval/`(gitignore 済)に置き、リポジトリには「使う / 使わない」の結論と信頼区間の幅だけ書く**(MCA §2.3(f))。
6. Phase 1(影): `jev_trace_export.py --review` を I-010〜I-012 を含む会話の記録(残っていれば)と、正常な 2 会話に当て、観測を記録。
7. 結論を `docs/AUDITOR/JEV/RESULT_2026-09-XX.md` に(数値なし)。オーナーへ報告。

## 6. 秘密情報・送信の規則(固定)
- 送るのは `redact` を通し `assert_clean` が通った本文だけ。**1 件でも型に当たれば送らない**(判断文書 §6)。
- 送らないもの: `.env`、会話の記録の生、`paper_logs/`、口座・注文・建玉に関わるログ。
- 呼び出しの記録は `data/jev/calls_*.jsonl`(本文なし、sha256 と使用トークンだけ)。
- モデルは版付き ID を固定して送り、応答の `model` を記録する。

## 7. 射程(何を測っていないか)
- 監査役の**再実行**はしない(A は既存の結果)。「前段があったときに監査役の見逃しが減るか」(資料 §15 の本来の問い)は**本単位では測れない**。測るのは「前段単独で正解ラベルを拾えるか」。
- 23 件は小さい。原則ごとの該当あり件数が 3 件未満の原則は「不明」。
- ラベルはリード 1 人が付ける(盲検ではない。事例名は伏せない)。
- Q3 は 3 件で結論を出さない。

## 8. 止める条件
資料 §17.2 + 判断文書 §6(redaction の型に 1 件でも当たれば停止 / 応答待ちで作業が止まったら外す)。加えて: 費用が本単位で $5 を超えたら止めて報告(概算の上限。23 件 × 6 万字 ≈ 40 万トークン ≈ $0.02 なので通常は届かない)。
