# 監査役の既知解集合(KNOWN_ANSWERS)

**目的**: L-104 で提案され L-105 で条件づけられた「オーナーをパーソナライズした AI 監査人」の
導入条件(L-104)は、過去の介入を既知解の検査集合にし、監査役が指示なしにそれらを捕まえる割合を
測ることだった。本書がその検査集合(現時点で 16 件)。

**読み方**: 各ケースは (1) オーナーの介入が起きる**前**にリードが出していた成果物(引用または
`file + section + commit`)、(2) オーナーの発言(原文)、(3) そこから取れる原則(オーナー自身の
言葉に近い形で 1 行)、(4) 失敗の型、(5) 「before」だけを読んだ監査役が出すべきだった問い、の 5 点。
**過去の検証結果の当否そのもの(相場についての主張)は再掲しない** — CLAUDE.md §5.1 の全捨てに従い、
ここで再掲するのは**手続き上の欠陥**(用語・網羅性・報告の形式・調査の有無)だけである。

「before」がこの作業ツリーに残っている場合はコミットと該当箇所を直接指す。無くなっている場合は
`docs/AUDITOR/before/<id>.md` に該当箇所を復元して保存した(出典コミットを明記)。

失敗の型の凡例: **データ取得可否 / 用語・定義 / 測定と登録の不一致 / 報告の形式 / 網羅性 /
なぜの欠落 / 外部調査の欠落 / その他**

- **監査役が出すべき問い**: 「この『取れない』行は経路由来のエラー(4xx・接続断)を根拠にしていないか。

## 用語・定義(「意味を変えて使い回す」)

### KA-04 — 出典: L-047 / I-004

- **Before**: `docs/PHASE2/K1/PREREG.md` §5.1・§5.2(コミット `fae8ec8` の親 `7367fb3`)。
  `sd` という同じ記号を①全足・符号なし ②シグナル足・符号なし ③1取引・符号あり(主指標そのもの)の
  **3つの量**に使い、古い定義文を消さずに追記していたため、同じ節に矛盾する定義が同居していた。
  手数料の出所も「一次資料」→「オーナーの記憶」と 2 回とも誤って表示していた(実際はリード自身の記憶)。
  復元: `docs/AUDITOR/before/KA-04.md`
- **オーナーの発言**: 「突然 sd の定義を説明なしで変えたように見える。§5.2 はどちらの sd か。
  一度出した用語の意味を変えて使い回すことは、後で何度でも言い訳できる無限の論点ずらしの許容と
  同義。どういう意図か。理由によっては重大なインシデント」
- **原則**: 量が変わったら記号も変える。訂正は**古い定義を消してから**行う。数値には出所の
  3 分類(一次資料 / 実測 / 仮定)を付け、仮定には誰の仮定かを書く。リードの記憶は「仮定」であり、
  一次資料でも実測でもない。
- **失敗の型**: 用語・定義
- **監査役が出すべき問い**: 「この記号は文書全体で同じ量を指しているか(冒頭の定義と、実際に
  使っている表の値を突き合わせたか)。この数値の出所は一次資料・実測・仮定のどれで、仮定なら
  誰の仮定と明記されているか」

## 測定と登録の不一致(「事前登録の定義を測定が実装していない」)

### KA-05 — 出典: I-005(L-049 の指摘から発覚)

- **Before**: `docs/PHASE2/K1/PREREG.md` §5.2(コミット `eda6f3a` の親 `c713715`)。決済ルールを
  「無効化 または 反対シグナルの早い方」と定義していたが、準備測定は反対シグナルの枝を落とし
  無効化だけで `sd_trade` を計算していた(旧値 144.0/255.2/517.3 bp、1・3・30 分は未測定のまま
  「事前登録は完成」と表示)。この誤った保有分布(中央値 8 本)が L-046 の判断材料になっていた。
  復元: `docs/AUDITOR/before/KA-05.md`
- **オーナーの発言**: 「30 分足についてはなぜ検討から外れていますか？明確な理由がないように
  思います」
- **原則**: 準備測定も測定である。事前登録の数値を作る測定は、条項ごとに実装と突き合わせ、
  族の全水準を測ってから「完成」と呼ぶ。決定を覆す測定は独立に再現するまで根拠にしない。
- **失敗の型**: 測定と登録の不一致(トリガーは網羅性の問い)
- **監査役が出すべき問い**: 「この測定は事前登録の決済規則を条項ごとに実装しているか。族の全
  水準に値が入っているか、それとも一部が『未測定』のまま完成扱いになっていないか」

### KA-06 — 出典: L-046

- **Before**: `docs/PHASE2/K1/PREREG.md` §3・§4(コミット `7367fb3` の親)。保有 `h∈{1,2}` を
  掃引軸に固定し、`r = signal × (close[t+h]/close[t]-1)` で測定していた。これは意図マップ
  `KATSUO_INTENT_MAP.md` の I-8(「反発の根拠が壊れたら降りる」= ○ 意図どおり実装済み)という
  決済ルールを測定から黙って外すことに等しく、しかも族が大きいと指摘された際にリード自身が
  この軸(仮説の意味を最も担う軸)を削ることを提案していた。復元: `docs/AUDITOR/before/KA-06.md`
- **オーナーの発言**: 「何度読み返しても h=2 の根拠はわかりません。反発力からトレンド転換を
  予測するロジックですが、このままだと『即座に反転する指標』としての評価になりませんか？もし
  この h が MDE を出すために用意したものなら、本末転倒です」
- **原則**: 意図マップで ○(意図どおり実装済み)と判定した項目を、測定の単純化の都合で黙って

- **失敗の型**: 測定と登録の不一致
- **監査役が出すべき問い**: 「この測定の単純化(固定パラメータ・軸の削除)は、意図マップで ○ と
  判定した項目のどれかを暗黙に無効化していないか。族を小さくする提案は、仮説の意味を担う軸を
  計算量のために削っていないか」

### KA-07 — 出典: L-055(層3 独立監査 #3)

- **Before**: `docs/PHASE2/K1/PREREG.md` §6.2(コミット `e0e3c11` の親 `7d9bba3`)。帰無 N2 の

- **原則**: 「壊さない」と書いた性質は、実装して実データと比べるまで確認されていない。準備測定も

## 報告の形式(「平均だけで、総量を出さない」)

### KA-08 — 出典: L-075

- **Before**: `docs/PHASE2/K1/RESULT.md` 第 11 部(コミット `ea66554` の親 `27337a4`)。
  4 マス {原典, H1, H2a, H1+H2a} の**取引あたり平均 bp** と取引数 `n` を並べ、次周(H3)へ進むかを
  検討していた。年ごとの総損益(bp の合計)は表になく、「言えないこと」の一覧にも挙がっていなかった。
  復元: `docs/AUDITOR/before/KA-08.md`
- **オーナーの発言**: 「次に進む前に、取引当たりの平均だけでなく年ごとの総損益を出さないと
  いけません。平均が上がっても総利益が減るなら改良とは呼べません」
- **原則**: 平均が改善しても、取引数が減れば総損益(実際に得られる利益の総量)は減りうる。

- **監査役が出すべき問い**: 「平均(1 取引あたり)の改善が、総損益(年間の合計)の改善に対応する
  ことを確認したか。取引数が変化する比較で、平均だけを見て『改良』と呼んでいないか」

- **監査役が出すべき問い**: 「この報告は判定(棄却/採用)で終わっているか、それとも『どこで

## 外部調査の欠落(「内的状況だけで『できない』と言う」)

### KA-13 — 出典: L-105

- **Before**(作業ツリーに現存): `docs/OWNER_LOG.md` L-104 行のリード回答。監査役が効くのは
  「既知の型」だけで、改良の余地は「オーナーの過去の指摘の蓄積」だけに限定されていた
  — 公開の批評方法論・検証チェックリスト・監査エージェントのリポジトリ・Obsidian 等の外部知識基盤
  を調査も考慮もせずに、監査役の設計を内的状況だけで確定させようとしていた。
- **オーナーの発言**: 「その監査役の改良の余地が『私の指摘の蓄積』しかないのが懸念点です…
  そういった外的な要素を調査も考慮もせずに内的状況でのみできないというのは違うと思います。
  これは『データを調査せずに取れない』というあなたの悪癖そのものです」
- **原則**: 改良の余地・限界を答える前に、外部の改良源(公開の方法論・チェックリスト・
  リポジトリ・知識基盤)を調査してから答える。内的状況だけで「これしかできない」と言うのは、
  データ取得可否で禁じたのと同じ悪癖の別形。
- **失敗の型**: 外部調査の欠落
- **監査役が出すべき問い**: 「この設計・この結論の限界は、外部の選択肢を調査した上で確定して
  いるか、それとも自分の知っている範囲(内的状況)だけで『これしかない』と言っていないか」

  を事前登録に含める規則。すでに存在していた)。この規則があるにもかかわらず、外部データを

- **オーナーの発言**: 「取引データ収集に限らず、このプロジェクトは外部のデータを自発的に調査
  する仕組みが非常に弱いと感じます…市場調査を担う調査班が必要だと感じますが、どうですか？」
- **原則**: 規則(調達票)は存在していても、単位ごとの着手前に**実行**されていなければ意味が無い。
  規則の欠如ではなく、既存の規則をリードが実行していなかったことが原因。
- **失敗の型**: 外部調査の欠落
- **監査役が出すべき問い**: 「この単位の着手前に、既存の調達票の規則(`DELEGATION.md` §3)は
  実際に実行されたか。規則が『無い』のではなく『あるのに読まれていない』可能性を先に確認したか」
