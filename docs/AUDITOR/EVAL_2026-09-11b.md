L-112/L-113(オーナー指示)により、`.claude/agents/owner-auditor.md` への変更(`EVAL_2026-09-11.md`
§5 の変更案 1〜3)は**未適用**。本測定は**委任前の定義**(コミット `2cfb5bd`、`EVAL_2026-09-11.md`
の測定時と一字一句同じ)に対して行った。変わったのは検査対象(`docs/AUDITOR/before/*.md` の

## 0. 方法

### 0.1 変わったこと・変わっていないこと

- **監査役の定義**: 不変(`2cfb5bd` のまま)。
- **ブラインド**: `docs/AUDITOR/before/KA-01・02・04〜10・16.md` を分割し、訂正コミットの
  メッセージ・オーナーの発言・「何が誤りだったか」節を `docs/AUDITOR/answers/<id>.md` へ
  移動した。`before/` 側には復元した原文(と最小限の出典行)だけが残る。全 10 件を
  `指摘`・`オーナーの問い`・`訂正`・`→`・当該ケース自身の L-/I- id で機械的に grep し、
  該当ゼロを確認した(コミット `dcf2c29`)。
- **既知解**: リードが `docs/OWNER_LOG.md` 全行・`INCIDENTS.md`・`DISCUSSIONS/` を再走査し、
  新規 12 件(KA-17〜28、`docs/AUDITOR/KNOWN_ANSWERS_ADDENDUM.md`)を追加した(L-111 の指摘
  「既知解 16 件は本当に全部か」への対応)。本測定はこの 28 件全部と、対照 3 断片を測る。
- **呼び出し方法**: 前回と同一。`claude -p --agent owner-auditor --output-format json
  --permission-mode dontAsk --allowedTools Read,Grep,Glob,Bash -- "検査対象: <path>"` を
  1 ケース 1 回、独立プロセスで起動。プロンプトには検査対象パスしか渡していない。
- **判定**: 前回と同じ基準(`KNOWN_ANSWERS.md`/`KNOWN_ANSWERS_ADDENDUM.md` が記す想定問いと
  同趣旨の問いが、事後解説を単になぞるのでなく独立に現れているかを筆者が厳格に判定)で、
  捕捉/部分/見逃しの 3 値。

### 0.2 ブラインドの程度(今回の限界)

- 16 件のうち 10 件(KA-01・02・04〜10・16)は、修正後も**復元元コミットへのポインタ
  (「抽出元コミット: `xxx`」)と復元コマンド自体**を before ファイルに残している。これにより
  監査役が Bash で `git show` を実行し原典と再照合する行動を誘発しており、今回の測定では
  この再照合行動(P10)が多くのケースで**元の対象原則(P1/P3/P6/P9 等)を独立に当て直す代わりに**
  出力の大半を占めた(§4 参照)。これは`EVAL_2026-09-11.md`が指摘した「答え同居」問題とは
  別の、**ブラインド修正自身が導入した新しい回避先**であり、変更案 1 だけでは塞げない。
- KA-05・KA-08 の before ファイルは、原典の欠陥を**記述する文**(「総損益は表に無い」等)を
  訂正コミットのメッセージからではなく前回のブラインド修正時にそのまま残しており、
  指定された 5 文字列(指摘/オーナーの問い/訂正/→/L-id)の grep には引っかからないが、
  答えを実質的に先取りしている。この点は本測定後に気づいたもので、**今回未修正のまま**
  測定した(§6 限界に記録)。
- KA-19(復元見送り)・KA-24・KA-25・KA-26・KA-27・KA-28 の before ファイルは「何が誤りだったか」
  相当の分析文を伴う独自形式で、KNOWN_ANSWERS.md 本編の 10 件とは異なる構造上のブラインド
  問題を持つ(§4 参照)。
- 対照 3 断片は前回と同一ファイル(現行 `docs/PHASE2/K1/RESULT.md` 該当節はこの間変更なし)。
  ただし `docs/DATA.md` の BitMEX 行はコミット `9ff7e66` で訂正済みのため、前回検出された

## 4. 観察: 「before の再照合」という新しい回避先

28 件中、監査役の出力が**想定問いより先に、または想定問いの代わりに**「この before ファイルの
抜粋は原典と一字一句一致するか」「この記号・太字・矢印は原典どおりか」(P10 的自己言及)、
または「この抜粋・この数値は CLAUDE.md §5.1(全捨て)に違反していないか」という**成果物自身の
構造への疑義**を出したケース: KA-04(部分的)・KA-05・KA-06・KA-07・KA-08・KA-09・KA-15・
KA-16・KA-17・KA-18・KA-19・KA-20・KA-21・KA-22・KA-23・KA-24・KA-25・KA-26・KA-27・KA-28。
28 件中 20 件で程度の差はあれ発生している。

これは的外れではない——実際に KA-22 では原典の後続コミットが該当記述を撤回していたことを
正しく検出しており、KA-09 では本ブラインド修正が「→」を「/」に書き換えたことで原文の意味
(段階的絞り込み→並列選択)が変わった可能性を正しく検出している。**しかし**、この検査対象は
`KNOWN_ANSWERS.md`/`KNOWN_ANSWERS_ADDENDUM.md` の想定問いが検査対象としているものではなく、
監査役に与える入力(検査対象の before ファイル自身が「抽出元コミット」「git show で復元」
「何が誤りだったか」等の自己言及的な構造を持つこと)が生んだ**測定固有の副作用**である。
【推定】将来オーナーが実際の(現行の)成果物を監査役にかけるときはこの副作用は生じない
可能性が高い(実運用の成果物は「抽出元コミット」のような復元メタデータを持たない)。
しかしこの推定は検証していない。
