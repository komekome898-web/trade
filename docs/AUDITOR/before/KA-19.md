# KA-19 の Before — 復元しない(方針上の決定、KA-11 と同じ扱い)

出典: L-017(2026-09-08)。マチルダ v37(TaroCamp)の説明について、オーナーが
「入りと出が非対称: エントリは中心 ± 2.0 × ボラ、利確幅は 0.8 × ボラ。…グリッド間隔は
1.0 × ボラ、最大 7 段。この部分の分析がおそらく間違っています。コードを確認して下さい」
と指摘した、その**指摘対象そのものの説明文**(訂正前にリードが出していた matilda v37 の
分析報告)。

## 復元しない理由

L-017 の訂正前の説明文は、**2026-09-08 の全捨て(コミット `f2c0cee`)で破棄された
過去の検証結果・分析結果の一部**である。CLAUDE.md §5.1 は明確に定める:

> **git 履歴から過去の結論を掘り起こして根拠に使ってはならない。** 参考に読むこともしない。

この禁止は「相場についての結論を今の研究の根拠にする」ことを防ぐためのものだが、
git 履歴を当たる行為自体(`git show` 等でコミット内容を読むこと)を条件抜きで禁じている。
既存の `docs/AUDITOR/KNOWN_ANSWERS.md` の KA-11 も同じ理由で
「マチルダの第 31 報 af・『マチルダ線 完全終了』の原文」の復元を**明示的に見送っており**、
「全捨ての方針上、当否の数値を復元すること自体を避けた」と記している。

本ケース(KA-19)も同じ対象(マチルダ v37)・同じ全捨ての範囲内にあるため、
**同じ方針を適用し、before テキストの復元を行わない。**

## 復元しなくても KA として成立する理由

L-017 の失敗の型(「原典コードを行番号つきで再照合するまで、要約・説明を正しいと
称してはならない」)は、**オーナーの指摘文自体**(`docs/OWNER_LOG.md` L-017 行、現存)と
**リードの対応列が記す訂正内容**(死にコードの扱い・エントリ門の実際の意味・段数の出荷既定)
から十分に読み取れる。これらは「相場についての主張」ではなく**手続き上の記録**であり、
CLAUDE.md §5.1 の対象外(残してよいもの: 事故の記録・手順)である。
`docs/OWNER_LOG.md` L-017 行を before の代わりとして参照する。
