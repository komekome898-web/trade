# KA-20 の答え(before/KA-20.md に対応。出典 L-036)

## オーナーの発言

「私が PC を使ってあなたのバッチをデバックしているこの状況は異常です」

## 何が誤りだったか

`data\liquidations` は常駐の記録プロセスが継続的に追記する生ファイルであり、他の全ての
生データ(`backtest_data\auto_*` 等)が「コピーしてコピーを commit」する方式なのに対し、
清算ストリームだけが `git add -f` で**生ファイルそのものを追跡**していた。記録が動いている
限り作業ツリーは決してクリーンにならず、`git pull --rebase` が構造的に一度も通らない状態を
作っていた(2026-09-09、`restart_all.bat` が `[1/5]` で実際に停止)。その結果、修正コードが
PC に届かない状態が固定化し、オーナーが手元でバッチファイルのマージ・pull の失敗を
診断・対処する役目を負うことになった。

## 原則

リードが自分で実行・検証できない環境(Windows バッチ)に欠陥を置くと、検出は必ず
オーナーの手作業を経由する。運用上の欠陥は、リードが自分で実行・テストできる形
(Python・生成物比較・CI 相当の検証)に落とし込むことで防ぐ。

それとも人間の手作業(実行し結果を貼る)を最終的な検出手段にしているか」
