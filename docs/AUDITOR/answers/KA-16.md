# KA-16 の答え(before/KA-16.md に対応。出典 L-048)

出典: `docs/PHASE2/K1/PREREG.md` §0・§5.1(コミット `fae8ec8`)
訂正コミット: `83076b2`(「Take cost out of K1 entirely: the upstream unit measures signal strength, not P&L」)

## 補足(衛生除去分、2026-09-11。before/KA-16.md から移動)

**§0 は「執行を含めた損益は射程外」と明記していながら、§5.1 で執行コスト前提(B = +5bp)を
判定バーとして使っていた。** 同じ文書の中で射程と判定基準が矛盾していた。

## 何が起きたか(オーナーの質問、L-048 原文)

「archive.org の確認は不要。なぜならば当時の手数料は戦略に関係ない。目指している目標は
現在の取引所での取引なので、手数料無関係の成績を今の取引所に当てはめたときにはじめて
手数料との差し引きを評価できる…今の時点でコストを意識しても下流にいくにつれて意味が薄まる
or 足枷になる危険がある。」

## 何が誤りだったか(訂正コミットのメッセージより)

> K1's own scope section already said execution was out of scope, so the 2019
> fee schedule was never an input to it. The bar was contradicting the scope
> in the same document.

さらに、リードは指摘を受けた直後に**同じ誤りを一段ずらして再演**した
(「2019年の手数料の代わりに現在の bitFlyer の往復コストを MDE の床にする」と提案) —
外すべきは「その数字」ではなく「コストという入力そのもの」だった。

## 原則

単位の位置に合うコストだけを扱う。上流の単位(執行を含まない)ではコストを引かず、
水準も仮定しない。判定バーは下流の単位にだけ課す。外すときは移す先(下流のどの関門か)を書く。

下流(執行・コスト)の制約を上流(シグナルの強度)の判定に持ち込んでいないか」
