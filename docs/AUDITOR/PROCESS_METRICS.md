## なぜ「判定: 通す」を数えるのをやめるか

Urbach et al., NEJM 2014(オンタリオ州 101 病院、導入前 109,341 件 / 導入後 106,370 件):
病院側の**自己申告コンプライアンスは導入 3 か月で 98%**。しかし
合併症 3.86% → 3.82%(OR 0.97、P=0.29)、死亡 0.71% → 0.65%(OR 0.91、P=0.13)で、**効果ゼロ**。

Leape, NEJM 2014:
> it is not the act of ticking off a checklist that reduces complications,
> but **performance of the actions it calls for**.

一方、効果が出た Haynes et al., NEJM 2009 の実体は**プロセス指標**にあった:
予防的抗菌薬の適正投与 56.1% → 82.6%、患者・術野の口頭確認 54.4% → 92.3%、
**6 指標すべて実施 34.2% → 56.7%**。

→ **`ACTION_LOG` の「判定: 通す」の件数は、オンタリオの 98% と同じ性質の数字である。
`TREND.md` の成果の指標としては数えない。**(押し出しの関門が判定行を使うので、
`ACTION_LOG` の行そのものは残す。)

## 指標の定義(実装は `scripts/trace_metrics.py`)

「手(move)」= オーナーの発言 1 件から次の発言までの区間。
フックの催促・システム通知・`task-notification`・ハーネスの再開文は**発言として数えない**
(除外語の一覧は `trace_metrics.py` の `NOT_OWNER`。増減は差分に残る)。

| # | 指標 | 分子 / 分母 | 何を見ているか |
|---|---|---|---|
| **P1** | ゴール参照率 | 書き込みのあった手のうち、**最初の Write/Edit より前**に `PROJECT_GOAL.md` / `OWNER_MODEL_SOURCE.md` / `OWNER_INTENT*` を **Read で開いた**手 / 書き込みのあった手 | `CLAUDE.md` と `OWNER_STATUS.md` は毎ターン自動で差し込まれるので**分子に入れない**(入れると常に真になり飽和する) |
| **P2** | 対応表の提示率 | 最初の Write/Edit より前に「オーナーの原文の該当語」を含む返答を出した手 / 書き込みのあった手 | §0.1 の表を出してから着手したか |
| **P3** | 主張と出力の同居率 | 断定語を含む返答のうち、**直前が道具の出力だったもの** / 断定語を含む返答 | O-3 の機械化。断定語の一覧は `trace_metrics.py` の `CLAIM_WORDS` |
| **P4** | 逐語の即時貼付率 | 監査役の呼び出しのうち、**その直後の道具呼び出しが `ACTION_LOG` への書き込み**だったもの / 監査役の呼び出し | I-009 の機械化。O-4「後でまとめて出さない」 |
| **P5** | 1 手あたりの道具呼び出し数 | 中央値と最大 | ④ の閾値の根拠。McMillan 2026 の OR=0.944 は「生成関数 1 個ごと」で単位が違うため、**この体制の分布を 2026-09-28 までに測ってから閾値を置く**(A-12) |
| **P6** | 指摘の実物反映率 | 監査役の呼び出しのうち、**次の監査役の呼び出しまでに `ACTION_LOG` 以外の実物が Write/Edit されたもの** / 監査役の呼び出し | 「直したと書いた」対「直っている」の差。2026-09-14 の最も重い誤りがこれ |
| **P7** | read-do を開いた回数 | `docs/AUDITOR/READDO/*.md` を **Read で開いた**回数 | ⑤ が効いたかの出口。「あるのに読まない」(L-102 / L-103)を測る |
| **R4** | 解除ファイルの作成 | 道具の入力に `owner_unlock_` が現れた Write/Edit/Bash の回数 | ③(a) の穴の回避を**機械で**数える。**手で書かない** |

## 射程(何を測っていないか)

- **記録は 1 つの会話の JSONL に限る。**オーナーの PC(Windows、CLI)側の会話は含まない。
- **P6 は近似である(v2)。**「監査の後、次の監査までに `ACTION_LOG` 以外の実物が編集されたか」しか見ていない。
  **試して駄目だったこと(範囲と方法)**: 指摘が名指しした絶対パスと、その後の Write/Edit の
  `file_path` を突き合わせる案を検討したが、**監査役の指摘は行番号つきの引用で来ることが多く、
  パスが本文の散文中にあって構造化されていない**(`ACTION_LOG` の逐語は引用ブロック)。
  JSONL からパスを取り出すには自由文の解析が要り、**TRACE に自由文を入れないという設計と衝突する。**
  そこで「実物が編集されたか」という粗い近似にした。**「何も直さずに次の監査へ行った」は捕まえる。
  「別の場所を直した」は区別できない。**
- **R4 は道具の入力に文字列が現れた回数**なので、**試験で作ったもの・文中で言及しただけのものも数える**
  (2026-09-14 の初回値 7 は、`verify_gates.py` の一時ディレクトリでの作成と本文中の言及を含む)。
  **実際に効いた解除は `.gitignore` の `!.claude/state/owner_unlock_*` で差分に残る。**
  **2 つの出所が食い違ったら、差分の方を正とする。**
- **P3 の断定語は語の一覧による近似**で、意味を見ていない。語を増減すれば値が動く。
- **P1 は「開いた」ことしか見ていない。**読んで使ったかは見ていない
  (Delta 1141 の「challenge と response の間 1 秒未満」と同じ限界。
   **引用の存在は遵守の証拠にならない**)。
- **この指標自体、フックが走っていないと更新されない。**2026-09-14 の段 0 で、
  この実行環境ではプロジェクト側のフックが 1 本も走っていなかった。
  `trace_metrics.py` は**手で走らせても同じ結果を出す**ので、そこは切れている。
