## 2. 結論が変わったもの(重要な順)

1. **bitFlyer の taker コスト**。私が「往復 5.8〜7.9bps」として何十もの提案を棄却してきた数字は、根拠のない
   「スリッページ 2bps/脚」という仮定にスプレッドを足しただけだった。実測は往復 2.0〜2.6bps(手数料 0% +
   スプレッド 1.9 + スリッページ約 1)。3 つの独立監査が一致。
2. **S12(時計窓バースト順張り、いまペーパー中)の設計根拠**。「1 取引 +23.7bps、信頼区間が全て正」は再現せず、
   再計算は +12〜13bps で区間はゼロをまたぐ。約 1,190 通りの探索から最良を拾った場合に偶然出る値の範囲内。
   新しいテープではマイナス。
3. **maker(指値)の逆選択 6〜9bps**。実測は約 1bps。maker が儲からないという結論自体は待ち行列モデルで再現したが、
   理由付けが誤りだった。さらに監査 3 つが「クオート位置・待ち行列・保有上限」の違いで −1.7 / ≈0 / +0.9bps と
   割れており、maker の経済性は「明確に正ではない」までしか言えない。
4. **「時計窓は極値タッチの継続を増幅する」という法則**。信頼区間がゼロをまたぎ、窓の位置をずらすと偶然と
   区別できず、Binance の 210 日では符号が逆。機構ではなく選択だった。
5. **「レンジ端のタッチは反転ではなく継続」という法則と、FX のバリアレース棄却**。反転率の基準は 50% ではなく
   47.9〜48.4%(レースの幾何学がそう作る)。この基準で見ると「継続」の証拠はない。
6. **maker 設計の支配軸の順序**、**約定率 18%**(実測 9%)、**両側フロー窓の稼働率 11.5%**(定義次第で 8〜40%)。
7. **「短い時間スケールも長いスケールも taker と同じ」という法則**。保有上限を長くすると符号が変わる。
8. **嵐時計ブラケット(S9)** は「効果なし」ではなく「サンプル 16 件では検出できず」に格下げ。

## 3. 生き残ったもの(審査官の順位。基準は再現の強さ・検出力・コスト後の余裕・新鮮さ)
