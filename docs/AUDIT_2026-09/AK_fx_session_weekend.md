# Packet AK — FX session clock / weekend gap / intervention tail — blind audit

Claims: FXL1, FXL2, FXL5, FXL6, FXC5, FXR4, FXT1, FXT2. Budget used: 34 tool calls.
Script: `scratchpad/audit_AK.py` + `audit_AK_part2.py` (own implementation, no source scripts read).

## Data / denominators
- `backtest_data/fx_usdjpy_1m_20260822.csv.gz`: 1,640,160 rows, 2023-01-01 00:00 → 2026-08-21 23:59 UTC, 1-min OHLCV + `ask_close`. `ask_close` populated only 2026-07-23→2026-08-21 (37,440 rows) — spread claims verifiable for that 1-month window only, not the full 3.5y.
- 21.9% of bars are zero-volume/flat repeats (weekend closures + thin periods) — included in vol calc (real market feature).
- `backtest_data/fx_fundamentals_20260822/mof_feio_daily.csv` (MOF intervention register, Shift-JIS, 1991–2026): 3 intervention dates fall inside the price-data window (2024-04-29, 2024-07-11, 2026-04-30); the largest historical interventions (Sep/Oct 2022, ¥5.5–2.8tn) predate the data (starts 2023-01-01) and are **unverifiable from this dataset**.
- `backtest_data/fx_event_ticks_2015_2026/calendar.csv`: 100 BOJ dates; sampled 40 for tick-level drift check.
- `backtest_data/binance_BTCUSDT_1m_210d_20260820.csv.gz` (BTC side, 2026-01-22→2026-08-20, 302,404 rows): only 24 NFP/CPI/FOMC/BOJ events fall in this window (NFP 7, CPI 7, FOMC 5, BOJ 5) — smaller n than the claims' 16-19/19 or n=5, but overlapping population.
- Session buckets (own definition, not read from source): Tokyo 00–08 UTC, London 08–16 UTC, NY 16–24 UTC (non-overlapping 8h blocks — a simplification I had to invent).

## Controls
- **Hourly vol shape**: day-shuffle placebo collapses the 0.70-1.63bps hour spread to a flat 1.037-1.143bps band → real intraday structure confirmed to exist (direction of FXL1/FXL2 supported), independent of the magnitude/trough-hour disputes above.
- **Barrier race**: (i) iid-shuffled-return synthetic random walk through the identical race code → 49.76% revert (n=2500, matches theoretical 50% null exactly) — **the race code itself is unbiased**; (ii) short-horizon (=N, not 20N) rerun gives the same 68-95% revert / positive EV pattern, ruling out "long horizon lets any ranging market eventually revert" as the sole explanation; (iii) touch-frequency check: **20-25% of all 1-min bars register as a "touch"** (new N-bar high/low) at every N tested — this is the likely real driver (see 前提の誤り).
- **FXT1**: random-timestamp placebo → 0.475 mean rank (null), confirms event-conditioning (not just BTC's general vol level) drives the elevated rank.
- **FXT2**: baseline storm rate from 200 random forward-windows = 15.5%; all 4 event types sit somewhat above this but sample per type is only 5-7 — underpowered (MDE below).

## Translation to money / MDE
- Cost: task states 0.71bps round-trip; I could independently verify only the spread component from `ask_close` (median 0.245bps ex-UTC21, Jul23-Aug21'26 window) — order-of-magnitude consistent with the claimed 0.314bps spread leg, but the 0.4bps commission leg has **no config source in this repo** for USDJPY (only `FX_BTC_JPY` crypto-CFD fees exist in `config/products.yaml`) — unverifiable, used as asserted.
- FXC5: recomputed median gap 6.47bps = 9.1x cost (vs claimed 6x) — conclusion (gap≫cost) holds, multiple is bigger.
- Weekend-gap 1st-hour reversion (task's specific requirement, not itself a packet claim): mean signed reversion 4.35bps, t=5.54, 95% CI [2.81, 5.89], n=189 weeks (day/week-clustered — one observation per weekend by construction) — statistically robust and **exceeds cost gross**, but this is a distinct, unclaimed finding; net-of-realistic-slippage-at-reopen feasibility not tested here.
- Barrier race MDE at n=2500/cell, α=.05, power=.8 around 50%: ±2.8pp — the observed 68-95% is far outside this, i.e., not a power problem; the discrepancy with FXR4 is a **definitional** one, not a detection-power one.
- FXT2 MDE at n=5-7 per type vs baseline 15.5%: with n=5, a true rate would need to be ≈70%+ to be distinguishable from 15.5% baseline at conventional power — **the claimed "FOMC survives all controls, n=5" is not achievable at this n** even if true; likewise my "NFP/CPI elevated" reading is not fully powered either. Both FXT2 readings (claimed and mine) should be treated as suggestive only.

## 前提の誤り (assumption findings)

1. **premise**: FXR3/FXR4's "barrier race" touch = a meaningful range-edge event | **source**: FXR3/FXR4 verbatim ("バリアレース") | **data shows**: using the plain definition "current bar's high/low equals or exceeds the trailing N-bar extreme," 20-25% of ALL 1-minute bars qualify as a touch — this is not a rare event, it is routine tick-by-tick noise in a persistently trending 3.5y sample (USDJPY 131→159, +21%) | **bias**: makes any "does it come back to the rolling mid" question closer to "does normal noise bring price back near its own recent local level," which is true far more often than a genuine breakout-continuation question, inflating revert% and EV | **inherits**: any claim built on "barrier race," "range breakout," or "touch" without a minimum-quality/rarity filter (FXR3 by name).
2. **premise**: UTC21 is the volatility trough (FXL2, 0.24bps) | **source**: FXL2 verbatim | **data shows**: UTC21 realized vol (RMS close-to-close) = 0.895bps, mid-pack, not minimum; UTC19-20 (0.70-0.77bps) are the true minimum | **bias**: if the original 0.24bps used a range-based (high-low) estimator instead of return-based, the daily-rollover convention at ~21:00 UTC (candle open=high=low=close artifacts, visible in the raw data as literal flat OHLC rows) would suppress a range-based estimator specifically at that hour without suppressing a return-based one — a likely definition-vs-estimator mismatch, not a data error | **inherits**: any hour-of-day claim computed with a range/high-low vol estimator vs one computed with close-to-close returns will disagree at rollover hours.
3. **premise**: cost = 0.71bps round trip, usable to grade FXC5/FXR4 margins | **source**: task framing (FXC1, not itself in this packet) | **data shows**: only the spread leg (≈0.245-0.314bps) is derivable from repo data; the 0.4bps commission leg has no config source for USDJPY anywhere in `config/` | **bias**: unknown direction — could not independently confirm or deny the commission component | **inherits**: every FX claim that expresses an edge "in units of cost" (FXC2, FXC5, FXR1, FXR4, FXR9 by mechanism).
4. **premise**: MOF intervention magnitude "hundreds of bps/min" (FXL5) | **source**: FXL5 verbatim | **data shows**: max observed single-minute move across the only 3 in-window interventions is 83.3bps; hundreds-of-bps is reached only cumulatively over the day (−119 to −208bps close-to-close) | **bias**: overstates per-minute tail risk if read literally, though day-level risk is understated if anything (2022's largest interventions aren't in this data at all) | **inherits**: any tail-risk-rule sizing that assumes "hundreds of bps in one bar" (FXL5's own tail-rule design).
5. **premise**: FXT1/FXT2 n (19, or 16/19, or n=5) reproducible from data on hand | **source**: FXT1/FXT2 verbatim | **data shows**: the only multi-month, 1-minute BTC file in `backtest_data/` covers 210 days (2026-01-22 to 2026-08-20), containing just 24 NFP/CPI/FOMC/BOJ events total, 5-7 per type — a different, smaller, non-overlapping-in-full population than whatever produced n=19/n=5 | **bias**: unknown — my FXT1 replication happens to agree in direction/magnitude, but FXT2 disagrees in direction; neither comparison is apples-to-apples on denominator | **inherits**: FXT3's "do not auto-transfer" policy claim is, ironically, reinforced by this exact denominator mismatch.
