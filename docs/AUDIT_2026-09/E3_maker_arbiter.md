# E3 — 仲裁(パケットE / クレーム L2:対称 maker 往復)

役割: 監査 E(naive fill-on-print, キュー無し → net **+0.39〜+1.02bps**、maker線は開いている)と
監査 E2(キュー位置+再提示 → net **−1.26〜−1.76 unit-bps**、閉じている)の不一致の裁定。
自前スクリプト `audit_E3.py` / `audit_E3b.py`、同一データ(`paper_logs/tape/{ticker,executions}_2026{0820..0904}.csv.gz`、
ticker 1,589,458 行 / 約定 750,191 行、2026-08-20 06:13Z〜09-04 12:32Z)。両監査のスクリプトを読み、
naive から**差分を1つずつON**して符号がどこで反転するかを特定した。

## 1. 両者のモデル差分(コードから抽出、全項目)

| 論点 | 監査 E (`audit_E.py`) | 監査 E2 (`audit_E2b/c.py`) |
|---|---|---|
| 約定判定 | 約定プリントが指値を**通過 or 同値**で即約定 | 通過なら即、同値は**先行キュー消化後** |
| キュー | 無し(`best_bid_size` を一切参照しない) | 先行 = その時の表示サイズ、自量 0.01BTC |
| 再提示 | **無し**(30秒間 静止指値) | best が有利側に動いたら失権 → 新 best に出し直し(chase) |
| エポック | 全 ticker 行 1,589,458 個 | 30s グリッドから無作為 n≈1,200〜2,500 |
| 脚の対応付け | **別エポック同士**を約定時刻順に貪欲マッチ | **同一エポックの両建て**、先に約定した脚が建玉、その時刻から反対脚を新規提示 |
| 上限時間 | 入口 30s / ペア成立も 30s | 入口・決済とも 300s |
| net の定義 | `cap1+cap2+drift`、cap は**発注時mid**基準、drift は**約定時mid**基準 | `side*(p_exit − p_entry)` = **実現価格差**(定義非依存) |
| 未決済の扱い | 対応相手が見つからない脚は**破棄** | 300s 内 maker 決済率 99.7〜100%、破棄ほぼ無し |
| 板フィルタ | 無し | 交差板・保守窓 19:00–19:10Z を除外 |

## 2. 再現ラダー(naive から1つずつON、同一データ)

### (a) 監査 E のペア集合を固定したまま、会計だけ直す(n=140,175 ペア、step=5 部分抽出)
まず監査 E をレプリカ再現: bid 約定率 58.38% / ask 59.94%(E の報告 58.4/59.9 と一致)。

| 段階 | 変更点 | net |
|---|---|---|
| S0 | 監査 E のまま(cap=発注時mid基準, drift=**約定時mid**基準) | **+0.672** bps (t=+59.0) |
| S1 | drift を**発注時mid**基準に揃える(会計を無矛盾に) | **−0.147** bps (t=−13.2) |
| S2 | net = 実現指値価格差 `(p_exit − p_entry)` | **−0.147** bps (t=−13.2) |

S1 と S2 は小数第3位まで一致 = 「capture を発注時 mid で測るなら drift も発注時 mid で測る」のが恒等式。
内訳: capture 和 +2.050、drift(約定時mid) −1.378、drift(発注時mid) −2.198 → **会計の食い違いだけで +0.820bps の下駄**。
原因は明確で、bid 脚は「価格が下がって」約定するので `mid_at_fill < mid_at_quote`、ask 脚は逆。
両端で mid をずらして差を取ると、**逆選択の損失がそのまま利益に化ける**。監査 E の +0.64 は
この下駄を外すだけで(キューも再提示も入れずに)**符号が反転する**。

### (b) 対応付けを同一エポック両建てに直し、以降を1つずつON(実現価格差ベース)

| 段階 | 変更点 | net | 入口約定% | maker決済% | n |
|---|---|---|---|---|---|
| S3 | 同一エポック両建て、静止指値、キュー無し、上限30s | **+1.265** | 86.6 | **40.6** | 825 |
| S4 | + 上限 300s | **+1.177** | 99.9 | **78.4** | 1,837 |
| S4c | + **未決済を破棄せず**300s でテイカー手仕舞い | **−1.744** (t=−10.9) | 99.9 | 78.4 | 2,344 |
| S5 | + 再提示(chase) | **−1.364** (t=−25.4) | 99.9 | 99.9 | 2,344 |
| S6 | + キュー先行=表示サイズ(E2 完全形) | **−1.688** (t=−28.4) | 99.9 | 99.9 | 2,344 |
| S7 | + 交差板/保守窓フィルタ | **−1.684** (t=−28.3) | 100.0 | 99.9 | 2,338 |

**符号反転を起こした assumption は2つ、いずれも単独で反転させる**:
1. **会計の整合**(S0→S1、+0.82bps)。
2. **打ち切りバイアスの除去**(S4→S4c、**+2.92bps**)。静止指値だと 21.6% のポジションが 300s 以内に
   maker 決済できず、監査 E の設計ではその脚は**黙って捨てられる**。捨てられるのは
   「値が走って戻ってこなかった=負けている」ポジションばかりで、生き残りバイアスそのもの。
   再提示を入れると決済率が 99.9% になり打ち切りは消える(S5 の closed-only −1.361 と全件 −1.364 が一致)。

**キューは決定要因ではない**(S5→S6 で −0.32bps のみ)。監査 E は自ら「キューを入れれば説明がつくかもしれない」と
留保したが、実際にはキューは寄与が小さく、真因は上の2点である。付随して、監査 E の別エポック貪欲マッチは
**21.8% のペアで「決済側の指値を建玉が付く前の時刻に置いた」先読み**になっており(脚間 p50 17.3s)、
執行可能な系列ではない。

## 3. どちらの前提が小口リテイル maker として現実的か

**現実的(E2 側)**
- **表示サイズの後ろに並ぶ**: 最良気配の表示サイズは中央値 bid 0.0163 / ask 0.0160 BTC で、
  0.01BTC は自量の約1.6倍の先行に並ぶ。同値約定を全部自分が取るという仮定(E)は成り立たない。
  ただし先行が薄いので影響は小さい(−0.32bps)という測定結果自体は妥当。
- **値段が抜けたら即約定、同値なら出来高がキューを超えて初めて約定**: 板の因果と一致。
- **best が動いたら出し直す**: 現実の MM/スキャルパーは必ず追随する。追随しない場合の
  「約定しなかったから無かったことにする」は在庫を無視した会計であり、**負けポジションを消す**。
- **実現価格差で PnL を測る**: capture/drift の分け方に依存しない唯一の量。

**非現実的(E 側)**
- 発注時 mid 基準の capture と約定時 mid 基準の drift を足す(**内部矛盾**、+0.82bps の系統的過大)。
- 未決済ポジションの破棄(**+2.92bps の生存者バイアス**)。
- 別エポック間の貪欲マッチ(21.8% が先読み、在庫方向の条件付けが消える)。
- 同値約定を優先度なしで全取り(キュー無視)。

なお E2 の分解も「独立2測定」ではない: 発注時半スプレッド基準の capture(+1.798)と残差ドリフト(−3.483)は
net(−1.686)に従属し、capture を約定時 mid 基準にすると +0.190 / ドリフト −1.876 と見かけが変わるだけ(S6, n=2,341)。
逆選択(約定後5秒)は **+1.04bps**(S6)で E の 1.15、E2 の 0.88 と整合 —「6〜9bps」はどちらでも支持されない。

## 4. L2 の裁定

**判定: 数値差異(結論維持)** — 監査 E2 が正しく、監査 E の +0.39〜+1.02bps は棄却する。

決定的な数字: **同一データ・同一 naive 出発点から、会計の食い違いを直すだけで +0.672 → −0.147bps(t=−13.2)、
打ち切りバイアスを直すだけで +1.177 → −1.744bps(t=−10.9)**。完全モデル(再提示+キュー+板フィルタ)で
**net = −1.68bps/unit(t=−28.3、n=2,338、maker決済率 99.9%)**、E2 の −1.26〜−1.76 帯の中。
クレーム L2 の結論(対称 maker 往復は全レジームで負=maker 線は閉じている)は**維持**。
水準は claim の −1.02〜−1.42 よりやや悪い −1.36〜−1.69。

## 5. テイカー片道コスト(L1 の独立確認)

約定価格 vs 直前 mid(符号付き)、n=750,117(全約定、交差板行を除く):
**片道 平均 1.299 / 中央 1.036 / 出来高加重 1.424 bps** → **往復 2.598 bps(出来高加重 2.847)**。
気配スプレッド中央値 1.912 / 平均 2.028 bps(n=1,588,662)。
→ **L1 ≈ 2〜2.6bps 往復は独立に確認**。監査 E(1.8〜2.6)・E2(1.91/2.58/2.16/3.09)と三者一致。
クレームの 5.8〜7.9bps・片道 3.2bps は**支持されない**(2.2〜3.0倍過大)。
