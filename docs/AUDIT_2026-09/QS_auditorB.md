## QS-1

母数 n=4085 営業日。ON 平均 **+4.300bps, t=14.21**, sd=19.34, 中央値 +4.342 — 見出し値は一致(誤差 0.0%)。
外れ値除去(|r| 上位0.5%除外, n=4064)で +4.128bps t=14.44、前半 +4.362(t=11.78)/後半 +4.238(t=8.85)、
曜日別 +2.94〜+4.98bps(月曜が特別ではない)、前日レンジ3分位で +4.87/+4.27/+3.76 と全セル正 — 頑健。
対照: 符号ランダム反転プレースボ 2000 回の |平均| 97.5%点は 0.585bps、p(|perm|≥4.30)=0.0000。
日中 (open→close) は −2.10bps t=−1.06 で、close→close +2.18bps はほぼ全額が翌朝ギャップ。
**機構(stale close)の検証**: close を `close_vwap5` に置換した ON は **+4.307bps, t=13.97**。
差 +0.007bps(対応のある t=0.12)で統計的にも実務的にもゼロ。close と vwap5 の乖離は平均 0.007bps・sd 3.93bps の
純ノイズで、corr(乖離_t, ON_{t+1}) = −0.009、corr(当日日中リターン_t, ON_{t+1}) = +0.005 — stale なら出るはずの
正の予測力が無い。プレミアムは close の更新遅延では説明できない。
換算(Q3): 4.30bps/日 × 252 ≈ 1083bps/年(粗)。自前計測の taker 往復コスト床 3.598bps(QS-5)を毎日払うと
0.70bps/日 = 176bps/年、想定元本100万円で約 17,600円/年。コスト前提が 1bps 厳しくなれば消える薄さ。
MDE 0.60bps に対し効果 4.3bps なので検出力は十分。反証文: 「vwap5 基準の ON 平均が 0.6bps 未満なら機構は正しい」→
実測 4.307bps で反証。
Verdict: 結論変更
Mechanism: 棄却

## QS-3

母数 n=4085 営業日。ON 平均 **+3.598bps, t=12.44**, sd=18.48 — 主張の **+7.2bps はちょうど 2 倍**で、
相対誤差 −50%(10% 帯の外)。存在・符号・有意性(t=12.4, 符号反転プレースボ p=0.0000)は再現。
頑健性: 外れ値除去後 +3.596(t=12.78)、前半 +3.816/後半 +3.380、曜日別 +2.90〜+4.13、レンジ3分位
+3.77/+3.41/+3.62。どの部分集合も 7.2bps には届かない(最大セルでも 4.13bps)ので、部分集合の取り違えでは
7.2 を再現できない。日中は −4.09bps t=−2.29 で close→close は −0.47bps(この系列は ON だけが正)。
**恒等式 2×Var(ON)÷日中スプレッド の検証**: Var(ON)=341.6bps^2、日中スプレッドを (H−L)/C とすると 132.3bps で
2Var/spread = **5.17bps**、|O−C|/C = 90.3bps とすると 7.57bps。どちらも実測 3.598 と一致しない。
決定的なのは他系列への適用で、2Var/(H−L) は delta 5.46 / echo 5.43 / foxtrot 5.44 / golf 5.17 と**ほぼ定数**なのに
実測 ON は +4.30 / −0.10 / +2.91 / +3.60 とばらつく。ON がゼロの echo にも 5.43bps を「予測」してしまうため、
この式は構成上の恒等式ではなく、プレミアムの説明力を持たない(相関ではなく無関係)。
7.2 に近い値は分母を |O−C| に選んだときにだけ現れる(7.57)= 分母の自由選択によるフィッティング。
換算: 3.598bps/日 は QS-5 の往復床 3.598bps とほぼ同値 → taker 毎日回転では純益ゼロ。
Verdict: 数値差異(結論維持)
Mechanism: 棄却

## QS-4

log リターンの lag-1 自己相関 **+0.0526**(claim +0.053, 誤差 0.8%)。対照系列 qs_flat は **+0.0051**。
シャッフル・プレースボ 200 回の AC 標準偏差 0.0032(flat 0.0035)、**MDE(2σ)≈0.0068** → momentum は有意、
flat は帰無と区別できない。対照の使い方は claim の通りで妥当。
**機構(メンテナンス合成足)**: 0 リターン足は両系列とも 600 本で、時刻は 19:00–19:09 UTC のみに
各 60 本(60日×10分)= bitFlyer のメンテ窓と一致。しかし
(a) 19:00–19:10 UTC を除外 → AC **+0.0528**(n=85739)、
(b) 0 リターン足を全部除外 → **+0.0526**(n=85799)、
(c) 隣接ペアの両足が非ゼロのものだけ → **+0.0527**(n=85738)。

平坦足は AC を作るどころか希釈している。代替説明(ボラ・クラスタリング、出来高、時間帯)も

Verdict: 結論変更

## QS-5

母数: 気配 51966 本 (2026-07-01..07-03)、約定 32274 本。
スプレッド = (ask−bid)/mid: 全件平均 1.996bps だが **ask≤bid のクロス気配が 52 本 (0.10%)** 混入しており、
これを除くと平均・中央値・最小・最大すべて **正確に 2.000bps**(定数スプレッド)。→ claim の 2.0bps は再現。
片道スリッページ: 約定価格を直前気配の反対サイド(BUY は ask, SELL は bid)と比較して
**平均 +0.799bps**(n=32274, sd 0.154, p5 0.552 / p95 1.046, サイズ加重 0.799、BUY 0.798 / SELL 0.800)。
手数料: `costs_qs.yaml: taker_fee_bps: 0.0`。リポジトリ側の対応キーは `config/products.yaml`
`FX_BTC_JPY.taker_fee_pct: 0.0`(= 0.0bps)で整合。現物 (`BTC_JPY` ほか) は 0.15% = 15bps なので、
0bps は CFD 商品限定の値である点に注意。
往復床 = 2×(2.000/2 + 0.799) + 0 = **3.598bps** — claim 3.6bps と誤差 0.06%。
**タイムスタンプ意味論**(manifest の警告): 約定ファイルは `t` = `ts` + 2.000 秒(全件一定)。`ts` で気配整合すると
タッチ内側での約定は 0.000% だが、`t` で整合すると 8.2% が「タッチ以内」になり物理的にありえない
(テイカーがタッチより良い価格で約定)。よって `ts` が板と同一時計、`t` は 2 秒遅れの受信時刻。
`t` で計算するとスリッページ 0.804bps とわずかに歪む。
**機構(maker リベート原資を taker が実質負担しており真のコストはさらに上乗せ)**: どのファイルにも
maker リベート列は無く(manifest も明記)、料率表も 0bps。テープ上の taker 約定は「反対タッチ + 0.799bps」に
完全に収まり、説明されない残差コストは存在しない(残差 sd 0.154bps、平均超過 0)。リベートを taker が負担するなら
手数料または実効スプレッドとして観測されるはずで、観測されない以上「真のコストはこの分だけ上乗せ」は
データに支持されない。床 3.6bps は上乗せ無しで完結している。
Verdict: 再現
Mechanism: 棄却
