## 手法(自前の約定モデルと、その理由)

- **母集団/イベント形成**: 300秒間隔の非重複グリッド(862時点)× 対称2方向(ロング先行=best_bid で買い→約定後 best_ask で売り、ショート先行はその鏡像)= **発注試行 1,724件**。
- **fill model A「キュー位置」(本監査の主モデル)**: 自注文は表示数量 `best_bid_size`/`best_ask_size` の**後ろ**に並ぶ。反対側テイカー約定が (キュー先行数量 + 自サイズ0.85) を食い切って初めて全量約定。自価格を**貫通**する印字(買い注文価格より下の約定)が出た時点で先行キューは消滅扱い(現実には自注文が先に食われる)。板が自価格の外へ引かれた場合も先行キュー=0。
- **fill model B「印字即約定」(naive)**: 自価格に触れる印字が1本出た瞬間に全量約定。キュー先行数量も**自サイズも**無視。
- **fill model C「同一価格厳格」(参考)**: 貫通印字を認めず、自価格ちょうどの同サイドテイカー数量のみでキューを消化 → **本テープでは約定率 0%**(後述:気配価格が刻み格子に載っていないため、過去の気配価格が再び印字されることがほぼ無い)。よってCは使用不能で、Aが唯一の実行可能な「正しい」モデル。
- **未決済(300秒以内に決済 quote が約定しない建玉)の会計**: (a) 300秒時点でテイカー手仕舞い(主), (b) mid でマーク, (c) 除外 — 3通り全部を報告。claim側の会計は未記載。
- **手数料キー**: `config/products.yaml: FX_BTC_JPY.taker_fee_pct = 0.0`(maker も 0%、同ファイル注記)+ 本パケット manifest「Fee: 0 bps maker and taker」。よって **fee 項 = 0、net = gross**。`config/config.yaml: costs.taker_fee_pct: 0.15` は本商品に適用されない別キー(使用せず)。

## QA-M1

- 再計算: **-13.589 bps/往復、t=-28.38、sd=15.88、n=1,100(発注試行1,724の63.8%が約定)**。うち maker で手仕舞えたのは 44.5%(平均 -2.13)、残り 55.5% は300秒でテイカー強制手仕舞い(平均 **-22.76**)。
- 会計を変えても符号は不変: mid マーク -13.09、未決済除外 -2.13、per-試行 -8.67。全て有意に負。
- 頑健性: step 120s/600s → -13.29/-13.92、cap 60s/900s → -13.85/-13.89、グリッド位相 +37s/+151s → -13.29/-13.53。自サイズのみが効く(0.05→-4.92、0.85→-13.59、3.0→-28.72)。
- 金額換算: 平均価格 982,359円 × 0.85 = 想定元本 835,005円/往復 → **-1,135円/往復**、367往復/日 → **-417千円/日**。主張の -0.84 bps なら -70円/往復。
- 結論(コストを上回らない)は方向・有意性ともに強く支持。ただし主張値は絶対値で16倍小さく、しかも主張の t=-1.50 は**非有意**(=「上回らない」ではなく「判定できていない」)。私の sd=15.9・n=1,100 での MDE は 1.34 bps なので、-0.84 bps という効果量はこの n では検出限界以下であり、主張の統計的根拠は結論を支えるほど強くない。

Verdict: 数値差異(結論維持)

## QA-M2

- モデルB(印字即約定、キュー・自サイズ無視)で **-4.268 bps、t=-12.91、n=1,507/1,724**。テイカー側フィルタを掛けても -4.351。**+0.3 bps は再現しない(符号が逆)**。
- モデルBが正になるのは、**未決済建玉を除外した場合のみ**: +2.253 bps(t=+31.9、n=1,082、= 発注試行の62.8%)。すなわち「収益機会に見える」ためには naive 約定だけでは足りず、**生存者バイアス(手仕舞えなかった28.2%、平均 -20.87 を捨てる)を重ねる必要がある**。
- キュー先行数量の影響は本テープでは小さい(表示数量の中央値 0.001・平均 0.0296 単位 = 自サイズ0.85 の 3.5%)。A と B の差 9.3 bps の主因は**キュー位置ではなく自サイズ0.85の吸収時間と貫通約定の扱い**。claim の「キュー位置を無視した仮定に依存する」という診断は、機構の名指しが誤り。
- 数値も符号も再現せず、「+0.3 bps の収益機会」という記述は正しい会計では成立しない。

Verdict: 結論変更

## QA-M3

- 1tick(0.3bps)内側 improve: モデルA **-13.686 bps、t=-29.02、n=1,120**、モデルB -4.351(t=-13.47)。いずれも **0 と有意差なし、ではない**(|t|>13)。主張の -0.43/t=-0.89 は再現しない。
- 加えて前提の破綻: 気配価格は宣言された 0.3bps 格子に **1本も載っていない**(51,517行中 0)。スプレッドだけが常に 6tick=1.8bps に量子化されている。したがって「1tick 内側」は板に存在しない価格であり、この価格が約定するのは貫通印字経由のみ。improve の効果はモデル上ほぼ定義されない。
- best との差も微小(A: -13.59 → -13.69、B: -4.27 → -4.35)。improve は改善しない。

Verdict: 結論変更

## QA-M4

- 逆選択の測り方で答えが変わる。**約定直後の気配** mid を基準にすると 1秒 +0.028(t=1.19)、**5秒 +0.281(t=3.72、MDE 0.21)**、30秒 +0.664(t=3.56)。**約定直前の気配** mid 基準では 5秒 +3.843(t=22.2)。前者は経済的には小さいが統計的には0と区別できる、後者は明確に大きい。「0と区別できない」は測定規約に依存し、無条件には成立しない。
- 決定的なのは推論の方。逆選択(約定後)が小さくても往復は黒字化しない。損失の源泉は5秒窓の**外**にある:
  - **発注→約定の間の逆行**: 発注時 mid に対する見かけのエッジは常に +0.90 bps(半スプレッド、定数)だが、約定時点までに mid は平均 **+3.22 bps 逆行**(t=19.6)。約定時 mid 基準のエッジは **-2.32 bps**(t=-14.1)= 約定した時には既に不利な価格を買っている。
  - **決済側の未約定**: 55.5% が300秒で maker 決済できず、平均 -22.76 bps。
- 対照: 約定選択を外した placebo(300秒内のランダム時刻で必ず約定と仮定)は **+1.45 bps(t=2.91、n=1,724)**、テイカー往復対照は -1.80 bps(= 定数スプレッドそのもの)。つまり機械的なスプレッド捕捉は正、それを打ち消しているのは**約定の選択**であり、「キュー位置さえ正しくモデル化すればプラスに転じる」は逆(正しくモデル化するほど悪化する: B -4.27 → A -13.59)。

Verdict: 結論変更

## QA-M5

- レシピ通りに適用しても**プラスにならない**。モデルA で未決済除外 = **-2.132 bps(t=-9.38、n=489 = 発注試行の28.4%)**、さらに「約定直前の ticker mid 基準」で両レグの capture を測ると **-6.06 bps(t=-13.3)**。
- プラスになるのは naive 約定(モデルB)と組み合わせた時のみ: 除外あり +2.253 bps、improve 版 +1.735 bps。
- 二つの操作はいずれも系統的バイアス: (i) 除外は生存者バイアス(捨てられる建玉の平均は -22.76 bps、全体の55.5%)、(ii) 約定直前 mid は構造的に古い(約定は価格が動いたから起きるので、直前気配は必ず有利側に取り残されている)。片側 +0.90 bps の「エッジ」は定数のスプレッド半値の言い換えに過ぎない。
- したがって、主張の数値(プラス)は正しい約定モデルの下では再現せず、再現する条件(モデルB+除外)は二重のバイアスの産物。

Verdict: 結論変更
