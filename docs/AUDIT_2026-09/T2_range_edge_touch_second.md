# T2 — レンジ端タッチ = 順張り? (packet T の第二独立監査)

対象クレーム: **L9**(レンジ端タッチは順張り: 23,642件バリアレースで戻り31.7% vs 突破61.4%。USD/JPYでも戻り40% vs BTC34%)、
**FXR3**(バリアレース逆張り: 全18セル戻り<50%。東京昼42.9%)。
自前実装 `scratchpad/audit_T2.py`(+ `extra.py`)。既存の監査レポート・研究レポートは一切読んでいない。

## 0. 定義(クレーム側は未文書 → 2定義を宣言してテスト)
- レンジ端: 直前 N 本の `hi=max(high)`, `lo=min(low)`(bar t は含まない)、幅 `W=hi-lo`。
- タッチ: (i) **plain** = `high[t]>=hi`(上)/`low[t]<=lo`(下)。(ii) **event** = plain + クールダウン(同側で直前 N 分にタッチ無し)+ `W >= 1.0×median(W)`。
- バリアレース: エッジから**等距離** `D=W/2`。戻り = レンジ中点、突破 = `edge±D`。t+1 以降の高値/安値で先着判定。判定ホライズン H は既定 N 分(感度は §5)。
- コスト: BTC = 手数料0%(`config/products.yaml: FX_BTC_JPY taker_fee_pct: 0.0`)+ スプレッド1.9bps + スリッページ1bps/side → **往復3.9bps**。FX = **0.71bps**(申告値をそのまま使用、検証は §前提の誤り 6)。
- 有効性フィルタ: 平坦かつ出来高0の bar、bitFlyer メンテ 19:00–19:10 UTC、直前 N 本に欠測を含む bar を除外。

## 3. 統制(第2問)
- **並べ替え(permuted return)統制は 50% にならない**。BTC 47.95%(t=−3.1 vs 50)、USDJPY 48.43%(t=−4.5)。
  すなわち**このレースの帰無値は 50% ではなく 48% 前後**。実データとの差は BTC −1.1pp(有意でない)、USDJPY **+0.8pp(戻り方向、クレームと逆符号)**、FX_BTC_JPY −4.8pp(se 2.9pp, t=1.6)。
- 符号反転統制(= 突破シェア)は自明に 1−戻りで、追加情報なし。
- 状態条件付き統制(vol tercile・セッション)は §4。並べ替え側も同じセッション偏り(TOK_MID 47.1%、NY_AM 48.5%)を再現する。

## 7. MDE と反証文(第10問)
50% からの検出可能差(80%検出力・両側5%、日クラスタ se): USDJPY N60 plain **0.93pp**、N30 plain 0.65pp、
BTCUSDT N60 plain 1.71pp、N30 plain 1.21pp、FX_BTC_JPY N60 plain 4.63pp、同 event **11.7pp**。
→ L9 の主張する 18.3pp の偏り(31.7% vs 50%)は BTC/USDJPY サンプルでは圧倒的検出力で検出できたはずで、
再現しなかったのは検出力不足ではない。逆に FX_BTC_JPY の event 定義単体(n=210)は 11.7pp 未満を検出できず、
このファイル単独でのバリアレース主張はいずれも未検証扱いが妥当。
**反証文**: 「等距離バリアの端タッチレースで、並べ替えリターン統制で測った帰無値(≈48%)より戻りシェアが
1pp 以上低く、かつ同方向の順張りグロス収益が正であれば、順張り説を支持する」。BTC・USDJPY のいずれもこの条件を満たさない。

## 8. 判定
| クレーム | 主張値 | 再計算値 | 判定 |
|---|---|---|---|
| L9 バリアレース配分 | n=23,642, 戻り31.7% / 突破61.4% | 戻り 42.7–49.6%(決着分母)/ 35.6–49.0%(全タッチ分母, 未決着 0.05–26.5%)。n は定義依存で 86–195,254 | **結論変更** |
| L9 USDJPY 40% vs BTC 34% | USDJPY の方が戻りやすい | 順序は一致(USDJPY 49.3% > BTC 46.9% > FX_BTC_JPY 45.8%, N60 plain)だが水準は +9〜15pp | 数値差異(順序のみ維持) |
| L9「タッチ=順張りイベント」 | 突破優位 | 並べ替え統制が 47.9–48.4% で、実データとの差は BTC −1.1pp(n.s.)/ USDJPY **+0.8pp(逆符号)**。リターン空間の follow グロスは負 | **結論変更** |
| FXR3 全18セル戻り<50% | 18/18 が <50% | USDJPY 42セル中 **10セルが ≥50%**(NY_PM N60 plain 53.0%, TOK_LATE N120 52.9% など) | **結論変更** |
| FXR3 東京昼42.9%(最悪) | 42.9% | TOK_MID は 43.6–49.9%(定義×N)。並べ替え統制の TOK_MID も 46.6–47.1% → 帰無内 | **結論変更** |

**justification**: 等距離バリアという素直な実装では、3商品・2定義・3つの N・4つのホライズン・フィルタ有無の全組合せで
戻りシェアは 42.7–49.6%(決着分母)に収まり、L9 の 31.7% は一度も現れない。L9 の戻り/突破比 0.52 は、突破バリアが
戻りバリアより近い(等距離でない)実装でしか生じ得ず、これは「同じ距離だけ突破」という言明と整合しない。
さらに決定的なのは統制で、リターンを並べ替えて系列依存を完全に破壊しても戻りシェアは 47.9–48.4% にしかならない。
「戻り<50% ゆえ順張り」という推論(FXR3 の骨格そのもの)は、レース幾何の機械的な偏りを効果と読み違えている。
実データが統制を上回る超過は、大標本では BTC −1.1pp(有意でない)、USDJPY は +0.8pp と**クレームと逆向き**。
金額でも follow のグロス期待値が両大標本で負であり、コスト後は follow・fade とも全セルで負。両クレームとも結論変更。

## 前提の誤り
| 前提 | クレーム内の出所 | データが示すこと | 結論へのバイアス方向 | 同じ前提を継承する他クレーム |
|---|---|---|---|---|
| バリアレースの帰無値は50% | L9・FXR3 の「<50%ゆえ順張り」推論 | 並べ替えリターン統制で BTC 47.95%(t=−3.1)、USDJPY 48.43%(t=−4.5) | 順張り側に強く有利。FXR3 の「全セル<50%」は統制でもほぼ成立 | 「勝率が50%を割る/超える」だけで方向性を結論づける全バリアレース系クレーム |
| バリアは等距離 | L9「同じ距離だけ突破」 | 等距離実装の戻り/突破比は 0.85–0.97。L9 の 0.52 は突破側が近い実装を示唆 | 突破優位を機械的に作り出す | バリアレース由来の全クレーム(FXR3 含む) |
| タッチ定義 | 未文書 | plain は N=30 で 13.9–18.1%(依頼文の20–25%より低い)、event 定義で 0.25–1.6% に落ちる。n が 86〜195,254 まで動く | n・CI・MDE が監査不能。小さい n のセルほど極端値が出やすい | 「イベント数 N 件」を根拠にするレンジ端系の全クレーム |
| 判定ホライズン | 未文書(L9 の未決着 6.9% から逆算すると H≈4N) | H=N で未決着 20–23%、H=4N で 2.5–3.7%、H=24N で 0.05–0.9%。配分がホライズンで大きく動く | 未決着の扱い次第で「突破61.4%」のような大きな数字が作れる | 先着判定を使う全クレーム |
| BTC 往復コスト ≈3.9bps(手数料0%+スプレッド1.9bps+スリップ1bps/side) | 依頼文/L9 | 手数料0%は `config/products.yaml: FX_BTC_JPY taker_fee_pct: 0.0` で確認。ただし**スプレッド1.9bpsは両BTCファイルから検証不能**(気配データなし)。リポジトリ自身のペーパー約定コストは `config/config.yaml: costs.taker_fee_pct 0.15 / slippage_pct 0.05` = 片道20bps・往復40bps | コストを最大10倍過小評価。本監査でも 3.9bps を採用したが、それでも全セル負なので結論は堅牢 | BTC 1分足で「往復数bps」を前提に採算を語る全クレーム |
| FX 片道コスト 0.71bps | 依頼文/FXR3 | `ask_close` がある 37,440 行(全体の 2.3%)で median(ask−close)=0.252bps(p25 0.189 / p75 0.381)。残り 1,602,720 行に気配なし | 0.71bps は実測の約2.8倍で保守側。戦略に不利な方向のバイアス | FX の bps 建て採算クレーム全般(全期間のスプレッドは検証不能) |
| USDJPY 1分足の母集団 | FXR3 の「全18セル」 | 1,640,160 行中 **285,006 行(17.4%)が平坦かつ出来高0**(週末・休場のフィラー。ファイル末尾も 158.94 の同値3連)。未フィルタだとタッチが +15% 増える | 偽のレンジ端が混入し、セル数・勝率がともに汚染 | fx_usdjpy_1m_20260822 を分母に使う全 FX クレーム |
| 「東京昼」の UTC 定義 | FXR3 | 未文書。03–06 UTC(12–15 JST)採用で 43.6–49.9%、00–03 UTC 採用なら 47.0–49.4% と 1–3pp 動く | セッション最悪セルの選択に自由度 | セッション別に最良/最悪セルを報告する全 FX クレーム |
| n=23,642 という分母 | L9 | 利用可能な bitFlyer ファイル(30–31日)からこの件数を再現する定義の組合せが無い。N∈{30,60,120} を束ねた plain 両側でも 11,756 件(しかも重複タッチを二重計上) | 分母不明のまま比率だけが引用されている | L9 を引用する下流のレンジ系クレーム |
| bitFlyer ファイルでの検定力 | L9 の BTC 側 | 32暦日・決着 2,812件(N60 plain)で MDE 4.6pp、event 定義では 11.7pp | 5pp 未満の効果は原理的に判定できない | candles_FX_BTC_JPY_31d 単独で勝率差を主張する全クレーム |
| ボラ状態依存 | 依頼文の vol tercile | USDJPY は単調性なし(48.5–50.3%)。FX_BTC_JPY N120 V3 の 33.1% は n=478・MDE 14.5pp・並べ替え統制 44.9% | 高ボラで順張りが効くという読み筋は支持されない | ボラ条件付きのレンジ端クレーム |

その他のカテゴリ(ティックサイズ、契約乗数、分割・配当調整、生存者バイアス)は本パケットの計算に入らないため該当なし。
bitFlyer メンテ窓 19:00–19:10 UTC は FX_BTC_JPY で 341 本存在し除外済み(除外前後で戻りシェアの差は 0.1pp 未満)。
