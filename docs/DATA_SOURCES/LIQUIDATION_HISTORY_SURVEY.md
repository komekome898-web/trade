# 清算(強制決済)履歴の入手可能性 — 全経路の実測(2026-09-08)

**きっかけ**: リードが「清算の履歴は買えない。記録を始めた日から先しか残らない」と書いたのに対し、
オーナーが「**本当にあとから取得できないのか。全ての方法・取引所を試したのか。外部のツールで
取れるものはないのか**」と差し戻した。全部当たり直した結果、**リードの主張は言い過ぎだった**。

方法: すべて **GET**(HEAD は使わない)。当セッションの経路からの実測なので、
**地域制限は オーナー PC と異なりうる**。日付は 2026-09-08。

---

## 1. 結論(先に)

| | |
|---|---|
| **誤りだった主張** | 「清算履歴は無料では取れない / 記録を始めるまで永久に空白」 |
| **実際** | **Gate.io が 1 件ごとの清算履歴を鍵なしで公開しており、ローリング約 90 日ぶん遡れる**【実測】 |
| **それでも記録が要る理由** | Gate の窓は**動く**(90 日より古いものは消える)。Binance は**ストリームのみ**で履歴が無い。取引所をまたいだ観測は記録でしか作れない |
| **締切の訂正** | 「今日から」ではなく「**90 日以内に Gate を取り込めば、そこまでは埋まる**」 |
| **未確認で残っているもの** | 集計サービス(Coinalyze / CoinGlass)の無料 API キー経由。**深さ不明 — キーを取れば分かる** |

## 2. 実測表

### 取れる

| 経路 | 何が取れるか | 深さ【実測】 |
|---|---|---|
| **Gate.io** `GET /api/v4/futures/usdt/liq_orders?contract=BTC_USDT` | **1 件ごと**の清算(`size` / `order_size` / `fill_price` / `order_price` / `time`)。**認証不要** | **ローリング約 90 日**。90 日前 = 取得可、95 日前 = 空 |
| **OKX** `GET /api/v5/public/liquidation-orders` | 1 件ごと(`side` / `sz` / `bkPx` / `ts`) | **ローリング約 24 時間**(頁送りで 1,525 件、最古 23.8 時間前で尽きた)。履歴ではないが**最大 24h の欠測を埋められる** |
| **Binance** WS `!forceOrder@arr` | 全銘柄の強制決済。**ストリームのみ、履歴なし** | 記録した分だけ |
| **BitMEX** WS `liquidation:XBTUSD` | 同上 | 同上 |
| **Hyperliquid** S3 アーカイブ | 未確認(中身を見ていない) | **Requester Pays バケット** — AWS アカウントがあれば取得可能、**転送料は当方負担**。匿名アクセスは 403 |

### 外部ツール(オーナーが共有した X 投稿の系統)

- **ccxt**: 統一メソッド `fetchLiquidations` を **bitmex と gate** で宣言している(GitHub の実装を確認)。
  つまり **ccxt 経由で Gate の履歴が取れる** — 上表と同じものへの別の入口。
  他(binance / bybit / okx / hyperliquid)は宣言していない。なお ccxt は**本リポジトリの依存に入っていない**
  (`pyproject.toml` に無い)。
- 投稿にあったオンチェーン系・監視系のリポジトリは、いずれも**取引所の清算履歴を配布するものではない**
  (配布元が持っていないものは中継もできない)。**集計サービス(Coinalyze / CoinGlass)の方が本筋。**

## 3. これで何が変わるか

- **すぐ取れる**: Gate.io の 90 日ぶん。認証不要・1 件ごと・時刻つき。**今日から取り込める。**
- **急ぐ度合いが下がった**: 「今日記録を始めないと永久に空白」ではない。ただし Gate の窓は動くので、
  **90 日以内に取り込む**必要はある。
- **それでも記録は要る**: Binance(最大手)は履歴を持たない。取引所をまたいだ同時観測、
  および受信時刻つきの粒度は記録でしか作れない。**記録器を作った判断自体は変わらない。**
- **先にやるべきこと**: 集計サービスの無料キーを取る。もし 1 件ごとで年単位の深さがあるなら、
  設計そのものが変わる(記録は保険に降格する)。**キー 1 本で分かることを、確かめずに設計を固めない。**

## 4. リードの誤りの型(3 回目)

本セッションで「取れない / 効かない」と早く締めて差し戻されたのは**これで 3 回目**である
(外部リポジトリの評価 → オンチェーンの入手経路 → 本件)。共通しているのは
**1 経路を試して全体を結論づけたこと**。今回で言えば、Binance Vision の 1 ファイルが 404 だったことを
「無料では取れない」に一般化した。**「取れない」と書くときは、当たった経路を全部並べる。**
並べられないなら、それは「取れない」ではなく「**探していない**」である。
