# 清算(強制決済)履歴の入手可能性 — 全経路の実測(2026-09-08)

**きっかけ**: リードが「清算の履歴は買えない。記録を始めた日から先しか残らない」と書いたのに対し、
オーナーが「**本当にあとから取得できないのか。全ての方法・取引所を試したのか。外部のツールで
取れるものはないのか**」と差し戻した。全部当たり直した結果、**リードの主張は言い過ぎだった**。

方法: すべて **GET**(HEAD は使わない)。当セッションの経路からの実測なので、
**地域制限は オーナー PC と異なりうる**。日付は 2026-09-08。

> **【2026-09-08 追記・L-032】この但し書きは現実になった。** オーナー PC からは
> Binance REST も Bybit REST も **200**、OKX の WS も接続できた
> (`LIQUIDATION_FEED_REACHABILITY.md`)。したがって**下表のうち 451 / 403 を理由に
> 「取れない」としたものは、オーナー PC で測り直すまで「不明」である**。
> 中身が空・列が無いことを確かめたものは経路と無関係なので変わらない。

## 2. 実測表

| 経路 | 何が取れるか | 深さ【実測】 |

| **OKX** `GET /api/v5/public/liquidation-orders` | 1 件ごと(`side` / `sz` / `bkPx` / `ts`) | **ローリング約 24 時間**(頁送りで 1,525 件、最古 23.8 時間前で尽きた)。履歴ではないが**最大 24h の欠測を埋められる** |
| **Binance** WS `!forceOrder@arr` | 全銘柄の強制決済。**ストリームのみ、履歴なし** | 記録した分だけ |

### Coinalyze — **足ごとに深さが違う**(2026-09-08、オーナー PC で実測)

返るのは 1 件ごとの約定ではなく**時間バケットの集計値**。1 点の中身は
`{"t": epoch秒, "l": ロング清算量, "s": ショート清算量}`(`convert_to_usd=false` なので単位は枚)。

| 足 | 遡れる深さ【実測】 | 使いどころ |
|---|---|---|
| **1min** | **約 7 日** | 分解能は十分だが**浅い**。カツオの機構(数分スケールの反転)には期間が足りない |
| 1hour | 約 86 日 | Gate.io と同程度の深さ。ただし 1 時間では機構の時刻が潰れる |
| **daily** | **1 年超**(二分探索は約 457 日を返したが、窓の取り方の影響で**境目は概算**) | **レジーム/文脈の変数**として使える。長期の「清算が多い時期か」 |

**含意**:
- **分単位の清算履歴は 7 日ぶんしか存在しない。** それより古い分解能は、**自前で記録した分しか無い**。
  これは「履歴が全く無い」より正確で、かつ**記録を続ける理由としては前より強い**。
- **1 年超の日次**は、機構の検定には粗すぎるが、**今の 90 日窓が特異な時期でないかの確認**や、
  ポジショニング族(#70)の遅い文脈変数として安く使える。
- 同じ鍵で**建玉・資金調達率・ロングショート比の履歴**も取れる(未測定)。#70 で当たる価値がある。

## 3. これで何が変わるか

- **機構の検定には Gate.io が最良【実測】**: カツオの機構は数分スケールなので**分解能が要る**。
  Coinalyze の分足は **7 日**しか無く、Gate.io の**1 件ごと・約 90 日**に及ばない。
  「年単位で遡れるなら設計が変わる」の分岐は**起きなかった**(年単位で取れるのは**日足**だけ)。
- **ただし収穫はあった**: Coinalyze の**日足 1 年超**は文脈変数として使え、
  **「分解能のある清算履歴は 7 日しか存在しない」**という事実は、記録を続ける理由を前より鋭くした。
- **すぐ取れる**: Gate.io の 90 日ぶん。認証不要・1 件ごと・時刻つき。**今日から取り込める。**
- **急ぐ度合いが下がった**: 「今日記録を始めないと永久に空白」ではない。ただし Gate の窓は動くので、
  **90 日以内に取り込む**必要はある。
- **それでも記録は要る**: Binance(最大手)は履歴を持たない。取引所をまたいだ同時観測、
  および受信時刻つきの粒度は記録でしか作れない。**記録器を作った判断自体は変わらない。**
- **先にやるべきこと**: 集計サービスの無料キーを取る。もし 1 件ごとで年単位の深さがあるなら、
  設計そのものが変わる(記録は保険に降格する)。**キー 1 本で分かることを、確かめずに設計を固めない。**

## 4. リードの誤りの型(3 回目)

本セッションで「取れない / 効かない」と早く締めて差し戻されたのは**これで 3 回目**である
(外部リポジトリの評価 → オンチェーンの入手経路 → 本件)。共通しているのは
**1 経路を試して全体を結論づけたこと**。今回で言えば、Binance Vision の 1 ファイルが 404 だったことを
「無料では取れない」に一般化した。**「取れない」と書くときは、当たった経路を全部並べる。**
並べられないなら、それは「取れない」ではなく「**探していない**」である。
