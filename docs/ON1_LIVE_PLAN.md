# ON1 実弾移行計画(L0→L1→L2)

**確定日: 2026-08-28。** オーナー決定: 手動フェーズは置かず、**最小ロット実弾×自動化(L1)**で
確認し、ゲート通過後に**適正ロット×自動化(L2)**へ。ペーパー台帳は並走を続け、
役割は「基準系列」(実弾約定値との差分 = 執行品質の実測)。

## L0 — 前提(オーナー側の手続き)

1. **三菱UFJ eスマート証券の総合口座 + 先物・オプション口座**の開設(審査あり)
2. **kabuステーションAPI の利用条件**: Professionalプラン
   (= 信用または先物OP口座開設済み + 直近の約定実績1回以上)。
   条件充足のための最初の1約定が必要な場合、その1回のみ手動で行う
   (検証フェーズではなく事務手続きとして扱う)
3. 資金: **1枚あたり15〜20万円**(証拠金約4.5万・年内1.9倍変動実績+連敗吸収)
4. PC側: kabuステーション常駐(Windows・同一PC/同一IP制約は既存運用と整合)

## L1 — 最小ロット実弾×自動(1枚固定)

- 毎営業日: 15:40 に引け成行(買)→ 翌 8:40 に寄り成行(売)を自動発注。
  中心限月はペーパーと同一規則(日中出来高最大のマイクロ限月)
- **ハードリミット(コードで強制)**:
  - ポジションは常に {0, +1枚} のみ。ショート・2枚目は構造的に不可能にする
  - 発注は1日最大4件(通常2件+ロール2件)。超過はその日の発注停止
  - 発注前サニティ: 価格帯・限月・銘柄コードの照合に失敗したら発注しない(fail-close)
  - **Kill Switch は bitFlyer 側と同一の設計**: ファイル永続・自動復帰なし・
    リポジトリ直下 KILL ファイルで停止
  - 曖昧な失敗は `OrderStateUnknown` として保持し**自動リトライしない**
    (照合が終わるまで再送禁止 — CLAUDE.md §1 と同一の不変条件)
  - LIVE 起動は bitFlyer 同様の二重ゲート(env + config ack)+ オーナー明示承認
- **監視**: ペーパー台帳との毎日突合(実約定値 vs 公表約定値)、ダッシュボード表示、
  PREREG_on1_forward §3 の警告/停止線をそのまま適用

### L1 → L2 昇格ゲート(事前固定)

**20営業日以上**経過し、以下すべてを満たすこと:

1. 発注失敗・未解決の状態不明が **0件**(解決済みの状態不明は記録の上で許容)
2. 実約定値と公表約定値の乖離が **95%以上の約定で ≤1ティック(5円)**
3. 実弾P&Lとペーパー台帳P&Lの差が **手数料+乖離分の説明範囲内**
4. 警告/停止線に非抵触
5. ロール(SQ週の限月乗換)を最低1回、無事故で通過

## L2 — 適正ロット×自動

- 枚数はオーナーの投入資本確定後に**リスク基準で別途合意**
  (目安: 3ヶ月p01級の連敗 −22% ≈ 1枚15万円の損失を資本の20%以内に収める枚数)
- 増枠は一度に2倍まで(1→2→4…)。各増枠後20営業日は再ゲート
- L2 の開始・各増枠は**その都度オーナー明示承認**

## 実装アーキテクチャ(L1)

- `src/bot/jpx/` 新設: kabuステーションAPI クライアント(REST localhost:18080、
  検証ポート18081)/ ON1 executor(時刻駆動: 15:40 エントリー・8:40 エグジット・
  ロール判定)/ 読み取り専用リコンサイラ(建玉・約定照会で状態確定)
- 発注コードは bitFlyer 系と共有しない(市場・API・失敗モードが異なるため、
  資産は設計原則のみ移す: 失敗分類・STATE_UNKNOWN・kill switch・二重ゲート)
- Windows タスクスケジューラに2ジョブ追加(15:35起動・8:35起動、二重起動ガード)
- 全発注ロジックに単体テスト。実弾前に検証ポートで統合確認

## 明示的な残リスク(L1でも消えないもの)

- ロング・ベータの尾部(2008年型の一晩 −5% ≈ −3.3万円/枚)
- 15:45→17:00・6:00→8:45 のヘッジ不能な窓
- 祝日取引・臨時休場・システム障害時は「その日の取引をスキップ」に倒す(fail-close)
