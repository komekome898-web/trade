## 2. 最大の乖離 — **機構は「清算」なのに、測っているのは「ヒゲ」**(I-6 / I-7)

意図は **「清算の連鎖が燃料を使い切ったところで反転する」** という**フロー**の話である。
実装が見ているのは **15 分足の OHLC だけ**で、清算の量も向きも建玉も出来高も参照しない。
ヒゲは清算連鎖の**痕跡(代理変数)**にすぎない。

**これを潰しておかないと、判定が出たときに切り分けられない**:

| もし結果が悪かったら | 考えられる原因 |
|---|---|
| 機構が無い | 清算連鎖のあとに反転は起きない |
| **代理が悪い** | 反転は起きるが、**ヒゲでは清算連鎖を拾えていない**(ヒゲの多くは清算ではない) |

**したがって検証は 2 本立てにする**(これが「事前に決めておく」の中身):

- **層 ①-a(代理)**: ヒゲ 4 分類が後続リターンを予測するか。→ BitMEX 1 秒バー 2017-2021 で測れる。
- **層 ①-b(直接)**: **清算フローそのもの**が後続リターンを予測するか。
  → Gate.io の 1 件ごと 90 日 + 記録中の 4 取引所で測れる(BitMEX の清算履歴は存在しないため、
  **同一ベニュー・同一期間での ①-a と ①-b の直接比較はできない**。これは射程として明記する)。
- ①-a が陰性で ①-b が陽性なら、**「機構はあるが代理が悪い」**と言える。
  ①-a が陽性なら代理は機能している。**両方測って初めて 1 と 2 が分かれる。**

## 3. I-8(無効化ライン)の 3 つの穴 — **意図とロジックが合っていない**

意図: 「その反発の根拠(ヒゲの先端)が壊れたら降りる」。実装には次の 3 つのずれがある。

### 3-a. `lcprice` が**建玉に紐付いていない**

`lcprice` はグローバルで、**シグナルが出るたびに上書きされる**(171 / 174 / 182 / 185 行)。
建玉を開いたときのヒゲ先端ではなく、**直近にシグナルを出した足の先端**を見ることになる。
向きが逆のシグナルが挟まると、買い建玉の無効化ラインが**上ヒゲの高値**になりうる。
**意図どおりなら、無効化ラインは建玉と一緒に保持されるべき。**

### 3-b. 無効化の判定が **`signal == 0` の足でしか走らない**

メインループの構造上、`lcprice` の判定は `else`(シグナルなし)の枝にしかない。
**新しいシグナルが出た足では、無効化ラインを割っていても判定されない。**
極端な例: 買い建玉中に価格がヒゲ先端を大きく割り、その足が「下ヒゲ陽線(強い買い)」なら、
**降りずに買い増す。**

### 3-c. 判定が**終値のみ**で、足の途中は見ない

15 分の間にヒゲ先端を大きく割って戻ってきた場合、無効化は発火しない。
意図は「根拠が壊れたら」であって「15 分後の終値で壊れていたら」ではない。
**これは意図の解像度の問題**でもあるので、**オーナーに確認したい**(§6)。

## 4. 意図に無いが実装されているもの(＋)の扱い

**原則: 機構の検証では外す。** 検証したいのは意図した機構であって、当時の執行の工夫ではない。

| 対象 | 第 1 周 | 後の周 |
|---|---|---|
| 2 本目の指値(ヒゲ半値戻り) | **外す** | 機構が陽性なら足して差分を測る |
| 決済の固定ドル階段 | **外す**(単純な決済に置換) | 陽性なら執行の層で測る |
| 建玉上限 | 1 単位に固定(増し玉なし) | 陽性なら増し玉を測る |

**理由**: これらを入れたまま陰性が出ると、「機構が無い」のか「執行の工夫が足を引っ張った」のか
分からない。§0 の 3 分類のうち **2 を消すため**に外す。

## 5. バグの扱い(**3 を消すため**)

| | 内容 | 検証での扱い |
|---|---|---|
| **A** | 建玉上限の条件が逆(`>=` であるべきは `<`)。建玉 0 では新規が入らない | **意図どおり `<` に直す**(合意済み) |
| **B** | 買いドテンの枚数が `size + mybtc` = 0 枚(売り側は正しく倍) | **直す**(合意済み) |
| **C** | `get_candle_first` が 900 秒(15 分)をハードコード | 足を掃引するので**直す** |
| **D** | `get_candle_first` が同じ足を `len(data)` 回追加 | 検証では初期化の仕方が違うので**該当しない** |

**バグを直した版で測る**というのが合意。**したがって「原典どおりの再現」は行わない** —
原典どおりでは新規建玉が入らず、検証にならないため。この選択自体を射程に書く。

## 6. オーナーに確認したいこと(2 件)

1. **I-5**: 弱いシグナル(上ヒゲ陽線 / 下ヒゲ陰線)で、**建玉が無いときに新規を建てる**のは
   意図どおりか。コードはそうなっているが、「弱い = 決済で止める」という説明とは読み方が分かれる。
   → 掃引の分岐として**両方測る**予定だが、意図がどちらだったかは記録しておきたい。
2. **3-c**: 無効化は**終値**で見るのか、**足の途中でも**割ったら降りるのか。
   当時の実装は終値のみ。意図としてどちらだったか。

**この 2 つは「意図の記録」であって、検証の実行を止めるものではない**(両方測る)。
ただし**どちらが意図だったかを先に書き残しておかないと、後から結果に合わせて選べてしまう。**
