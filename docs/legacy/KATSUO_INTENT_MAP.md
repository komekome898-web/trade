## 2. 最大の乖離 — **機構は「清算」なのに、測っているのは「ヒゲ」**(I-6 / I-7)

意図は **「清算の連鎖が燃料を使い切ったところで反転する」** という**フロー**の話である。
実装が見ているのは **15 分足の OHLC だけ**で、清算の量も向きも建玉も出来高も参照しない。
ヒゲは清算連鎖の**痕跡(代理変数)**にすぎない。

**これを潰しておかないと、判定が出たときに切り分けられない**:

| もし結果が悪かったら | 考えられる原因 |
|---|---|
| 機構が無い | 清算連鎖のあとに反転は起きない |
| **代理が悪い** | 反転は起きるが、**ヒゲでは清算連鎖を拾えていない**(ヒゲの多くは清算ではない) |

**したがって検証は 2 本立てにする**(これが「事前に決めておく」の中身):

- **層 ①-a(代理)**: ヒゲ 4 分類が後続リターンを予測するか。→ BitMEX 1 秒バー 2017-2021 で測れる。
- **層 ①-b(直接)**: **清算フローそのもの**が後続リターンを予測するか。
  → Gate.io の 1 件ごと 90 日 + 記録中の 4 取引所で測れる(BitMEX の清算履歴は存在しないため、
  **同一ベニュー・同一期間での ①-a と ①-b の直接比較はできない**。これは射程として明記する)。
- ①-a が陰性で ①-b が陽性なら、**「機構はあるが代理が悪い」**と言える。
  ①-a が陽性なら代理は機能している。**両方測って初めて 1 と 2 が分かれる。**

## 3. I-8(無効化ライン)— 当初 3 件挙げ、**1 件は取り下げ、1 件は格下げ、1 件が残った**

意図: 「その反発の根拠(ヒゲの先端)が壊れたら降りる」。
**オーナーの回答(L-044)で、私の指摘のうち 2 件は的外れだった。**

### 3-a. `lcprice` が**建玉に紐付いていない**(**残る。ただし実害は限定的**)

`lcprice` はグローバルで、**シグナルが出るたびに上書きされる**(171 / 174 / 182 / 185 行)。
建玉を開いたときのヒゲ先端ではなく、**直近にシグナルを出した足の先端**を見る。

**実害が小さい理由**: 逆向きのシグナルが出たときは同時に `order_exit` も呼ばれるので、
建玉は閉じに向かう。**破綻するのはその決済指値が約定しなかった場合だけ** —
買い建玉が残ったまま `lcprice` が上ヒゲの高値になり、次の無効化判定
(`Close > lcprice` なら保持)がほぼ必ず偽になって即決済に倒れる。

**検証では建玉に紐付けた版を既定とし、原典どおりの版と差分を測る。**

### 3-b. 無効化の判定が **`signal == 0` の足でしか走らない** —(**格下げ: 穴ではなく思想の帰結の可能性が高い**)

`lcprice` の判定は `else`(シグナルなし)の枝にしかない。買い建玉中に価格が先端を割り、
その足が「下ヒゲ陽線(強い買い)」なら、**降りずに買い増す。**

当初これを穴として挙げたが、**3-c の答え(L-044)を踏まえると、同じ思想の帰結**である:
先端を割ったこと自体が**新しいヒゲの一部**なら、根拠は壊れたのではなく**更新された**。
だから新しいシグナルが出た足で古い無効化ラインを見ないのは、一貫している。

**未確認として残すこと**: これが意図だったのか、たまたまそうなったのかは
オーナーに確認していない。**検証では両方(新シグナル時も無効化を見る版 / 見ない版)を並べる。**

### 3-c(**取り下げ**)判定が終値のみ — これは**意図どおり**だった

私は「穴」として挙げたが、**誤りだった。オーナーの答え(L-044)**:

> 終値で見る。**足の途中ではその値がヒゲになるかわからない**ため、
> **ヒゲになったならさらに反発の根拠になる**

つまりカツオは **「確定した足の形」だけを信じる**という一貫した思想で作られている。
足の途中で先端を割ることは、**それ自体が新しいヒゲの形成過程でありうる**ので、
そこで降りるのは根拠の取り違えになる。**終値で見るのは仕様であって、限界ではない。**

**この答えは 3-b の読み方も変える** → 下記。

## 4. 意図に無いが実装されているもの(＋)の扱い

**原則: 機構の検証では外す。** 検証したいのは意図した機構であって、当時の執行の工夫ではない。

| 対象 | 第 1 周 | 後の周 |
|---|---|---|
| 2 本目の指値(ヒゲ半値戻り) | **外す** | 機構が陽性なら足して差分を測る |
| 決済の固定ドル階段 | **外す**(単純な決済に置換) | 陽性なら執行の層で測る |
| 建玉上限 | 1 単位に固定(増し玉なし) | 陽性なら増し玉を測る |

**理由**: これらを入れたまま陰性が出ると、「機構が無い」のか「執行の工夫が足を引っ張った」のか
分からない。§0 の 3 分類のうち **2 を消すため**に外す。

> **外してはいけないもの(2026-09-09、L-046。自分で破ったので明記する)**
> **○ と △ の項目は外さない。** 外してよいのは **＋(意図に無い実装)だけ**である。
> K1 の最初の事前登録は、主指標を「固定 `h` 本後のリターン」に置いていた。
> これは **I-8(ヒゲ先端の無効化 = ○)を黙って取り除く**ことであり、この §4 に自分で違反していた。
> **カツオに固定の保有期間は存在しない**(「反発の根拠が壊れるまで持つ」)。
> 実データでも保有の中央値は **8 本**で、`h = 1, 2` は分布の下から 1/4 しか見ていなかった。
> **教訓**: 「意図に無いものを外す」を実行するとき、**外した結果として何が失われるかを
> 意図マップに突き合わせ直す**。外す作業そのものが、○ を巻き添えにしうる。
