# P2-02 設計監査 1(盲検)

対象: `docs/PHASE2/P2-02/PREREG.md`(草案、凍結前)。読み取りはタスク指定の許可ファイルのみ。

## 10問チェック

1. **仮説文に数値・過去判定が混入していないか** — 可。「存在し、捕捉できるか」のみで数値・判定なし。

2. **分母・n・MDE** — 致命。開発セット(2009-01-05〜2021-04-12)を実測すると r_night 有効件数 n=3019(PREREGの「n≈3,000」は妥当)。
   ただし想定 std=80bps は未検証の仮定値で、実データでは **前提次第で結果が激変する**:
   - 生データのまま(マスクなし): std=374.5bps → SE=6.8bps → MDE≈19bps/日。これは保守コスト後に必要な平均 14bps/日を**上回る**ため、真の効果が生存境界ちょうどでも検出力不足になる。
   - open=0 の4行(下記8)を除外: std=88.3bps → SE=1.6bps → MDE≈4.5bps/日(PREREGの「MDE≈4bps」に近い)。
   MDEの値がマスク規則の有無で 4倍以上動く。マスク規則(どの関数で何を弾くか)を凍結前に明記し、その規則で算出したMDEを事前登録すること。

3. **封印境界の一致・開発セットとの非重複** — 可。SEALED.json は主系列 `etf_1343_daily.csv` の calendar 30%点(2021-04-13)を**全ファイル共通**の境界として適用しており、PREREGの記載と一致。`reit_index_daily.csv`(2025-06-16〜)は全行がこの境界以降のため `load_unsealed` で0行(PREREGの「全期間封印」と整合)。dev/train/valの日付は境界に触れていない。

4. **コスト定数がすべて measured/primary_document か** — 致命。`sor_commission_yen=0` は primary_document だが **2026-05-18約定分から**有効(constants.yaml 明記)。開発セット全体(2009-2021)と封印期間の大半(2021-04〜2026-05)はこの無料化以前であり、当時の実手数料は0円ではない。PREREGは「手数料0+丸め0/1ティック」を**全期間一律**に適用しており、無料化前の期間に無料化後の定数を遡及適用している。`etf_spread_bps` はnull/assumedのため不使用としている点は適切(可)。

5. **対照3種+反事実性** — 可。シャッフル/全時刻無作為+状態内無作為(診断)/符号反転の3種に加え1321比較を追加。仕様§の(i)(ii)(iii)を満たす。

6. **探索面 N0** — 可。「N0=1」と明記、診断(ボラ三分位3・曜日5・月12・権利落ち前後2)は選択に使わないと明記。

7. **停止規則・反復予算** — 可。仕様書と同一(直近3反復のval改善<MDE、または8回)。

8. **既知欠陥への対処** — 致命。PREREGが引く既知欠陥は「上場直後の出来高0(93日)」「権利落ちの機械的下落」のみ。しかし実データ検査で **`etf_1343_daily.csv` 自身に open=0 の異常行が4件**(2009-07-01, 07-03, 07-27, 08-06。いずれも開発セット内)存在し、これが r_night=-100% という偽の外れ値を生み主指標を汚染する(2番参照)。schema/reit_onr.jsonの既知欠陥はこの型のエラッタを **1321のみ**に記載し1343には記載がなく、PREREGもこれを拾えていない。また「出来高0が93日続く」との記載は実測(2009-01-05より前の行数=71、暦日換算=111日)のどちらとも一致しない。数値を実測に修正し、open<=0/close<=0 の行を明示的にマーキング(除外ではなく両建て報告)する規則を追加すること。

9. **執行様式の既知正解テスト合格** — 要修正。`qa_pipeline_daily_20260905/RESULTS.md` は `overnight_returns/drop_glitches/mean_t` の回収(Y=0/2/5bps全てwithin MDE=YES)とグリッチ検出(11件中11件検出)に合格しており、日次・板寄せ型の一般部分は合格記録として妥当。ただし本研究固有の**配当調整ロジック(権利落ち日のopen(t+1)への分配金加算)はこの既知正解テストの対象外**で未検証。極小テープでの手計算検証を追加すべき。

10. **反証文の具体性** — 可。「封印期間で保守コスト後95%CIがゼロを含むなら棄却」「楽観のみ正なら保留、引き金=スプレッド実測」は具体的かつ引き金名指し済み(仕様§6の要件を満たす)。

## 個別検証項目

- **配当調整の妥当性**: 引成で買い(close(t)所有開始)→翌寄成で売り、t+1が権利落ち日なら close(t) 時点で権利確定の最終日にあたり、権利落ちによる機械的下落分をopen(t+1)に加算して補正する設計は方向として妥当(可)。
- **保守コスト**: 「1ティック/片側」は板寄せの丸めのみを想定しており、スプレッドは`etf_spread_bps`未計測につき欠落。特に薄商いの初期(2009-2013、開発セット内にも出来高0が22日残存)は実効コストが1ティックを超え得る。保守バーが真に保守的かは未保証(要修正)。
- **取引可能性基準の定義**: 「1口固定の最大ドローダウン ≤ 年間期待利益×3」は未定義。(a)年間期待利益の算出窓・年率化方法、(b)最大ドローダウンが単一実現値かブートストラップ分布のどの点(中央値/95%点)か、(c)倍率3の根拠、のいずれも記載なし。単一路の最大DDはサンプル依存性が大きく、このままでは判定不能(致命)。
- **1343二系統の突合**: 重複期間(2011-09-05〜2026-09-03, n=3687)でopen/closeが**完全一致(差分0)**。両系列とも実質同一のYahoo Chart APIに由来し独立ソースではないため、PREREGが期待する「誤プリント・分割・配当調整の検出」用の突合は検出力ゼロ。さらに突合対象期間は2011-09-05以降のみで、開発セット内で実際に見つかった2009年の異常4行(上記8)はそもそも突合の射程外。
- **closing auction 時刻変更(2024-11-05)**: 大引けが15:00→15:30に変更(constants.yaml)。封印評価期間(2021-04-13〜2026-09-03)がこの構造変化をまたぐが、PREREGに記載なし。板寄せ戦略が「close(t)」の定義そのものが変わる境界をまたいで評価される点は、最終評価時に前後分割報告を検討すべき(要修正)。
- **上場初期の薄商い**: 2008-09-16〜2009-01-02(出来高0)は開発セットの起点2009-01-05より前に正しく除外されている(可)。ただし2009-01-05以降も散発的なゼロ出来高(開発セット内22日、祝日フラット含む)が残り、上記スプレッド論点と合わせて印付け方針の徹底が必要。

## 総合判定

**致命あり(要差し戻し)**。項目2・4・8・および「取引可能性基準の定義」が未解決のまま凍結すると、主指標の値・検出力・判定基準のいずれも再現性を持たない。

## 修正リスト

1. open<=0/close<=0 の異常行マスク規則を明記し、そのマスク後のstdでMDEを再計算して事前登録する(項目2・8)。
2. schema/reit_onr.jsonへの1343側エラッタ追記を依頼するか、PREREG側に自己申告の既知欠陥として明記し、「93日」の数値を実測値に訂正する(項目8)。
3. 手数料0円が2026-05-18約定分からである旨を明記し、それ以前の期間(開発セット全体・封印期間の大半)に適用する手数料前提を無料化前の実額に差し替えるか、少なくとも「無料化前提の楽観シナリオ」として明示的に切り分ける(項目4)。
4. 配当調整ロジック専用の極小テープ(手計算値付き)を既知正解テストに追加する(項目9)。
5. 「取引可能」基準(最大DD/年間期待利益)の算出窓・分布化(ブートストラップ等)・倍率根拠を定義する。
6. 1343二系統の突合は独立検証にならない旨をPREREGに明記し(過信しない)、代わりにopen/high/low/close間の内部整合性チェック(high>=open,close等)や生JSON(adjclose・events.splits)照合など独立性のある検証に置き換えるか、突合の限界を明記した上で残す。
7. closing auction時刻変更(2024-11-05)を既知の構造変化として記載し、最終評価時に前後分割の参考値を出す方針を追加する。
8. 薄商い日のスプレッド未計測リスクを「保守コスト」の限界として明記する。
