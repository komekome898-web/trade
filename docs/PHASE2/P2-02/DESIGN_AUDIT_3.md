## 監査 2 の未解決/部分項目の判定

1. **項目4(配当調整の極小テープ)— 未解決**。本稿 §執行様式パイプラインにも「作成中(合格記録の場所を本書に追記してから凍結)」
   と明記されたまま。合格記録は依然リンクなし。唯一の残存項目。
2. **項目7(closing auction 2024-11-05 前後分割)— 解決**。最終評価節に「2024-11-05 の引け板寄せ 15:30 化の前後を分けて併記する
   (判定は封印期間全体)」が追加され、監査1・2が求めた前後分割の記載義務を満たした。
3. **項目8(薄商いのスプレッド未計測リスク)— 解決**。コスト節に「出来高が想定ロットの100倍未満(5,000口)の日を印付けし、
   除いた主指標も併記(判定は全体)」という具体的閾値・扱いが追加された。実測(下記)で dev セット中 volume<5,000 は26行
   (うち21行は幽霊行と重複、実質的な薄商いは5行)で規模は小さい。
4. **ex_date 規約(監査2の新規問題)— 解決**。導出規則(記録日→以前の最終取引日→T+3期は2取引日前/T+2期は1取引日前)を
   実装・実行し、PREREG指定の手計算4件のうち実データに存在する2013-02-10→02-06、2019-08-10→08-08は完全一致。
   2018-03-31→03-28、2020-03-31→03-30 は関数を仮想入力に適用しても一致(下記「新規問題」参照、データそのものには
   この2レコード日は存在しない)。**データ検証**: 導出した dev セット33件で r_night(x−1) 中央値 = **−71.9bps**(≤−50bps 合格)、
   r_night(x−1)+amount/close(x−1) 中央値 = **+4.4bps**(±50bps 以内、合格)。**規約は正しいと判定でき、補正を使ってよい**。
5. **幽霊行(監査2の新規問題)— 解決**。規則2(volume=0 かつ OHLC同値 かつ close=前日close)を実装・適用。
   dev セット内21行検出(schema記載の「約20行」と整合)。全て機械的除外基準に合致。

## 開発セットでの欠陥規則の再現(規則1・2適用)

- 生ペア n=3,019(2009-01-05〜2021-04-12、価格ファイル自身の日付列に基づく)。
- **規則1(open/close=0・空、誤プリント)**: 実データでは open=0 の4行(2009-07-01/03/27, 08-06)のみが該当し、
  いずれも close は正常値(誤プリント判定式でも close は30%乖離なし)。formula が実際に参照する値
  (close(t) と open(t+1))のみで判定すると除外4ペアで **n=3,015**(監査1・2の実測と一致)。
  ※文言「行を含むペアは…除外」を字面通り(前後2ペアとも除外)に取ると n=3,011 になり、
  PREREG自身が引用する「n≈2,974/3,015」と食い違う。下記「新規問題」参照。
- **規則2(幽霊行)適用後**: n=**2,976**(PREREGの実測記載 n≈2,974 とほぼ一致、僅差は境界ペアの数え方のみで結論に影響なし)。
- 費用後評価に使う分布: **n=2,976、平均 4.58bps/日、σ=88.78bps、SE=1.63bps、MDE(α0.05, power0.8)≈4.56bps/日**。
  PREREGの記載(n≈2,974、σ≈89bps、MDE≈4.6bps)を実測で再現・確認。

## 薄商いマーキング(volume<5,000)

- dev セット価格行のうち volume<5,000 は **26行**。うち21行は上記幽霊行(volume=0)と重複するため、
  幽霊行以外の「真の薄商い」は**5行**のみ。規模は小さく主指標を動かす懸念は低いが、印付け自体は仕様通り機能する。

## 新規問題

- **規則1の文言と実測値の不一致**: PREREGの「行を含むペアは全期間で機械的に除外」という表現は、素直に読むと
  問題行の前後2ペアを除外する(n=3,011)が、実際にPREREGが引用しているn(≈2,974〜3,015)は「ペアの計算式が
  実際に参照する値(close(t)またはopen(t+1))自体が0/誤プリントの場合のみ除外」という狭い解釈(n=3,015)でしか
  再現しない。今回は狭い解釈で実測し既存数値と整合したが、次の実装者が字面通りに広い解釈を採ると n が変わり
  再現性が崩れる。**要修正**: 規則1の文言を「close(t) または open(t+1) 自体が0/空/誤プリントの場合に限りそのペアを
  除外」に明確化すること(致命ではないが、放置すると監査4回目で再び揺れる)。
- **手計算ケースの一部が実データに存在しない**: 分配金ファイルの記録日は常に2/5/8/11月の10日固定(実測で確認)なのに、
  PREREGの手計算4例のうち2018-03-31・2020-03-31はこのパターンに属さず、実際のファイルに該当レコードがない
  (仮想入力として関数に通せば期待値と一致するので**アルゴリズム自体は正しい**)。実データに基づく検証を装う記述として
  紛らわしいため、実在する2013-02-10・2019-08-10の系列(既に一致確認済み)に差し替えるか「架空例」と明記すべき
  (軽微、致命ではない)。
- **`overnight.py: ex_dates_from_record_dates`は現時点で未実装**(grep で不在を確認。他ワーカーが作業中の可能性はあるが
  読み取り時点では該当関数なし)。今回の検証は監査側で独立に規則を再実装して行った。着手前にこの関数がPREREGの規則と
  一致することを別途確認する必要がある(実行前の残タスクとして明記推奨)。

## 総合判定

**要修正**ではあるが致命は無し。監査2の5論点中4件(項目7・8・ex_date規約・幽霊行)は実測で解決確認、
項目4(既知正解テープ)のみ未解決。新規に見つけた2件(規則1文言の曖昧さ、手計算例の一部が実在しない)は
軽微で、数値自体(n/σ/MDE)の再現性には影響しない。

**既知正解テストの合格記録の追記を条件に凍結可**。追加条件として、規則1文言の明確化(狭い解釈である旨の明記)を
次稿までに反映することを推奨する。
