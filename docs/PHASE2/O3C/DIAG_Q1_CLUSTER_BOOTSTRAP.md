# O-3c 段0(Q1)診断 — クラスタ(起点日)ブートストラップで 16 セルを引き直す

**これは判定のやり直しではない。ブートストラップの再標本化の単位だけを直した測定記録である。**
統計量の定義・対照の定義・窓の定義・データ範囲は `RESULT_STAGE0.md` の判定時と一切変えていない。
**リードの読みは書かない**(依頼の指示)。

対象: `results/o3c_stage0/stage0_binance_cm_2024-06-13_2024-10-14.csv`(判定時に書き出された 11,933 行)。
判定区間 Binance COIN-M BTCUSD_PERP 2024-06-13〜2024-10-14(124 日)のみ。
**この診断で新しくデータファイルを開いていない**(事実。判定時の生成物 CSV だけを読んだ)。

## §0 直した欠陥

判定時のブートストラップ(`scripts/run_o3c_stage0.py` の `boot_diff_ci`)は
**カスケードを 1 件ずつ独立に復元抽出**していた。しかし 5,638 カスケードは 124 の起点日に載っており
(1 日あたり平均 45.5 件、最大 269 件)、**同じ日のカスケードは同じ相場つきを共有するので独立ではない。**
同じ欠陥は Q2 の診断でも指摘されている(`DIAG_Q2_PERMUTATION_NULL.md` 落とし穴 3)。

起点日あたりの件数(**事実**、CSV の `start_ms` を UTC の暦日に落として数えた):

| 群 | n | 起点日の数 | 日あたり min / 中央 / 平均 / max |
|---|---|---|---|
| real 全体(long+short+mixed) | 5,638 | 124 | 2 / 45.5 / 45.47 / 269 |
| real long | 3,314 | 123 | 2 / 25.0 / 26.94 / 161 |
| real short | 2,288 | 123 | 1 / 16.0 / 18.60 / 93 |
| placebo long | 394 | 94 | 1 / 3.0 / 4.19 / 29 |
| placebo short | 299 | 90 | 1 / 2.0 / 3.32 / 22 |

**プラセボ窓にも起点日がある**(事実。CSV の `start_ms` が群を問わず入っている)。ただし
プラセボが載っている日は 124 日のうち 94 日 / 90 日で、**全日を覆っていない**。

## §1 手順

1. **再標本化の単位を起点日にする。** 日の集合(real ∪ placebo の起点日 = 124 日)から
   **日を 124 個復元抽出**する。その日のカスケードは**全部まとめて入るか全部入らないか**。
2. **実群と対照群は同じ日の抽選を共有する**(同日は同じ相場つきを共有するため)。依頼の
   「プラセボ側も同じ日単位のクラスタで扱う」に対応。独立に引いた場合は §6 に併記した。
3. **統計量は判定時と同じ「プールした平均の差」**。クラスタ版では日ごとの合計と件数を足し上げた
   比推定 `Σsₐ/Σcₐ − Σs_b/Σc_b` で計算する。**点推定は判定時と完全に一致する**(下記 §2)。
4. 反復 **10,000 回**、種は判定時と同じ **`numpy.random.default_rng(20260913)`**
   (`scripts/run_o3c_stage0.py:201` の `BOOT_SEED` を読み取った。**事実**)。
5. 区間は差の分布の 2.5% / 97.5% 分位(判定時と同じ)。
6. 対象は依頼のとおり **向き 2 × 窓 4 × 主張 2 = 16 セル**、対照は**主のプラセボのみ**
   (「行きすぎ」= 平均 bp 差、「転換」= `-sign(内部方向bp) × 反応窓bp` の差)。

### 変えていないもの(確認)

- カスケードの構成、プラセボの抽出、無清算窓の抽出 — **再実行していない**。判定時の CSV をそのまま使う。
- NaN の扱い(`clean()` で除外)、転換指標のタイ除外、窓 1/5/15/60 分、族 16。
- 固定値(`PREREG.md` §6)には触れていない。

- **並べ替え後の幅比の平均は 16 セルすべてで 0.93〜1.04**(全セルの範囲 0.75〜1.25)。
  **実装は正しく較正されている**(日の構造を消せば iid 版に戻る)。
- 実測の幅比が並べ替え後の範囲の外にあったのは **16 セル中 8 セル**:
  1分 long 行きすぎ 0.55 / 5分 long 行きすぎ 0.83 / 5分 long 転換 0.69 /
  1分 short 行きすぎ 0.66 / 5分 short 行きすぎ 0.67 / 15分 short 行きすぎ 0.66 /
  **60分 short 行きすぎ 1.33** / 60分 short 転換 0.83。
  **このうち幅が広がる向きだったのは 60分 short 行きすぎ の 1 件だけ**で、残り 7 件は狭まる向き。
- 残りの 8 セルは並べ替え対照と区別がつかない = **日の構造の効果が検出できなかった**。
- この較正対照は反復 4,000 回・乱数の消費順も別のため、ここの幅比は §3 の表(10,000 回)と
  小数第 2 位で数 % ずれる(例: 15分 long 行きすぎ §3 で 0.80、ここで 0.77)。**分類には使っていない。**


再現手順(スクリプトは一時領域に置いた。リポジトリにはコミットしていない):

## §6 自分が置いた仮定と限界

1. **【仮定】クラスタは「UTC の暦日」。** `start_ms` を UTC の暦日に落とした。
   日をどこで切るか(UTC 0 時 / 取引所の資金調達時刻 / 日本時間)で結果は変わりうる。
   **UTC 以外の切り方は測っていない。** 判定区間の清算データは ms の UNIX 時刻で UTC が確定している
   (`PREREG.md` §7)ので、日の境界の選択だけが仮定。
2. **【仮定】「転換」の予想符号は向きに依らず正。** 事前登録は転換の統計量を定めていない
   (`RESULT_STAGE0.md` §3 の逸脱 #3 / §7 の不備 3)。実行時に定義された
   `-sign(内部方向) × 反応窓bp` は「戻る = 正」なので、機構の予想は正だと読んだ。
   **この読みは事前登録の逐語ではない。**
