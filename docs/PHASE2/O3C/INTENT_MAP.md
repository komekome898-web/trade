### §4.1 この判定から出る帰結(最重要)

**✕ が 3 件(I-01・I-06・I-08)残っている。** `research-protocol` §0.5 と CLAUDE.md §5.2 により、
**この状態で測って出た陰性は陰性ではなく「不明」**にしかならない。したがって:

1. **事前登録の前に I-01 と I-08 の測定機構を実装する。** 具体的には (a) 清算イベントの時刻を起点に
   反応窓を切り、対象市場の価格系列と突き合わせる測定器、(b) 価格別の約定の積み上げと建玉から
   清算価格帯の候補を出し、実際の清算価格と照合する測定器。どちらも新規。
2. **I-06 は原文どおりには実行できない。** BitMEX を「最初に使う」ことはできない(清算が無い)。
   代わりに使える BitMEX 由来のものは保険基金の日次残高(2016-02-28〜、取得済み)だけで、
   これは清算の**強度の代理**であって清算イベントではない。**オーナーに事実として報告する。**
3. I-04・I-05 の △ は、1 の測定器を作れば自動的に解消する(入口を清算イベントに差し替えるため)。

| 3 | `anchor_max_staleness_ms` / `future_max_staleness_ms` = 300_000 | 起点・反応窓で価格を何分前まで遡って許すか | 固定する。欠測の多い区間の扱いに直結 |
| 4 | `max_attempts=200` | 無清算窓の再抽選の上限 | 固定する(結果に効かないが再現性のため) |
| 5 | 規模 = 数量 × 価格 | 契約単位の差を吸収していないため**同一取引所内の相対比較専用** | **取引所を跨いで規模を比べない**と事前登録に書く |
| 6 | Binance COIN-M の `SELL` = ロング強制決済 | 向きの対応 | **一次資料で未確認。**向きの非対称は族の軸なので、**事前登録の前に公式ドキュメントで確認する**(未確認のまま測ると I-01 が △ に戻る) |

**#6 は測る前に潰す必要がある。**向きを取り違えると、ロング清算とショート清算の非対称という
族の軸そのものが反転する。
