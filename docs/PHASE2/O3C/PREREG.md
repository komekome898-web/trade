## 1. 問い(2 つに分ける。混ぜない)

- **Q1 観測**: 清算の連鎖(カスケード)の後に、価格は戻るか。**「行きすぎ」と「転換」を別の 2 主張として測る**
  (INTENT_MAP §4.2 の決定 3)。
- **Q2 予測**: 清算が起きる価格帯を事前に当てられるか。入力は 3 通りを**並べて**測る
  (約定の積み上げ / 建玉の積み上げ + 資金調達率 + L/S 比 / 現在値からの乖離)。
  **資金調達率は建玉のアーカイブに列が無く**(実測)、別系統の月次アーカイブから取得した(2023-05〜2024-11、19 か月、欠測 0)。

Q1 と Q2 は別の検定単位。Q2 が当たっても Q1 が無ければ執行の根拠にならず、逆も同じ。

## 3. 族(何を 1 つの検定にするか)

- 検定単位 = **カスケード**(個々の清算ではない)。
  **注意(探索区間の観察、2026-09-13)**: `n_events` は常に偶数で、中央値は 2(`POWER_INPUTS.md` §2)。
  取引所が 1 つの清算オーダーに対して約定行を複数出すため、**中央値のカスケードは実質 1 オーダー**である。
  機構の主張は「連鎖」についてのものなので、**規模あたりのインパクト(bp / 規模)を主の読み方**にし、
  単純な平均 bp を主にしない。規模を層にして族を増やすことはしない(多重性を増やさないため)。
- 軸: 取引所 × 向き(**ロング清算 / ショート清算 / 混在**の 3 水準。`none` = 清算なしは対照群であって族の水準ではない)× 反応窓(1・5・15・60 分)。
- **取引所ごとに別の族**にし、混ぜない(清算方式と時刻精度が違う。INTENT_MAP §4.2 の決定 5)。
- **ローソク足の時間軸は族に入れない**(同 決定 1)。
- **取引所を跨いで規模を比べない**(契約単位の差を吸収していないため。INTENT_MAP §4.3 の #5)。
- **族の大きさ(2026-09-13 に確定)**:
  - **段 0** = 取引所 1(Binance COIN-M)× 向き **2** × 反応窓 4 × **主張 2**(行きすぎ / 転換)= **16 検定**
    **訂正(2026-09-13)**: 当初 向き 3 で 24 としたが、**mixed は判定区間に 36 件しかなく**(`POWER_INPUTS.md` §6)、
    標準偏差も long/short の 3〜5 倍ある。検定に耐えないので**族から外し、記述のみとする**。
  - **段 1** = 取引所 2(Binance COIN-M・Gate)× 向き 2 × 反応窓 4 × 主張 2 = **32 検定**。
    ただし **Gate の判定区間は存在しない**(90 日を探索で焼いた、I-008)ので、実際に判定できるのは
    Binance COIN-M 側の 16 のみ。Gate は**探索としてしか読めない**
  - **段 2(Q2)** = 手法 3 × 向き 2 = **6 検定**(反応窓は Q2 に無い)
  - **多重性は段ごとに閉じる**。段 0 で 16、段 2 で 6 として補正する。段をまたいで合算しない
    (段 1 は段 0 が通った場合にのみ開くので、その時点で改めて数える)
  - **周回数を算入する**: 改良して測り直したら、その周回分を上の数に足す(`research-protocol` §0.3)
- **向きの軸の出所(監査 #1)**: 段 0 の Binance COIN-M は**一次資料で確認**(公式文書の 2 経路、`O3C_VERIFY_LIQUIDATION_SIDE_2026-09-13.md` 主張 1)。
  **Gate は一次資料では決まらず、傍証で決着した。**その傍証は「ロング清算は売りをぶつけるので価格が下がる」という、
  **Q1 が測ろうとしている機構そのものを前提にラベルを割り当てている**(循環)。したがって:
  **判定の主戦場である段 0 の向きの軸は循環していない。循環するのは段 1 の Gate 側だけ**であり、そのことを結果の読みに必ず添える。

## 4. 対照(偽陽性を機構から分ける)

1. **プラセボ**: 規模を揃えた「清算を伴わない出来高の急増」。
2. **清算の無い時間帯**。

清算のカスケードの後の動きが、単なる出来高の急増の後の動きと変わらないなら、機構は清算ではなく出来高。

### 5.1 探索済みの区間(I-008、2026-09-13)

**Gate の清算 90 日(2026-06-10〜09-08)は探索済み。** 清算データの `size` の符号の意味を決めるために、
リードの指示で**実データにイベントを定義して集計をかけた**(79,183 件を 60 秒のギャップで塊にし、
塊の中の約定価格の変化の向きを数えた)。これは測定であり、`research-protocol` §0.0 の規則により
**この区間は判定に使えない**。

**そのとき見た数値**(探索済みの観察であって、Q1 の結果ではない): 同符号の塊のうち、
正の符号は 80.0% が価格下降、負の符号は 80.5% が上昇。**この数値を Q1 の結論に使わない。**
Q1 は「塊が終わった後に価格が戻るか」を問うており、上の観察は「塊の最中に価格がどちらへ歩いたか」
であって別の量だが、同じ区間・同じイベント定義から出ているため、区間ごと判定から外す。

## 7. MDE と反証(**最重要の空欄**)

- **MDE(2026-09-13 に確定。Binance COIN-M の段 0 について)**

  前提(すべて `POWER_INPUTS.md` の実測。探索区間 251 日のみから取った。効果は読んでいない):
  判定区間のカスケード件数 long 3,314 / short 2,288、プラセボの規模一致率 0.144(探索の実測値を
  判定区間にも当てはめる。**これはリードの仮定**)、反応窓ごとの標準偏差は同票 §3。
  検定は両側、**族 16 で Bonferroni**(α = 0.05/16 = 0.00313)、検出力 0.80。

| 反応窓 | 方向 | カスケード n | プラセボ n | 標準偏差 bp | **MDE bp** |
|---|---|---|---|---|---|
| 1 分 | long | 3,314 | 476 | 10.97 | **2.04** |
| 1 分 | short | 2,288 | 329 | 9.94 | **2.23** |
| 5 分 | long | 3,314 | 476 | 27.83 | **5.18** |
| 5 分 | short | 2,288 | 329 | 24.88 | **5.57** |
| 15 分 | long | 3,314 | 476 | 36.86 | **6.86** |
| 15 分 | short | 2,288 | 329 | 37.83 | **8.47** |
| 60 分 | long | 3,314 | 476 | 64.99 | **12.09** |
| 60 分 | short | 2,288 | 329 | 68.98 | **15.44** |

  **読み方**: 1 分と 5 分は 2〜6 bp を検出できる。**15 分と 60 分は 7〜15 bp 未満を検出できない。**
  長い窓で「効果なし」が出ても、それは陰性ではなく**不明**である(この表を結果に必ず添える)。

  **検出力の律速はプラセボの側**。探索区間で規模を揃えられたのは 10,268 件中 1,476 件(14.4%)だけだった。
  対照を「清算の無い時間帯」(1 対 1 で全件揃う)にすると MDE は半分になる(1 分 long で 1.02 bp)。
  **ただしプラセボを外すと「清算」と「単なる出来高の急増」を分離できない**ので、プラセボを主の対照に残す。
  無清算窓は副の対照として併記する。

  **取引所ごとに別の MDE を書く**(監査 #8)。上の表は Binance COIN-M のもの。Gate は判定区間が無いので
  MDE を書かない。規模の定義が取引所間で比較できない(§6 の規模 = 数量 × 価格)以上、単一の基準は作れない。
  (経費の床では決めない。上流ではコストを判定バーにしない = R-091)
- 欲しい効果 < MDE なら**実行しない**(CLAUDE.md §5.2)。
- **反証の条件(2026-09-13 に確定。数値は MDE が決まってから入る)**:
  - **段 0 の機構が「無い」と言える条件**: 判定区間の 16 検定すべてで、
    **カスケード後の反応がプラセボ(規模を揃えた清算なしの出来高急増)と区別できない**
    (差の信頼区間が ±MDE に収まる)。**この条件を満たしたときだけ「陰性」と書く。**
    信頼区間が MDE より広ければ**「不明」**であって陰性ではない(CLAUDE.md §5.2)
  - **段 2 の予測が「できない」と言える条件**: 3 手法すべてで、実際の清算価格が候補の帯に入る割合が、
    **帯の幅から期待される割合(帰無)を MDE 以上に上回らない**
  - **段 1 に進む条件**: 段 0 で、いずれかの向き × 窓で、プラセボとの差が MDE を超え、
    かつ符号が機構の予想と一致する。**進む条件を満たさなければ段 1 を開かない**
  - **「効かない」ではなく「この設計では検出できない」で終わる場合**を明記する:
    NaN の割合が高い / カスケードの件数が検出力の前提を下回る / 時刻の前提(建玉の UTC)が崩れた場合
- **なぜ陰性になりうるか**(事前に列挙する): データ技術者の役が挙げた偽陰性の 3 条件
  (記録停止と「清算なし」の区別がつかない / 時刻のずれ / 秒の清算を分に丸める)。
  それぞれを除く方法を本文に書く。
- **未解決の前提(2026-09-13、実測で決着せず)**: Binance COIN-M の建玉アーカイブの時刻列 `create_time` が
  **UTC かどうか確定していない**。清算(ms の UNIX 時刻で UTC 確定)と資金調達率(同左、00/08/16 時 UTC の
  スケジュールと一致)と並べても日付ラベルに矛盾は出ないが、`create_time` に曖昧さのない時刻表現が無いため、
  **固定のずれ(例えば日本時間)で自身の暦日でファイルが分かれている場合と区別できない**。
  実装は UTC と仮定したままである。**ずれていれば建玉と清算の対応が最大で数時間ずれ、Q2 が直接壊れる。**
  決着させる経路: (a) オーナー PC から Binance の建玉履歴 REST(ms の UNIX 時刻を返す)を数行取り、
  アーカイブの `create_time` と突き合わせる(この環境からは地域制限で不可)、(b) 一次資料での明記を探す。
  **Q2 を測る前に決着させる。**

## 8. オーナーに見せる点(判断を求めるもの)

1. **BitMEX を最初に使うという原文の方針は実行できない。** 保全した約 246 GB に清算イベントが無いため
   (2026-09-08 と 09-12 の 2 回、全経路で確認)。使えるのは保険基金の日次残高だけで、これは清算の
   **強度の代理**であって清算そのものではない。
2. **段 0 の場所を Gate ではなく Binance COIN-M にする。** 再枠組みでは 5 役全員が Gate を挙げたが、
   Gate の価格はマーク価格のみで実約定ではない。マーク価格は操作されにくいよう平滑化された指標で、
   「清算が値段に跡を残すか」を測る変数として筋が悪い。COIN-M は実約定が 375 日ある。
3. **Q2 の入力を原文の「約定の積み上げ」だけにせず、建玉の積み上げも並べて測る。** 原文の入力も
   同じ場所で測るので、どちらが良いかは結果で決まる。
4. **Gate の清算の向きは一次資料では決まらず、傍証で決着した。**その傍証は Q1 が測ろうとしている機構を
   前提にしている(循環)。段 0 の Binance COIN-M は一次資料で確認済みなので、**判定の主戦場は循環していない**。
5. **リードの誤りで、Gate の 90 日を探索に使ってしまった(I-008)。**そのため Gate のこの区間は判定に使えない。
   海外の清算で判定に使えるのは Binance COIN-M の 375 日だけになった。
