読んだもの: `PROJECT_GOAL.md`、`STRATEGY_IDEAS.md` O-3/O-3b/O-3c/O-6、`OWNER_INTENT_2026-09-12.md` §1、
`DATA.md` §2、`O3C_PROCUREMENT*.md`(5本)、`NEGATIVE_FACTS.md` N-011。リードの枠組み(§2以降・K1)は未読。

## 1. 機構の仮説

因果を4段に分ける(2段目までは価格由来データだけでも部分検証できるが、3・4段目は清算識別が要る)。

1. **建玉の蓄積**: 海外高レバ取引所で、ある価格帯を中心に新規建玉(≒将来の清算価格の集合)が積み上がる(仮定: 参加者の平均レバレッジ・エントリー分布は時間で緩やかにしか変わらない)。
2. **清算の発火と板の消費**: 価格がその取引所の証拠金維持率しきい値を割ると、清算エンジンが成行(またはIOC)でポジションを解消し、その取引所の板の**その時点の**厚みを消費する(事実: 清算は取引所のマッチングエンジンが自動発注する強制取引であり、通常の任意注文とは発注動機が異なる — 一般的な無期限先物の設計)。
3. **取引所間の伝播**: 現物・裁定・マーケットメイクの資金がその価格変化を他会場に運ぶ。bitFlyer FX_BTC_JPY は USD建てBTCとJPY建て建玉の合成のため、**BTC/USDの伝播 × USD/JPYのFXレート**という2層構造(推定: bitFlyerの商品設計から)。伝播の速さと大きさは、仲介する裁定資本の量と bitFlyer 自身の板の薄さに依存する。
4. **燃料切れと戻り**: 一方向の清算に使えるレバレッジ玉がその価格帯で尽きると、強制フローが止まり、逆方向の裁定・利確・ショートカバーが優勢になって戻る(O-3のヒゲ仮説と同じ結果だが、ここでは「なぜ止まるか」を清算残量という**観測可能な状態変数**で説明できる可能性がある、という点が価格由来の代理変数と違う)。

**強さの鍵**: 2→3の伝播はゼロで良いはずがない(bitFlyerは海外上位CEXの出来高比で概ね1/200、`O3C_PROCUREMENT_SUPP_D` D1・要点6、事実)。伝播が弱ければ4の戻りはbitFlyer側では観測されず、機構全体が「海外だけで完結し自市場に効かない」で終わる可能性を最初から織り込む必要がある。

## 2. 最初に測るもの

**最初は「3→4」ではなく「2」を単独会場内で測る** — 清算イベント自体の価格インパクト関数(イベント単位、ミリ秒〜秒)。理由: 3・4を跨ぐ前に、そもそも清算が観測可能な会場でどれだけ価格を動かすかという基礎項が要る。ここが小さければ、bitFlyerへの伝播を測るまでもなく機構は弱い。

- 単位: **イベント**(個別清算 fill、またはギャップ閾値でクラスタ化した「カスケード」)。分足・日足はこの段では使わない(集計すると発火直後のインパクトと事後の戻りが同じ足に混ざる)。
- 会場: **Gate.io**(清算90日・OI/mark 1分粒度179日が同一エンドポイントで揃う唯一の会場、事実: `O3C_PROCUREMENT_SUPP_B` §0-2/§1.3)。副系列として **Binance COIN-M**(清算・aggTrades・tradesが2023-06-25〜2024-10-14で全て個別約定粒度、事実: `O3C_PROCUREMENT_SUPP_B` §0-5)を「なぜそうなるか」の高精度な事後分析用に使う(古いのでライブ運用の根拠には使わない)。
- なぜ最初か: 清算識別と価格系列が**同一取引所・同一時計**で揃わない限り、インパクト関数そのものが測れない。bitFlyerとの突き合わせ(時計・レイテンシ・FXレート)はさらに誤差源を足すので、後段に回す。

## 3. 検定単位と族

- **検定単位 = 1カスケード**(個別清算ではなく、事前登録したギャップ閾値内の連続清算をまとめた塊)。個別清算を単位にすると同一カスケード内のイベントが強く相関し、実効サンプル数を過大評価する。
- **族の切り方**(交差させると組合せ爆発するので、直交する3軸を別々の族として扱う):
  1. 会場軸(Gate単独 / Binance COIN-M単独 / 会場→bitFlyer)— 会場ごとにマッチングエンジン・清算方式が違うため合算しない。
  2. 向き軸(ロング清算=下落カスケード / ショート清算=上昇カスケード)— レバレッジのロング・ショート比が対称でない(事実として未測定、`O3C_PROCUREMENT_SUPP_B` §3「レバレッジ分布の直接API無し」)ため、対称と仮定して片方の結果をもう片方に流用しない。
  3. ホライズン軸(発火直後のインパクト窓 / その後の戻り窓)— 別の仮説(2と4)なので同じ検定に混ぜない。
- 多重性: 上記3軸 × 会場数ぶんの検定を**事前登録の時点で数え上げ**、主検定(Gate・両向き合算しない・インパクト窓)を1つ指定してから残りは探索的と明記する。周回のたびに族を作り直さない。

## 4. 反証の条件

- **プラセボ比較**を反証の主軸に置く: 同じ会場・同じ規模の「清算ではない」出来高急増(規模をマッチさせた無作為抽出)を対照群にし、清算フラグ付きイベントの価格インパクト・事後戻りが対照群と統計的に区別できなければ、「清算という**識別子**に情報がある」という機構は棄却できる(=清算は単なる大口出来高の一種で、清算固有の力学は無い)。
- MDEは「経費の床」ではなく**インパクト係数(bp/清算規模)の検出力**で決める。既存の床(bitFlyer往復0.01BTC成行 p50 2.16bp、`NEGATIVE_FACTS.md` N-011)は戦略化の可否には要るが、機構の有無を測る第一段(会場内インパクト)には無関係(推定: インパクトは会場・イベント規模次第でbitFlyerの取引コストとスケールが異なる)。会場内インパクトのMDEはブートストラップで事前に計算し、対照群との差がそれを下回れば「不在」、サンプル数が足りず区間が床をまたぐなら「不明」と明記する(N-011と同じ扱い方)。

## 5. この案が見落としているもの

**無い情報**:
- bitFlyer**自身**の強制決済を識別する手段が無い(`executions`にフラグ無し、一次資料確認済み、`O3C_PROCUREMENT_SUPP_A` A1、事実)。したがって「海外清算→bitFlyer」の**受け皿側**の反応は常に価格・出来高からの推測であり、bitFlyer側で実際に清算が連鎖したかは検証不能。
- レバレッジ分布(証拠金倍率別の建玉内訳)を返す無料APIが見つかっていない(未確認、`O3C_PROCUREMENT_SUPP_B` §3)。清算価格帯の理論的な推定には維持証拠金率とレバレッジの仮定が要るが、その仮定を検証するデータが無い。
- BitMEXの清算オブジェクトに取引所発の時刻が無い(一次資料: 公式swagger、事実、`O3C_PROCUREMENT_2026-09-12` §3)。時刻精度が要る「イベント単位」の検定からBitMEXは除外が必要。

**無い視点**:
- 板の厚み(deep book)そのものの時系列が無い(OKXは現在値のみ、他は自前記録が断続、`DATA.md` §2)。清算インパクトは板の厚みに反比例するはずだが、厚み抜きで「規模→インパクト」を測ると規模の代理変数(OI変化)だけで厚みの効果を見落とす。
- 会場の相対規模比較が単一時点のスナップショットのみ(`O3C_PROCUREMENT_SUPP_C` C4)。カスケードの大きさが会場規模比で相対的にどう変わるか(時系列)は見ていない。

**既存成果の向上**:
- O-3のヒゲ仮説はN-011で「経費の床を超えず不明」と測られた(範囲: bitFlyer自市場5/15分足、2022〜2026)。O-3cはヒゲを清算の**直接**観測に置き換える案だが、直接観測できる期間(Gate 90日・Binance COIN-M旧2023-06〜2024-10)はいずれもN-011の測定期間と重ならない・短いため、「ヒゲより精確か」を同一期間で比較できない(範囲外)。
- N-011は5分・15分足のみで、1時間以上の足は未測(再開条件(ii)として残っている)。清算カスケードの寿命は本来イベント単位で分単位以下のことが多く(推定: 強制決済の執行速度)、5分足より短い粒度で測るほうが機構の検出力は上がる可能性がある。

## 6. やらないこと

- **候補取引所全部を横断で回す測定はしない。** 個別履歴とOI/L-Sを同一粒度・同一取引所で揃えられるのはGateだけ(事実、`O3C_PROCUREMENT_SUPP_B`)。他会場を先に測ると「揃わないデータ同士を無理に突き合わせた」誤差が先に立つ。
- **レバレッジ分布を仮定で埋めた清算価格の理論値計算はしない。** 一次資料が無いまま仮定した維持証拠金率・レバレッジで価格帯を「予測」すると、検証ではなく作文になる(§5.3の全捨ての教訓と同型のリスク)。
- **Hyperliquidの深掘りはこの段ではしない。** 清算識別自体は一次資料で可能だが、深い履歴はRequester PaysのS3のみで中身未確認(`O3C_PROCUREMENT_SUPP_C` C1)。規模もOKX 1本より大きいという単一時点の弱い根拠しかない。

## 7. オーナーの「価格帯の予測」への答え

**見立て(推定)**: 「価格ごとの**約定量**(volume at price)の積み上げ」を素朴に清算価格帯の予測に使うのは弱い代理指標だと考える。清算は個々のポジションの**建玉価格×レバレッジ×維持証拠金率**で決まる幾何であり、その価格を誰が「約定量が多かったから」通っただけの水準(非レバレッジのスポット的フローも含む)と混同するリスクがある(事実として未検証、一般的な清算エンジンの設計原理からの推定)。約定量そのものより、**建玉(OI)の増加が起きた価格帯**の方が理論的に近い代理指標になる(推定)。

**測る方法**: (a) Gateの`contract_stats`(OI・mark price、1分、179日)を使い、ある価格帯でOIが積み上がった後、その後90日の清算履歴(`liq_orders`)がその価格帯に実際に集中するかを事後的に照合する — これは「OI蓄積→清算価格帯」の予測力を実データで検証できる、現状唯一の組合せ(事実:両エンドポイントの期間が重なる)。(b) 素朴な「約定量」版を試したいなら、Binance COIN-Mのaggトレード/清算アーカイブが同一期間(2023-06-25〜2024-10-14)で個別約定粒度で揃うので、そちらで対照実験できる(事実)。(a)と(b)を同一の予測力指標(例: 清算密度の的中率、対照群との比較)で比べれば、「約定量」と「OI蓄積」のどちらが良い代理変数かも副産物として分かる。

**エントリー/利確への応用の見立て(仮定)**: 予測が当たったとしても、それは「価格帯」という**空間的な確率分布**であって「いつ」を当てるものではない。時間軸の予測(§1の3→4)と組み合わせて初めてエントリー・利確のトリガーになりうる。単独の価格帯予測だけでは執行判断には使えないと考える。
