## 1. 機構の仮説

- **BitMEX だけ取引所発の時刻が構造的に無い**(公式 swagger、事実)。受信時刻 `recv_us` で代用すると、
  観測遅延(未測定、`data/latency/ws_vm.csv` は 9.6 分 1 回のみ)の分だけ「戻り」の時間軸がずれる。
  真に先行する反応を遅行と誤判定(偽の無相関)、または無関係な同時変動を相関と誤判定(偽の相関)
  しうる(推定)。
- **粒度の不一致**: 清算は秒/ms、bitFlyer 側で使える連続データは 1 分足のみ(lightchart)。
  同じ分内で清算が先か価格変化が先か分からず、その分の終値を使うと未来情報混入(ルックアヘッド)
  になりうる(推定)。
- **欠測とストリーム停止は記録上区別できない**(`schema/liquidations.json` known_defects、事実)。
  ログ突き合わせを怠ると「清算が無かった分」を実際は「記録が止まっていた分」として数え、
  効果が薄まる方向(偽陰性)に効く(推定)。
- **銘柄混入**: binance_um と okx は全銘柄(BTC 限定でない、事実)。フィルタ漏れは他銘柄清算を
  BTC 清算として混入させ、スプリアスな相関を作りうる(推定)。
- **取引所間の時計精度そのものの一次資料が無い**(未確認)。各取引所のサーバ時計の正確さを
  検証していないので、突き合わせの時刻誤差の下限が分からない。

## 3. 検定単位と族

データの制約から逆算すると、検定単位は自然に「取引所ペア × 期間窓」で分かれ、**1 つの窓に
複数取引所を揃えられる組み合わせは限られる**:
- 2023-06-25〜2024-10-14: Binance COIN-M(清算+約定+OI)× bitFlyer 1 分足。この窓に Gate/OKX/Bybit の
  清算は存在しない(記録開始が 2026 年)ので、この窓では**取引所横断ではなく単一ペア**。
- 2026-06-10〜09-08: Gate(清算+OI/LS 比)× bitFlyer 1 分足。単一ペア。
- 2026-09-08〜現在: 4 取引所(Binance_cm/Bybit/OKX/BitMEX)を同時に持てる唯一の窓だが、
  期間が短く、レジーム(BitMEX は閉鎖に向かう清算)も混じる。
**族の切り方**: 期間の異なるペアを 1 つの検定に統合しない(異なる市場レジームが交絡する)。
ペアごとに独立した検定単位として登録し、多重性はペア数 × 清算の向き × サイズ閾値で数える。

## 4. 反証の条件

- ログとの突き合わせを省くと、記録停止期間を「清算無し」として数え、効果が薄まる(偽陰性)。
  除去: connect/disconnect ログ(`logs/liquidations.out.log`)でカバレッジが確認できる期間だけ使う。
- BitMEX の受信遅延を無視して秒〜分単位の窓で戻りを測ると、真の効果が窓の外にこぼれる(偽陰性)。
  除去: BitMEX は時刻精度が要る検定から外すか、窓を数分単位に広げて誤差を吸収する。
- 分足の粒度で清算時刻を丸めると、同じ分の中の順序が失われ効果が平均化される(多くは偽陰性方向)。
  除去: 清算が起きた分自体を解析対象から除き、次の分から測る。
- Gate の代替 1 分足(`contract_stats` の `mark_price`)は OHLC・出来高を持たない。ヒゲなど高値/安値に
  依存する代理変数はこの窓では作れず、検出力が落ちる(偽陰性方向)。

## 5. この案が見落としているもの

**無い情報**: (1) 板の深さの履歴(bitFlyer・OKX とも現在値のみ、事実)— 清算による吸収・スリッページが
直接観測できない。(2) レバレッジ分布(証拠金倍率別の建玉内訳)を返す無料 API が見つかっていない
(未確認、L/S 比は代理に過ぎない)。
**無い視点**: (1) 補遺 D の規模上位(WEEX/MEXC/Toobit/WhiteBIT/HTX 等)は「規模」と「清算データの
観測可能性」が一致しない(WhiteBIT は 12 位相当だが清算関連エンドポイント自体が無い、事実)—
規模順に深掘りすると外れを引く。(2) 取引所自身のサーバ時計精度という軸そのものが調査に無い。
**既存成果の向上**: (1) BitMEX は 2026-09-16 に上場廃止(事実)— 個別清算は不可能なままだが、
保全済み全深度アーカイブ(trade/quote、オーナー PC)から連続成行の塊という代理を今のうちに厚くする
余地がある。(2) bitFlyer 側の板全深度記録は 4 時間分しかない(既知、AR-78)— 清算連鎖時の板吸収を
見るには全深度記録の期間を今から増やす必要がある。

## 6. やらないこと

- BitMEX 個別清算履歴の再探索(ccxt ソース・S3 一覧・REST の起点指定まで確認済みで構造的に無い)。
- Hyperliquid の市場全体清算率の測定(ユーザー単位 API しか無く、網羅にはインデクサへの投資が要る。
  この段では過大)。
- Gate の 1 分足 OHLC を `mark_price` から合成すること(出来高もレンジも無い値から作ると、実態より
  精緻に見える偽の OHLC になる。「無い」と明記する方が安全)。
- 記録開始前(2026-09-08 以前)の Binance USD-M/Bybit/OKX の清算を価格の急変から逆算するプロキシ作り
  (それは価格由来の内生量に戻り、O-3c が観測したかった「価格の外の情報」という価値を失う。
  K1 が既に測った族と混同する)。

## 7. オーナーの「価格帯の予測」への答え

価格別約定の積み上げ→清算価格帯の予測には、同一期間に (a) 1 件ごとの清算履歴(答え合わせ用ラベル)、
(b) 1 件ごとの約定履歴(積み上げの材料)、(c) 建玉(OI)履歴(ポジション規模の分母)の**3 つ**が要る。
**3 つが同一取引所・同一期間で揃うのは Binance COIN-M(BTCUSD_PERP)の 2023-06-25〜2024-10-14
(約16か月)だけ**(清算アーカイブ・aggTrades/trades・Vision metrics の OI、いずれも鍵不要・公開)。
Gate の 90 日窓(2026-06-10〜09-08)は (a)(c) は揃うが、(b) が欠ける — `candlesticks` は 5〜8 日しか
遡れず、代替の `contract_stats`(mark_price)は 1 件ごとの約定ではないため「積み上げ」の材料にならない。
bitFlyer 自身は (a) が構造的に無く、bitFlyer 単独での価格帯予測はできない。組める構成は
「Binance COIN-M の過去窓で予測手法を作り、それが同時期の bitFlyer 価格(1 分足は揃っている)に
先行するかを別途測る」という間接構成のみ。欠けているのはレバレッジ分布そのもの(未確認、無料では
未発見)— これが無いと同じ OI でも清算価格帯の幅を左右するレバの高低が測れず、L/S 比という粗い代理に
留まる。
