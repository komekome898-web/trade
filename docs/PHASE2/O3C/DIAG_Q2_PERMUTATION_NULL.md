# O-3c Q2 診断: 並べ替えで作った帰無分布

**これは判定ではなく診断である。**判定区間(Binance COIN-M BTCUSD_PERP、2024-06-13〜2024-10-14、
124日)は `RESULT_Q2.md` で既に開封・消費済みであり、本記録の数値を「陽性」「陰性」と呼んではならない。
目的は **「正しい帰無なら向きと大きさはどうなるか」を知ること**だけである。

対象・既定値・測定器は `RESULT_Q2.md` と同一(価格の刻み 50.0 / 積み上げ遡り 24h / 上位 K=3 /
レバレッジ倍率 5・10・25・50・100 / 素朴な帯の半幅 25bp / 照合期限 24h /
カスケードの `gap_ms=60_000`)。`src/bot/research/liq_bands.py`・`liq_response.py` は**一切変更していない**。
判定区間以外のデータ(探索区間の zip)は開いていない(事実)。

## §1 手順

### 1.1 帯の位置を作り直した(既存 CSV には帯が入っていないため)

`results/o3c_q2/q2_cascade_matches.csv` は `in_band_*` / `distance_bp_*` しか持たず、帯の位置が無い。
そこで `RESULT_Q2.md` §1 と同じ入力・同じ起点(2024-06-13 00:05 UTC から 24h 刻みで 124 個)で
`lb.build_candidates_at` を回し直し、起点ごとに **`current_price`(起点価格)と手法 a/b/c の帯の
`(low, high)`** を取り出した。

**再現の確認(事実)**: 読み込み件数(aggTrades 24,299,128 / metrics OI 35,678 / metrics L/S 35,669 /
清算 26,014)、カスケード数(合計 5,638 = long 3,314 / short 2,288 / mixed 36)、照合行数 5,602、
skip 0、NaN 0 がすべて `q2_summary.json` と一致した。**6 セルの的中率も小数第 12 位まで完全一致**
(下表「実測の的中率」列)。よって以下の診断は判定時と同じ対象・同じ帯の上で行われている。

### 1.2 相対位置に直した

- 起点 k の帯 → `[low / P_k, high / P_k]`(`P_k` = その起点の `current_price`)
- カスケード i の清算 → `first_price_i / P_{k(i)}`(`k(i)` = i が照合された起点)
- 帯に入るかの判定は元の測定器と同じ**閉区間** `low <= x <= high`。
  相対位置で計算し直した観測的中率が絶対価格での観測値と一致することを 6 セルすべてで確認した(事実)。

### 1.3 並べ替え(主たる帰無)

**帯の形(幅・本数・起点価格からの相対位置)はそのまま保ち、「どのカスケードの帯を、どのカスケードの
清算に当てるか」だけを入れ替えた。**

- 各セル(手法 × 向き)の内側で、カスケード i すべてについて、
  **起点日が 7 日以上離れた**別のカスケード j をセル内から乱択し、
  「i の帯(相対)」に「j の清算(相対)」が入るかを判定する。
- 1 回の並べ替えで得られるセル平均が帰無分布の 1 点。**並べ替えは 2,000 回**、
  乱数の種 **20260913**(`numpy.random.default_rng`)。
- 離す条件を 0 / 1 / 3 / 7 / 14 / 30 日に変えた場合も各 500 回計算した(§2.2)。
- 全単射版の対照として **起点日を k 日巡回ずらし**(k = 7…117、111 通り)も計算した(§2.3)。
  こちらは起点日ごと(クラスタ単位)に丸ごと入れ替えるので、カスケード単位の乱択より
  帰無分布が広くなる。

## §3 実装上の落とし穴(委任先が気づいたもの)

**落とし穴 1(最も重い)— 手法 (c) の相対帯は全起点で完全に同一なので、並べ替えは構造上 power を持たない。**
`candidate_bands` の手法 (c) は `long_center = current_price * (1 - 1/L)` で作られるため、
`current_price` で割った相対帯は **`(1 ∓ 1/L) * (1 ± 25bp)` という定数**になる。
124 起点すべてで相対帯が一致することを数値で確認した(`np.allclose` = True、事実)。
したがって「どの起点の帯を当てるか」を入れ替えても帯の形は 1 ミリも変わらず、
帰無分布は「別のカスケードの清算相対位置を同じ固定テンプレに当てる」ものになり、
**実測と同じ母集団を測ることになる**(§2.3 でずらし版の区間幅が厳密に 0 になったのがその証拠)。
これは実装のバグではなく、**手法 (c) が起点固有の情報を一切持たない固定テンプレである**という
手法そのものの性質である。並べ替えの結論「実測 = 帰無」は、手法 (c) については
**「この帯の配置には予測の中身が無い」を正しく言い当てている**(推定)。

**落とし穴 2 — 帯の幅は絶対値(50 USD)なので、相対に直すと幅が価格水準で変わる。**
手法 (a)(b) の帯は `_bin_low` による 50 USD 固定幅の bin なので、相対幅は
68,000 USD なら 7.4bp、57,000 USD なら 8.8bp と約 19% 違う。本診断は「相対位置を保つ」を採ったので
相対幅が保たれ絶対幅が動く。逆に「絶対幅を保つ」設計も取り得たが、
相対位置(起点価格からの距離)を保てなくなる。**両立しない**。
判定区間の価格レンジ(§2.4 の相対位置レンジから逆算しておよそ ±15%)では差は小さいが、
より広い価格レンジで同じ診断をするときは明示的に選び直す必要がある(仮定)。

**落とし穴 3 — 観測値のクラスタ構造を、判定時のブートストラップが無視している。**
124 起点に 5,602 カスケードが載っている(1 起点あたり平均 45.2 件)。同じ起点のカスケードは
**同じ帯**に当てられるので独立ではない。`run_q2.py` のブートストラップはカスケードを i.i.d. に
再抽出しており、**95% 区間が狭すぎる**。本診断の §2.3(起点日を丸ごと入れ替える全単射版)では
手法 (a)(b) の区間が一回り広くなった(例 a_long: [3.17%, 4.41%] → [3.38%, 5.01%])。
判定に使った区間の幅そのものが楽観的だった、ということ(事実)。

**落とし穴 4 — 手法 (b) は起点によって帯の本数が違う(実測 min 1 / max 3)。**
OI 増分の bin が 3 本に満たない起点があり、そこでは候補が 1〜2 本しか出ない。
並べ替えは「帯の形をそのまま保つ」方針なので本数も一緒に入れ替わる(意図どおり)が、
**3 本の起点のカスケードが 1 本の帯に当てられる**ことが起きる。帰無平均をわずかに下げる向きに効く
(推定)。NaN(帯ゼロ)は判定区間では 0 件だったので、行の脱落は起きていない(事実)。

**落とし穴 5 — 既存 CSV だけでは診断できない。**
`q2_cascade_matches.csv` は `in_band_*` と `distance_bp_*` しか持たず、**帯の位置も起点価格も無い**。
`distance_bp` は「最も近い辺までの符号なし距離」なので、帯がどちら側にあるかも復元できない。
以後この種の測定器の出力には、**起点価格と帯の (low, high) を列に持たせる**べきである(提案)。

## §4 置いた仮定と限界

1. **(仮定)** 相対位置は**比**(price / origin_price)で表した。手法 (c) が乗法的に定義されているため
   比が自然だが、bp 差で表す設計も可能で、その場合は落とし穴 2 の向きが変わる。
2. **(仮定)** 並べ替えの相手 j は**同じ手法・同じ向きのセル内**から、**復元抽出**で引いた
   (タスクの基本案どおり)。全単射(復元なし)版は §2.3 の巡回ずらしで別途示した。両者で結論は同じ。
3. **(事実)** 起点は 124 個で照合期限 24h・刻み 24h のため、各カスケードはちょうど 1 つの起点に
   対応する。並べ替えはこの 1 対 1 対応だけを壊し、帯そのものも清算そのものも作り変えていない。
4. **(限界)** これは**判定ではない**。判定区間は既に開封済みで、データを見た後に統計量を変えている。
   本記録の数値から「予測できる/できない」を結論してはならない。正しい帰無での判定には
   **新しい単位と新しい区間**が要る(`RESULT_Q2.md` §7)。
5. **(限界)** 帰無は「帯の形は正しいが、どのカスケードに当てるかがランダム」という形の帰無である。
   「帯の形そのものが無意味か」(例: 出来高の山という概念に意味があるか)は測っていない。
6. **(限界)** 多重性の調整はしていない(6 セル)。ただし 0 / 6 が有意なので調整しても結論は動かない。
7. **(限界)** §2.5 の補助帰無は委任先が追加したもので、事前登録にも本タスクの指示にも無い。
   §2.5 本文に書いた交絡(近い帯ほど当たる)を潰していないので、単独では解釈できない。

# リードの読み(2026-09-13)

## §6 読み: **Q2 の 3 手法はいずれも、帯を無関係な清算に当てたときと区別がつかない**

実測 ÷ 並べ替え帰無の平均は **0.917〜1.010**、**6 セルとも帰無の 95% 区間の中**。
上回りも下回りもしない。**「その日の帯が、その日の清算に当たる」ことが、「他の日の清算に
当たる」ことより優れている証拠は無い。**

**私が `RESULT_Q2.md` §5 に書いた「正しい帰無なら 6 セルすべてが逆に転ぶ可能性が高い」は
外れている。**粗い 4 倍補正は手法(a)(b) ではほぼ当たったが、手法(c) では行き過ぎていた
(正しい帰無は 42〜48% ではなく 27.5〜30.5%)。**正しくは「逆転する」ではなく「区別がつかない」。**
これは推定を実測で置き換えた結果であって、§5 の推定は診断前の見積もりとして残す。

**§5 の結論(6 セルの陽性は帰無の弱さの産物であって予測の腕前ではない)は変わらない。**
むしろ強まった: 事前登録の p0 は帰無を **2.6〜4.1 倍過小**に見積もっていた。

## §7 手法(c)について(ここが一番効く発見)

診断は「手法(c) は並べ替えに対して構造上 power を持たない」ことを示した。
相対帯が `(1∓1/L)(1±25bp)` という**定数**なので、124 起点すべてで相対帯が完全一致する。
**手法(c) は起点固有の情報を一切持たない固定テンプレである。**

これは診断の欠陥ではなく、**手法(c) そのものの性質を言い当てている**。
的中率 27〜30% は「現在値から一定割合離れた所に帯を置けば当たる」という**幾何**であって、
市場の状態を読んだ結果ではない。**原文の問い「価格毎の約定の積み上げから清算価格帯を予測できるか」
に対して、手法(c) はそもそも答えになっていない対照だった**、と位置づけ直す。

委任先が補助で測った「1/L をランダム化した帰無」(実測 27.4/30.3% 対 帰無 19.0/21.2%、p=0.0005)は、
**「近い帯ほど当たる」という幾何の再測定**である疑いが強く、単独では解釈しない(§2.5 のとおり)。

## §8 新たに判明した事前登録の不備(4 件目。これは Q1 にも及ぶ)

**判定時のブートストラップがクラスタ構造を無視していた。**124 起点に 5,602 カスケードが載り
(1 起点あたり 45.2 件)、同じ起点日のカスケードは同じ帯に当たるので独立ではない。
起点日ごと入れ替える版では区間が一回り広くなる(a_long: [3.17%, 4.41%] → [3.38%, 5.01%])。
**判定に使った 95% 区間は楽観的だった。**

**同じ欠陥が Q1 にもある**(同じ 124 日に 5,638 カスケードが載り、同じ日の清算は同じ相場つきを
共有する)。ただし **Q1 の読みの向きは変わらない**: 区間が広がれば「有意」が減るだけで、
Q1 の結論は「プラセボと比べると 3/16 しか残らない = 清算固有の効果は見えない」だったから、
**広げても同じ向きに強まる**。残った 3 件が更に弱くなる、という形で効く。
`RESULT_STAGE0.md` §7 の自己申告に 4 件目として追加する。

## §9 道具の直し(次の測定器に持ち込む)

診断が既存の出力だけでは回せなかった(`distance_bp` が符号なしで帯の側を復元できない)。
**以後、帯や窓を扱う測定器の出力には、起点価格と帯の `(low, high)` を列として持たせる。**
中間生成物は「結論を再現できる」だけでなく「**別の帰無で測り直せる**」形で残す。

## §10 この単位の結論

- **Q1(観測)**: 清算後の戻りの正体は「清算」ではなく「大きな売買の塊」。清算固有の効果は見えない。
- **周回 2(建玉の軸)**: 失格。むしろ**建玉が増えた**プラセボが最大の反応を示した。
- **Q2(予測)**: **3 手法いずれも、帯を無関係な清算に当てた場合と区別がつかない。**
- **O-3c の原文の仮説「清算の監視で行きすぎと転換を捉えられる」は、Binance COIN-M の 124 日では
  支持されなかった。**ただし**陰性と書くのはこの単位の射程内だけ**である(後述の射程を参照)。

**射程(測っていないこと)**: 取引所は Binance COIN-M 1 つ、期間は 124 日、

**秒スケール(清算の直後 1 分未満)では測っていない。**Q2 の帯の刻み・遡る期間・上位 K は
実装者の仮定のまま 1 通りしか試していない。
