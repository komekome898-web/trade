## 2. 設計に無かった判断(符号)— どう仮置きしたか

**設計 §3 は符号について 2 つのことを書いていて、その 2 つは食い違っている**(**事実**、設計 §3 の
冒頭):

> すべて**清算の向きに正**で揃える(SELL 清算 = ロングの強制決済 → 下向きが正、BUY 清算 → 上向きが正)。
> 符号の約束は OI_DIST §2.0 の `*_liqdir` と同じ(**事実**)。

`OI_DIST §2.0` の実装は `LIQ_SIGN = {"SELL": +1.0, "BUY": -1.0}`(**事実**、
`scripts/o3c_oi_distance.py:127`)なので SELL に +1 を掛ける。距離 `(位置 − p_liq)/p_liq` では、
ロング清算の建玉は清算価格より**上**にあるので +1 倍で正になり、文の意図(積み上がった位置を
正に置く)と合う。しかし**値動き**に +1 を掛けると、SELL 清算のあとの下落は**負**になり、
同じ §3 の「**下向きが正**」「**正 = 継続、負 = 反転**」と逆になる。

**仮置き(委任先の判断。勝手に決めずここに書く)**:

- 距離の列 `*_liqdir` は `LIQ_SIGN` のまま。**1 つも変えていない。**
- 値動き・到達・最大順行/逆行は `*_reactdir` という**別の列名**にし、
  `REACT_SIGN = {"SELL": -1.0, "BUY": +1.0}`(= `LIQ_SIGN` の符号違い)を掛けた。
  こうすると §3 の操作的な文「SELL 清算は下向きが正」「正 = 継続、負 = 反転」が成り立つ。
- 対照行(side が無い)は `REACT_SIGN` を +1 として生の値を入れ、`bp_*_abs` を併記した。

テスト `test_react_sign_is_opposite_of_liq_sign` がこの関係を固定している(**事実**)。
**どちらを採るかはオーナー / リードが決めることで、本書は両方を別の列で持っているだけである。**
