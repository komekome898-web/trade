## (5) 設計に無い判断(全部)

1. **【要確認・最優先】出口(連鎖の終わり)の約定価格に遅れ d を足すか**: R2.4 の文は
   「入る値段 = `at_or_after(t₀+d)`」「決済/ドテンは次のプリントの `at_or_after(ts+d)`」と
   明記する一方、「出る値段 = 連鎖の終わり(最後のプリント+60秒)の `at_or_after`」だけを書き、
   この箇所だけ「+d」が無い。改訂前の用語表(§0.1「約定価格」行)は「入る・出る・ドテンは
   すべて『その時刻+遅れ』以後」と明記していた。**この段1では改訂前の用語表を踏襲し、出口にも
   +d を足した**(`simulate_cascade`/`simulate_baseline` とも `cascade_end_ts + delay_ms`)。
   段2の前に確認を要する(帯・行動の表そのものではないが、それに準ずる価格規則のため、ここで
   最優先として報告する)。
2. **方策の数**: R2.3 は5項目の番号付けだが、項目4「全部逆張り/全部順張り」は2本の方策名を
   含むので、字面どおりに読むと named な方策は **6 本**(logistic_3択・logistic_2値0.5・規則・
   完全な判断・全部逆張り・全部順張り)になる。一方 R2.5 の行の見積もり式は「方策9×型2×遅れ3」
   と書かれており、6 との対応が取れない(型を方策名に畳み込む・「基準率で2値」を独立方策に
   数える、等いくつか試したが9に一致する分解を見つけられなかった)。**この段1は6本で実装した**。
   段2の多重性の数え方に影響するので、確定は段2の前にリードへ持ち帰る。
3. **主の遅れ(MAIN_DELAY)**: R2.4 は 0.5/1/2 秒を対等に3通り書くだけで「主」を名指ししない。

   **遅れ1秒を代表**にした(連鎖ごとの損益分布そのものは3通り全部を `dist_table.csv` に出す)。
4. **「入らなかった」の3つ目の内訳行**: R2.5 は「位置別(1件目で入った/途中で入った)の内訳」と

## (6) サニティ

- **手計算一致**: 合成の連鎖3本((3)節)の損益を独立に手計算し、コードの出力と一致(0.2 /
  −0.45 / 0.0)。
- **符号対称性**: 「全部逆張り」と「全部順張り」の中央値は符号だけが逆(0.5043 と −0.5043、
  p25/p75 も入れ替わって符号反転)。清算の向きではなく建玉の向きで符号が付いていることの
  構造的な確認(`test_pnl_sign_follows_position_direction_not_liquidation_side` でも確認)。
- **欠測ゼロ**: 200連鎖×6方策×2型×3遅れの全組み合わせで、価格が引けなかった行(`欠測`列)は
  **0**(`summary.json`「欠測(価格が引けなかった行数、遅れ別)」)。
- **規則・完全な判断の「止まる」がちょうど連鎖ごとに1回**: どちらも「止まる」の合計件数が
  ちょうど **200**(=抜いた連鎖の本数)。規則は連鎖の最初のプリント(定義上、直前60秒に同じ側
  の清算が無い=材料1が常に0)で必ず「止まる」、完全な判断は連鎖の最後のプリントで必ず
  「止まる」——どちらも1連鎖につき1回だけ発生する構造なので、一致は設計どおりの結果であり
  偶然ではない。
- **logistic_3択 だけが「入らない」を持つ**: 位置別内訳で「入らなかった」が非ゼロ(37/200)
  なのは logistic_3択 だけ(他5方策は「わからない」を持たないか、判断を見ずに入るため)。
- **完全な判断が最も高い中央値**: 遅れ1秒・含める表で、完全な判断(A: 2.8754 / B: 3.6977)が
  他の判断ベース方策(logistic_3択 0.0000、logistic_2値0.5 −0.1501、規則 −0.2789)より高い。
  完全な判断は事後ラベルをそのまま使う上限として定義されているので、この順序は構造的に
  一貫している(戦略の当否についての判定語ではない、位置関係の確認)。
- **決定的な抽出**: `sample_cascades` は同じ種で同じ200本を返す(`test_sample_cascades_is_
  deterministic_for_fixed_seed`)。
- **読み取り専用**: 入力ファイル6本(`rows_continue.csv.gz`・`rows_materials.csv.gz`・
  `o3c_signal_logit_{first,chain}.yaml`・`logit_ecdf_{first,chain}.npz`)の MD5 を
  `summary.json` に記録。実行前後で変更していない(Edit/Write で触っていない)。

## (7) 限界

- 段1は**状態機械の配線と価格の引き方が設計どおり動くこと**の確認であり、方策の値・効果に
  ついての判定は一切含まない(判定語を使わないだけでなく、判定そのものをしていない)。
- (5)-1 の「出口に+dを足すか」は**未確認のまま暫定の選択で進めた**。段2(後半2,000本、
  一度だけ)の前に確定が必要。
- (5)-2 の「方策9」との不一致も未解決。段2の多重性の積み上げに影響する可能性がある。
- 検知の遅れ・state作成の遅れ(d=4項目の和のうち2項目)は設計自身が「未測定」としており、
  この段1でも測っていない(0.5/1/2秒はそのまま外側の値として使っただけ)。
- 前半のみを対象にしており、設計§6が触れる「前半には反証者6致命4と同種の偏り(特定の1日の
  影響)がありうる」という限界は、この200本サンプルについて個別には確認していない(前半か後半
  かを問わず、抽出そのものは種20260920による無作為抽出)。
- logistic の較正・順位分離などモデル自体の性能数値はこの報告では扱っていない(§7.7の記録を
  読むだけを尊重し、再検証していない)。
