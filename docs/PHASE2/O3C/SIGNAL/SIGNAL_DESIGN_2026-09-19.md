## 2. 問い

判定の量 `r_h` = 清算の向きに符号を付けた h 分後の価格変化(bp)。清算行では表の列 `bp_{h}m_reactdir` そのもの、対照 (ii) の行では相手の束の側の符号を `bp_{h}m` に当てたもの(§4)。負 = 反転、正 = 継続。h ∈ {1, 5, 15, 30, 60, 240} 分。

| # | 問い | 予測できると言える形 |
|---|---|---|
| Q1 | 向き: 束の直後、値は清算と逆(反転)か同じ(継続)か | h ごとの反転の割合(`r_h` < 0 の割合)が、対照 (ii) の同じ割合より高い(または低い) |
| Q2 | 大きさ: 動く幅(bp)は束の属性で予測できるか | 属性の 3 分位で切った群ごとの `r_h` の平均(対照との差)が、群の間で順序どおりに並ぶ(属性の値と単調) |
| Q3 | 時間軸: 反転はいつ最大で、その後どう変わるか | `r_h` の平均(対照との差)± SE を 6 本の h で並べた形。「最大」= 差が最も負の h(記述)。**「消える」の線引きはこの単位では置かない**(±2 SE の線は検定と同型になるので外した = 監査 2 の指摘 6。線は判定の段の事前登録で置く)。最大順行 / 逆行は同じ h の並びで併記 |

**この単位で答えない問い(次の単位)**: Q4 = 4 時間で継続側に行く束を、束の時点かその直後の量(建玉の減りの続きなど)で見分けられるか(S-4)。Q5 = 同じ予測が bitFlyer の値動きにも出るか(S-6)。Q6 = 清算の束が起きる価格帯を約定の積み上げから事前に当てられるか(S-7)。

## 7. 走らせる前に決めること

- 束の属性の切り方(分位の数): **3 分位**(1 周目の軸と同じ数)。群の n は属性ごとに違う(欠測が違う。実測: `doi_pre_1h` は 15,143 件、`implied_leverage` は 13,151 件 = 監査 2 の指摘 4 の監査役の実測。束は 21,198 件)ので、**n は属性ごとに実測して表に出す**。n < 500 の群は表に出すが読みに使わない。500 の根拠(リードの計算、2026-09-19): 2 周目の事前登録 §6 の係数 z + 0.8416 = 4.77、§7 の標本の SD(1 分、D1 8.7 bp / 対照 C 5.2 bp)で、1 群 500 なら MDE = 4.77 × sqrt(8.7²/500 + 5.2²/500) ≈ 2.2 bp。1 周目 §7.1 の 1 分の差 −7.5 bp(距離をそろえた値)より十分小さい。前版の「7.5 bp・SD 9 bp で約 2.6 bp」は出所と式を書いていなかった(監査 2 の指摘 3)。
- 多重性: 探索段なので検定はしない。表の数だけ数えて次の単位の事前登録に引き継ぐ(周回数に算入)。
