## 3. 翻訳(量は問いを測っているか)

**部分的にしか測っていない。**3 点。

(a) **5 つの表のどこにも清算の前の価格が無い。**起点は約定価格、h 後も約定価格で、`bounce` も起点どうしの差である。したがって **−6.8 bp が「大きく動いた分の一部の戻り(一時的インパクトの減衰)」なのか「元の水準を超える行き過ぎ」なのかを、この数表では分けられない。**「値動きの予想」は前者では成立しない(戻りは掃きを出した側の費用であって、他人の予想材料とは限らない)。設計 §3 の候補にあった `reach_back_vwap` は Jev の順位で「無関係」とされ測られていない。
E4 の `|dist_vwap_bp|` の順序(Δ=0: Q1 −3.7406 / Q2 −6.1271 / Q3 −10.5334、Δ=10: −2.2416 / −3.4083 / −5.6855)は、**VWAP から遠いほど戻る = 戻りの向きの読み**と整合する。

(b) **起点が清算自身の約定であること(前段の致命 1)は、実測では反転の源ではない。**Δ=0 を lag で分けると(計算): lag==0(n=16,850)は h=1 −0.5672 ± 0.0273 / h=60 **−6.6662 ± 0.1824**、lag>0(n=4,348、lag 中央値 164 ms)は h=1 −0.5625 ± 0.0375 / h=60 **−7.3205 ± 0.2355**。**起点が清算の約定そのものでない行の方が、むしろ反転が大きい。**「起点 = 掃きの終端のプリント」だけでは −6.8 bp を説明できない。

(c) **60 秒の形は 1 プリントの跳ねでは説明できない**(疑点 2 の答え)。清算から 1 秒の累積は −0.5663 bp で、60 秒の −6.8004 の **8.3%** にすぎない。残り 91.7% は 59 秒かけて溜まる。板を掃いた終端の 1 プリントが戻るだけなら次の約定でほぼ全部戻るはずで、そうなっていない。**気配の跳ね(bid-ask bounce)でも説明できない**: BTCUSD_PERP の刻みは 0.1 USD(**仮定**。外部知識で、この数表では確かめていない)なので、期間中の価格帯 25,000〜73,000 USD では 0.014〜0.040 bp = h=1 秒の −0.566 bp の 1/14〜1/40 である。
したがって残るのは「板掃きの機械的な跳ね」ではなく「**数十秒スケールの一時的インパクトの減衰**」であり、これは(a)により「予想」と分離できていない。

## 特に疑ってほしかった 7 点への答え

**1. # 致命: 有

1. **E1(Δ 階段)が機構を分けていない。**`bounce(Δ)` は `r(0,Δ)` と同じ量(行ごとの相関 0.981〜0.999、平均の差 0.03 bp 以内)で、`bounce(Δ)+r(Δ,60)` は Δ によらず −6.78〜−6.82。**掃きの戻りと「60 秒で完了する平均回帰」は同じ Δ 階段を作るので、この設計では区別できない。**前段の致命 1 は解けていない。

### 使ったコマンド(「計算」と印を付けた値の出所)

すべて `python3` のヒアドキュメント(pandas / numpy)。作業用の pickle は `/tmp/claude-0/.../scratchpad/` に置いた(リポジトリには何も書いていない、コミットもしていない)。

1. `md5sum` — `backtest_data/o3c_signal_explore2_20260919/{e0..e4}.csv, rows_gap{30,60,180}.csv.gz, tables.md` と `backtest_data/o3c_reaction_20260918_full/gap60_w8/table.csv`。
2. 行の読み込み: `pd.read_csv("backtest_data/o3c_signal_explore2_20260919/rows_gap{30,60,180}.csv.gz")` → pickle。
3. `bounce` の同値性と分解: `kind=='liq'` を `delta_sec` で分け、`cascade_id` で突き合わせて `bounce(Δ)` 対 `r_Δ`(相関・平均絶対差)、`bounce(Δ)+r_60`。
4. 束の間隔: `gap60_w8/table.csv` の `kind=='liq'` を `(day, start_ms)` で並べ、`next start_ms − end_ms`。gap30 / gap180 は `rows_gap*.csv.gz` の `delta_sec==0` の `anchor_ts_ms` を束の終わりの代理にした(**束の開始で測るより少なめに出る**)。
5. 日クラスタ SE: `m=mean(v)`、`s_d=Σ_{i∈d}(v_i−m)`、`SE=sqrt(Σ_d s_d²)/n × sqrt(G/(G−1))`(道具の `mean_se_cluster` と同じ式)。
6. 対照 (i) の組み替え: 一様行の符号なし値 `u = r × s`(s=±1)から、`Σ_d n_d·ū_d·s̄_d / N`(日内で組を無作為化したときの期待値)を計算し、1 対 1 の平均と比べた。
7. 符号頻度: `sign(−r)` の平均(タイは 0)を同じ日クラスタ式で。
8. MDE: 日クラスタ SE × 2.802(両側 5%・検出力 80%)。
9. bitFlyer: `bf_r_h` のちょうど 0 の割合、`anchor_ts_ms % 60000`、`README.md` の逐語「`ts` — start of the 1-minute bucket」。
10. 1 周目との一致: `gap60_w8/table.csv` の `kind=='liq'` の `bp_{1m,5m,240m}_reactdir` の平均。
