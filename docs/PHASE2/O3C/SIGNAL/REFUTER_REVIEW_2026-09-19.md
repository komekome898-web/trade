## 2. 対照 (ii) は反事実になっているか

**なっていない。** 3 点。

(a) **対照の時刻は「清算が無かった瞬間」ではなく「どの清算からも ±5 分以上離れた 1 分刻みの時刻」**(`o3c_reaction.py` の `allowed_intervals` + `MATCH_GRID_MS`、`control_gap_minutes: 5.0`)。つまり対照は**その日の閑散部だけ**から引かれている。結果、状態が揃っていない: 1 分の mae は清算 −11.881 / 対照 −4.016、mfe は 3.599 / 3.723。清算側の窓は最初の 1 分で 2 倍近く荒い。|dist_vwap_bp| の平均は清算 85.54 / 対照 63.13、中央値 66.50 / 49.43(計算)。

(b) **対照の平均が h とともに正へ流れるのは「日の方向」である。** 対照 (i)(一様、`control_uniform` 21,378 行。この道具は使っていない)を同じ日の平均に束の符号を当てて集計すると h=240 で **+10.703 bp**(計算)で、対照 (ii) の +10.896 とほぼ同じ。すなわち +10.9 は薄さ合わせの副作用ではなく、**清算の向きがその日の実現トレンドと同じ向きに選ばれている**ことの反映である(下げた日は long 清算 = SELL が多い → SELL 符号でその日のどの時刻も正に出る)。符号の付け方が日の実現方向と相関している以上、差は「清算がなければどうなったか」ではなく「同じ日の別の時刻と比べてどうか」を測っている。

(c) **その結果、h が延びるほど差は対照側だけで動く。** 清算側の平均は h=1 −6.800 → h=240 −7.421 とほぼ平ら(差 −0.621 bp/239 分)。標準化した差は −6.476 → −18.860。**差の h 形状(設計 Q3 の「最大」)は 100% 対照の漂流でできている。**差を見て「反転は 240 分で最大」と読むと、清算側の実際の値動き(1 分でほぼ全部終わっている)と逆の像になる。

## 3. 翻訳 — 「清算の向きに符号を付けた価格変化」は値動きの予測を測っているか

**ここが最大の疑点。** `anchor` は `compute_reactions(anchor="after_shift")` で `prices.at_or_after(end_ms)`、価格系列は約定そのもの(走行 params: `granularity: "trades(反応・到達)/ 60 秒バーは使っていない"`)。`end_ms` は束の**最後の清算イベントの時刻**である。

実測(計算、kind 別に `anchor_lag_ms` を集計):

| 区分 | lag==0 の割合 | lag 中央値 |
|---|---|---|
| 清算 | **0.7949** | 0 ms |
| 対照(matched) | **0.0020** | 633 ms |
| 対照(uniform) | — | 904.5 ms |

つまり清算側は 79.5% で**起点の約定が最後の清算イベントと同じミリ秒にある**= 起点価格は清算自身の約定(板を掃いた終端の価格)そのものである可能性が高い。対照側は 0.2% しかそうならない。**両群の「起点」は別の物である。**清算自身の板掃きの戻り(機械的な跳ね)は、定義上すべて差に入る。

補足(誤読を防ぐため): `anchor_price_diff_bp` は 79.5% の行で before と after が同一の約定になるため恒等的に 0 で、平均 0.016 bp。**この列では跳ねの大きさを測れない**(スプレッド説を否定も肯定もできない)。

機械的な読みを支持する所見が 3 つある:
- **1 分より後にはほぼ何も残らない**(計算): r5−r1 = −0.270(naive SE 0.166 / 日クラスタ SE 0.189)、r15−r1 = −0.630(0.283 / 0.404)、r240−r1 = **−0.622**(0.934 / **1.693**)。1 分後に入った場合の平均は 0 と区別できない。
- **束が 1 件・幅 0 ms のもの(12,029 件 = 56.75%、計算)でも 1 分 −3.971 bp が出る。**連鎖でも燃料切れでもない単発の 1 プリントで −4 bp の「反転」が出る。
- **束ね方(gap)という恣意的な既定値で 1.6 倍動く。** 1 分平均は gap30 −4.762 / gap60 −6.800 / gap180 −7.512、反転の割合は 0.653 / 0.737 / 0.781。gap は `build_cascades` の docstring 自身が「判断の置き所」と書いている値である。掃きをどれだけ起点の手前に取り込むかで効果量が動く、という形になっている。

# 致命: 有

- **致命 1(起点の非対称)**: 起点が清算側では 79.5% で最後の清算イベントと同じミリ秒の約定(= 清算自身の約定)、対照側では 0.2%(中央値 633 ms 後)である(計算)。両群の起点が別の物なので、清算自身の板掃きの戻りは定義上すべて差に入る。h の最小が 1 分であるため、この数表では戻りと予測を分離できない。**「予測できるか」への答えとしてこの差を使えない。**
- **致命 2(差の h 形状が対照だけでできている)**: 清算側の平均は h=1 −6.800 → h=240 −7.421 とほぼ平らで、1 分より後の増分は −0.622 ± 1.693(日クラスタ、計算)= 0 と区別できない。一方で標準化した差は −6.476 → −18.860 に広がる。この広がりは対照の +10.9 bp(= その日の方向、対照 (i) でも +10.703、計算)だけで作られている。**設計 Q3 の「最大 = 差が最も負の h」という定義のままだと、清算側の実際の値動きと逆の結論(240 分で最大)が出る。**
- **致命 3(束ね方で効果量が 1.6〜2.1 倍動く)**: 1 分平均 −4.762 / −6.800 / −7.512、5 分 −5.280 / −7.071 / −11.140(gap30 / 60 / 180)。gap は原文に指定の無い既定値である。**どの gap の数字を次の単位の事前登録に書くかで、MDE も判定バーも変わる。**固定の根拠が必要。

### 使ったコマンド(計算と印を付けた値の出所)
すべて `backtest_data/o3c_reaction_20260918_full/gap60_w8/table.csv` を `csv.DictReader` で読んだ python3 のヒアドキュメント。フィルタは (a) `kind=='liq'` / `kind=='control_matched'`(符号は `matched_liq_id` から相手の `side` を引いて SELL=−1 / BUY=+1)/ `kind=='control_uniform'`(日ごとの平均に束の符号を当てる)、(b) 日クラスタ SE は `sqrt(Σ_day (Σ_i (v_i − v̄))²)/n × sqrt(G/(G−1))`、G=456、(c) 期間の穴と欠測日は `summary.json` の `per_day` を走査。MD5 は `md5sum backtest_data/o3c_reaction_20260918_full/gap60_w8/table.csv` → `80be954122d877a0809db703e50460e8`。
