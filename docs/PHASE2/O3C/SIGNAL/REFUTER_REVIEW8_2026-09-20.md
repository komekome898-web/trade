### 致命-2:「完全な判断 = 上限」という用語表の主張が、前半200本の実測で崩れている(連鎖単位で非優越)

用語表(§1)の逐語: 「**完全な判断 | 各プリントで事後のラベル...をそのまま判断に使う = 上限**」。
R2.3 も「5. 完全な判断(事後のラベル。**上限**。連鎖の道筋に沿って計算。L-267)」と重ねて書く。

「上限」は「連鎖ごとの損益で他のどの方策よりも下回らない」という意味に読めるが、実測データで
連鎖単位に突き合わせると、10〜35/200 本(5〜17.5%)で「完全な判断」が他方策を**大きく下回る**。

再計算コマンドと出力:
```python
cdf = pd.read_csv(".../cascades.csv.gz")
for ptype in ("A","B"):
    for delay in (0.5,1,2):
        perfect = cdf[(cdf["方策"]=="完全な判断")&(cdf["型"]==ptype)&(cdf["遅れ_秒"]==delay)].set_index("bundle_id")["pnl_bp"]
        for other in ["logistic_3択","logistic_2値0.5","規則"]:
            o = cdf[(cdf["方策"]==other)&(cdf["型"]==ptype)&(cdf["遅れ_秒"]==delay)].set_index("bundle_id")["pnl_bp"]
            common = perfect.index.intersection(o.index)
            diff = perfect.loc[common] - o.loc[common]
            n_violate = (diff < -1e-9).sum()
            if n_violate>0:
                print(ptype, delay, other, "violations", n_violate, "min diff", diff.min())
```
出力(抜粋、全パターンで違反あり):
```
A 1 logistic_3択 violations 34 min diff -35.744508
A 1 logistic_2値0.5 violations 19 min diff -43.787994
A 1 規則 violations 9 min diff -25.797484
B 1 規則 violations 12 min diff -48.69203
（全 18 通り〈型2×遅れ3×比較先3〉で違反件数 9〜35 件、最小差 -19.25〜-52.85bp)
```
原因は設計自身の構造にある。「完全な判断」が上限になるのは「この後60秒以内に同じ側の清算が
来るかどうか」という**続く/止まるラベル**を当てる問題についてだけであり、清算プリント直後の
短期の値動き(しばしば一時的な反発を伴う)を当てる問題ではない。連鎖が続く/止まるを完全に
言い当てても、その方向に賭けた建玉が実際の価格経路で勝つとは限らない(規則や logistic の
「誤った」判断が短期反発を偶然拾って勝つ場合がある)。段1報告の§6サニティは中央値だけを比較して
「完全な判断が最も高い中央値」「順序は構造的に一貫している」と書いているが、**連鎖単位の非優越を
検査していない**ため、この文が示唆する「上限」の性質(=どの連鎖でも他方策以上)は成立しない。

**対応**: 段2の報告では「完全な判断」を字義どおりの上限として扱わず、「事後の続く/止まるラベルを
言い当てる問題での参照点(価格変動そのものの上限ではない)」と明記し、中央値だけでなく非優越の
実測(上記のような violations 件数)も併記すること。用語表・R2.3 の「上限」という語自体を直すか、
注記を付けるかはオーナー/リードの判断だが、**このまま「上限」の字義どおりに段2結果を解釈すると
誤った結論(logisticが上限を超えた=バグ、等)を招く**。
