## 1. 測る対象と測らない対象

### 測る(これだけ)

板寄せの成行注文が**実際にいくらで約定するか**、そしてそれが**印字された終値・始値からどれだけ離れるか**。
すなわち、判定案が「仮定」で埋めていた 1 つの数 — 往復執行コスト **c** — を実測に置き換える。

### 測らない(明記。ここを取り違えると単位の判定が汚染される)

- **プレミアムそのもの**。n = 50 では検出力がない: 夜間リターンの σ ≈ 90bps に対し n = 50 の MDE ≈ **35bps**
  (α 0.05・検出力 0.8)。想定される平均 7〜8bps は原理的に見えない。
- したがって **この 50 往復の実現損益は、P2-02 / P2-03 の再評価の証拠にならない**。損益は記録するが、
  「儲かった/損した」を根拠に判定を動かすことは事前に禁止する。プレミアムの再評価は別の関門
  (P2-03 §2 の関門 (2) = フォワード 250 夜、P2-02 §3 = 新しいフォワード期間)で、別の事前登録の下で行う。
- **サイズの効果**。1 売買単位のみ。板の厚みを食う大きさでの執行コストは測らない。
- **1306 / 2516 / 1348 / 1305 など他銘柄**、**指値執行(G2 セル)**、**日中執行**。
- **2024-11 以降への効果の集中**(P2-03 の別関門)。

## 3. 標本

- 銘柄 **2 つ**: 1591(JPX400)と 1343(J-REIT)。両方を**同じ夜に**建てる(同一の板寄せ環境で比べるため)。
- **各銘柄 50 往復**(= 50 夜)。片方が欠けた夜はその銘柄だけ n に数えない。
- 暦: 平日(JPX 営業日)。開始 = オーナー承認の翌営業日以降。所要 ≈ 50 営業日 + 除外分 ≈ **10〜12 週**。
  想定終了 2026-11 下旬。**締切 2027-01-27**(§0)。

### 除外する夜(機械的規則。実行中に目で選ばない)

1. **権利落ち日、およびその前営業日**にかかる往復(建玉日または決済日が該当する往復を落とす)。
   権利落ち日は `docs/PHASE2/RESOURCES.md` R7 の検証済み規則(権利確定日 → T+2/T+3)で導出し、
   **実行開始前に日付を列挙して本書の付録 A に凍結**する。基準日は 1343 = 毎年 2/5/8/11 月の 10 日、
   1591 = 毎年 4 月 7 日・10 月 7 日(発行会社ページ)。窓に入るのは 1591 の 2026-10-07 と 1343 の 2026-11-10。
   理由: 権利落ちの板寄せは需給が特異で、執行コストの代表値にならない。分配金は c の計算には入らない(c は約定 vs 印字の差)。
2. **四半期 SQ(3/6/9/12 月の第 2 金曜)の朝に決済が当たる往復**(= SQ 前日の引けで建てる往復)。窓に入るのは
   2026-09-11 と 2026-12-11 → 建玉日 2026-09-10 と 2026-12-10 を落とす。理由: SQ 日の寄付き板寄せは特異。
3. **前夜の状態が FLAT でない夜**(建玉が残っている / STATE_UNKNOWN)。
4. **売買停止・値幅制限に張り付いた銘柄**(`GET /symbol` の `UpperLimit`/`LowerLimit` に接触)。
5. 除外は**件数と日付をすべて報告**する。除外の有無で主指標を両方出し、判定は除外後の値で行う。

### 不成立(n に数えない)

- 全数約定しなかった往復(部分約定・失効・期限切れ・発注エラー)。**記録は残す**。
- 同一銘柄で不成立が 2 夜連続したら §6 の停止規則。

## 4. 1 往復あたりに測る量

記号: 建玉日 t、決済日 t+1。P = 価格(円)、bps = ×10⁴。

| 記号 | 定義 | 出所 |
|---|---|---|
| `fill_buy` | 引け板寄せの**実約定価格** | `GET /orders?product=1&id=<OrderId>` の `Details[]` で `RecType 8`(約定)の `Price` |
| `fill_sell` | 翌寄付き板寄せの実約定価格 | 同上 |
| `print_close(t)` | 当日の**印字終値** | 主 = P2-02/P2-03 の判定に使ったのと同じ日次系列(`backtest_data/jpx_etf_daily_*`)。副 = 15:31 に取った `GET /board` スナップショット |
| `print_open(t+1)` | 翌日の印字始値 | 同上 |
| `idx_close(t)` / `idx_open(t+1)` | 連動指数の終値・始値(1343 = 東証REIT指数、1591 = JPX日経400) | 日次取得(`data/onr/reit_index_daily.csv` と同型) |
| `commission` | 実際に課された手数料 + 消費税 | `Details[]` の `Commission` + `CommissionTax` |
| `tick(t)` | その値段帯の呼値(円) | `config/constants.yaml` の帯表。`GET /symbol` の `PriceRangeGroup` と突き合わせ |

導出量(すべて bps):

- 買い側乖離 **e_buy(t)** = (`fill_buy` − `print_close(t)`) / `print_close(t)` × 10⁴  … 正 = 印字より高く買った
- 売り側乖離 **e_sell(t)** = (`print_open(t+1)` − `fill_sell`) / `print_open(t+1)` × 10⁴ … 正 = 印字より安く売った
- **往復執行コスト c(t)** = 印字ベースの夜間リターン − 実現夜間リターン
  = [`print_open(t+1)`/`print_close(t)` − 1 − (`fill_sell`/`fill_buy` − 1)] × 10⁴ + 手数料の bps 換算。
  一次近似で c ≈ e_buy + e_sell。**判定に使うのはこの c**(定義は減算の形を正とし、近似式は検算に使う)。
  これは判定案が「呼値 1 ティック × 片側 2 回」と**仮定**していた量そのもの
  (1343 = 10.4bps、1591 = 5.4bps に相当)を、実測で置き換えるもの。
- ティック換算 **c_ticks(t)** = c(t) / (tick(t) / `print_close(t)` × 10⁴)
- 指数照合(**診断のみ、判定に使わない**): `fill_buy` と `fill_sell` を、指数の同時刻の動きから含意される
  理論価格と比べた乖離。P2-02 §2 の機構(「ETF は寄りで +9.4bps 高く、引けで −9.0bps 安く印字される」)が
  **印字の癖**なのか**実約定の癖**なのかを切り分ける。ここが c と別物であることを明記する:
  c は「印字 vs 実約定」、指数照合は「指数 vs 印字/実約定」。
- 付随記録(判定に使わない): 受注〜約定の時刻、`OrdType`、`State`、板寄せ直前(15:29 / 08:59)の板スナップショット、
  実現損益(円)、`TradingUnit` と `Qty`、`Exchange`、`ExchangeName`(SOR がどこに回したかの手がかり)。

## 5. 推定量・信頼区間・合格規則

- 推定量: 銘柄ごとの **c の平均**(n = 50)。副次に中央値・sd・最大・95 パーセンタイル・c_ticks の分布。
- CI: **ブロック・ブートストラップ、ブロック長 5(営業日)、2,000 回**、seed 固定、再実行決定性あり
  (`bot.research` の既存実装を使う。ネットワークアクセスなし)。両側 95% パーセンタイル CI。
- **合格規則(判定案からの転記。ここで新しく決めない)**:

  | 銘柄 | 合格 | 出所 |
  |---|---|---|
  | 1343 | c の平均の **95% CI 上限 < 6.1bps** | P2-02 §3(楽観平均 8.3bps の CI 下限) |
  | 1591 | c の平均の **95% CI 上限 < 6.3bps** | P2-03 §2 の関門 (1)(楽観 CI 下限) |

  合格 = その銘柄の実行段階の関門を 1 つ通過(1343 は「新しいフォワード期間での再評価」へ、
  1591 は残る関門 (2) フォワード 250 夜と (3) オーナー承認へ)。**不合格 = その銘柄は棄却**(P2-02 §3 の明文)。
- **標本量の妥当性チェック(事前登録)**: n = 50 で CI 半幅 ≈ 1.96·sd(c)/√50 = 0.277·sd(c)。
  合格判定が意味を持つには **sd(c) < 22bps** が必要(平均 0 のとき上限 6.1bps に収まる境界)。
  実測 sd がこれを超えたら「n = 50 では判定不能」とし、**同一手順のまま n = 80 まで延長**(延長は 1 回のみ、
  ここで事前登録済み。§0 の締切内で終わらない場合は「判定不能」として報告し、関門は係属のまま残す)。
- **1 回だけ計算する**: 平均と CI は n = 50(または延長後 n = 80)に達した時点で**一度だけ**計算する。
  途中経過で c の平均を見て継続/中止を決めない(見るのは §6 の停止規則だけ。あれは 1 往復ごとの値で、集計量ではない)。
  集計・作図スクリプトは**初回発注の前に書いて凍結**し、出力形式も固定する。
- **監査**: 判定案の合格/不合格をオーナーに報告する前に、リードの説明文を渡さない独立の実装者が、
  生台帳(`data/etf_exec/ledger.csv` と `events.jsonl`)だけから c と CI を**盲検再計算**し、一致を確認する
  (`.claude/skills/research-protocol` §11)。不一致なら保留。

## 6. 停止規則(1 つでも当たったら発注を止め、オーナーに報告する)

| # | 条件 | 動作 |
|---|---|---|
| S1 | どちらかの脚の約定が印字から **3 ティック超**ずれた(\|e_buy\| または \|e_sell\| > 3 × ティック bps) | **両銘柄の以後の建玉を停止**し報告。再開はオーナー承認。既存の建玉は翌朝ふつうに決済する(閉じる脚は止めない) |
| S2 | **STATE_UNKNOWN**(曖昧な発注失敗) | 全停止。自動リトライしない。人間が読み取り専用の照合(`run_etf_exec_reconcile`)を実行し、積極的証拠が取れるまで再開しない(CLAUDE.md §1) |
| S3 | 同一銘柄で**不成立が 2 夜連続** | 停止して報告(注文が板寄せに参加していない疑い) |
| S4 | 実現損益の累計が **−15,000 円**を下回った | 停止して報告(§7 の想定帯の外側) |
| S5 | Kill Switch(リポジトリ直下 `KILL` / `data/kill_switch.json`) | 何もしない(既存の共通機構) |
| S6 | `GET /symbol` の `TradingUnit` が事前登録値(1343 = 10 / 1591 = 1)と違う | **その銘柄を停止**して報告(§0 の単位変更が前倒しされた等) |
| S7 | 手数料が 0 円でなかった | 停止はしない。記録し、`config/constants.yaml: jpx_cash_equity.sor_commission_yen` を再検証して反復として台帳に記録 |

S1〜S4・S6 による停止は「その時点までの n」で凍結し、n < 50 のまま §5 の判定に進んではならない
(**判定不能**として報告し、関門は係属のまま残す)。

## 7. 資本(実弾。金額は無視できるが、金額を偽らない)

| 項目 | 金額 |
|---|---|
| 1 夜の建玉(1343) | 10 口 × 1,925 円 ≈ **19,250 円** |
| 1 夜の建玉(1591) | 1 口 × 37,000 円 ≈ **37,000 円** |
| **同時に晒す最大** | **≈ 56,250 円**(両銘柄を同じ夜に持つ) |
| 実行コストの累計(想定) | 仮定どおり往復 5〜10bps なら 50 夜 × 56,250 円 × 7.5bps ≈ **2,100 円** |
| 損益の揺れ(1σ、50 夜累計) | √50 × 90bps × 56,250 円 ≈ **3,600 円** |
| 現実的な着地帯 | **±10,000 円**。停止規則 S4 は −15,000 円 |
| 1 夜の最悪(値幅制限級の逆行 10%) | ≈ −5,600 円 |

判定案の「1 口 ≈ 2,000 円」に対し実際は **1343 だけで 19,250 円**。それでも金額は無視できる水準だが、
**必要な口座残高は約 6 万円**であり、承認の前提として明示する(§0 の訂正)。

## 9. 反証文(この実測が「失敗」だと分かる形)

- 1343: c の平均の 95% CI 上限が **6.1bps 以上** → P2-02 は**棄却**(判定案 §3 の明文)。
- 1591: c の平均の 95% CI 上限が **6.3bps 以上** → P2-03 の 1591 は**棄却**。
- どちらも、sd(c) が大きすぎて n = 80 でも上限が確定しない場合は **判定不能**(棄却でも合格でもない。係属のまま)。
- 副次的な反証: c が印字とほぼ一致(|c| < 1 ティック相当)なら「板寄せの成行は板寄せ価格で約定する」が支持され、
  判定案の「呼値 1 ティック/片側」という保守コストは**過大**だったことになる。この場合も、それを根拠に
  プレミアムの判定を動かしてよいのは**新しいフォワード期間の再評価**を通ったときだけ(§1)。
