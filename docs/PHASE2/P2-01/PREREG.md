## リターンの定義(実行に一致させる)
- 夜間リターン r_night(t) = open_day(t+1) / close_day(t) − 1(**単純収益**。日中セッションの引け板寄せで買い、翌営業日の寄付き板寄せで売る)。
  `day_session_daily` の close と次行の open から計算。祝日・休場をまたぐ場合もその 1 往復を 1 標本とし(標本数は営業日数 − 1)、泊数を付す。
  実装は `src/bot/research/overnight.py: overnight_returns(kind="simple")` を使う(既定の `kind="log"` は既知正解テスト用で、本単位では使わない)。
- 日中リターン r_day(t) = close_day(t) / open_day(t) − 1(比較対照)。
- **誤プリント除外の閾値(事前登録、自由パラメータにしない)**: `drop_glitches` の閾値 = 0.10(モジュール既定値
  `GLITCH_ABS_LOG_RET_DEFAULT`)。関数は列 `r` を素で比較するため、本単位(kind="simple")では**|単純収益| > 0.10** として効く
  (監査 3 の実測: 開発セットの該当 3 件、対数と単純で件数一致)。先物では 1 日 10% 超はサーキットブレーカー水準で、
  該当は誤プリントかロール段差のどちらかである。
  除外件数を報告し、除外の有無で両方報告(判定は除外後)。閾値は変更しない(変更する場合は反復として N に加算)。
- 夜間セッション日次(`night_session_daily`)の open→close は「夜間セッション内」の値動きであり、上の r_night と時間帯が異なる。
  対照 3(下記)に使い、主指標には使わない。

## 指標と分母
- 主指標: (1) 保守コスト後の平均ネット夜間リターン r_net(bps/ペア)と 95% CI、(2) 夜間 − 日中の差の平均と 95% CI。
  CI はどちらも**ブロック・ブートストラップ**(ブロック長 20 営業日、リサンプル 2,000 回、percentile 法)。
  **分母 = 開発セットのペアからロール隣接ペア(月次規則)を除いた集合、n = 2,769**(除外前 3,240 も併記)。
- 副指標: Sharpe(年率換算 = 平均 / 標準偏差 × √(年あたりペア数 = n / 年数)。泊数が不均一なため √250 は使わない)、
  最大ドローダウン(マイクロ 1 枚固定、費用後)、勝率、ロール隣接ペアを含めた場合、四半期規則で除外した場合(n = 3,081)、
  夜間セッション無しの 5 日を除いた場合、1 泊のみの集合、泊数別平均、制度区分別、誤プリント除外の有無。
- MDE(α 0.05・検出力 0.8、独立標本の SE による下限。ブロック・ブートストラップの CI は自己相関のぶん広くなり得るので、
  実測 CI 幅から逆算した実効 MDE も台帳の反復 0 に記録する): 月次規則で除外後の σ(r_night) = **113.18bps**(監査 3 の実測)、
  n = 2,769 → SE 2.15bps → **MDE = 6.03bps/ペア**。差(夜間 − 日中)は σ = **151.55bps** → **MDE = 8.07bps/ペア**。
  四半期規則に切り替えた場合は同じ手順で再計算して台帳に記す(規則は変えない)。
- 着手前の関門(**実務上の最小値**、効果の事前見込みは置かない): 平均ネット r_net(保守コスト控除後)が MDE(6.03bps)未満なら、
  統計的に検出できても「取引価値なし」として棄却候補。主指標は平均なので費用も**平均** 8.89bps で見る: グロスの平均が
  8.89 + 6.03 = **14.9bps/ペア**以上ないとこの関門を越えないことを事前に記す(結果を見てから緩めない)。

## 対照(反事実)
本仮説は「毎晩保有する常時オン型」なので、「全営業日から無作為に同数選ぶ」対照は期待値が同じ空の対照になる。よって:
1. **日中保有(主対照)**: 同じ日に open → close で保有した r_day。仮説の主張「日中より高い」の直接の反事実。夜間 − 日中の差と
   その 95% CI を主指標の一部とする(下記)。
2. **シャッフル帰無**: 夜間リターンの符号を無作為化(1,000 回)し、平均と Sharpe の帰無 95 点を得る。
3. **区間分解対照(夜間セッション内のみ保有)**: r_night を 3 区間に分解する — (a) 日中引け → 夜間セッション寄り、(b) 夜間セッション
   寄り → 夜間セッション引け(`night_session_daily` の open→close、**取引可能な区間**)、(c) 夜間セッション引け → 翌日中寄り。
   ペア (t, t+1) には夜間行 t+1 を当てる(上記の整列規則)。(b) だけを保有する反事実の平均と CI を対照 3 とする。プレミアムが
   (a)(c) の板寄せギャップに集中していれば「夜間セッション内で取引しても捕捉できない」ことになり、機構の診断にもなる。
   (a)+(b)+(c) = r_night は恒等式なので整合性テストには使わず、整列は水準比較で検証する。
   CI の算出法(ブロック・ブートストラップ)は手法であり対照ではない(監査 2 の指摘で分離)。
4. **レジーム診断(選択に使わない、記述のみ、p 値・有意判定は書かない)**: 20 日実現ボラ三分位、制度区分、SQ 近傍、泊数。
符号反転は主指標の決定論的な鏡像なので対照としては用いない。

## 探索面
- 主検定の自由パラメータ: なし(保有窓は「引け → 翌寄り」の 1 通り)。N0 = 1。
- 診断(選択に使わない): ボラ三分位(3)、曜日(5)、月(12)、年代(制度改正区切り 3)、泊数。診断は平均と n の記述のみで
  p 値・有意判定を書かない(多重検定を判定に持ち込まないため)。診断の結果で主検定を変えることは禁止。
  変える場合は反復として台帳に記録し、N に加算する。事前登録済みの規則切替(ロール規則の四半期化)も反復として N に加算する。

## 停止規則
直近 3 反復の val 主指標の改善 < MDE、または反復 8 回。延長は理由付きでオーナー申請。

## 最終評価(封印データ、1 回のみ)
- 封印期間 2020-12-21 .. 2026-08-28 とフォワード(2026-09-06 以降、ペーパー台帳)で 1 回だけ評価。
- バー: 「累計 N 通りの最良」の帰無分布の 95 点を超える、かつ保守コスト後(ペアごとの cost_bps(t))の平均ネット夜間リターンの
  95% CI が正、かつ夜間 − 日中の差の 95% CI が正。
- 反証文(棄却): 封印期間(ロール隣接ペア除外、誤プリント除外、保守コスト後)で「平均ネット夜間リターンの 95% CI がゼロを含む」
  または「夜間 − 日中の差の 95% CI がゼロを含む」なら本仮説は棄却。ロール隣接ペアを含めた場合にのみ成立する結果は採用しない。
- 保留区分: 楽観コスト(手数料のみ)では CI が正だが保守コストでは CI がゼロを含む場合は「存在するが取引価値は丸め次第」として保留。
  引き金 = フォワードのペーパー台帳で板寄せ執行差(実測の丸め)が得られること(最終評価の後、反復として記録)。
- 封印期間の制度区分別(2021 夜間延長、2024-11 引け延伸)の併記は判定に使わず、フォワードとの接続の参考にのみ使う。
