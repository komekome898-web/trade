## 1. 10 問への回答

### Q1 仮説文に数値・過去判定が混入していないか → 可
「夜間セッションを買い持ちすると日中より高いリターンが得られるか」。数値なし、過去判定なし、方向のみ。§1 の二層ブラインドに適合。

### Q2 分母・n の見込み・MDE → 要修正
- **n が 5 ずれる**。PREREG は「夜間 3,236 営業日、n ≈ 3,235」と書くが、r_night は `day_session_daily` のみから作る定義なので実際の母集団は日中 3,241 行 → 3,240 ペア。差の 5 日は上表の「夜間行が無い日」。分母の定義文(何行のどのファイル)を日中基準に書き直すこと。
- **MDE の算術が σ の過小仮定に依存**。PREREG の「σ≈100bps」は実測 120.97bps。正しくは MDE ≈ 5.96bps(単独)/ 7.84bps(差)。差は独立仮定の √2 倍(171bps)ではなく相関があるため 159.3bps で、PREREG の 7bps より大きい。両方を実測値で書き換えること。
- **効果の事前見込みが無い**。テンプレ Q2 の「見込みが MDE を下回るなら着手前に棄却候補」という関門が、見込み欄が空のため発動しない。着手前に、過去結論に依らない根拠(制度・機構からの見積り、または他市場の同型効果の桁)で見込み幅を書くこと。書けないなら「見込み不明・探索的」と明記して同じ扱いにする。

### Q3 封印と開発セットの非重複 → 要修正(境界 1 ペアが未処理)
- SEALED.json の 7 ファイルはすべて `seal_from_ts = 2020-12-21T00:00:00+00:00`、`forward_start = 2026-09-06`。PREREG の記述と**一致**。`load_unsealed` は `min(seal_from, forward_start)` 未満のみ返すので、境界の実装は正しい(実測で封印外末尾が両系列とも 2020-12-18)。
- **致命に近い漏れ**: r_night(t) は open(t+1) を要求する。開発セット末尾 t = 2020-12-18 のペアは open(2020-12-21) = **封印行**を必要とする。PREREG のリターン定義にはこの端点処理が書かれていない。「開発セットのペアは両端とも封印外の行に限る(最終ペア = 12-17→12-18)」と明記すること。逆向き(封印期間の初回ペアが close(2020-12-18) を使う)は最終評価時に開発行を1つ参照するだけなので許容だが、これも明記。
- **系列の呼称が実態と食い違う**。PREREG は `night_session_daily` を「主系列」と呼ぶが、主指標も副指標も `day_session_daily` だけで計算される。封印境界 2020-12-21 は夜間系列の 70/30 点であって、日中ファイル自身の 70/30 点は 2015-08-29(SEALED.json の `seal_from_ts_per_file`)。日中ファイル全体では封印率 15.6% に過ぎない。解析窓を 2007-09 以降に限れば 30% で整合するので設計としては可だが、「封印 30% は解析窓 2007-09 以降に対して」と条件付きで書くこと。

### Q4 コスト定数が全て measured / primary_document か → 要修正
- 3 定数(手数料 11 円/片側、呼値 5 円、乗数 10 円/pt)はいずれも `config/constants.yaml` で `source_type: primary_document`、`verified_on: 2026-09-05`。`assumed` の混入なし。**この点は可**。
- 板寄せスリッページを定数で仮定せず、「手数料のみ」「手数料 + 1 ティック/片側」の 2 本立てで報告し保守側で判定する方針は**誠実で妥当**。ただし合計値が書かれていない(22 円 = 0.33bps/往復、5pt×10 円×2 = 100 円 = 1.50bps/往復 → 保守側の床は **1.83bps/往復**)。明記すること。コスト床 1.83bps は MDE 5.96bps より小さいので、検出力の議論を変えない旨も書き添えると誤読が減る。
- **致命的な手続き違反**: スリッページの実測元として `paper_logs/on1_ledger.csv` の `micro_minus_large_*` 列を指定しているが、このファイルは SEALED.json 上**全期間封印**(フォワード)。反復中に読めば封印違反。加えて `micro_minus_large` は schema 上「同時刻のマイクロ − ラージのトラッキング差(net_yen には課していない診断値)」であって**板寄せの執行差ではない**。n も 9 前後。(i) 実測は最終評価時に `load_sealed` の三重ガード経由でのみ行う、(ii) 測っているのは限月・契約サイズ間ベーシスであってスリッページではないと明記、(iii) 反復中は保守側(1.83bps)固定 — の 3 点に書き換えること。

### Q5 対照 3 種が仮説の反事実になっているか → 致命
- (1) 符号無作為化 1,000 回: 平均の帰無分布としては成立(対称性を仮定する検定であることを明記すれば可)。
- (2) 「全営業日から無作為に同数を選んだ保有」: **反事実になっていない**。本戦略は全営業日を毎晩保有する常時オン型なので、同じ母集団からの無作為部分集合は構成上同じ期待値を持つ。空の対照。本仮説(夜 > 昼)の真の反事実は**時間帯の入れ替え** — 同じ日数だけ日中を保有する、または夜間と同じ長さの日中窓を無作為に選んで保有する — であり、現状これは「副指標」に格下げされている。日中対照を対照(ii)に昇格させること。
- (3) 「符号反転(夜間を売り持ち)」: 主指標の決定論的な鏡像(平均が −1 倍になるだけ)で情報量ゼロ。さらに括弧書きの「= 日中買い持ちに近い」は誤り(−r_night ≠ r_day、両者の相関は独立ではない)。この括弧を削り、(3) は「レジーム別に符号反転しても対称に効くか」の診断など、独立な情報を持つ形に置き換えること。

### Q6 探索面 N0 → 可(注記あり)
N0 = 1(自由パラメータなし、保有窓 1 通り)は数え上げとして正しい。診断(ボラ三分位 3・曜日 5・月 12・年代 3)を選択に使わない旨と、使った場合は反復として N に加算する旨が明記されている。注記: 診断は 23 スライスあるので、報告時に p 値や「有意なスライス」を併記すると事実上の多重検定になる。診断は点推定と CI の**記述のみ**、判定文を書かない、と一文足すこと。

### Q7 停止規則と反復予算 → 可(実質空回り)

### Q8 既知欠陥(schema)への対処 → 致命
- 出来高欠損 1990-2000: 開発セット外(実測 0 件)。対処不要と書けば可。
- 1 分足の取引日慣行: 板寄せ代理に使わないと明記済み。可。
- vs_cash 中央値 0.179% 乖離: 先物内で完結する定義なので無関係。可。
- **GW ギャップ(2019-04-26 .. 05-07)**: 「祝日をまたいでも 1 往復 = 1 標本」という規則により、10 泊の保有が 1 泊と同じ 1 標本として平均に入る。分散も期待値も別物。仕様 §5 の taker 型の作法(妥当性マスク・除外は印付けのみ・適用前後の両方を報告)に倣い、**連休またぎ標本に印を付けて両方報告**すること。現状は言及すらない。
- **限月乗換え(ロール)**: PREREG は「限月乗換えの扱いは 225Labo 側」と書くだけで、これは**対処ではなく丸投げ**。日次 4 ファイルには限月列が無く、`manifest.json` にもロール方式(素の継ぎ接ぎ / 後方調整)の記載が無い。限月列を持つ `paper_logs/nk225_sessions.csv` と `bars_1min.csv.gz` は**いずれも全期間封印**。したがって**開発セット内ではロール方式を確認する手段が存在しない**。素の継ぎ接ぎなら、限月乗換え日の close→open にカレンダースプレッド分の人工的な段差が入り、それは**まさに本研究が測っている量**に年 4 回混入する。本監査で測れた範囲: 四半期 SQ 日(3/6/9/12 月第 2 金曜、開発セット内 53 日)を t とする r_night の標準偏差は 161.8bps、その前日は 179.9bps、それ以外の日は 119.0bps。段差の存在を証明も反証もしないが、**汚染がありうる方向の観測**である。着手前に、(a) 225Labo に方式を照会して一次資料として記録する、(b) 出来ないなら SQ 前後 ±2 営業日を印付けし主指標をマスク前後の両方で報告する、のいずれかを事前登録に書くこと。

### Q9 執行様式の既知正解テスト → 要修正
`backtest_data/qa_pipeline_daily_20260905/RESULTS.md` は実在し、植え込み 0 / 2 / 5bps を MDE 内で回収(t = 0.86 / 4.20 / 9.21)、分割・誤プリント 11 日の検出も確認済み。**合格記録としては有効**。ただし 2 点。
- 計算経路は `scripts/research_overnight_onr.py` の `overnight_returns` / `drop_glitches` / `mean_t`(合成 **ETF** テープ)。仕様 §5 の「板寄せ型は日次型の関数経路を共有」に依拠するなら、**P2-01 が実際にどの関数を import して使うか**を事前登録に名指しすること。名指しが無いと「共有」の主張が検証できない。

### Q10 反証文 → 要修正(軽微)
「封印期間で費用後平均の 95% CI が 0 を含む、または 夜−日 の差の 95% CI が 0 を含むなら棄却」は具体的で事前特定されている。不足 2 点: (a) CI の算出法(t 近似か bootstrap か、オーバーナイト収益の系列相関・不均一分散の扱い)が未指定で、監査者が同じ数字を再現できない。(b) 仕様 §6 は 採用/棄却/保留 の 3 区分で、保留には引き金の名指しが要る。本文には保留の道が無く、事実上 2 択。それで良いなら「本単位に保留区分を設けない」と明記すること。

## 2. 設計が黙って仮定していること(Q(j))

1. **暦の整合**: 日中と夜間で 5 日ずれる(上表)。うち 4 日は年始、1 日は 2016-07-19。これらの日の「引け→翌寄り」は**夜間セッションが存在しない**保有であり、仮説が述べる「夜間セッションを買い持ち」とは別物。印付けして除外前後を報告すること。
2. **祝日・連休**: 1 往復 = 1 標本という規則は、保有時間が 1 泊〜10 泊にばらつくことを平均 bps/日 の分母が吸収しない。Sharpe の年率換算(副指標)を √250 で行うと、この不均一な保有時間により歪む。年率換算の定義を書くこと。
3. **セッション時間のレジーム**: PREREG は夜間の 2011/2016/2021 の変更を挙げるが、**日中セッションの引け時刻の変更に触れていない**。schema は日中 close を全期間「15:45 の引け板寄せ」と記すが、これは 2024-11-05 の延伸後の姿で、開発セット(2007-2020)の引けは別時刻。エントリー時刻は標本内で一定ではなく、しかも**開発セットと封印期間の間に制度変更が挟まる**(封印期間 2020-12-21 .. 2026-08-28 は延伸をまたぐ)。最終評価の解釈に直接効くので明記すること。`config/constants.yaml` には先物のセッション時刻定数が無い(現物の `closing_auction_time_since_2024_11_05` のみ)ので、必要なら一次資料から追加。
4. **限月ロール日**: 上記 Q8。開発セット内では確認不能。
5. **建てる商品と価格系列の不一致**: コスト・執行はマイクロ(乗数 10 円)で書かれているが、225Labo の系列はマイクロではない。マイクロ先物の上場は 2023 年で、**開発セット全期間および封印期間の大半にマイクロの値段は存在しない**。「ラージ/ミニの継続系列で測った収益率を、マイクロの手数料・呼値で費用化する」という置換を行っていることを明記し、置換の妥当性(呼値 5 円は共通か、板の厚さの差)を一次資料で確認すること。
6. **出来高欠損年**: 開発セット外(実測 0 件)。実害なし。
