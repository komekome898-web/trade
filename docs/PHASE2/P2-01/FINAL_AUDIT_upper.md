## 2. 当方の数値からの判定(記録値を見る前に確定した結論と同一)

- **バー(3 条件)**: ① 累計 N = 2 の最良の帰無 95 点超え → **満たす**(6.057 vs 5.459/5.468。ネット基準で読み替えても実測 best
  2.489 vs 帰無 95 点 1.94 で満たす=統計量の取り方に依存しない)。② 保守コスト後ネットの 95%CI が正 → **満たさない**
  [−2.563, 7.446]。③ 夜間−日中の CI が正 → **満たさない** [−1.570, 11.700]。**3 条件同時充足せず**。
- **反証文 A(ネットの CI がゼロを含む)= 該当、B(差の CI がゼロを含む)= 該当** → 原文どおりなら棄却。
  付帯条件(ロール隣接を含めた場合にのみ成立)には該当しない(含む集合でも CI はゼロを含む)。
- **保留区分**: 楽観コスト CI [0.392, 10.351] が正・保守 CI がゼロを含む → **該当**。
- 凍結 PREREG は反証文(棄却)と保留区分(保留)が同じ状態を指しており**内部で衝突している**。より特定的で、かつ
  PHASE2_SPEC §6 が保留に要求する「名指しの引き金」(= フォワード台帳で板寄せ執行差の実測)を伴うのは保留区分の側なので、
  形式上の帰結は**保留**と読むのが妥当。ただし下記のとおりこの保留は実質的に空である。
- **決定的な補足(当方の計算)**: 着手前の関門は「平均ネット ≥ MDE」。封印標本で MDE を引き直すと **8.23bps**(σ 108.79、n 1,370)、
  事前登録値でも 6.03bps。実測ネットは 2.489bps、**丸めコストをゼロにした楽観側でも 5.414bps** で、どちらの関門にも届かない。
  グロス 6.057bps も事前登録の関門 14.9bps の 4 割。すなわち保留の引き金(執行差の実測)をどう引いても採用には到達し得ない。
  実務上は棄却相当であり、保留とするなら「引き金を引いた時点で自動的に棄却へ落ちる保留」であることを明記すべき。
- 機構の読み: 対照3 leg(b) はグロス 4.205 で CI 下限が +0.038bps(実質ゼロ)、費用後は 0.636 [−3.530, 4.837]。
  プレミアムは薄く、夜間セッション内保有でも板寄せギャップでも費用後には残らない、が当方の読み。

## 3. スクリプトの欠陥(コード = 主張としての審査)

事前登録との一致を確認した点(欠陥なし): 端点規則(両端封印内 → `build_pairs` が最終行を落とすことで自然に成立)、
ITER.md のペア読み(SQ 当日/前営業日のいずれかを端点に持つペア = 1 SQ 3 ペア)、ペア別コスト 122/(close(t)×10)×10^4 と楽観 22 円、
CI(ブロック 20 / 2,000 回 / percentile / seed 20260906)、best-of-N の構成(1 シャッフルで共通の符号ベクトルを引き 2 構成の最大値)、
開発セットの混入なし(`p2_01_run.py` からは凍結済み定数と検定済み関数のみ輸入)、封印データを見てから選んだパラメータなし
(唯一の後付けは §6 の 2021 分割で、これは記述専用かつ §10 で開示済み)。入力 7 ファイルの MD5 は SEALED.json と全件一致、
RUN.json の inputs も一致。

SE ≈ 33bps 相当、封印期間の +2.5bps と矛盾しない(識別不能)。本節を「診断のみ・費用に反映しない」とした処理は事前登録どおりで妥当。
