# K1 段階 A — 違いの裁き(升ごとに 当時の値 / 新しい値 / 差 / 裁き / 根拠)

委任文 §2-3「**違いの裁き**: `DIFF.md`: 升ごとに 当時の値 / 新しい値 / 差 / 裁き(一致・環境の欠陥・当時の誤り・不明)/ 根拠(規則の文の番号・場面・参照の出力)。「一致」は数が同じという事実だけを書き、正しさの根拠には書かない」。方針(L-479a、オーナー「**方針はそれで良い**」): 過去の結果は正解ではなく**違いの検出器**。

## 0. 読み方

- **当時の値** = `docs/PHASE2/K1/RESULT.md` 第 2 部の表 2.1〜2.6 の数(2026-09-09〜10 に当時のスクリプトが出した数)。`scripts/k1_newenv_diff.py: parse_old` が RESULT.md 132〜243 行の表を機械的に読む(`old_values.json`)。
- **新しい値** = 新しい環境の実行記録から `scripts/k1_newenv_tables.py` が作った `cells.json`(TABLES.md と同じ数)。
- **差** = 新 − 当時(表の 2 桁で比べる。|差| ≤ 0.005 bp を「一致」= 表に印字される数が同じ)。
- **裁き**: 「一致」= **数が同じという事実だけ**。「環境の欠陥」「当時の誤り」「不明」は違いのある升にだけ付け、根拠(規則の文の番号 = INTENT_MAP の S-*/P-*/T-*、小さな入力での再現、独立の参照の出力)を書く。
- **`*`(95% 区間)の欄は別扱い**: INTENT_MAP T-5 のとおり、環境には日ブロックのブートストラップが無く、表の生成側に書いた代理(△)である。同じ種・同じ回数でも**乱数の消費順が当時と同じである保証は無い**(当時は 1 本の `random.Random(20260909)` を 234 升の周回順で使った。新しい側も同じ順に呼ぶが、30 件未満で飛ばす升や周回の順が当時のスクリプトと完全に同じかは、算術を写さない以上確かめない)。**したがって `*` の食い違いは「比べられない(代理)」であって、環境の欠陥でも当時の誤りでもない。**
- 独立の参照 `src/bot/bt/reference/bar_sim.py` は場面集の規則(R-T1 翌足始値の taker 執行 …)の参照で、**K1 の規則(その足の終値で建てる・ヒゲ先端の無効化・ドテン)は場面集の規則に無い**(ENV_DEFECTS E-3)。したがって K1 の升の裁きに `bar_sim` の出力は使えない。使ったのは (a) 規則の文(RESULT.md 1.3 / 1.4)からの手計算の場面(`tests/test_k1_wick.py`、6 場面)と (b) 当時の表との一致・不一致である。

## 3. 違いのあった升の裁き

- **平均(mean r)に違いのある升は 0 升(234 升中)**。「環境の欠陥」「当時の誤り」と裁く升は無い。**一致は数が同じという事実だけで、正しさの根拠にはしない**(§0)。
- **`*`(95% 区間)の食い違いは 0 升**。06:40 UTC の中間の再生成(155 升)では 8 升が食い違っていたが、これは表の生成側の区間が 1 本の乱数を升の周回順に使うため、未測定の升があると乱数の消費順が当時とずれたことによる(234 升が揃った 07:09 の再生成で 0 升)。T-5 のとおり `*` は代理の統計であり、一致しても環境の検査にはならない。
- **一致が何を確かめたか(射程)**: 同じ入力で、データ層の日ファイルの読み(`bot.bt.data.load`)・足の畳み(新設の `bars_from_bars`)・核(`bot.bt.core` の事象の順)・記録の口(`bot.bt.repro.runner`、2 回実行して byte 一致 = 155 升すべて)を通した約定の列が、当時の自前の計算と同じ平均・取引数・保有本数を出した。**確かめていないもの**: 約定の値付けは作業者が戦略側に書いた `BarCloseMarketFill`(E-3 の回避)であり、**環境の約定の模型(項目 2)・費用・口座は通っていない**。統計(平均・区間)は表の生成側 `scripts/k1_newenv_tables.py` の計算で、**環境の指標・検証の部品(項目 3)は通っていない**。
