## 0. 問い

BitMEX 2017-2019 で測ったカツオの機構の効果は、**2019 に向かって消えていた**(`RESULT.md` §4.4)。
**その先(2020-2026)で残っているか**を、封印(BitMEX 2020-2021)を使わずに見る。
同時に、**取引所を跨いで同じ構造(第 5 部: 実体の戻りが主因、ヒゲは実体小でだけ古典的)が出るか**を見る。

**判定は出さない。** K1 の成果物は効果量 bp と区間であって合否ではない(L-056)。
帰無・MDE・判定バーは作らない。経費は引かない(流れの ④)。

## 2. 同条件・同方法(変えないもの)

BitMEX 側の測定と**同じコード経路**を通す。**複製しない。** `--source binance` で切り替える。

| 項目 | BitMEX と同じか | 出所 |
|---|---|---|
| 足 | 1 / 3 / 5 / 15 / 30 / 60 分 | `RESULT.md` §1.3 |
| 門 | `s ∈ {off, −, 10, 19, 30}` bp × `b ∈ {−, 24, 40}` bp、13 通り | 同 |
| シグナル | `measure_katsuo_effect.signals()`。**`int()` 切り捨てを主とする**(原典どおり) | 同 |
| 強さ | 強い / 弱い / 両方 | 同 |
| 機構 | `measure_katsuo_effect.simulate()` の 4 分岐そのまま | §1.4 |
| ホライズン | 1 / 2 / 3 / 5 / 10 / 20 / 50 本 | 第 4 部 |
| 層 | ヒゲ長 7 層 × 実体比 6 層(bp 建て・比なので通貨に依らない) | 第 5 部 |
| 決済の変種 | 原典 / 無効化のみ / 反対シグナルのみ / 3 本固定 | 第 7 部 |
| 統計 | 日単位ブロックブートストラップ 200 回、種 20260909、**セルごとに種を固定** | §4.4 |
| 建値・決済値 | その足の終値。経費なし | §1.4 |

**変わるもの(同条件にできないもの。結果に必ず併記)**:

- **先物 → 現物**。「取引所の違い」と「先物/現物の違い」は分離できない
- **USD → USDT**、呼値 0.5 → 0.01。`int()` 切り捨ての効き方が違うので、
  **切り捨てなし(`--no-trunc`)も並べる**(第 6 部の方法)。主は原典どおり
- 年が 2017-2019 の 3 つから **2017-2026 の 10 個**になる(2017・2026 は部分年)。
  族は増やさない(足 × 門 × 強さ × h は同じ)。**年は軸ではなく分割**である

## 4. 実装の指示(調査 = 下位モデル)

### 4.1 変更の形

- 新規 `scripts/k1_source.py`: `load_bars(source, start, end) -> [(ts, o, h, l, c), ...]`。
  `bitmex` は `measure_katsuo_dispersion.load_seconds` を呼ぶだけ、`binance` は上記 CSV を読む。
  ソースごとの既定の期間と出力ディレクトリもここに置く
- 5 本のスクリプトに `--source {bitmex,binance}` と `--start/--end`(既定はソースごと)を足す。
  **`--source bitmex` の既定の挙動・既定の出力パスは一切変えない**
- 年のハードコードを外す(`effect.py` / `exit_ablation.py` / `direction_bias.py`)。`signal_horizon.py` は既に動的
- 描画 4 本(`render_k1_*.py`)に `--dir` を足し、`binance/` の JSON からも同じ表が出るようにする
- **最小差分。** 無関係な整形・リネーム・リファクタ禁止。モデル名を書かない

### 4.2 再現ゲート(**これが「同じ方法」の証明。通らなければ何も報告しない**)

`--source bitmex`(既定)で 5 本を回し直し、**コミット済みの JSON と一致すること**:

- `signal_horizon.json` / `body_wick.json` / `exit_ablation.json`: セルごとに種を固定しているので
  **全フィールドが一致**するはず(区間も)
- `effect.json` / `direction_bias.json`: 共有乱数列なので区間は消費順で動きうる。
  **n・平均・年別・決済理由・保有中央値は一致**すること。区間が動いたなら**そう報告**する

比較は目視ではなくスクリプトで行い、不一致の一覧(あれば)を報告に含める。
**メモリ: BitMEX の測定は 1 本ずつ**(1 プロセス約 9 GB、箱 15 GB。HANDOFF §8)。

### 4.3 Binance 側の内部整合

- `body_wick.json` の再現ゲートが `binance/signal_horizon.json` に対して通ること
- `exit_ablation.json` の再現ゲートが `binance/effect.json` に対して通ること
- 1 分足では `fold()` が恒等であること(1 分足の行数 = 読み込んだ行数 − 落とした行数)を assert

### 4.4 報告に入れるもの

1. §1 のデータ品質の事実
2. §4.2 の再現ゲートの結果(一致 / 不一致の一覧)

5. 描画 4 本の出力(`binance/` に対して)を `results/PHASE2/K1/binance/TABLES.md` にまとめて置く
6. **数字の解釈は書かない。** 事実だけ。解釈はリードが第 8 部に書く
7. Do not commit. Do not push.
