## 1. 診断の測定(実装者)— `scripts/measure_katsuo_robustness.py`

### 1.1 母集団と族

- 出所: `--source {bitmex,binance}`(`k1_source.load_bars`)。**bitmex は `end <= 2019-12-31` を assert する**(封印)
- 足 6 × 門 **2 つ(`s19/b24`, `s-/b-`)** × 強さ 3(strong / weak / both)× h ∈ {1, 2, 3, 5, 10} = **180 セル**。
  門を 2 つに絞る理由: 第 4・8 部の年別表がこの 2 門で書かれており、診断はその表の数字に対して行う。
  **13 門すべてには広げない**(広げるなら別の設計)。
- シグナルは `measure_katsuo_effect.signals()` を import(原典どおり `trunc=True`)。足は `measure_katsuo_dispersion.fold()`。
  **書き写さない。**
- 1 セルの材料 = シグナル足ごとの行 `(i, sig, r_h, day, year, hour, wday, wbp, body_bp, stale_close, vol_prev)`

### 1.2 診断(1 パスで全部出す)

| ID | 何を測るか | 出力 | 何が分かるか |
|---|---|---|---|
| **D1 基準線** | 第 4 部と同じ `r_h = sig × (close[i+h]/close[i] − 1) × 10⁴`。区間は `measure_katsuo_signal_horizon.day_bootstrap` + `cell_rng(key)` を **import** し、key も第 4 部と同じ `f"{foot}|{gate}|{keep}|{h}"` | n, mean, ci95, 年別 | **再現ゲート**: `signal_horizon.json` の該当セルと n・mean・ci95 が**全フィールド一致**すること(区間も。同じ種・同じ手順なので一致するはず)。不一致なら止まる |
| **D2 区間の頑健性** | 同じ材料で (a) 日ブロック 1,000 回 (b) **週ブロック**(`day // 7`)200 回・1,000 回 (c) **月ブロック**(暦月)200 回。numpy で可(種は `SEED` とセル名から固定)。年別は (b) 200 回のみ | 各 ci95、0 を跨ぐか | 日ブロックが**レジームの塊**を無視して区間を狭くしていないか |
| **D3 1 本遅らせた入口** | `r'_h = sig × (close[i+h]/close[i+1] − 1) × 10⁴`(h ≥ 2)。シグナル足の終値という**1 つのプリント**を経由しない | n, mean, ci95(日 200)、年別 | 効果が**最初の 1 本(気配の往復・古い終値)に閉じている**か、その先も続くか |
| **D4 古い終値の除外** | `stale_close = (close[i] == close[i−1])` のシグナル足を除いた mean/ci95、除いた割合(年別) | 年別 | Binance 2017 の異常と同じ型が他の年・BitMEX にどれだけあるか |
| **D5 分割の一致** | 年ごとに (a) ISO 週の奇偶 (b) 上半期/下半期 で分けた mean と n。**符号が一致した組の数**を年・強さごとに数える | 年別 | 年内でも符号が揃うか。BitMEX 2017 は上半期(呼値 0.01/0.1)と下半期(0.5)で違うか |
| **D6 時間帯** | UTC 3 時間 × 8 区分。n, mean, ci95(日 200)。全期間と年別 | | 効果が特定の時間帯に**住んでいる**か(BitMEX の資金調達 04/12/20 UTC を含む区分に印) |
| **D7 曜日** | UTC 曜日 7 区分。n, mean, ci95(日 200)。全期間 | | 週末(現物・先物で参加者が違う)に偏るか |
| **D8 ボラ区分** | `vol_prev` = 直前 100 本の \|終値対数リターン\| の平均(bp)。**先読み無し**(i−100..i−1)。足ごとに**全シグナル足の三分位**で 3 区分。n, mean, ci95(日 200), 区分内の平均 vol_prev・平均 wbp。全期間と**年別 × 区分** | | **年で消えるのは、ボラ区分内で消えるのか、区分の構成が変わるだけか** |
| **D9 年 × ヒゲ層** | `wbp` を第 5 部の `WICK_BINS` (0,5,10,19,24,40,70) で 7 層。n, mean, ci95(日 200), 平均 wbp。**年別**。加えて `mean(r_h / wbp)`(ヒゲ 1 単位あたり。**派生量と明記**、bp と並べる) | | 同じヒゲ長でも効果が縮んだのか、長いヒゲが減っただけか |
| **D10 年の成分表** | 年ごとに: 全足の realized vol(全足の \|bp リターン\| 平均)、シグナル足の平均 wbp・平均 \|実体\| bp、**実体 > ヒゲ の足の割合**(strong 内)、シグナル数 / 全足数(門の通過率) | 年別 | 減衰の**横に並べる成分**(引かない) |

**D6〜D9 の区間は numpy 版(日ブロック 200 回、セル名から種)でよい。D1 だけは原典の `day_bootstrap` を使う。**

## 3. 先読み・符号の検査(実装者)— `tests/test_k1_lookahead.py`

合成足で、次を**テストとして固定**する(§3.5 で「先読みの検査は走らせていない」と書いた項目):

1. `signals()` の足 i の出力は、i より後の足を変えても・切り落としても変わらない
2. `fold()` の窓境界: ts=59 → バケット 0、ts=60 → 60、`open_time` が +20 秒ずれた行も正しい分に入る。o=最初、c=最後、h=max、l=min
3. `simulate()` の各取引のリターンは、建てた足と決済した足の**終値だけ**から計算されている(合成足で再計算して一致)
4. 前方リターンの添字: 単調増加の合成列で `r_h` が `close[i+h]` を使っていること(h 本ぴったり)
5. **植え込み回収**: ランダムウォークの合成足に「ヒゲ条件を満たす足の直後 h 本に +X bp の drift」を植え、
   シグナル単体の測定が X を(誤差内で)回収する。符号が逆なら落ちる
6. `day_bootstrap` は全日同一の値なら区間 = その値
