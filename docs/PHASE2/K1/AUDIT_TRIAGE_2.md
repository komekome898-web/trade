## 1. 重大(18 件)

### #1 判定条件を 1 本削った根拠が逆【認】

**私は「私はこれを計算していなかった」と書きながら、今回も計算していなかった。**

- 条件 1 = 族 198 セルの**最大** `|mean(r)|` が帰無の 95 点を超えること。
  独立なら 1 セルあたり `0.95^(1/198)` → **両側 3.65 sd**
- 旧条件 2 = `mean(r) > MDE = 2.49 sd`
- **2.49 < 3.65 なので、条件 1 の方が厳しい。** 「条件 2 が条件 1 を死なせていた」は成り立たない

**ただし条件 2 の削除自体は維持する。** 理由が変わる:
削除の正しい理由は「**§5.2 が MDE を『陰性の射程』と宣言しているのに、判定の線に使っていた**」
という**文書内の矛盾**であって、包含関係ではない。**行動は同じ、根拠は差し替える。**

→ **C10 の対象**: この種の主張は今後 `【計算: 式 = 値】` を義務づける。

### #2 `MDE = 2.80 × (帰無分布の sd)` が定義不能、かつ実効バーと桁が合わない【認】

**指摘のとおり、どちらの読み方でも壊れている**:

- 「帰無分布」= **族の最大の分布**なら、0 中心ではないので `2.80 × sd` は意味を持たない
- 「セルごとの帰無 `mean(r)` の sd」なら多重性を含まないので、
  **MDE(2.80 sd)< 陽性バー(3.65 sd)** になり、その帯の効果は
  「陽性でない」かつ「MDE 超だから陰性」と**両方に落ちる**

**原因**: MDE を**実際に使う判定規則ではなく、単一検定の一般式**から作っていた。

**対処**: **MDE は実際の判定規則から導く。**
判定は「族の最大が帰無の 95 点を超える」なので、そのセルが単独で判定を通す確率が 80% になる効果量が MDE:

```
MDE(セル) = (帰無の族最大 95 点)+ 0.84 × (そのセルの帰無 mean(r) の sd)
```

桁感で **≈ 3.65 + 0.84 = 4.49 sd 相当**【計算: 3.65+0.84 = 4.49】。
**バーより必ず大きくなる**ので、「陽性でないが陰性」の帯は消える。

### #3 帰無 N2 が実データのセルと交換可能でない【認・最も重い】

監査が **N2 を実装して実データと比較した**(2019・15 分・`s19/b24`):

| | strong の n | weak の n | `sd_trade` | 保有中央値 |
|---|---|---|---|---|
| 実データ | 3,137 | 4,931 | 104.2 bp | 3 |
| N2 世界 | 4,044〜4,069 | 3,999〜4,024 | 92.7〜95.8 bp | 2 |

**原因は私の設計そのもの**: 強弱は「シグナルの向きと足の色が一致するか」で決まるので、
**向きをコイン投げにすると強弱が必ず 50/50 になる**。実データは 37〜43%。
さらに `lcprice` を反対側の先端に付け替えると、**負けた側の(短い)ヒゲ先端**になる場合が生じ、
無効化が早く効いて保有が縮み `sd_trade` が 9〜11% 小さくなる。

**帰無分布が実データより狭い → 95 点のバーが低い → 偽陽性方向。**
§6.2 の「壊さないもの: 保有区間の重なり」も §A.3 の「壊れるのは向きの対応だけ」も、
**実測で成立していない。**

**私は帰無を作り直したのに、作り直した帰無を一度も走らせなかった。**
規約 §1.1「準備測定も測定である」に自分で違反している。

**対処**: 帰無を**もう一度**設計し直す。**枠組みなのでオーナーに諮る**(→ §4)。

### #4 「同じ置換世界」の共有単位が未定義【認】

「族 198 セル全部を同じ置換世界で計算」と書いたが、コイン投げを
**足ごとに引くのか / セルごとに引くのか**を書いていない。
門が違えばシグナル集合が違い、足が違えばバーそのものが別物なので、**自明に定義できない**。

- セルごとに独立に引く → セル間の相関が消えて**バーが上がる**(偽陰性方向)
- 足ごとに 1 回引いて全門で共有 → **バーが下がる**(偽陽性方向)

**手続きの未記載部分だけでバーが動く。** #3 と併せて設計し直す。

### #5 サニティ 2(符号反転)は無意味か必ず落ちるかのどちらか【認】

`signal` を反転すると決済も変わる(反対シグナル判定・色条件・`lcprice` の側が
すべて `s` に依存)。**正しく反転すれば絶対値は一致しない。**
一致するのは最後の掛け算だけ裏返した場合で、それは恒等式の確認にすぎない。

**§8 の前口上「落ちない検査は検査ではない」を、差し替えた新しい検査自身が破っていた。**

**対処**: 統計的なサニティから外し、**単体テストにする**
(`s = +1 / −1` で `r` の符号計算が対称であることを、合成データで直接確かめる)。

**段 0 では実測の最大が無いので、この規則は実行できない。**

**対処**: **段 0 で無条件に 10,000 回走らせる**(実測を見ずに決まる)。
1,000 回で足りるかを実測依存で判断する規則を**削除**する。

## 4. オーナーに諮る枠組み — **2 件**

残りは私の側で直せるが、次の 2 つは**枠組み**なので判断を仰ぐ。

### 枠組み A: 帰無をどう作り直すか(#3 / #4 / #26)

**N2(向きのランダム化)は実測で失格した。** 強弱の比率が 37〜43% → 50% に動き、
`lcprice` の付け替えで保有が縮む。**帰無の方が実データより狭くなり、バーが下がる = 偽陽性方向。**

候補:

| 案 | 中身 | 難点 |
|---|---|---|
| **N4 ブロック順序入替**(推奨) | 価格系列を**日単位のブロック**に切り、日の順序をランダムに入れ替える。シグナルは入れ替え後の系列から**計算し直す** | 日をまたぐ保有が壊れる(保有 95% が 1 日以内のセルなら影響小)。日内周期は保存、日をまたぐ自己相関は壊れる |
| **N5 別銘柄・別期間** | 同じ規則を**関係のない期間**に当てる | 「エッジが無い世界」ではなく「別の世界」なので、帰無として厳密でない |
| N2 の修正 | 強弱の比率と `lcprice` を実データに合わせて補正する | **補正の妥当性を検証する手段が無い**。私の設計ミスを設計で覆うことになる |

**私の推奨は N4。** 「シグナルを入れ替え後の系列から計算し直す」ので、
**強弱の比率も保有構造も自然に実データと同じ分布になる**(#3 の失敗が構造的に起きない)。

### 枠組み B: 建玉状態を持つか(#12)

意図マップで **○** と判定した I-4(ドテン)/ I-5(建玉が無ければ弱いシグナルでも建てる)は、
**建玉状態が無いと表現できない**。いまの測定は持っていない。

| 案 | 中身 | 代償 |
|---|---|---|
| **B1** | **建玉状態を持たせる**(建玉 1 単位、ドテンあり) | n が約 45% に減る(MDE ×1.5)。ただし**○ を外さずに済む** |
| **B2(推奨)** | 持たせない。**○ を 2 つ外していることを射程と前提表に明記** | 「意図どおりの機構を測った」とは言えなくなる。**射程が狭まる** |

**私が B2 を推す理由**: 本単位の問い(§0)は「**足の形から後続リターンが予測できるか**」で、
建玉管理は**執行の話(層 ②)**である。ただし **L-046 で「○ を外すな」と自分で書いた**ので、
**外すなら明示的にオーナーの承認が要る**。黙って外すのが最悪である。
