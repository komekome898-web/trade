## 4. 測るもの — **固定保有をやめ、カツオ自身の決済で測る**(L-046 で全面改訂)

### 4.1 なぜ変えたか(**私の設計ミス**)

当初は固定保有 `h` 本後のリターンを主指標にし、`h` を掃引軸に置いていた。**これは二重に誤っていた。**

**誤り 1: `h` に戦略的な根拠が無い。** `{1,2,4,8}` は根拠なく並べた選択肢で、
族が大きいと指摘されたとき**私はこの軸を削ることを提案した** — 仮説の意味を最も担う軸を、
計算量の都合で削ろうとした。オーナーの指摘「**もしこの h が MDE を出すために用意したもの
なら本末転倒**」は、経緯として正しい。

**誤り 2(より重い): 意図に入っている決済ルールを、黙って外していた。**
`KATSUO_INTENT_MAP.md` の I-8「反発の根拠(ヒゲ先端)が壊れたら降りる」は **○ = 意図どおり
実装済み**と判定してある。**カツオに固定の保有期間は存在しない。**
固定 `h` で測ることは、**○ の項目を取り除く**ことであり、意図マップ §4 の
「外すのは ＋(意図に無い実装)だけ」に自分で違反していた。
**意図マップが防ぐはずだった失敗を、意図マップを書いた本人がやっていた。**

**そして実データが、指摘の内容そのものを裏付けた**(探索区間 2017-2019、カツオ自身の決済):

| 足 | 保有の中央値 | 25% | 75% | 95% |
|---|---|---|---|---|
| 5 分 | **8 本(40 分)** | 2 本 | 43 本 | 96 本(8 時間) |
| 15 分 | **8 本(120 分)** | 2 本 | 43 本 | 96 本(24 時間) |
| 60 分 | **8 本(8 時間)** | 2 本 | 50 本 | 96 本(4 日) |

**中央値が 8 本**なので、`h = 1, 2` は**分布の下から 1/4 しか見ていない**。
オーナーの言うとおり、それは「トレンド転換の予測力」ではなく
**「即座に反転するか」の評価**になっていた。

### 4.2 主指標(改訂)

**カツオ自身の決済ルールで持ったときの符号付きリターン**:

- 建値 = シグナルが出た足の**終値**
- 決済 = 次のどちらか早い方
  1. **無効化**: 終値がヒゲ先端(`lcprice`)を割った足(I-8。終値で見る = L-044)
  2. **反対シグナル**: 反対向きのシグナルが出た足(原典の 4 分岐どおり)
- **上限 96 本**で打ち切る(原典に上限は無い。**これは検証の都合で入れる制約**なので、
  上限に達した割合を必ず報告し、48 本 / 192 本での感度も併記する)

```
r = signal × (close[決済] / close[建玉] - 1) × 10^4
```

### 4.3 保有期間は「掃引軸」ではなく「報告する曲線」にする

`h = 1 … 96` の各時点での `mean(r)` を**曲線として報告する**。ただし
**これは記述であって選択には使わない**(曲線の最良点を選べば、それは h の掃引と同じになる)。

曲線が答えるのは、まさにオーナーが問うたこと:

- **最初の 1〜2 本で終わる山**なら → 「即座の反発」であって、トレンド転換ではない
- **数十本かけて伸びる**なら → トレンド転換の予測として筋が通る
- **すぐ立って、その後戻る**なら → 執行が速くないと取れない(層 ② の話になる)

**選択に使うのは §4.2 の主指標だけ。** 曲線は「なぜそうなるのか」(規約 §0.2)に使う。

**総経費は主指標から引かない。** 引くべき経費は執行(層 ②)で測るもので、
ここで仮定の数字を引くと**仮定の誤りが機構の判定に混入する**。代わりに §5 の 3 本の線で比較する。

## 5. 採用基準(**数値バーを先に置く**)

### 5.1 執行の前提 — **単一のハードルではなく 3 本の線を引く**(L-045 で全面改訂)

当初「往復 15 bp(テイカー往復)」の 1 本にしていたが、**それは戦略の設計を無視していた**。
オーナーの指摘:

> post only で指値を出す方式は**まさにそのテイカー手数料を払わないため**。当時の BitMEX は
> **メイカーにマイナス手数料、テイカーに手数料**という形で、なおかつ**流動性が高く
> スプレッド幅が小さい**。従ってできるだけメイカーで注文を出すことを目指していた。

**これは原典の実装と一致する**: 新規の 1 本目も決済の 1〜3 本目も
`ParticipateDoNotInitiate`(post only)である(`KATSUO_PARAMETER_INVENTORY.md` §6)。
**メイカーで取ることが設計の中心**であって、付随的な工夫ではない。

**呼値の実測【事実】**: 2019 年の価格は **.0 と .5 しか現れない = 呼値 0.5 ドル**
(2019-09-04 の全 OHLC で確認)。当時 BTC ≈ 8,000〜10,000 ドルなので
**1 ティック ≈ 0.6 bp、通常のスプレッド 1 ティック ≈ 0.6 bp**。
**手数料(数 bp〜15 bp)に比べてスプレッドは桁で小さい。** オーナーの
「流動性が高くスプレッドが小さいからメイカーを狙う」は、数字の上でも筋が通る。

| 線 | 執行の想定 | 往復の手数料 |
|---|---|---|
| **A(楽観)** | 新規も決済もメイカー | **−5 bp**(リベート収入)【仮定】 |
| **B(採用するバー)** | **新規メイカー / 決済テイカー** | **+5 bp**【仮定】 |
| **C(悲観)** | 両方テイカー | **+15 bp**【仮定】 |

つまり**決済は少なくとも一部がテイカーになる設計**。新規は post only なので待てる。
**B は「コードが実際にやっていること」に一番近い。**

> **手数料率の出所と、その弱さ【重要】**
> 上の −5 / +5 / +15 bp は **2019 年に メイカー −0.025% / テイカー +0.075% だった**という
> 前提で計算している。**出所はオーナーの記憶であって、一次資料で確認できていない。**
> **今日の BitMEX API(`/api/v1/instrument`、2026-09-09 取得)は
> `makerFee: 0.0005` / `takerFee: 0.0005` = 両方 0.05% の定額**で、**リベートは無い**

> - **報告では 3 本の線すべてで結果を出す。** B だけを見せない。
> - 陽性が **B は超えるが C は超えない**場合、結論は「**手数料の前提に依存する**」と書き、

**測っていない最大の項目 = 逆選択。** post only の指値が約定するのは、**相場がこちらに

→ **層 ②**(BitMEX `quote` アーカイブ 197.8 GB、オーナー PC に取り込み中)。
**したがって本単位の陽性は「執行前の予測力がある」までしか言えない。**

### 5.2 検出力

**用語の意味を先に固定する**(誤読を防ぐため):

- **`h`(保有)= シグナルの出た足の終値から、**何本後**の足の終値までを見るか。
  単位は**本**であって分ではない。`h=2` は 15 分足なら 30 分、5 分足なら 10 分。
- **`sd` = その `h` 本後リターンの標準偏差**(bp)。**相場のノイズの大きさ**であって、
  戦略の成績ではない。シグナルが無くても存在する、その足の「揺れ幅」。
- **`bp` = 0.01%**。BTC が 10,000 ドルのとき 1 bp = 1 ドル。

**`sd` の出し方(再現できるように書く)**: 探索区間の全足について
`(close[i+h] / close[i] - 1) × 10^4` を並べ、その母標準偏差を取る。

#### 条件付きの sd を使う(**訂正**)

最初は**全足**の sd を使ったが、**それは誤りだった**。使うべきは
**シグナルが出た足に限定した sd** である — 検定するのはその部分集合の平均だから。
そして**長いヒゲが出る足はもともと荒れている**ので、条件付き sd は全足より**大きい**。
全足の sd を使うと **MDE を過小評価し、必要な n を過小評価する**(= 検出力があるつもりで
足りていない、という**楽観方向の誤り**)。

**実測【事実、探索区間 2017-2019、シグナル足に限定】**: 固定保有 h=2 の場合、
条件付き sd は全足 sd の 1.02〜1.51 倍(足が細かいほど差が大きい)。
**必要な n はこの条件付き sd で置く。**

#### 主指標(カツオ自身の決済)で測り直すと、検出力の話が変わる【実測】

保有が伸びる(中央値 8 本)ので、**リターンのばらつきも大きくなる**:

| 足 | 保有中央値 | **リターン sd** | **MDE<5bp に要る n** | 建玉 1 つで回した実 n |
|---|---|---|---|---|
| 5 分 | 8 本 | **144.0 bp** | **5,141** | 9,738 |
| 15 分 | 8 本 | **255.2 bp** | **16,148** | 3,475 |
| 60 分 | 8 本 | **517.3 bp** | **66,354** | 844 |

**「建玉 1 つで順番に回す」と数えると、15 分足も 60 分足も検出力が足りない。**
これは足の粗さの問題ではなく、**決済までが長いので 1 取引が高くつく**という構造の問題。

#### したがって n の数え方も変える(**重複を許し、帰無で処理する**)

**シグナルを 1 つずつ順番に処理する**(建玉を 1 つに制限する)と、
シグナルの大半が「前の建玉の最中」で捨てられる。15 分足なら 38,609 → 3,475 と**9 割減る**。
これは検定力を捨てているだけで、**予測力の測定としては必要ない制約**である
(建玉の重複は執行の話 = 層 ②)。

そこで:

- **すべてのシグナルを測る**(重複する保有区間を許す)
- 重複による観測の相関は、**巡回シフトの帰無が自動的に扱う**(§6)。
  自己相関と日内周期を保存したまま帰無を作るので、重複ぶんの水増しは帰無側にも同じだけ乗る
- **MDE も t 公式ではなく帰無分布から出す**: 帰無分布における `mean(r)` のばらつきが、
  重複も自己相関も込みの**正しいノイズの尺度**である。
  **MDE = 2.49 × (帰無分布の sd)** とし、実行時に組み合わせごとに算出して報告する
- t 公式(`n = (2.49 sd / 5)²`)は**独立を仮定するので使わない**。上の表は
  「どのくらいの規模の話か」の目安としてのみ残す

**実行前の宣言(規約 §4.1)**: 帰無分布から出した **MDE > 5 bp** の組み合わせは
**陰性と呼ばない**。必要な n の見積もりと併記して**不明**として報告する。

**先に見えている制約**: 60 分足は門なしでもシグナルが 12,472 本、`beardline` で 6〜7 割
落ちると 4,000 本前後。主指標の sd(517 bp)に対してこの n では**まず足りない**。
**「60 分足 × 強い門」は測れない見込み**であることを、実行前に宣言しておく。

### 5.3 候補と呼ぶ条件

探索区間で、次を**すべて**満たすもの:

1. `mean(r) > 5 bp`(線 B)
2. `mean(r) > MDE`(§5.2)
3. 族全体の巡回シフト帰無の **95 点を超える**(§6)
4. 探索区間の 3 年(2017 / 2018 / 2019)で**符号が揃う**

## 6. 帰無と多重性

- **帰無**: 同じ足の集合に対し、シグナルの**発生時刻を巡回シフト**して族全体(**324**)を
  同じ置換世界で計算し、**最大 `mean(r)` の分布**を作る(1,000 回)。
  実測の最大がこの分布の 95 点を超えなければ、**族として陽性と呼ばない**。
- 時刻の巡回シフトを使う理由: ランダム並べ替えだと日内周期と自己相関が壊れ、
  帰無が**楽になりすぎる**(偽陽性側に倒れる)。
- **帰無分布から出した MDE > 5 bp の組み合わせは族から除外**する(§5.2)。
  **除外した数と、それぞれの実 n・MDE を報告に書く**。除外は「測らなかった」であって
  「効かなかった」ではない。除外によって族が小さくなれば、帰無の最大統計量も
  その小さい族で取り直す(除外前の族で取ると帰無が不当に厳しくなる)。
- **保有が重複するので、シフトの単位は「シグナル 1 本」ではなく「時系列全体」**にする。
  リターン系列ごと巡回シフトすることで、保有区間の重なりも自己相関も帰無側に保存される。

## 10. この単位が言えないこと(**射程。陰性のときに必ず併記する**)

- **代理の妥当性は本単位では測れない。** 陰性なら「ヒゲでは捉えられない」までしか言えず、
  「清算連鎖のあとに反転が無い」とは言えない。それは K2(層 ①-b)が答える。
- BitMEX に清算履歴が無いため、**同一ベニュー・同一期間で ①-a と ①-b を突き合わせられない**。
- **執行を含んでいない。** 陽性でも「取れる」ことは意味しない。層 ② が必要。
- **建玉の重複を許して測っている。** 実際には資金と建玉上限があるので、
  同時に全部は取れない。**取引可能性ではなく予測力の測定**である。
- **打ち切り上限 96 本は原典に無い制約**。上限に達した取引が 17〜20% あるので、
  その分の真のリターンは測れていない(打ち切り時点の値で代用している)。
- 期間の選び方(2017-2021)は探索面の一部であり、他の期間での再現は測っていない。
- **手数料の前提が一次資料で裏付けられていない**(§5.1)。2019 年のメイカーリベートは
  オーナーの記憶が出所で、今日の API は定額 0.05% を返す。**バーを甘くする方向の仮定**なので、
  結論が線 B と線 C の間に落ちたら「手数料の前提に依存する」と書く。
- **逆選択を測っていない。** post only の約定は不利な瞬間に偏るが、板の履歴が無いと測れない。
  本単位の陽性は「執行前の予測力」までで、「取れる」ことは意味しない。
