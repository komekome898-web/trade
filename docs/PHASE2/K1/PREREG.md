## 4. 測るもの

シグナルが出た足の**終値**を基点に、`h` 本後の終値までの**符号付きリターン**(bp):

```
r = signal × (close[t+h] / close[t] - 1) × 10^4
```

`signal = +1`(買い)は上昇を、`-1`(売り)は下落を予測する。**`r > 0` が予測の成功。**

主指標: **`mean(r)` の片側 t 検定**(帰無 `mean(r) ≤ 0`)。
副指標: 勝率、中央値、`h` 別の減衰、強い/弱いの差。

**総経費は主指標から引かない。** 引くべき経費は執行(層 ②)で測るもので、
ここで仮定の数字を引くと**仮定の誤りが機構の判定に混入する**。代わりに §5 の 3 本の線で比較する。

## 5. 採用基準(**数値バーを先に置く**)

### 5.1 執行の前提 — **単一のハードルではなく 3 本の線を引く**(L-045 で全面改訂)

当初「往復 15 bp(テイカー往復)」の 1 本にしていたが、**それは戦略の設計を無視していた**。
オーナーの指摘:

> post only で指値を出す方式は**まさにそのテイカー手数料を払わないため**。当時の BitMEX は
> **メイカーにマイナス手数料、テイカーに手数料**という形で、なおかつ**流動性が高く
> スプレッド幅が小さい**。従ってできるだけメイカーで注文を出すことを目指していた。

**これは原典の実装と一致する**: 新規の 1 本目も決済の 1〜3 本目も
`ParticipateDoNotInitiate`(post only)である(`KATSUO_PARAMETER_INVENTORY.md` §6)。
**メイカーで取ることが設計の中心**であって、付随的な工夫ではない。

**呼値の実測【事実】**: 2019 年の価格は **.0 と .5 しか現れない = 呼値 0.5 ドル**
(2019-09-04 の全 OHLC で確認)。当時 BTC ≈ 8,000〜10,000 ドルなので
**1 ティック ≈ 0.6 bp、通常のスプレッド 1 ティック ≈ 0.6 bp**。
**手数料(数 bp〜15 bp)に比べてスプレッドは桁で小さい。** オーナーの
「流動性が高くスプレッドが小さいからメイカーを狙う」は、数字の上でも筋が通る。

| 線 | 執行の想定 | 往復の手数料 |
|---|---|---|
| **A(楽観)** | 新規も決済もメイカー | **−5 bp**(リベート収入)【仮定】 |
| **B(採用するバー)** | **新規メイカー / 決済テイカー** | **+5 bp**【仮定】 |
| **C(悲観)** | 両方テイカー | **+15 bp**【仮定】 |

**なぜ B を候補のバーにするか**: 原典の決済は 4 本の階段で、**最後の 1 本は成行 Stop** である。
つまり**決済は少なくとも一部がテイカーになる設計**。新規は post only なので待てる。
**B は「コードが実際にやっていること」に一番近い。**

> **手数料率の出所と、その弱さ【重要】**
> 上の −5 / +5 / +15 bp は **2019 年に メイカー −0.025% / テイカー +0.075% だった**という
> 前提で計算している。**出所はオーナーの記憶であって、一次資料で確認できていない。**
> **今日の BitMEX API(`/api/v1/instrument`、2026-09-09 取得)は
> `makerFee: 0.0005` / `takerFee: 0.0005` = 両方 0.05% の定額**で、**リベートは無い**
> (同時に `tickSize` も 0.1 で、2019 年の 0.5 から変わっている。上場廃止に向けた
> 手仕舞い期でもあるため、今日の値は 2019 年の証拠にならない)。
> **この仮定はバーを甘くする方向に効く**(規約 §5「棄却方向・採用方向どちらの前提にも
> バイアスの向きを明記する」)。したがって:
> - **報告では 3 本の線すべてで結果を出す。** B だけを見せない。
> - 陽性が **B は超えるが C は超えない**場合、結論は「**手数料の前提に依存する**」と書き、
>   一次資料(当時の料金表のアーカイブ)を探すことを次の作業に積む。

**測っていない最大の項目 = 逆選択。** post only の指値が約定するのは、**相場がこちらに
不利に動いた瞬間**であることが多い。その分は手数料と別に効き、**板の履歴が無いと測れない**。
→ **層 ②**(BitMEX `quote` アーカイブ 197.8 GB、オーナー PC に取り込み中)。
**したがって本単位の陽性は「執行前の予測力がある」までしか言えない。**

### 5.2 検出力

**用語の意味を先に固定する**(誤読を防ぐため):

- **`h`(保有)= シグナルの出た足の終値から、**何本後**の足の終値までを見るか。
  単位は**本**であって分ではない。`h=2` は 15 分足なら 30 分、5 分足なら 10 分。
- **`sd` = その `h` 本後リターンの標準偏差**(bp)。**相場のノイズの大きさ**であって、
  戦略の成績ではない。シグナルが無くても存在する、その足の「揺れ幅」。
- **`bp` = 0.01%**。BTC が 10,000 ドルのとき 1 bp = 1 ドル。

**`sd` の出し方(再現できるように書く)**: 探索区間の全足について
`(close[i+h] / close[i] - 1) × 10^4` を並べ、その母標準偏差を取る。

#### 条件付きの sd を使う(**訂正**)

最初は**全足**の sd を使ったが、**それは誤りだった**。使うべきは
**シグナルが出た足に限定した sd** である — 検定するのはその部分集合の平均だから。
そして**長いヒゲが出る足はもともと荒れている**ので、条件付き sd は全足より**大きい**。
全足の sd を使うと **MDE を過小評価し、必要な n を過小評価する**(= 検出力があるつもりで
足りていない、という**楽観方向の誤り**)。

**実測【事実、探索区間 2017-2019、h=2、v03 のシグナル定義】**:

| 足 | 探索区間の足数 | **全足 sd** | **シグナル足 sd** | 比 | シグナル数 | **MDE<5bp に要る n** |
|---|---|---|---|---|---|---|
| 1 分 | 1,523,877 | 19.8 bp | **29.9 bp** | 1.51 | 165,917 | **222** |
| 3 分 | 520,960 | 33.1 bp | **41.2 bp** | 1.24 | 107,945 | **421** |
| 5 分 | 314,169 | 42.1 bp | **49.6 bp** | 1.18 | 80,858 | **612** |
| 15 分 | 105,056 | 70.0 bp | **74.5 bp** | 1.06 | 38,609 | **1,378** |
| 30 分 | 52,544 | 98.0 bp | **101.6 bp** | 1.04 | 22,330 | **2,558** |
| 60 分 | 26,276 | 135.5 bp | **138.0 bp** | 1.02 | 12,472 | **4,726** |

(片側 5%・検出力 80%、`n = (2.49 × sd / 5)²`。h=2 の sd = 2 つのうち厳しい側)

**差は足が細かいほど大きい**(1 分足で 1.51 倍、60 分足で 1.02 倍)。
短い足ほど「ヒゲが出る足」と「普通の足」の性格差が大きいということ。
**必要な n はこの条件付き sd で置く。**

**実行前の宣言(規約 §4.1)**: **シグナル数がこの n を下回る組み合わせは実行しない。**
陰性ではなく**不明**として、必要な n と実 n を併記して報告する。

**先に見えている制約**: 60 分足は門なしでもシグナルが 12,472 本しかない。
**`beardline` で 6〜7 割落ちると 4,000 本前後**になり、必要な 4,726 を割る。
つまり **「60 分足 × 強い門」は原理的に検出力が足りない**。
これは**実行してから気付くのではなく、いま宣言しておく**。
(門を通したあとの実シグナル数は掃引で確定するので、**除外は実 n を見てから機械的に行う** —
「効かなかった」ではなく「測れなかった」として区別する)

### 5.3 候補と呼ぶ条件

探索区間で、次を**すべて**満たすもの:

1. `mean(r) > 5 bp`(線 B)
2. `mean(r) > MDE`(§5.2)
3. 族全体の巡回シフト帰無の **95 点を超える**(§6)
4. 探索区間の 3 年(2017 / 2018 / 2019)で**符号が揃う**

## 6. 帰無と多重性

- **帰無**: 同じ足の集合に対し、シグナルの**発生時刻を巡回シフト**して族全体(**324**)を
  同じ置換世界で計算し、**最大 `mean(r)` の分布**を作る(1,000 回)。
  実測の最大がこの分布の 95 点を超えなければ、**族として陽性と呼ばない**。
- 時刻の巡回シフトを使う理由: ランダム並べ替えだと日内周期と自己相関が壊れ、
  帰無が**楽になりすぎる**(偽陽性側に倒れる)。
- **§5.2 の「要る n」を満たさない組み合わせは族から除外**する(足ごとに違う: 1 分 98 〜 60 分 4,555)。
  **除外した数と、それぞれの実 n を報告に書く**。除外は「測らなかった」であって
  「効かなかった」ではない。除外によって族が小さくなれば、帰無の最大統計量も
  その小さい族で取り直す(除外前の族で取ると帰無が不当に厳しくなる)。

## 7. アブレーション(**要素別の寄与を分けて出す**)

1. 長さの門 なし → 絶対 → ボラ比(**主要な関心**。`beardline` の復元が効くか)
2. 強い / 弱いの差(オーナーの「上ヒゲ陰線・下ヒゲ陽線が最も強い」が数字で出るか)
3. `int()` 丸めの有無(0.9% の差が結果を動かすか)
4. 足の向きによるヒゲの測り分け vs 単純な `High - max(O,C)`
5. **無効化ライン**: 建玉に紐付ける / 原典どおりグローバル(§3-a)、
   新シグナル時にも見る / 見ない(§3-b)。**この 2 つは未確認事項なので必ず両方出す**

## 8. サニティ(全部通してから結果を読む)

- **先読みが無いこと**: シグナルは足の確定後にしか立たない。実現ボラは直前 20 本のみ。
  → シグナル時刻を **1 本後ろにずらすと効果が消える**ことを確認する(消えなければ先読み)。

## 10. この単位が言えないこと(**射程。陰性のときに必ず併記する**)

- **代理の妥当性は本単位では測れない。** 陰性なら「ヒゲでは捉えられない」までしか言えず、
  「清算連鎖のあとに反転が無い」とは言えない。それは K2(層 ①-b)が答える。
- BitMEX に清算履歴が無いため、**同一ベニュー・同一期間で ①-a と ①-b を突き合わせられない**。
- **執行を含んでいない。** 陽性でも「取れる」ことは意味しない。層 ② が必要。
- 期間の選び方(2017-2021)は探索面の一部であり、他の期間での再現は測っていない。
- **手数料の前提が一次資料で裏付けられていない**(§5.1)。2019 年のメイカーリベートは
  オーナーの記憶が出所で、今日の API は定額 0.05% を返す。**バーを甘くする方向の仮定**なので、
  結論が線 B と線 C の間に落ちたら「手数料の前提に依存する」と書く。
- **逆選択を測っていない。** post only の約定は不利な瞬間に偏るが、板の履歴が無いと測れない。
  本単位の陽性は「執行前の予測力」までで、「取れる」ことは意味しない。
