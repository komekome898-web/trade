## 1.2 足を作る

秒バーを UTC の壁時計で `foot` 分ごとに畳む。始値 = 窓内最初の秒の `o`、高値 = 最大の `h`、
安値 = 最小の `l`、終値 = 最後の秒の `c`。

**約定が 1 秒も無い足は行を作らない**(値動きなしではなく欠測として扱う)。

## 1.3 1 本の足からシグナルを決める(全足について)

```python
candle = c - o
csign  = +1 (陽線) / -1 (陰線) / 0 (同値 → シグナル無しで確定)

陽線なら  top = h - c,  under = o - l
陰線なら  top = h - o,  under = c - l

# 条件 3: 向きを決める。int() で切り捨ててから比較(原典どおり)
int(top) > int(under)   → 売り候補 (sig=-1, w=top,   lcprice=h)
int(under) > int(top)   → 買い候補 (sig=+1, w=under, lcprice=l)
同値                     → シグナル無し

wbp = w / c * 10000                      # ヒゲ長を終値に対する bp に直す

# 条件 1・2 = 小門の枝、条件 = 大門の枝。**どちらか成立でシグナル**
小門の枝 = (s != "off") かつ (s is None または wbp >= s) かつ (w > |candle|)
大門の枝 = (b is not None) かつ (wbp >= b)
シグナルあり ⇔ 小門の枝 または 大門の枝

強さ = "強い" if sig == csign else "弱い"
      強い = 下ヒゲ陽線(買い)/ 上ヒゲ陰線(売り)
      弱い = 上ヒゲ陽線(売り)/ 下ヒゲ陰線(買い)
```

**掃引した水準**:

| 軸 | 水準 | 数 |
|---|---|---|
| 足 `foot` | 1 / 3 / 5 / 15 / 30 / 60 分 | 6 |
| 小門 `s` | `off`(枝を使わない)/ `-`(最小長なし)/ 10 / 19 / 30 **bp** | 5 |
| 大門 `b` | `-`(枝を使わない)/ 24 / 40 **bp** | 3 |
| 強さ | 強い / 弱い / 両方 | 3 |

`s=off, b=-` は条件が空なので除外。`s > b` は `(off, b)` と同じ規則になるので除外。
→ **門は 13 通り、族は 6 × 13 × 3 = 234 セル。**

## 1.4 建玉を 1 単位持って回す(足を 1 本ずつ、先頭から)

```
その足のシグナルが「行動対象」か(強さの絞りを通ったか)を判定

行動対象でない場合:
    建玉があり、かつ **足の色が建玉と反対** なら:
        買い建玉で 終値 <= lcline  → 決済(理由: invalidated)
        売り建玉で 終値 >= lcline  → 決済(理由: invalidated)
    ※ 足の色が建玉と同じ向きなら、何も見ない(原典どおり)

行動対象の場合:
    建玉が同じ向き    → 何もしない。lcline だけ更新(増し玉はしない)
    建玉が反対向き    → 決済
                        強いシグナルなら、その足の終値で **逆に建て直す**(ドテン、理由: reversed)
                        弱いシグナルなら、**建て直さない**(理由: opposite_weak)
    建玉が無い        → その足の終値で新規(強弱を問わず)
```

**建値も決済値も「その足の終値」。** 板も気配も使っていない。

**1 取引のリターン**: `r = sig × (決済の終値 / 建玉の終値 − 1) × 10⁴` [bp]。
**経費は引いていない。**

### (a) 「ヒゲの向きに予測力があるか」に、この測定は答えていない

さらに、同じ足・同じ門・同じ決済ルールで**向きだけコイン投げ**にすると:

| 3 | 4,898 | −0.73 bp |

**本物のシグナル(−1.67 bp)はこの範囲の中にある。**

**理由は決済の構造にある**(2019・5 分足・`s19/b24`・両方、n = 3,944):

| 決済理由 | 件数 | 平均 | 寄与 |
|---|---|---|---|
| 反対の弱いシグナルで決済 | 41.6% | **+46.13 bp** | +19.19 |

| **合計** | | | **−1.67** |

**±20 bp が打ち消し合った残りを見ている。** `mean(r)` は
「向きの情報」と「決済ルールの構造的な差し引き」を混ぜた量である。

### (b) 「強い / 弱い」の差 — **訂正を 2 回した。現在の事実**

| 足 | 強いの勝率 | 弱いの勝率 |
|---|---|---|

**勝ち負けの大きさはほぼ同じで、負ける頻度だけが違う。**

### この差の原因は **【測っていない】**

思いつく候補はあるが、**どれも検証していないので書かない**。
**確かなのは「勝率が違う」という測定結果までである。**

**したがって、オーナーの記憶(上ヒゲ陰線・下ヒゲ陽線が最も強い反発)について
言えることは次のとおり**:

- **【測った】** 「強い」と分類したシグナルの方が、この決済ルールの下では成績が悪い
- **【測っていない】** それがシグナルの質によるのか、決済ルールとの相性によるのか
- **【言えない】** 記憶が誤っていた、とはまだ言えない
