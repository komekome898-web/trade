# P2-07 設計監査(第1稿・盲検第1者) 2026-09-06

対象: `docs/PHASE2/P2-07/PREREG.md` 第1稿。実測は `load_unsealed(events.csv/px/*.csv, "P2-07")` で
開発セット(256件、封印74件、2018-06-12以降は未読)を集計。

## (1) 日付規約の裏取り
`get_calendar_points()` の規約(effective_date前営業日引け=リバランス)を出来高で検証。
開発セット usable 104件で T−1 出来高 / 直前20営業日中央値の**中央値 = 7.85倍**(add 7.60倍・n=83、
delete 9.75倍・n=21)。明確な出来高急増があり、規約は**データで裏付けられる**。可。

## (2) n・σ・MDE の再計算 — 致命
PREREG は分母を「add約60/delete約45」と見込むが、実測は **add 83 / delete 21**(delete のみ執行可能)。
delete は想定の半分以下。さらに delete 側の超過リターンに1件、**未検出の**外れ値(9201・2002-09-25、
r=−88%)があり、`QUALITY_px.json` の `split_candidate`(4ファイルのみ、9201は含まれず)にも
`known_defects` にも載っていない。この1件の扱いで結果が激変する:
- 含める: n=21(14日)、σ=1930bps、95%CI(クラスタ・ブートストラップ2000回)=(−1450, +87)bps、
  MDE(n=21)≈1180bps、MDE(日クラスタ=14)≈1445bps。
- 除外: n=20(13日)、σ=143bps、CI=(−41, +106)bps、MDE(n=20)≈90bps、MDE(日=13)≈111bps。
13倍のブレ。**主指標の符号すら不定**であり、この1件を放置したまま凍結すると結果は実質的に
「その1件を残すか消すか」で決まる。判定不能の意味は「効果があってもσに埋もれて見えない」だが、
今回は判定不能以前に**指標自体が未定義**。日クラスタ数(13〜14)もブートストラップの前提(数十
クラスタ推奨)に対して少なく、CI自体の信頼性も低い。致命。着手前に (a) 9201 の当該行を実資料で
検証し除外基準に組み込む、(b) 分母をadd83/delete21(または除外後20)で登録し直す。

## (3) 生存バイアス(delete側)— 致命
delete の usable 率は 21/128 = 16%(add は 83/128 = 65%)。除外理由は「価格ファイル無し」が主
(上場廃止・統合)。除外は退出銘柄のうちまさに深刻な業績悪化・買収で消えた銘柄に偏り、残る20〜21件は
「消えずに済んだ」相対的にましな除外組である可能性が高い。PREREGの「記述するが補完しない」は方針として
妥当だが、現状は記述のみで**結論の適用範囲(生存した delete 銘柄に限る、との明記)がない**。この限定を
本文に明記しない限り、封印での「利用できる/できない」の判定はどちらに転んでも母集団全体への一般化が
できない。要修正(限定文言の追加)ではなく、母集団の性質上補正不能なので**致命**(結論のスコープ記載必須)。

## (4) 探索面と対照
N0=2(add/delete)は数えられており妥当。反復1の出来高三分位条件付け(N=8)も梯子として妥当。
対照(i)無作為窓・(ii)暦シフト・(iii)符号シャッフルはイベント研究の反事実として概ね妥当だが、
同日に最大16件のイベントが同時発生する(distinct date 59、複数件日16)ため、(i)(iii)を**個別
イベント単位**で無作為化すると同日クラスタの相関を壊し、帰無分布を過小評価する。日付クラスタを
保った無作為化(日付ごと束ねて置換)への修正が必要。要修正。

## (5) コスト定数
`constants.yaml` に個別株(非ETF)の呼値表は未登録(ETF用 `etf_tick_size_yen_by_price_band` と
先物用のみ)——PREREGの記載通り。凍結前に一次資料(JPX呼値の単位)から個別株の呼値バンド表を
`measured`/`primary_document` として登録必須。さらに PREREG 本文は「TOPIX100 構成銘柄と他で異なる」
と書くが、`constants.yaml` に登録済みの JPX 表の区分は **TOPIX500** であり TOPIX100 ではない(用語誤り)。
加えて TOPIX500 構成は時点により変動するため、各イベント時点でどちらの列を使うかは
events.csv/px データだけからは**決定不能**(別途 TOPIX500 採用銘柄の履歴が必要)。致命(登録+用語訂正+
別データ入手のいずれかが凍結条件)。
