## リターンの定義(実行に一致)
- 採用銘柄(add): r_add = open(T) / close(T−1) − 1 の**符号反転**(引けで売り、翌寄りで買い戻す = 空売り。信用口座が要る)。
- 除外銘柄(delete): r_del = open(T) / close(T−1) − 1(引けで買い、翌寄りで売る = 現物で可能)。
- 市場調整: 同じ窓の日経平均リターンを引いた超過リターン(主指標は超過リターン、生も併記)。
- **執行可能な脚は delete 側(現物ロング)のみ**(オーナーの口座は現物)。add 側は「存在」の確認と、信用口座取得後の候補として評価。

## コスト定数(`config/constants.yaml`、`assumed` は使用不可)
- 現物: SOR 手数料 0 円(2026-05-18〜、primary_document)。呼値は銘柄の価格帯表(`etf_tick_size_yen_by_price_band` は ETF 用。
  **個別株の呼値表は未登録 → 一次資料(JPX 呼値の単位、TOPIX100 構成銘柄と他で異なる)で登録してから凍結**)。
- 保守 = 手数料 0 + 呼値 1 ティック/片側(銘柄ごとの当時の価格帯)、楽観 = 0。判定は保守。
- 空売り(add 側)の貸株料・逆日歩は定数が無いため、add 側は楽観のみ・存在の確認に限る(取引可能性は判定しない)。

## 指標と分母
- 主指標: (1) delete 側の保守コスト後の平均超過リターン(bps/件)と 95% CI(イベントは日付で束なるため、**イベント日で束ねたクラスタ・ブートストラップ** 2,000 回)、
  (2) add 側の平均超過リターン(符号反転後)と CI(楽観)。
- 分母: 開発セット 104 件(add 約 60 / delete 約 45、実装時に確定)。
- MDE(α 0.05、検出力 0.8、σ は実装時に実測。イベント日の超過リターンの σ ≈ 300bps の見込み): n=45 で ≈ 125bps、n=60 で ≈ 110bps。
  **検出力不足を最初から記す**: 数十 bps の効果は本データでは見えない。判定不能が最も起こりやすい結果。
- 副指標: 勝率、最大 DD(1 単元)、年代別、add/delete 別、イベントの規模(同日の件数)別、T−1 の引けの出来高倍率(通常日比)。
- 着手前の関門: 保守コスト後の平均が MDE 未満なら「検出できても取引価値なし」。

## 対照(反事実)
1. 同銘柄の非イベント日から無作為に同数の (T−1, T) 窓を選ぶ(1,000 回)。
2. 暦シフト・プラセボ: 同銘柄の T−6/T−5、T+5/T+6 の窓。
3. 符号シャッフル(1,000 回)。
4. 診断: 効果の時間推移(エッジ推移 §5: 単位 = 年、窓 = 20 件、区切り = 年代)、条件分析 §6: 出来高倍率三分位・同日件数。

## 探索面
自由パラメータなし(窓 = (T−1, T) の 1 通り、脚 = add / delete の 2)。N0 = 2。窓の変更・脚の追加は反復として N に加算。
反復の梯子(事前登録): 反復 1 = 出来高倍率三分位で条件付け(2 × 3 = 6、N = 8)。
**反復(データ追加、N 不変)**: 他指数(MSCI・FTSE・TOPIX 定期入替)のイベントを一次資料から取得して母集団を広げる。取得できた時点で
別単位(P2-07b)として封印・事前登録する(本単位の封印と混ぜない)。

## 停止規則
直近 3 反復の val 主指標の改善 < MDE、または反復 8 回。

## 最終評価(封印データ、1 回のみ)
- 封印期間 2018-06-12 .. 2026-09(使える 61 件)。
- バー(delete 側): 累計 N の帰無 95 点超、かつ保守コスト後の平均超過リターンの 95% CI が正。
- 反証文: 封印期間で「delete 側の保守コスト後の CI がゼロを含む」なら「利用できる」は棄却。add 側の楽観 CI もゼロを含むなら「存在」も棄却。
- 判定不能区分: 封印 61 件の MDE(≈ 110bps)未満の効果は「判定不能(標本不足)」と書き、棄却と区別する(資源登録簿へ)。
- 保留区分: add 側のみ CI 正 → 「存在するが現物では取れない」、引き金 = 信用口座 + 貸株料の定数登録。
