## 1. 手作り系列(50 分)

格子: 足 i の開始時刻 = 2023-06-01 04:40 UTC + i 分(i = 0..49)。UTC 05:00 の決済時刻は i = 20。
パラメータ: k = 1、thr = 1.0%、exit = 0.2%、stop = 1.0%、片道費用 1.3 bps(往復 2.6)、資金調達 0.02%/決済、
5 分超欠損 = 連続する有効足の間隔 > 5 分、サイズ 0.01 BTC。

Binance 終値 c(i)(k = 1 なので m(i) = c(i)/c(i−1) − 1)と bitFlyer 四本値はテストファイル冒頭の表のとおり。
bitFlyer の既定足は o 1,000,000 / h 1,001,000 / l 999,000 / c 1,000,000(建値 1,000,000 から ±1% のストップに触れない)。
空の分: i = 12、30〜35(6 分)、40〜45(6 分)、48。

## 3. 付随テスト

- 時刻の飛び版(空行を削除)で同じ台帳になること、5 分超の境界(間隔 5 分は欠損でない、6 分は欠損)、捨てる窓の境界(t_a − 4 は捨てる、t_a − 5 は採用、t_a の信号は繰り延べずに捨てる。`apply_masks=False` なら繰り延べ)。
- 誤プリント(+30% 超かつ翌有効分で 5% 以内に復帰)の空白化と、復帰しない急変は残すこと。
- ストップと exit が同一足で重なったときは `stop` と記録。データ末尾で保有中は最終有効足の終値で `end`。
- 決済またぎの数え方 entry_ts < s ≤ exit_ts。`regime` の境界 2024-03-28 00:00 UTC。
- `momentum_signal` が index 位置でなく時刻で k 分前を引くこと(欠けた分は NaN)。
- `block_permute_log_returns` が総対数リターン・最初の水準を保存し、日内の順序を保ったまま日ブロックを置換すること、NaN の位置を保存し seed で再現すること。
