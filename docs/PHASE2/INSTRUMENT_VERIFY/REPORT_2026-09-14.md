### 1.1 **4 本の地平線は独立な 4 件ではない**

`build_synthetic` の乱数列は `horizon_min` に一切依存しない。`horizon_min` が動かすのは
価格 3 点目の**時刻** `future_ms` だけで、`p_start` / `p_end` / `p_future` の**値は 4 本とも同一**。
実測(`evidence_2026-09-14/03`): h=1 / 15 / 60 のいずれも先頭スロットの仕込み反転は **+18.6000bp で一致**。
**4 本は「同じデータを 4 通りの時刻ラベルで読んだ」ものであって、4 件の独立な確認ではない。**

### 1.2 前回報告した 60 分の不合格は、**測定器ではなくリードのバグ**だった

`build_synthetic(..., horizon_min=HORIZON_MIN)` の既定引数は**定義時に束縛**されるので、
`--horizon` が `global HORIZON_MIN` を書き換えてもデータ生成に届かず、データは常に 15 分で
作られていた。条件だけが `bp_60m` を探し、45 分の陳腐化で
`future_max_staleness_ms=300_000`(`liq_response.py` 315 行)に全行弾かれて全 NaN になっていた。
実測: `evidence_2026-09-14/01`。地平線を明示的に引き回して直した。

### 1.3 継続側を初めて回して出た欠陥(**条件 4 がゴム印になっていた**)

条件 4(符号)は `if r_bp > 0: (score>0 を数える) else: n_match += 1` と書かれており、
**`else` が r_bp<0(継続側)も飲み込んでいた**。継続側では符号一致率が構造的に 1.0000 になり、
**変異 b(符号反転)が検出できなくなっていた**。表示の「[r_bp=0 のため参考値]」は
`r_bp == 0` のときしか付かないので、**継続側では普通の `[OK] 符号一致率=1.0000` に見えていた**。
壊れても止まらず、もっともらしい数値を返す — 09-13 に焼かれた型そのもの。直した。
オーナーの原文「**トレンド転換が起きるか、またはそれがトレンドになるのか**」
(`OWNER_INTENT_2026-09-12.md` §1.1)が**両方**を観測対象にしているので、継続側は射程外にできない。

### 1.4 タイの場面 — **前回の「合格」は 2 つの誤差の打ち消し合いだった**

前回の報告は `keep` 方針の平均だけを見て「反転側は効果が残る(19.866)」と書いた。
**これは割り算で崩れる。**生ログ `raw_horizon_15min.log` から:

- `drop`(タイを落とす): 非タイ **262 行**の平均 = **22.747**(仕込み 20.0 に対し **+2.747bp の過大**)
- `keep`(タイを 0 として数える): 262 × 22.747 ÷ 300 = **19.866** ← keep の値と一致

つまり 19.866 は「測定器がタイに耐えた」のではなく、「**+2.747bp の偏りと 38/300 の 0 埋めが
打ち消し合った**」値である。継続側は非タイ分の偏りが **+2.744bp** と**ほぼ同じ量**で、
262 × (−17.256) ÷ 300 = **−15.070** — こちらは打ち消さずに重なった。
**同じ一つの現象が、片方では True、片方では False として報告されていた。**

**なぜ 40bp でこうなるか**: タイ行の反応そのものが量子化の産物になっている。
**反応 bp は 1 行ずつ数えた。score は合計からの逆算である**(`evidence_2026-09-14/07`。
bp が ±40 の 2 値で合計が −1520 なので、38 行とも −40 に**確定する**):

| 向き | タイ行の**反応 bp** の内訳(38 行) | `refine` 後の**score**(38 行) |
|---|---|---|
| 反転 | **0.0 が 38 行**(0 以外は 0 行) | 1 行あたり **0.0** |
| 継続 | **+40.0 が 19 行 / −40.0 が 19 行**(符号は割れている) | 1 行あたり **−40.0** |

**`bp` と `score` は別の量である**(`score = −sign(internal_bp) × bp`。`keep` は
`sign=0` なので score が 0、`refine` は `first_price`/`last_price` から向きを決め直す)。
継続側は **bp の符号が割れていて、score は −40.0 にそろう**。
反転側は bp が全行 0.0 なので、`refine` が「38 件解決」と数えても score は 0 のままで、
平均は `keep` と同一(19.866)になる — **`n_tie_resolved=38` は何も変えていない。**
(初版はここを平均からの逆算で「継続側は全部 ±40.0」とだけ書いていた。監査 5 回目が
「逆算しか根拠が無い」と指摘したので、行ごとの出力を `evidence_` に置いた。)

**なぜ非タイ 262 行が +2.747bp ずれるのか(実測、`evidence_2026-09-14/09`)**:
40bp の格子では score は **0 付近か 40 付近の 2 値しか取れない**。実測の内訳は
`{0.0: 113 件(43.13%), 39.7〜40.3: 149 件(56.87%)}` で、40 付近の平均は 39.999。
`0.5687 × 39.999 = 22.748` が測定平均と一致する。
**仕込み 20bp は格子 40bp のちょうど半分**なので、40 側に丸まる割合が 50%(= 平均 20.000)を
超えた分だけ平均が上振れる。実測の割合は 56.87% で、その差 **+6.87% が偏りを作っている**。
**偏りは格子の丸めそのものであって、測定器の欠陥ではない。**
**継続側も測った**(同 log の (3)): 割合は **43.13%**(反転側の 56.87% の**鏡像**)で、
`0.4313 × −40.011 = −17.256` が測定平均と一致する。同じ乱数列に同じ格子を当てているので、
反転側で 40 側に丸まった行が継続側では 0 側に丸まる。その結果、**符号付きで見ると偏りは
両方向とも +2.7bp**(反転 20→22.747 / 継続 −20→−17.256)になる。
(このログの初版に「割合も 56.87% で一致」と書いたのは誤りで、上の実測と食い違っていた。訂正済み。)

**向きが重要である(監査 7 回目の指摘)。**符号付き bp では両方向とも +2.7bp だが、
**効果の大きさに対しては逆向き**である:
- 反転側は仕込み 20 に対し **22.747** — **効果を 13.7% 大きく**報告する。
- 継続側は仕込み −20 に対し **−17.256** — **効果を 13.7% 小さく**報告する。

**継続側で効果が小さく出るのは、実データで陰性を作る向きである**(A-18「構造的に安全側に振れる」/
L-019「時間と機会の損失は正直かなり痛い」)。**粗い分解能の区間では、継続(トレンド化)の効果が
実際より小さく見える。**§1.5 と合わせて、**粗い区間は陰性の材料に使えない。**

**合否を 3 方針すべてに課すことにした(締めた。緩めていない)。**
`keep` だけで判定するのは、同じ測定の 3 つの方針のうち 1 つだけを説明なしに使う形だった。

| 刻み(bp) | 向き | keep | refine | drop | n_tie | drop の n_used |
|---|---|---|---|---|---|---|
| 400 | 反転 / 継続 | 0.000 / 0.000 | 0.000 / 0.000 | nan / nan | 300 / 300 | 0 / 0 |
| 200 | 反転 / 継続 | 0.000 / 0.000 | 0.000 / 0.000 | nan / nan | 300 / 300 | 0 / 0 |
| 100 | 反転 / 継続 | 24.002 / 0.000 | 24.002 / −39.667 | 100.010 / 0.000 | 228 / 228 | 72 / 72 |
| **40** | 反転 | **19.866** | **19.866** | **22.747** | 38 | 262 |
| **40** | 継続 | **−15.071** | **−20.137** | **−17.256** | 38 | 262 |
| 10 | 反転 / 継続 | 20.499 / −19.369 | 同左 | 同左 | 0 / 0 | 300 / 300 |
| 1 | 反転 / 継続 | 20.393 / −19.610 | 同左 | 同左 | 0 / 0 | 300 / 300 |

(全文: `evidence_2026-09-14/06`。n_tie は両方向で一致するので上表では並べて書いた。)

**反転側が 3 方針とも通っているのは余裕があるからではない。**`drop` の |差| は **2.747bp** で、
許容 3.0bp との差は **0.25bp** しかない。しかもこの許容は「R=20 なら通り R/2=10 なら落ちる」
分離を狙って選んだ値(スクリプト 67〜71 行)で、**タイの偏りを測るために選んだ値ではない。**

**刻みは動かさない。**動かせば「検査を通すための調整」(A-9 / O-10)になる。

### 1.5 粗い分解能のとき、測定器は `nan` ではなく **`0.000`** を返す

400bp / 200bp では両方向とも `keep`・`refine` が **0.000**。
100bp の継続側は **`keep` と `drop` が 0.000**(`refine` は −39.667)。
前版はここを「100bp の継続側も 0.000」とだけ書いており、直前が `keep`・`refine` の話なので
**その 2 方針が 0.000 だと読める書き方だった。**§1.4 の表の −39.667 と食い違っていた。
**仕込みは −20bp あるのに、効果が無いときと区別のつかない数字が、警告も除外もなく返る。**
これは §5.2 の言葉でいうと**陰性ではなく不明**である。
**過大に出る経路もある(監査 7 回目の指摘)。**同じ表の `100bp / 反転 / drop` は **100.010** で、
仕込み 20bp の **5 倍**である。`drop` は 100bp で実群 72 行しか残さず、その 72 行が
「格子 1 個分 = 100bp」に丸まったものだけになるため。**粗い分解能は、過小にも過大にも振れる。**
前版はこの節を「0.000 が返る」= 過小側だけで書いており、**同じ表にある 5 倍のずれを落としていた。**この性質を書かずに実データへ進むと、
**粗い区間の「効果なし」がそのまま陰性として積み上がる**(A-18)。

## 2. 射程 — **この検証で塞がっていない穴**

オーナー逐語: 「**測定器を直すは対処療法で、またどうせ新たな不具合を生むだけです**」(09-13)。

1. **合成の価格系列は 1 カスケードにつき 3 点だけ**(`build_synthetic` 149〜151 行)。実データは密。
2. **変異 e(地平線の読み違い)が h=1 / 5 / 60 で「検出できた」のは、間違った時刻に価格点が
   存在せず陳腐化で弾かれて nan になったから**である(`n_used=0 / exclusion_rate=1.0000`)。
   密な実データでは間違った時刻にも価格点があるので、**この形では現れない**。
   「地平線を正しく読んだ」と言えるのは **±5 分の粗さまで**で、「手前を読んで 0.0 になる」経路を
   実際に通ったのは **h=15 の 1 本だけ**である。
3. **欠測は「素の走行では一度も起きていない」**(4 本とも `n_excluded_missing=0`)。
   変異 e では起きている(上の 2)。**測っていないのは「群間で非対称な欠測」**である。
   09-13 の「片方の群だけ約 8 割を黙って除外」はタイ側でしか測っていない。
   (前版はここを「欠測の経路は一度も通っていない」と書いており、2 と矛盾していた。)
4. **読み出し層**(`load_binance_cm_liquidations` / `load_gate_liquidations`)と清算 `side` の向きは、
   合成が `LiquidationEvent` を直接作るので**この検証を一度も通っていない**。`side` は
   `docs/DATA/surveys/O3C_VERIFY_LIQUIDATION_SIDE_2026-09-13.md` で別途決着している
   (Gate は符号が逆で修正済み)。**その決着に乗っているだけで、ここでは測っていない。**
5. **対照窓の作り方が一度も検証を通っていない。**合成は対照 `Cascade` を**自分で 300 個作って**
   渡している(`build_synthetic` 142〜147 行)。実データで「清算が無い窓」をどう選ぶかは未検証。
   09-13 の欠陥表に「対照の二重計上」がある。
6. **カスケードの束ね方(`build_cascades`、`gap_ms=60_000`)が一度も試されていない。**
   合成は `SLOT_MS = 2 時間` と 111 行の `assert` で**カスケードが絶対に重ならないことを保証**
   している。実データの清算は連続するので、併合・分割の判断はここでは一度も起きていない。
7. **効果の大きさが ±20bp の 1 点でしか較正されていない。**`TOLERANCE_BP = 3.0` は
   「R=20 なら通り R/2=10 なら落ちる」分離を狙った値である。実データで期待される数 bp の効果では
   **条件 1 は自動的に通る。**(L-046「MDE を出すために用意した値なら本末転倒」と同じ向き。)
8. **`tie_policy=refine` は群間で非対称な処理である。**`liq_response.py` 565 行の逐語:
   「**対照窓は `first_price`/`last_price` を持たない**ので、この方針は実群だけを細かくする」。
   **実群だけを細かくする方針が存在すること自体が射程である。**
9. **`tie_policy=drop` は対照群を全滅させる。**実測: `drop` の対照は `n_used=0 / excl=1.0 / mean=nan`。
   実群は 12.67% しか落ちない。**これも群間非対称。**strict=True はこれを止める(変異 d で確認済み)。
10. 効果は**時間に依らない 1 段の階段**として仕込んでいる。**減衰する効果・途中で向きが変わる効果は
    一度も測っていない。**
11. **タイの合否は継続側で不合格のまま**(§1.4)。反転側の通過は許容との差 0.25bp。
12. **タイを作った経路が、09-13 に実際に起きた経路と違う。**この検証のタイは
    `quantize_prices` で**価格を 40bp の格子に丸めて**作っている。ところが
    `liq_response.py` 365〜367 行が記録している実在の欠陥は「**カスケードは数秒〜数十秒で
    終わるため 1 分バーでは起点と終点が同じ終値になり**、タイは実カスケードで 8 割」で、
    原因は**時間分解能**である。スクリプト 390 行にリード自身が
    「実データでこれが起きたのは『1 分バーの終値』を両方に使っていたとき」と書いている。
    **価格の刻みで作ったタイは通した。時間分解能で起きるタイは通していない。**
13. **合否条件が実群の平均だけで、実群 − 対照群の差を一度も条件にしていない。**
    条件 1・2・4 はすべて `report.groups["real"]` だけを見る。対照群が使われるのは
    条件 3 の行数と、除外率の非対称だけである。実データでの問いは
    「清算のあった窓と無かった窓で違うか」なので、**群差を取り出せるかは一度も測っていない。**
    (射程 5 は「窓の選び方」の話で、これは「指標そのものに群差が入っていない」という別の穴。)

14. **乱数の種が 1 つしかない。**報告の数字は全部 `SEED = 20260913`(スクリプト 48 行
    「日付をそのまま使っただけ(意味は無い)」)の 1 回の引きから出ている(零効果だけ `SEED+1`)。
    **種を 7 本引いて実測した**(`evidence_2026-09-14/09`): 反転側 `drop` の |差| は
    **1.134 〜 2.747** の範囲で、**7 本すべて許容 3.0 の内側**。
    **報告に使った種 20260913 は 7 本中もっとも悪い**(2.747)。つまり 0.25bp の余裕は
    最悪ケースの値で、種を変えると余裕は広がる方向である。**ただし 7 本しか引いていない。
    落ちる種が無いとは言えない。**合否は依然として種 1 本の引きに乗っている。

## 3. 実データで何をどう測るか(設計)

**判定区間はまだ開けない。**段 0 と段 1 は封印の外で行う。

- **「事前に煮詰めておきたいこと 3 件」(オーナーが「事前に煮詰めておきたい」と挙げた 3 件。`OWNER_INTENT_2026-09-12.md` §1、L-139)**
  オーナー逐語: 「**価格毎の約定履歴の積み上げからどの価格帯で清算が起きるかの予測できるか、
  できるならエントリーや利確に活かせるか(これにより分析の軸や評価方法が変わる)**」/
  「**必要データ収集の手段と管理の徹底方法**」/「**進行する上で足りないこと、足りないと
  予想されることは何か**」。
  **1 件目は「分析の軸や評価方法が変わる」とオーナー自身が書いているので、開ける前に置く。**
  軸が変わりうるものを埋めずに開けると、開けたあとで軸が変わる。3 件とも未着手。
- **段 0b(射程 1〜14 を埋める。封印の外)**
  1. 実データの**価格系列の分解能**を測る。§1.4 の表のとおり、粗ければ効果が食われ、
     §1.5 のとおり **0.000 が返る**。刻みが 10bp より粗い区間は射程外として明示する。
  2. **欠測と除外の群間非対称**を測り、**実群 − 対照群の差**を指標に入れる(射程 3・8・9・13)。`n_excluded_missing` と
     `n_excluded_tie` を群別に出し、`ReversalExclusionImbalance` が実データで立つかを見る。
     **立つなら開けない。**
  3. **読み出し層を通した合成**(射程 4)。合成イベントを実データと同じ CSV 形式で書き出し、
     `load_*` 経由で読ませて同じ検証を回す。
  4. **対照窓の選び方**(射程 5)と**カスケードの束ね方**(射程 6)を、実データの分布で決めて
     合成でも同じ選び方を通す。
  5. **小さい R(数 bp)で 1 本回す**(射程 7)。費用はほぼ 0。
  6. **種を複数本引く**(射程 14)。合否を種 1 本に乗せない。
  7. **時間分解能でタイを作る**(射程 12)。価格の刻みではなく、
