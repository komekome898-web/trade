## 2. 機構の発見(この棄却の価値)

### 2.1 N=1 の腕は「設計恒等式」として死んでいる(機構水準)

凍結写像は β=δ=2(原典 entry_setting=exit_setting=2 の保存)。よって**エントリ閾値と
TP 目標は同一価格**(v52 の `lsp==lep` / `ssp==sep` — 原典コードでも同じ)。N=1 の往復は
原理的に建値ガードを超えて稼げず、実測でも TP 決済の55〜61%が建値ガード価格ちょうど
(+0.0008bps = 1ティック)。**2020年の±100円ガード(≈1bp)が原典の実質的な利益単位で
あり、それが今日1ティック(0.0008bp)に腐食したことで、この設計の利益源は消滅している** —
壁capture(第27報で棄却)と並ぶ、マチルダのスケール腐敗の最深部。

### 2.2 損失は「強制決済」ではなく「緩和」に集中する(v52 の設計直観の反転)

出口内訳: TP 73〜91%(+0.04〜+0.25bps)、**T1緩和 9〜26%(−7.3〜−15.1bps、P&L の
ほぼ全量)**、T2強制 0〜0.3%。機構: T1 で建値ガードを外して中心側に置き直した瞬間、
その価格は既に市場に突き抜けられている(逆行したからこそ TP に届かなかった)ため、
**緩和指値は実質 taker 執行**になる。(T1,T2) 軸は T1 のみの軸に退化 —
「時間で緩める」は「時間で taker を払う」の別名だった。

### 2.3 在庫平均化は1単位を救うが集計を悪化させる

平均化の寄与は実測 **+2.4〜+3.5bps/unit**(段1単独 −5.12 → 平均化後 −2.71)— 実在する。
しかしゼロに届かず(残 −2.3〜−3.4)、代償に notional が1.7倍になるため
**集計損失はむしろ拡大**(N=4 −7,141 vs N=1 −3,922 bps/日)。深い段ほど約定単価は
良いが逆選択はわずかに悪化(−0.70→−0.82)。損益均衡には負けバケットを **11.5〜64倍**
縮める必要があり、それはパラメータではなく「TPを届かなくした逆行の60〜120秒継続」
そのもの(第26報の5秒逆選択の時間積分)。

### 2.4 スプレッドMM対称族への設計制約(銀行入り)

(a) **片側の在庫平均化では閉じない** — 対称族は「反対側の capture をもう1本稼ぐ」
両側同時性で稼ぐしかない(u §6.7 の天井の機構と一致)。
(b) **時間による出口緩和は taker の別名** — 対称族の在庫解消は「反対側クオートの約定」
であるべきで、時間トリガの片側譲歩ではない。

## 3. 棄却水準(§10)

- **機構水準**: N=1 の腕と登録形(β=δ恒等式・建値ガードの腐食・T1緩和=taker)。
- **点水準**: β/γ/δ(2に凍結)・寿命10s・取消C1・両側同時在庫・ドテンは未掃引 —
  この方向の生死は主張しない。ただし β≠δ に開いても、それは「エントリより近い TP」=
  高速サイクル族(S8、恒久閉鎖)か「遠い TP」= レンジ幅依存(レンジ逆張り、棄却)の
  いずれかに接続することを注記する。
