## 5. bitFlyer の口と意味が違う所【事実】

- **時刻**: 違いはありません。open_time = 足の始まりで、BarEvent の受け取りは始まり + 60 秒です(試験で確かめました)。
- **取引の無い分**:
  - bitFlyer は値段の列を空にした行を no_trade の宣言で落とします。
  - Binance は前の終値で埋めた行を書いています。そこで `n_trades = "0"` の行を synthetic と宣言して落とし、落とした後は同じ意味(足が無い)にしました。
  - 前例は `scripts/k1_newenv_g_fold.py` の宣言です。
- **ずれた行(Binance だけ)**:
  - 2017-12-04T06:00:20Z〜2017-12-18T10:00:20Z の 20,401 行(20 秒ずれ)と、2018-02-09T09:59:14Z〜2018-02-10T05:59:14Z の 1,201 行(14 秒ずれ)です。
  - 入れると前後の足と時間が重なり、`run_card` が拒みます。なので落としました。
  - 落とした結果、日本時間の 2018-02-09 は足が 0 本になり、その日の量がありません。2019 年の境は 2018 年の 364 日から出ています。
  - 入れた場合と比べると、区分が食い違うのは 2019-01-03 の 1 日だけです。2017・2018 年を入れる形で読み直して確かめました(使った台本は scratchpad の `offgrid_effect.py`)。
- **行の無い分**: どちらも gap = accept です。
- **日の境**: 同じく日本時間の日です。Binance は 2017-08-17 の 13:00 JST から始まるので、最初の日は半日です。部品 3 の既定の始まりは 2017-08-17T15:00Z(最初の丸 1 日)にしました。
- **持ち高のセッションまたぎ**:
  - カードの規則は同じです。区切りの足が無いと、持ち高が区切りをまたぎます。
  - 損益の日は、決定の時刻 t の日(daily.csv と同じ)です。
  - その日の一覧 `boundary_carry_days.csv` を足しました。diag_c8 と件数・和が合うことを、作り物の足と `--dry` で確かめています。
- **値段の単位**: Binance は USDT、bitFlyer は JPY です。値段を 157.3 倍した作り物の足で、持ち高は完全に同じ、損益は 1e-9 の幅で同じになりました。中ほどの値でも同じです。
