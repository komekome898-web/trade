## なぜ

測る前の 3 問(第 4 版 §3-1)。原文 D1-D-21 の「なぜ」をそのまま使う【原文】。

- 誰が損をしているか: 上乗せの開いた側の価格で売買する人(原文)。
- なぜ続くか: 差を埋める人の容量(資金・移動の時間)が限られているから(原文)。
- 何で崩れるか: 上乗せが開く原因が需給でなく、海外の価格の先行(bitFlyer が追い付いている途中)のとき(原文)。

【推定】このカードは bitFlyer の脚だけを持つので、上の「なぜ」のうち、戻りが bitFlyer の価格の側で起きる分だけが損益に出る。海外の価格の側で戻る分は損益に出ない(意図の地図 I-6b)。

## 期待する向きと場面

- 向き: 上乗せが直近の分布の上にあるとき bitFlyer を売り、下にあるとき買う(原文の「向き = 上乗せが戻る向き(という読み)」)。未測。
- 場面: 円の上乗せが開いたとき(原文)。窓の中の位置が端に近いほど持ち高が大きい。
- 効く項: 円の上乗せ(原文)。損益は bitFlyer の値動きで測るので、BTCUSD と USDJPY の項の動きも損益に入る【推定】。
- 制度: 期間は全部 SFD の時代(W4 の仕様 §3)。CFD の時代は開封の後(この回の範囲外)。

## 反証

- 原文: 「開いた上乗せの後の動きが、戻りでなく海外の価格への追い付きで説明できると測れたら、この「なぜ」は違う。」
- このカードの測り方での言い換え【推定】: 持ち高 e_t と、次の足の「上乗せの変化」(bitFlyer の動きから、Binance × USDJPY の動きを引いたもの)の積の平均が 0 と区別できなければ、上乗せの戻りは測れていない。この量は W1 の測定器の出すもの(C5 の a〜h)に無い。測定の回に診断として出し、bitFlyer の脚の損益と並べる。検定の数には入れない(迷った点 4 へのリードの答え。INTENT_MAP.md §4-3)。

## 約定の模型

- 成行。足の終わり t に出した持ち高 e_t は、次の足の始値で約定したとみなす(W1 の仕様 C2)。原文は「未定」。
- 経費は入れない(段 2 は経費前。W1 の仕様 §0)。
- 持ち高が 0 の足(窓が満ちるまでの足、Binance の同じ分の行が無い足、USDJPY の行がまだ 1 つも届いていない足)も、測定の分母に入る。持ち高が 0 の足の割合は測定の回に出す(迷った点 8 へのリードの答え)。

## 迷った点(リードが決めること。欄の検査の外)

仕様に無い判断が要った所。推測で埋めずに、置いた形と別の形を並べた。各項の末尾に、リードの答え(2026-10-02)を書き足した。

1. **窓(「直近」の長さ)**: 原文に無い。W1 の仕様 C4 の 3 つ(1 時間・1 日・1 週)を変種として関数に持たせた。1 つに決めるか、3 つとも測るかはリードが決める(第 4 版 §3-1「無ければリードが測る前に決めた理由」)。3 つとも測るなら、3 つを並べて出し、どれかを選んで報告しない。
   - **リードの答え(2026-10-02)**: 1h・1d・1w の 3 つの変種をそのまま持たせる。3 つとも測り、選ばずに並べる。族の切り方はリードがオーナーに見せる。
2. **参照の行の時刻**: 置き場の時刻の列は 1 分の始まり(Binance `open_time`・bitFlyer `ts` は README に明記。USDJPY `timestamp` は取得の道具の説明からの【推定】)。W4 の仕様 §3 の「遅れ 0(同じ分の終わりに使える)」に合わせ、行の時刻を +60 秒して 1 分の終わりにする、と CARD.md に書いた。測定を組む回にこれを落とすと、close が 1 分早く届く(未来を読む)。USDJPY の時刻の付け方は、測定の前に確かめる手段を PROCUREMENT.md の USDJPY の行に書いた。
   - **リードの答え(2026-10-02、カード 1 の読みで置き換え)**: +60 秒のずらしはしない。行の時刻は置き場の open_time のまま(1 分の始まり)、lag_ns = 60 秒。Binance は `ref_at(OVERSEAS, t − 60 秒)`、USDJPY は `ref_latest(FX)` で読む。理由: 置き場の値をずらさないので、ずらし忘れが起きない。遅れの宣言が違えば run_card が拒む。USDJPY の時刻の付け方の【推定】は、測定の回に PROCUREMENT.md の手段で確かめる。
3. **測る期間の終了**: W4 の仕様「2022-12-31 まで」を、UTC の 12-31 の終わり(終了 = 2023-01-01T00:00:00Z)と読んだ。別の読み: 終了 = 2022-12-31T00:00:00Z(USDJPY の最後の行の終わり)、または日の境に合わせて日本時間の 12-31 の終わり(2022-12-31T15:00:00Z)。どれでも USDJPY の最後の行より後はカードが 0 を持つので、違いは 12-31 の bitFlyer の足が分母に入るかだけ。
   - **リードの答え(2026-10-02、置き換え)**: 日の境が Asia/Tokyo なので、端を日本時間の日の境にそろえる。終わり = 2022-12-31T15:00:00Z(日本時間の 2023-01-01 の 0 時)。始まり = 3 系列がそろう最初の日本時間の 0 時(2017-08-17T15:00:00Z)。第 2 稿の注: USDJPY を as-of にしたので、USDJPY の最後の行より後も最後の値で上乗せを作る。上の「USDJPY の最後の行より後はカードが 0 を持つ」は第 1 稿の形についての記述。
4. **測定の回に足す量**: 意図の地図の △・✕ の切り分け(INTENT_MAP.md §4-1 の (4) 現物で作った上乗せ、§4-2 持ち高の大きさの区分、§4-3 上乗せの変化との積、§4-4 海外の直前の動きの場面)は、W1 の測定器の出すもの(C5 の a〜h)に無い。足すかどうか、足すなら §4-4 の窓をどうするかはリードが決める。足さなければ、それぞれの射程(INTENT_MAP.md §2・§4)を報告に書く。
