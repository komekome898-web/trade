## 1. 数え(走らせなし): 片側だけの取引を、どの扱いの違いで片側だけになったかに分けた

分け方の決まり D1〜D10 は `c2_ref_vs_g_cause.py` の docstring にあり、表を出す前に試験(`test_c2_ref_vs_g_cause.py`)と一緒に書いた。要点:
- 合図の足を 4 通りに作り直す: none(参照)・join(参照に (a) の内部結合だけを当てる)・n0(参照に (b) の n_trades == 0 を落とすだけを当てる)・both(段階 G)。
- 両方の機械を写して(D4)、既存の取引の記録と全部一致することを先に確かめる(下の表 1。2019〜2022 年に建てた取引で、一致しない取引は 0 本)。
- 片側だけの取引 1 本ごとに、入りの行動で (A) 合図が違う・(B) 行動の時刻が違う・(C) 直前の持ち高が違う、のどれかを見る。(A)(B) は (a) だけ・(b) だけを替えた作り方で、どちらで相手の値になるかで帰属を決める(D7)。(C) は、持ち高が最後に同じだった時刻の次の行動に (A)(B) を当てて元を決める(D8、表の「持ち高を経て」)。
- 1 足以内にずれた同じ向きの対は別に数える(D5、表 2)。
- (c) 約定に使う bitFlyer の足は、両方の機械で行動の判断に値を使わないので、取引の有無を変えない(D9。片側だけの表の (c) の列は決まりで 0)。ただし値が無い足では行動しない(参照は値が無ければ行動しない、K1 の simulate は値 ≤ 0 の足を飛ばす)。2019〜2022 年にそれが起きていないことは、写しが記録と全部一致したこと(1-表 1)で確かめた範囲。(c) は共通の取引の損益に効くので、表 4 で数えた。
