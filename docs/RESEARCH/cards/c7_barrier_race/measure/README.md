# c7_barrier_race の測定(W4 第 2 陣、軽い測り方)

リードの決定(`docs/RESEARCH/cards/W4_batch2_LEAD_REVIEW.md`)と委任文の測り方で測った記録。言葉の判定(効く・効かない)は書かない。損益は bp・持ち高 1 単位あたり・経費前。書いてあるのは実際にしたことだけ。

## 何をどう走らせたか

- カード: `src/bot/research/cards/library/c7_barrier_race.py` の `BarrierRace(window)(window = 1h / 1d / 1w)`。関数は変えていない。
- 期間: 2015-11-28T15:00:00Z 〜 2023-12-17T15:00:00Z(全変種で同じ)。
- 持つ足: bitFlyer FX_BTC_JPY の 1 分足を封印の門(`bot.bt.data.loader.load`、kind bar、ts = 1 分の始まり、gap は accept、no_trade は drop)から読んだ。
- 区切り: 暦年(UTC の 1 月 1 日 0 時)ごとに、その区切りの足だけを門から読み、**同じカードの物を区切りをまたいで使い続けて** `run_card` に通し、記録をつないだ(scratchpad の `run_b2.py`。つなぎ方は前の 3 枚の `run_v2.py` の `run_carry` と同じ)。
- **慣らし(区切りの前の足を新しいカードに通して状態を作る形)は使っていない。** 委任文は「慣らしは、各カードが過去を読む最大の長さ以上にする」だが、カード 7 は当たりの連鎖(起点 = 直前の当たりの足)なので、新しいカードを 1 週慣らしても、全期間を一度に走らせたときの連鎖と同じ起点になるとは限らない【推定: 連鎖の起点が合うのは 2 つの連鎖が同じ足で当たったときだけ】。カード 5・7・8 は `view.bars(1)` と自分の属性しか読まず、カード 6 はそれに参照の行の位置が加わるだけなので、物を使い続ければ区切りの頭の状態は全期間を一度に走らせたときと同じになる。同じになることは下の照合で確かめた(範囲は照合の欄)。4 枚とも同じ形にした。
- 温まり: カードは渡された最初の足から窓を数える(CARD.md 測る期間「温まりを … 置くかは測定器の決まり」)。期間の始まりより前の足は渡していない(置き場の最初の行は 2015-11-28 04:54 UTC で、期間の始まりの約 10 時間前しか無い)。だから各窓の最初の 1 窓分(1h・1d・1w)は持ち高 0。
- 測定: 重い `measure_card`(1 分ごとの 1,000 回の作り直し・200 通りの対照)は打っていない(L-556)。`bot.research.cards.pnl.pnl` の P_t から、日ごとの系列の測定(`daily_stats.json`。式はファイルの `formula`。前の 3 枚の `daily_stats.py` と同じ)と、取引・落ち込み・月・買い売り(`extra.json`。式はファイルの `formula`)と、軽い診断(`diagnostics.json`)を出した。
- 区間: 日本時間の日ごとの損益 S_d を、塊 1 日・5 日の circular block bootstrap(`bot.bt.validation.block_bootstrap_ci`)、1,000 回、種 20261002、95%(百分位)。
- npz(`<変種>/run.npz`): open・high・low・close・exposure・decided・end_ns と、P_t を作り直すのに要る start_ns・volume(全足、区切りをつないだもの)。
