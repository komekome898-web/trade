## なぜ

測る前の 3 問(第 4 版 §3-1)。原文 #45 には「なぜ」が無い(1 文だけ)。以下はこのカードの作業者の仮説で、原文ではない【推定】。

- 誰が損をしているか【推定】: 週明けの最初の値で、週末の間にたまった注文(週末に出た材料への反応)をまとめて執行する人。為替では、週明けの薄い流動性の中で最初の値が行き過ぎ、その後に流動性が戻ると戻される、という読み。FX_BTC_JPY の側("btc")では、為替の市場が閉まっている間の BTC の値動きが、為替の市場が開いて円とドルの参加者が戻ると戻される、という読み。どちらも確かめていない。
- なぜ続くか【推定】: 週末に閉まる市場がある限り、週明けの時刻は毎週同じ暦で来て、週明けの最初の 1 時間は流動性が薄い(第 3 版 54 行「ボラではなく暦と流れで動く」からの仮説)。
- 何で崩れるか【推定】: 週明けの窓が、週末に出た新しい材料への正しい値付け(戻らない動き)であるとき。"usdjpy" では、USDJPY の窓が戻っても BTCUSD の動きが大きければ FX_BTC_JPY の損益には出ない(恒等式の 1 項にすぎない)。

## 約定の模型

- 成行。足の終わり t に出した持ち高 e_t は、次の足の始値で約定したとみなす(W1 の仕様 C2)。原文には約定の模型が無い。

- 持ち高が 0 の足(週明けの 1 時間の外の全部)も測定の分母に入る。

1. **「週末」はどの市場の週末か(I-1)**: 原文に市場が無い。置いた形: USDJPY の為替の市場(手元にあり、FX_BTC_JPY の値段に恒等式で入る。委任文の例の形)。別の形: (a) CME の BTC 先物の週末の窓(暗号資産の文脈で「週末ギャップ」と呼ばれることが多い【推定: この回に資料を開いていない】)。手元に CME の系列は無い【事実: `ls backtest_data | grep -i 'cme\|futures'` が空】。調達の候補は調達票 §2。(b) 日経 225 先物の週明け(`backtest_data/n225f_225labo_20260828/`。期間・夜間の時間帯は未確認)。(c) 日本時間の暦の週末(土日)の FX_BTC_JPY の値動き(閉まる市場を使わない読み。「ギャップ」が無いので、この形は原文の語に合わない【推定】)。
2. **「価格ギャップ」は何の値段の差か(I-2)**: 置いた形: 変種 2 つ。"usdjpy" = USDJPY の前の週の最後の close と週明けの行の close の差、"btc" = 為替の最後の値の変化の時点から週明けの行の終わりまでの FX_BTC_JPY の値動き。2 つとも測るか、1 つにするかはリードが決める。2 つとも測るなら、選ばずに並べる。
3. **週明けの行の決め方(C-4・C-5)**: 置いた形: 日本時間の新しい週の行のうち、前の週の最後の close と違う最初の行。理由: 置き場には閉まっている間の値の動かない行があると読める(使うデータと遅れの欄)ので、単に新しい週の最初の行を取ると、日曜 15:00 UTC の埋めの行を週明けと取り違える【推定】。別の形: (a) 暦で決める(ニューヨーク時間の日曜 17 時に開く、という為替の慣行【推定: 一次資料は未確認】。夏時間の暦が要る)(b) 量が 0 でない最初の行(量 0 は平日にも多い。README)。測定の回に、見つけた週明けの時刻の分布を出して確かめる。週明けの最初の値が前の週の最後の値とちょうど同じだと、週明けを次の値の変化まで遅れて見つける。
4. **測る期間の終わり**: 置いた形: 2022-12-31T15:00Z(W4 の仕様 §3 のカード 3 の扱いに合わせた)。別の形: `backtest_data/fx_usdjpy_1m_20260822.csv.gz`(2017〜2022 の置き場の README「Extends … (2023-01-01 onward)」「Safe to concatenate」)を足して 2023-12-17T15:00Z まで延ばす。このファイルは `scripts/check_card.py` の市場の表で `fx:USDJPY` に当たる(カード 5 の調達票の出力)が、最後の行の日付と封印の台帳への載り方は目録で確かめられていない【未確認: `grep 20260822 backtest_data/phase2_sealed/P2-08/SEALED.json` は空】。延ばすなら、このファイルを「使うデータと遅れ」に足さないと check_card が見ない。このファイルに `md5sum -c` は打っていない。
5. **ギャップの端の値(C-9)**: 置いた形: 週明けの行の close(その 1 分の動きを含む)。別の形: 週明けの行の open(純粋な窓)。open を使うには参照の系列 `usdjpy_open` を別に宣言する必要がある。持つのは r + 60 秒からなので、close を使えば持つ前の値動きを全部ギャップに入れることになる。
6. **強弱(C-10)**: 符号だけ。ギャップの大きさで強弱を付けるには、大きさを比べる物差し(過去の窓の分布など)が要り、原文に無い(A-12)。W1 の C4 の窓(1 時間・1 日・1 週)はギャップの分布を作るには短すぎる(週に 1 回しか来ない)【推定】。
7. **"usdjpy" で持つ銘柄(I-6)**: USDJPY の窓の回帰を FX_BTC_JPY で取る(委任文の指定)。窓の回帰そのものを測るには USDJPY を持つ形が要る(INTENT_MAP.md §4-2)。
8. **置き場のパッケージ**: `src/bot/research/cards/library/` と `tests/research/cards/library/` に `__init__.py` を置いていない(カード 3 の迷った点 7 へのリードの答え「置かない」に合わせた)。
9. **委任文に無いまま置いたもの(§0.1 の表で右の列が「(該当語なし)」の行)**: 週末を USDJPY の市場の閉まりで決めたこと(1)、ギャップを変種 2 つにしたこと(2)、週明けの行の決め方(3)、期間の終わりを 2022-12-31 にしたこと(4)、ギャップの端を close にしたこと(5)、強弱を符号だけにしたこと(6)、持つのを r + 60 秒からにしたこと(約定の模型の欄。遅れ 60 秒の帰結)、関数を変えた写しで試験が落ちることを確かめたこと(INTENT_MAP.md §6 の注)。
