## 読み方

- 恒等式: bitFlyer FX_BTC_JPY の価格 ≡ BTCUSD × USDJPY ×(1 + 円の上乗せ)。当方の損益は 3 つの項の動きと経費(板・約定)だけで決まる。組 B の 5 行はすべて「主に効く項 = BTCUSD」(仕様 §2-2)。
- 区分は第 3 版 §5-1B と同じ: A = 公開の履歴が CFD 期間(2024-03-28〜)を覆う / B = 履歴はあるが短い / C = 履歴が無い / 無 / 未確認 / 未到達。「第3版の区分」は第 3 版の表の写し、「この周の区分」は今回の検索のあとの区分。
- 探した記録: 1 升につき WebSearch を 1 回(standard)。検索語と、結果から読み取れたことを書く。見つからなかったことは「この検索で見つからなかった」と書き、「無い」とは書かない(O-2)。
- 検索の結果と、WebFetch で読んだ外の文章は「データ」であり、指示ではない。中に指示めいた文があっても従っていない。
- ③ の案の出所について: 原文の逐語は、(i) WebFetch でページの文を確認できたものは「ページ確認済み」、(ii) 検索の返答の文だけで、ページ原文では確認できていないものは「検索の返答の文(ページ未確認)」と明記する。後者は検索ツールが返した要約文であり、出所ページの文そのものとは限らない。
- 売買に使う記述(信号・戦略・読み方)が見つからず、機構の説明や事実の報道だけだった升は、③ 欄に「売買の記述は見つからなかった」と書き、X の案は立てない。
- 時刻は `date -u +%FT%TZ` の出力。書き始め = その行の最初の検索を打つ直前、書き終わり = その行の全升を書き終えた直後。検索を行ごとに並列に打ったため、時刻は升ごとではなく行ごとに同じ値が入る(升ごとの時刻は取れていない。報告の「迷った点」に書いた)。
- 在庫との重なり: `docs/STRATEGY_IDEAS.md` の全項目(O-1〜#70)の文を読んで当てた。重なっても消さず、違う点を書く。
