## D1-C-1(① 由来・升 P11-関心)

- 原文: 升 P11-関心。企業の財務の「関心(信念が生まれる)」の段階の跡は、株主総会の議案(暗号資産を財務に組み入れるかの議案)とその採決の結果である。総会の日と議案は事前に公開され、採決の結果は決まった時刻に確定する。結果が確定すると「その企業が BTC の買い手になりうるか」が一度に決まる。
- 意図の地図: 入る条件 = 暗号資産の組み入れ議案の採決結果が公表された時刻の後(結果が採用か否決かで向きを分ける。向きの割り当ては未定)/ 出る条件 = 未定 / 保有中の判断 = 未定 / 強弱の付け方 = 未定(議案の対象となる企業の現金の大きさを使うかは未定)。
- なぜ: 誰が損をしているか = 採決の前に結果を見込んで BTC を建てた人(結果が見込みと逆なら)。なぜ続くか = 採決の日と議案が公開でも、結果が出る時刻まで確定しないため。何で崩れるか = 採決の結果が事前に委任状の集計で分かってしまっている場合(結果が織り込み済み)。
- 期待する向きと場面: 採用なら BTCUSD の買い圧、否決なら買い手の期待の剥落、と考える。場面 = 総会の暦のある日。効く項 = BTCUSD。注文の主体 = 議案の企業の財務部門(組み入れた場合の現物購入)と、その結果に賭ける海外の個人の注文。
- 反証: 採決の結果の公表時刻の前後で、BTCUSD の動きの向きが採用と否決で区別できなければ、この「なぜ」が違うと分かる。
- 段 3 の種類: (a) 海外で見える跡で bitFlyer を持つ。
- 水準とその出所: 未定(W4 で測る前に決める)。
- 使うデータと遅れ: 総会の暦・議案・採決結果(SEC への提出書類・各社の発表)。区分は未確認。使える時刻は各社の公表時刻(未確認)。
- 約定の模型: 成行。

## D1-C-2(① 由来・升 P11-予告)

- 意図の地図: 入る条件 = 資金調達の開示書類が提出された時刻の後(提出の種類と、調達の対象が BTC の購入かどうかを条件にするかは未定)/ 出る条件 = 未定 / 保有中の判断 = 未定 / 強弱の付け方 = 未定(調達額を使うかは未定)。
- なぜ: 誰が損をしているか = 購入の資金が集まったことを知らずに BTC を売る人。なぜ続くか = 開示書類は公開でも、読んで BTC の購入に結びつける人が限られていれば反映が遅れる(仮説)。何で崩れるか = 調達した資金が BTC の購入に使われない場合。
- 期待する向きと場面: 資金調達の開示の後に BTCUSD の買い圧が出る方向。場面 = BTC を財務に持つと表明している企業の開示の後。効く項 = BTCUSD。注文の主体 = 開示した企業の財務部門の現物購入。
- 反証: 調達の開示の後と、開示の無い日で、BTCUSD の動きの向きが区別できなければ「なぜ」が違うと分かる。

## D1-C-4(① 由来・升 P11-約定)

- 原文: 升 P11-約定。企業の財務の「約定」の段階。企業の購入は、数日にわたって人とアルゴリズムで分割して約定される(検索結果の要約で、本文での確認は未了)。分割された買いは、約定の期間じゅう同じ向きの注文として市場に出続ける。購入だけを分離した公開の履歴は見つからなかったので、米国現物の Coinbase の価格と、他の現物の価格との差を代理にする。
- 意図の地図: 入る条件 = Coinbase の価格が他の現物の価格より高い状態が続いたとき(続く長さ・差の大きさは未定)/ 出る条件 = 未定 / 保有中の判断 = 未定 / 強弱の付け方 = 未定。
- なぜ: 誰が損をしているか = 分割された買いが続く間に売る人。なぜ続くか = 注文が数日にわたって分割されるため、買いの圧が 1 日で終わらない(仮説)。何で崩れるか = 購入が OTC で完結して公開の取引所の価格に出ない場合。
- 期待する向きと場面: 企業の購入が続く間は BTCUSD の買い圧が続く向き。場面 = 企業の購入の週。効く項 = BTCUSD。注文の主体 = 企業の財務が取引デスクに出す分割の買い。
- 反証: 企業の購入のあった週となかった週で、Coinbase の差の持続の長さが区別できなければ「なぜ」が違うと分かる。
- 段 3 の種類: (a) 海外で見える跡で bitFlyer を持つ。
- 水準とその出所: 未定(W4 で測る前に決める)。
- 使うデータと遅れ: Coinbase の 1 分足と他の現物の 1 分足(区分 A、第 3 版 B-14)。使える時刻は 1 分足の確定時刻。購入の週の特定には開示書類(月曜)が要り、それは事後でしか分からないので、探索の条件付けにだけ使う(判断の時点では使えない)。
- 約定の模型: 成行。

## D1-C-5(① 由来・升 P11-持ち高)

- 原文: 升 P11-持ち高。企業の財務の「持ち高」の段階の跡は、企業が持つ BTC の量と、その企業の株価である。保有量 × BTC 価格 = 企業の BTC の純資産(NAV)で、株価の時価総額をそれで割った比(mNAV)が、その企業が株や債券を出して BTC を買い増せるか、売らざるを得ないかを分ける。
- 意図の地図: 入る条件 = 保有量の大きい企業の mNAV が分かれ目(NAV に等しい)を上から下へ、または下から上へ跨いだとき(どの企業を数えるか・分かれ目の幅は未定)/ 出る条件 = 未定 / 保有中の判断 = 未定 / 強弱の付け方 = 未定(企業の保有量の合計を使うかは未定)。
- なぜ: 誰が損をしているか = 企業が買い手から売り手に変わる転換に気づかず買う人。なぜ続くか = mNAV は株価と保有量の 2 つを合わせないと分からず、保有量の更新が遅れるため(仮説)。何で崩れるか = 企業が BTC を売らずに別の手段で資金を作る場合。
- 期待する向きと場面: mNAV が分かれ目の上なら企業の買い(BTCUSD の買い圧)、下なら企業の買いの停止か売りの方向。場面 = 保有する企業の株価が大きく動いた日。効く項 = BTCUSD。注文の主体 = BTC を財務に持つ上場企業の財務部門の現物の売買。
- 反証: mNAV が分かれ目の上と下で、その後の企業の購入(開示書類)の有無と BTCUSD の動きの向きが区別できなければ「なぜ」が違うと分かる。
- 段 3 の種類: (a) 海外で見える跡で bitFlyer を持つ。
- 水準とその出所: 分かれ目は mNAV = 1(NAV に等しい)。出所は X1-C-4 の原文(株価が NAV に等しいところで増資の意味が変わる)。分かれ目の幅などは未定(W4 で測る前に決める)。
- 使うデータと遅れ: 企業の BTC 保有量(開示書類・bitcointreasuries.net・CoinGecko・NewHedge。区分は未確認)+ 企業の株価(区分は未確認)。保有量の更新は開示の時刻(週次などの規則は未確認)。
- 約定の模型: 成行。

## D1-C-6(① 由来・升 P11-強制)
