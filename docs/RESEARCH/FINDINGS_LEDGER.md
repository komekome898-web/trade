# 知見台帳

測定から分かったことを、戦略をまたいで溜める置き場です(L-604「**知見台帳は必要ですが**」)。
1 行は戦略の合否ではなく、**場面か仕組みについての観察**です。決まりの本文は `.claude/skills/research-protocol` §0.7。

- 検査: `python3 scripts/check_findings_ledger.py`(問題があれば 1 件 1 行で出て、終了コード 1)。測定の報告には `--report <報告.md>` も当てる。
- 書くのはリードだけ(L-606「**分析は絶対あなた役割です**」)。下位モデルは書かない。
- 入れるのは全捨て(L-019、2026-09-08)より後の測定だけ。
- 「知見なし」「言えない」で行を終えない。否定を含む行は射程(データ・期間・場面)を付け、射程の外(ほかのカードを飛ばす理由など)に使わない。
- 探索(標本内)の観察は「陽性 / 陰性」と呼ばない(research-protocol §0.0)。確かさは 監査済 / 未監査 / 推定 のどれか。

## 書式

観察の行(番号は K-001 から順に。消さない。誤りが分かったら状態を「覆った(K-…)」にして、新しい行を足す):

```
### K-001 <短い見出し>
- 観察: <何が見えたか。1〜2 文>
- 対象: 場面 | 仕組み
- 出所: `<リポジトリの中のファイル>` の <表・節>(ここから数字をもう一度出せること)
- 測った日: YYYY-MM-DD
- 射程: <どのデータ・期間・取引所・足・約定の仕方で見たか>
- 大きさ: <数と単位。区間か SE があれば添える>
- 確かさ: 監査済 | 未監査 | 推定
- 監査: <ACTION_LOG の見出し> | なし
- 否定を含む: はい | いいえ
- 渡す先: <どのカードのどの改良か・どの段か(段 3 bitFlyer へ / 段 4 組み合わせの場面の変数 など)>
- 次の問い: <次に何を測るか>
- なぜの仮説: ① <仕組みの仮説> ② <別の仕組みの仮説> ③ 偶然 ④ 測りの癖(<何>)| 未
- 予言: ①-a <予言>(外れ = <数の条件>)→ <当たった / 外れた / 決まらない / 未> … / 試した n・当たった n・外れた n・未 n | 未
- 確かめのデータ: 見つけたのと同じ(<出所>)| 別: <何のデータ・期間>(見つけるのに使っていない)
- 状態: 開いている | 確かめた(K-…) | 覆った(K-…)
```

**L-702(2026-10-05)で足した 3 つの欄と「確かめた」の意味**: 台帳の行は、見つけたままの候補として書く(分析のスキル D9b)。偶然か市場の仕組みかは、なぜと予言のスキル(`.claude/skills/why-predict`)で、なぜの仮説から出した予言を、見つけるのに使っていないデータで確かめて決める。
- **確かめた(K-…)** = なぜの仮説から出た予言が、見つけるのに使っていないデータで当たった(確かめのデータが「別: …」)。同じ測定の出力の読み直しは確かめたにしない。
- 欄を足す前(測った日 2026-10-05 以前)の行には初期値「初期値(L-702 で欄を足した。1 行ずつは未確認)」を入れた。なぜと予言のスキルが候補を受け取ったときに 1 行ずつ埋める。
- 外れた候補(覆った)も消さずに残す。試した数を数える材料になる。

カードの節(戦略 1 つに 1 節。物差しは月 10 万円ではなく、次の 6 つ。L-603「**統合する前提の単体の戦略で月10万円目指してるのはズレてます**」):

```
### カード: <呼び名(番号)>
- 状態: 測定中 | 休止 | 閉じた
- 場面ごとの効き: <K 番号> | 未
- なぜ: <K 番号> | 未
- 安定: <K 番号> | 未
- 重なり: <K 番号> | 未
- 経費と約定: <K 番号> | 未
- bitFlyer で効くか: <K 番号> | 未
- 改良の周: <数>(「なぜ」から出た改良を何周試したか。記録の場所)
- 次に打てる手: <閉じたカードにも書く>
```

閉じるのは重くする: 改良の周が 0 のカードは閉じられない(検査が止める)。
