## 1. 診断(棚卸しから読めること。数値は棚卸しを数え直した事実、解釈は推定)

- 事実: 128 件。「実行を狭める」60 件の内訳は 事前登録後 18・**納品 21**・運用 13・枠組み前 6・全段 2。事前登録後と運用は偽陽性と事故を防ぐ。**納品段が最大**で、これは監査役の門(L-112)に集中している。本提案は納品段の門を廃止しない(§4.4)。
- 事実: 「枠組みを狭める」29 件のうち **14 件が枠組み前**に効く。ここが視点を殺している場所。
- 事実: 出典なし **81 件(63%)**。どの失敗を防ぐか書かれていない規則が 6 割。
- 事実: 3 か所以上に重複 21 件。「取れない・無い」の規則は 6 か所。
- 事実: フックは Bash / Read / Write / Edit / Agent のすべてに掛かり、2 本は毎ターン無条件。`git push` の部分一致で説明文にも発火する。
- 推定: 規則は失敗のたびに**追加だけ**され、削除の手順が無い。同じ趣旨を複数箇所に書くのは「読まれないから」、読まれないから毎回フックで貼る、という循環。
- 推定: 最も重い狭さは数ではなく**形**。「問いを変えない」「例外は無い」「登録簿からのみ」は、案を出す段に禁止を掛けている。
- 推定(逆方向、同じ水準で扱う): フックや重複を減らすと、規則が行動の直前に無くなり KA-01/02/03/15 型の失敗が再発しうる。**どちらの推定も実測で決める**(§4.4: 可逆な変更にとどめ、発火回数を測る)。

## 3. 規則を減らす規則(削除の手順を作る。本提案で確定するのは**基準**で、総数の目標は §5-1 の処分一覧の後に確定する)

1. **単一出所**: 各規則の本文は 1 つのファイルにだけ置く。CLAUDE.md は「安全不変条件 5 件 + 索引」に縮める。**行動の直前に置く「1 行の参照 + 要旨」(委任雛形・フック・チェックリスト)は重複と数えない**。統合するのは同じ本文の再掲だけ。
2. **出典の義務**: 規則には「防ぐ失敗(L / I / KA)」を付ける。出典なし 81 件は、(a) 取り返しのつかない損害を防ぐもの(安全・秘密・発注)と (b) 偽陽性を防ぐもの(封印・族・多重性・MDE)は出典「設計原理」として残し、(c) それ以外は削除または既定値化。処分の一覧は下位モデルが作り、リードは判断列だけ書く。
3. **追加には削除を**: 規則を 1 件足すときは既存 1 件の削除または統合を同時に提案する。
4. **形の書換**: 「〜しない」を「〜の段では〜」に。

## 4. 思考の自由度を高める策

### 4.1 探索段の新設(research-protocol に 1 節。R-072 の書換と対)

### 4.3 対話の枠を分ける
- 「判断が要る項目(最大 3 件 yes/no)」は決定の枠として残す。
- 別に「**視点の提示**」の枠を作り、件数の上限を置かない。差分表・探索の観察・ゼロベース見直しはここに載る。オーナーは読むだけで、答える義務は無い。

### 4.4 フックの修正(廃止ではなく、可逆な変更にとどめ、実測で決める)

- `owner_turn_digest`: 「共有経路・使用率・求めている行動」の 3 行に縮小。進行中項目の行は状態板を読めば足りる。
- `prereg_source_reminder`・`budget_delegation_reminder`・`session_start_digest`: 現状維持。
- 2 週間、各フックの発火回数を記録し、その実測で削除の可否を再提案する。
