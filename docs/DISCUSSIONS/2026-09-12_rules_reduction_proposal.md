## 1. 診断(棚卸しから読めること。印: 事実は棚卸しの数値、推定は解釈)

- 事実: 128 件のうち「実行を狭める」61 件はほぼ事前登録後・運用の段にあり、偽陽性と事故を防ぐ。これは残す。
- 事実: 「枠組みを狭める」29 件のうち 14 件が**枠組み前**に効く。ここが視点を殺している場所。
- 事実: 出典なしが 85 件(66%)。**どの失敗を防ぐか書かれていない規則が 3 分の 2**。
- 事実: 同じ規則が 3 か所以上に書かれているものが 21 件。「取れない・無い」の規則は 6 か所。
- 事実: フックは Bash / Read / Write / Edit / Agent のすべてに掛かり、うち 2 本は毎ターン無条件。`git push` の部分一致で説明文にも発火する。
- 推定: 規則は失敗のたびに**追加だけ**されてきた(削除の手順が無い)。同じ趣旨を複数箇所に書くのは「読まれないから」で、読まれないから毎回フックで貼る、という循環。**毎回同じ注意文を読むこと自体が入力を狭める**。
- 推定: 最も重い狭さは規則の数ではなく**形**。「問いを変えない」「例外なしの 1 つの型」「登録簿からのみ」は、案を出す段に禁止を掛けている。案を出す段に禁止があると、生成は起きない。

## 3. 規則の総数を減らす規則(削除の手順を作る)

1. **単一出所**: 各規則は 1 つのファイルにだけ本文を置き、他はリンク。CLAUDE.md は「安全不変条件 5 件 + 索引」に縮める(現行 §4〜§8 の本文は各統治文書へ)。重複 21 件がここで消える。
2. **出典の義務**: 規則には「防ぐ失敗(L / I / KA)」を必ず付ける。出典なし 85 件は、(a) 取り返しのつかない損害を防ぐもの(R-001〜R-005 等の安全・秘密・発注)と (b) 偽陽性を防ぐもの(封印・族・多重性・MDE)は出典「設計原理」として残し、(c) それ以外は**削除または既定値化**。処分の一覧は下位モデルに作らせ、リードが判断だけ書く。
3. **追加には削除を**: 規則を 1 件足すときは、既存 1 件の削除または統合を同時に提案する(増やさない規則を規則にも適用)。
4. **形の書換**: 「〜しない」を「〜の段では〜」に。例: 「問いを変えない」→「事前登録の後は問いを変えない。前は代替を 3 つ出す」。

## 4. 思考の自由度を高める策(規則を減らすだけでは生まれない)

### 4.1 探索段の新設(research-protocol に 1 節)
- 事前登録の**前**に、データを見て仮説を作る段を正式に置く。条件は 2 つだけ: (a) 探索で見た区間は事前登録に「探索済み」と書き、判定区間から外す、(b) 探索の結果を「陽性 / 陰性」と呼ばない(生成であって判定ではない)。
- これで「仮説は在庫からしか出ない」(原因 3)が解ける。偽陽性は (a) で防ぐ。

### 4.2 生成役(L-142 §4.1、承認済み)
- 単位ごとに盲検の並列再枠組み(5 役)。差分表をオーナーに見せ、オーナーは選ぶ。O-3c で実施済み(`docs/PHASE2/O3C/REFRAME/`)。

### 4.3 対話の枠を分ける
- 「判断が要る項目(最大 3 件 yes/no)」は**決定**の枠として残す。
- 別に「**視点の提示**」の枠を作り、件数の上限を置かない。差分表・探索の観察・ゼロベース見直しはここに載る。オーナーは読むだけで、答える義務は無い。

### 4.4 フックの整理(6 → 3)
- 廃止: `agent_delegation_reminder`(Agent 呼び出しのたびに §5.2 を貼る)、`prereg_source_reminder`(同)、`git_push_audit_reminder`(部分一致の誤発火。監査の門は owner-audit skill にある)。

- 残す: `session_start_digest`、`budget_delegation_reminder`(対象が限定され、費用の事故を防ぐ)。

### 4.5 予算(L-142 §4.4、承認済み)
