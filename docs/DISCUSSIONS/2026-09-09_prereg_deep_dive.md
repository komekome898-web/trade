# K1 事前登録の深掘り(2026-09-09、オーナー指示により記録)

オーナーが事前登録の数字を 1 つずつ「意味と根拠は何か」と問い直した往復の記録。
**質問 6 回で、リードの誤り 5 件が出た。うち 2 件は数字の誤りではなく、
「言葉の使い方」と「出所の表示」の誤りで、こちらの方が重い。**

記録の目的は、**同じ形の失敗を次の単位で繰り返さないこと**。
個々の数字より、**どういう問い方が何を掘り当てたか**を残す。

## 2. `sd` — 同じ記号で 3 つの量を指していた

### 何が起きたか

| 版 | 中身 | 符号 | 対象 |
|---|---|---|---|
| 1 | `(close[i+h]/close[i]−1)` | **なし** | **全足** |
| 2 | 同上 | なし | **シグナル足**(対象だけ訂正) |
| 3 | `signal × (close[決済]/close[建玉]−1)` | **あり** | **1 取引**(量そのものが別物に) |

**訂正のたびに「訂正」とは書いた。しかし古い定義を消さなかった。**
結果、§5.2 の冒頭には版 1 の定義(「相場のノイズであって戦略の成績ではない」)が残ったまま、
その下の小節が版 2 を、さらに下の表が版 3 を使う、という状態になった。

### なぜ悪いか(オーナーの指摘の通り)

**同じ記号が 3 つの意味を持つと、どの主張も後から「そちらの意味だった」と言い直せる。**
悪意が無くても**結果として論点ずらしが可能な構造**であり、
この構造を許すこと自体が、2026-09-08 の全捨ての原因(誤差が片方向に溜まる)と同型である。

### 直したこと

- **`sd_all(h)` / `sd_sig(h)` / `sd_trade` の 3 つに記号を分けた。**
  それぞれ符号の有無・対象・用途を表で固定し、**`sd_all` は「使わない」と明記**した。
- 版 1 の定義文を**削除**した(残さない。残すと同居が再発する)。
- **規則化**: **量が変わったら記号も変える。同じ記号を別の量に使い回さない。**
  訂正は「古い方を消してから」行う。

## 4. 一般化(**他の単位にも効く**)

この往復で効いた問い方は 3 つ。**リードは自分でこれを回すべきだった。**

1. **「その数字はどこから来たか」を 1 つずつ問う。**
   → 出所の偽装(一次資料でないものを一次資料と書く)を炙り出す。
2. **「同じ言葉が前と同じ意味か」を問う。**
   → 記号の使い回しを炙り出す。**訂正したことと、訂正を反映しきったことは別物。**
3. **「その設定は仮説から出たか、都合から出たか」を問う。**
   → `h` のように、**計算の都合で置いた値が仮説の中心に居座る**のを炙り出す。

**規約への反映**(`research-protocol` §1):
事前登録の各数値に **出所の 3 分類**(一次資料 / 実測 / 仮定)を必ず付け、
**仮定にはさらに「誰の仮定か」**(オーナーの発言・リードの記憶・慣行)を書く。
**リードの記憶は「仮定」であり、一次資料でも実測でもない。**

## 5. 続き — **7 回目と 8 回目の問いで、手数料そのものが不要と判明した**(L-048)

§3 は「水準が未検証なので `archive.org` で確認する」で終わっていた。**その前提ごと崩れた。**

### 5.1 オーナーの問い(7 回目)

> archive.org の確認は不要。**当時の手数料は戦略に関係ない**。目指している目標は
> **現在の取引所での取引**なので、手数料無関係の成績を今の取引所に当てはめたときに
> **はじめて**手数料との差し引きを評価できる。当時手数料込みで勝てていたかを評価するのではなく、
> **シグナルとしての強度を確認する作業**という認識。

**正しい。** K1 の §0 は最初から「確定した足の形だけから後続リターンが予測できるか」であり、
執行は射程外と書いてあった。**つまり 2019 年の手数料は最初から K1 の入力ではなかった。**
私は**自分で書いた射程に反する量を、判定バーに据えていた**。

### 5.2 私はここで**同じ誤りをもう一度やった**

2019 年の手数料を外した直後、私は
**「代わりに現在の bitFlyer の往復コストを MDE の床にする」**と提案した。

**これは同じ誤りを 1 段ずらしただけである。** 下流(執行)の制約を上流(現象の実在)に
持ち込んでいる点で、2019 年の手数料を持ち込むのと構造が変わらない。
**外すべきは「その数字」ではなく「コストという入力そのもの」だった。**

### 5.3 オーナーの問い(8 回目)— 全体の流れの確認

> 当時の BITMEX 履歴からカツオのロジック評価 → BITMEX 以外の現在の取引所で流用できるところを選定
> → その環境で適応するように改良 → そのシグナルを用いて bitFlyer で取引する
> **取引所横断手法の確立と評価** → ペーパートレード → 実弾
>
> という流れの**1 番上流に今位置している**認識。この流れは理解できているか。
> **今の時点でコストを意識しても下流にいくにつれて意味が薄まる or 足枷になる危険**があり、
> 適正な評価をするためというより**ノイズになるリスクの方が高い**のではないか。

**この問いが、5.2 の私の誤りを直接に指している。** 段ごとの役割:

| 段 | 何を決めるか | コストを見るか |
|---|---|---|
| ① K1 | 予測力が実在したか。**どの大きさで、なぜ** | **見ない** |
| ② 流用先の選定 | 現象が何に依存していたか → 今どこにあるか | 見ない |
| ③ 改良 | その環境に合わせて作り直す(I-11) | 見ない |
| ④ 横断手法の確立と評価 | シグナル元 → bitFlyer 執行の実現損益 | **ここで初めて全部** |
| ⑤ ペーパー / ⑥ 実弾 | 想定と実際の差 | 実測に置換 |

**上流でコストを引くと壊れる 3 つの理由**(K1 事前登録 §5.1.2 に記載):

1. **① の成果物は合否ではなく「なぜ」**(L-020)。バーを下回ると「なぜ」を書く作業が止まり、
   **② への入力が消える**
2. **① の効果量は改良前(③ の前)の値**。改良前の値を改良後のコストで足切りするのは順序が逆
3. **① の bp は BitMEX の bp** で、bitFlyer の別の板・別の時代に移らない

### 5.4 直したこと

- **K1 から経費を全部削除**: 3 本の線 A/B/C、5 bp のバー、現代コストの床、`archive.org` の宿題
- **陰性の言い方を変えた**: バーの代わりに **MDE がそのまま射程**になる
  (「効果が無い」ではなく「**MDE を超える効果は不在**」)
- **忘却を防ぐ手続き**: 効果量を必ず bp + 信頼区間で報告し、
  **④ の入口に「①③ の効果量 vs 現代ベニューの実測コスト」の関門を事前登録する**。
  **コストの検査を消したのではなく、正しい段に移した**
- **規約化**(`research-protocol` §3.1): **単位の位置に合うコストだけを扱う。
  上流の単位に下流の制約を持ち込まない。外すときは移す先を書く。**
- 副次: **BitMEX `quote` アーカイブ(197.8 GB)は K1 の前提条件から外れた** →
  **P10 の完了を待たずに K1 を実行できる**(保全自体は閉鎖期限があるので続ける)
- 副次: §6 の族の大きさが **324** のまま残っていた(§3 は 162)。**L-046 の改訂の直し漏れ**。162 に統一

## 6. 一般化の追記 — **効いた問い方は 4 つになった**

§4 の 3 つに加えて:

4. **「その数字は、この単位が答える問いの入力か」を問う。**
   → 射程に書いてあるのに判定に紛れ込んでいる量を炙り出す。
   **自分で書いた §0(答えない問い)と、自分で置いた §5(判定バー)を突き合わせる**だけで
   見つかったはずのものだった。
