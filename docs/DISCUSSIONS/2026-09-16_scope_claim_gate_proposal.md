## 1. 何を検査するか(全文)

**置き場所**: `Stop`(返答をオーナーに出す直前)。新規 `.claude/hooks/scope_claim_gate.sh`。
既存の `reply_audit_gate.sh` と同じ入口で、返答本文を `last_assistant_message` から取る。

**引き金(この語が返答にあるとき、かつこのときだけ)**:

```
全部数え / 全件数え / 全文検索 / 漏れなく / 1 件残らず / すべて直した / 全部直した
/ 全部数えた / すべて数えた / 全部の / すべての箇所
```

**引かない語(重要)**: 「限界を**全部**書く」「**すべて**の主張に印を付ける」のような、
**数える・直す・検索するに係らない全称語は引かない。**
`CLAUDE.md` §5.0 に「**限界(全部書く)**」が実在するので、素朴な語一致だと毎回鳴る。
根拠: Drew 2014 / Joint Commission — **警報の 85〜99% は介入を要しない**。鳴りすぎる警報は無視される。

**検査(引き金が引かれたときだけ走る)**: その返答の中に、次のどちらかがあるか。

- (A) **範囲を切っていない検索の出力**。具体的には `git ls-files` または `git grep` で始まる行と、
  その下に出力が続いていること。
- (B) **「範囲を切った」「除いた」「に絞った」のいずれかの語**(= 切ったことを書いている)。

どちらも無ければ引っ掛ける。

## 3. 誤って止まったとき何が起きるか

**止めに切り替えた後**の話である(いまは止めない)。

- 返答が出ない。リードは語を言い換えるか、範囲を切っていない検索を打って出力を貼るしかない。
- **解除の口を作らない**(③(a) の解除ファイルのような穴を増やさない)。
  代わりに**止めるのは返答だけ**で、道具の呼び出しは止めない。作業は続けられる。
- **誤警報が続いた場合、オーナーの手を煩わせずにリードが止められてしまう**という穴がある
  (リードが引き金の語を消せば通る)。**これは塞げない。**回避は R6 の「鳴らなくなった」で見る。

## 4. 却下側の逐語(両論。これが前版に無かった)

オーナー逐語(L-102): 「**2.機械が検査する仕組みは既に多すぎるほど、検査したから大丈夫と
いう調査しない言い訳に使うリスクの方が上がるため不当**」

**この提案は、その却下の射程に入りうる。**両論を並べる。

## 5. 【承認後に分かった、決定を変えうる事実】この環境ではフックが 1 本も走らない

## 6. 入れない場合に残る穴

- **11 巡で止まった型が、次も同じ頻度で出る。**いま立っているのは `CLAUDE.md` §3 の規則 1 行だけで、
  **11 巡のどれもそれでは止まらなかった。**
- ただし**監査役は毎回捕まえている**(11 巡とも実物を開いて拾った)。
  **つまり穴は「オーナーに届く前に捕まらない」ではなく、「捕まえるのに監査役を毎回回す必要がある」である。**
  コストは監査役の呼び出し回数。
