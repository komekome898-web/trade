# 根本原因 — オーナーの原文が、体制の中を旅していない(2026-09-13)

**オーナーの指摘**:
> 「あなたに求められて答えた私の原文が、何も意図通りに伝わらず、挙句に読まれずに無視されていた
> ことが問題なのではないですか？」

**そのとおりである。**リードは前に 2 回、根本原因を出したが、どちらも外した。
1 回目「答え合わせの相手が無い」= 測定の質の話。2 回目「入口の篩が無い」= 効率の話。
**どちらも、測る対象が間違っていたという事実を説明しない。**質も効率も、対象が違えば無意味である。

## 1. 事実(コードと文書で確認した、2026-09-13)

| 確認したこと | 結果 |
|---|---|
| 委任の型(`delegated-study` / `DELEGATION.md`)に**オーナーの原文を貼る枠があるか** | **無い。**「原文」「オーナーの言葉」「OWNER_INTENT」の語が**一度も出てこない** |
| 監査役(`owner-auditor.md`)は**何と突き合わせるか** | **「オーナーの標準的な問い」を代わりに当てる。**定義に「**オーナー本人でも、承認機関でもない**」と明記。**オーナーの原文そのものを読む工程が無い** |
| `CLAUDE.md` §7 が定める「真実」 | 「**この 3 ファイルが真実。会話だけに残した指示は『無かったこと』とみなす**」= **リードが自分の形式に書き写したものが真実。書き写されていないオーナーの言葉は、規則上「無かったこと」** |
| 本単位でリードが §1 の原文を再読した回数 | **オーナーに「出してみろ」と命じられるまで、ゼロ。**設計・事前登録・測定・結果の読み・診断・監査のどの時点でも開いていない |

## 2. 機構(なぜ起きたか)

原文は**入口で一度だけ**読まれ、`INTENT_MAP` に変換された。**以後、下流の全員が見たのは変換後だけである。**

```
オーナーの原文
   ↓ (リードが 1 回だけ読む)
INTENT_MAP(リードの語彙への変換)
   ↓
事前登録 → 測定の指示文 → 委任先 → 結果 → 診断 → 監査
        ↑
   この線から先に、原文は 1 バイトも流れていない
```

**これは「読み間違い」ではない。読み間違いなら誰かが気づける。**
**変換が原典を置き換え、原典が下流に存在しないので、照合が原理的にできない。**

監査役も同じ線の内側にいる。**監査役が持っているのは「オーナーならこう聞くだろう」という模型**であって、
オーナーの文ではない。**模型はリードが書いた。**だから監査もまた閉じている。

## 3. 何が落ちたか(今回の実害)

1. **末尾の分岐。**原文と補足が求めたのは「**転換が起きるか、またはそれがトレンドになるのか**」。
   リードは戻りの大きさだけを測り、**継続が出た所を「符号が予想と逆」「交絡の疑い」として捨てた。
   捨てたものがオーナーの問いそのものだった。**
2. **「燃料が尽きる」の観測。**建玉の回で「**減った側より増えた側が大きく動く**」形が出たのに、
   リードは「軸として失格」と書いて閉じた。**燃料が足された時と尽きた時で挙動が違う、という観測だった。**
3. **「簡単な観測」と「理論を見つける」。**求められたのは記述と理論。当てたのは事前登録・封印・
   判定区間・多重性・MDE・反証条件という**合否の道具一式。オーナーは一度も「判定してくれ」と言っていない。**

## 4. なぜ「規則を足す」では直らないか

規則も、監査役も、状態板も、**すべて変換後の線の内側にある。**
線の内側でいくら検査を足しても、**原典と照合されないという構造は変わらない。**

**そして今回の誤りが 8 件とも同じ向き(棄却・閉じる)だったのも、ここから説明できる。**
変換先の語彙(検定単位・帰無・反証条件・多重性・MDE)は**棄却するための語彙しか持っていない。**
「材料を見つける」に対応する語が無いので、変換した時点で**棄却以外の出口が消えていた。**
リードの癖ではなく、**翻訳先の言語の性質**である。

## 5. 再発防止(原典を線の上に流す)

**足すのは規則ではなく、原典の経路である。**

1. **委任の指示文の先頭に、オーナーの原文を逐語で貼る。**リードの枠組みより**前**に置く。
   委任先への指示に一文加える: **「リードの枠組みと原文が食い違うと思ったら、作業を止めて指摘せよ」**。
   → `delegated-study` と `DELEGATION.md` に枠を新設(現在は語すら無い)。
2. **監査役の第一の検査を「原文との突き合わせ」にする。**
   模型ではなく**原文そのものを渡し**、こう問わせる:
   **「原文のどの語に答えたか。どの語に答えていないか。原文のどの語が、別の語に置き換わっているか。」**
   これは体制で唯一、**外から情報が入る検査**になる(外部の正解ではなく、オーナーが外部である)。
3. **結果の文書に「原文対応表」を必須にする。**原文の各句を引用し、**答えた / 答えていない**を書く。
   答えていない句があること自体は構わない。**見えなくなることが問題。**
4. **翻訳を可視化する。**原文の語をリードの語に置き換えるときは、**両方を併記し、置き換えの理由を書く。**
   (例:「材料を見つける」→「検定単位」は**許されない置き換え**だった)
5. **`CLAUDE.md` §7 の「真実」の定義を直す。**
   現行は「3 ファイルが真実」= リードの書き写しが真実。
   **改める: オーナーの逐語が真実であり、3 ファイルはその索引である。**
   I-001 の趣旨(会話が失われても指示が残る)は、**逐語を保存する**ことで満たす。要約に置き換えない。
6. **リードが原文を再読する時点を決める。**設計を書く前 / 結果の読みを書く前 / オーナーに出す前の 3 回。
   **今回は 0 回だった。**

## 6. オーナーに決めていただきたいこと

上の 1〜6 を実装してよいか。**1・2・5 が本体**(原典の経路そのもの)。3・4・6 は補助。
**いずれも規則の追加ではなく、既存の工程への原典の差し込みと、真実の定義の訂正である。**
