# W4 の仕様: 最初の 3 枚(計画 第 5 版 §4 W4)

リードが委任の前に書く仕様(F2)。目標から導いた選び方を書く(KA-52: 目標から答えが出る問いをオーナーに投げない)。

## 0. 目的と、この仕様の範囲

- 目的: 段 2・3 の測定を、測定器(W1)で実際のデータに当てて始める。最初の 3 枚で作り方(カードにする関所・測定・なぜ)に問題が無いかを確かめてから残りに進む(計画 W4 の「最初の 3 枚を通した時点で、作り方に問題が無いかを確かめてから残りに進む」)。
- この仕様の範囲: 最初の 3 枚の選び方・測る期間・カードにする関所・委任の分け方・終わる条件。封印の開封の手続き(W4 の (2))は別の文書で扱う。最初の 3 枚は封印の外のデータだけで測れるので、開封を待たない。

## 2. カードにする関所(第 4 版 §3-2 と研究手順書 §0.5)

1. 下位モデルが、原文から CARD.md(W1 の 10 欄)と関数を書く。
2. **意図の地図**(`INTENT_MAP.md`): 意図を 1 項ずつに割り、関数のどこで実装したかを ○ / △ 代理 / ✕ 未実装 / ＋ 意図に無い で付ける。コードの側からも走査する。
3. リードが、原文と意図の地図と関数を並べて読む。意図が落ちていたら差し戻す。
4. **オーナー由来の案(カード 2)は、意図の地図をオーナーに見せて確かめてから測る**(研究手順書 §0.5 の検収)。カード 1・3 はリードの確認で測る。
5. カード 1 は、最初の 3 枚のうちで「別の下位モデルが原文だけから独立に書き直す」検めを行う(第 4 版 §3-2 の 3)。持ち高が食い違う足が全体の 0.1% を超えたら、または食い違いの理由を 1 件でも説明できなければ止めて原因を書く。カード 1 は今の bot のコード(`src/bot/strategy/xborder_momentum.py`)とも突き合わせる。
6. 調達票(研究手順書 §14)をカードごとに書き、リード盲点監査(安い監査者 1 名、≤ 15 ツール呼び出し)を通す。

## 3. 測る期間と測定の設定

- 期間: 各系列の始まり(Binance 2017-08-17、bitFlyer FX の 1 分足の始まり、USDJPY 2017-08-01 の遅い方)〜 2023-12-17(封印の境の前日)。カード 3 は USDJPY の置き場が 2022-12-31 までなので、そこまで。
- 制度の境(場面の変数「制度」): bitFlyer の SFD の時代 / 2024-03-28 以降の CFD の時代。今回の期間は全部 SFD の時代【事実: 期間の終わりが 2023-12-17】。制度の違いは開封の後に測る。
- 測定の設定(CARD.md の「測定の設定」): 日の境 = Asia/Tokyo(bitFlyer の日と、オーナーの時間で読むため)。vr の q = 原文に無ければ「なし」(vr を出さない。根拠の無い値を置かない、A-12)。参照の系列の遅れ = 1 分足どうしは 0(同じ分の終わりに使える)、出所はデータの置き場の説明。
- 出すもの: W1 の C5 の a〜h。区間の両端と MDE を並べ、言葉の判定はしない(計画 段 2 の訂正)。ブロックの長さは 1 日と 1 週の両方で区間を出し、差を見る(W1 の批評家の注記への応答)。

## 4. 委任の分け方と、終わる条件

- カードごとに 1 人の下位モデル(カード 1 は書き直しの検めに 2 人目)。委任文には、この仕様・W1 の仕様・研究手順書 §0.5・§14・事前の検死の失敗の型のうち測定に関わるもの(行 1・13・14・17・18・33)を入れる。
- 終わる条件(カードごと): CARD.md が `scripts/check_card.py` を通り、意図の地図がリードの読み(カード 2 はオーナーの確認)を通り、調達票と盲点監査の記録があり、測定の出力(C5 の a〜h)と「なぜ」の仮説(研究手順書 §0.2 の 3 問)が台帳にある。
- 最初の 3 枚が終わったら、作り方に問題が無かったかを書き(どこで時間がかかったか、差し戻しの回数、批評家・監査の指摘)、残りに進む前にオーナーに出す。
- 差し戻しが 2 回目になったら、直し続けずに止めて原因を出す(計画 §4-1)。
