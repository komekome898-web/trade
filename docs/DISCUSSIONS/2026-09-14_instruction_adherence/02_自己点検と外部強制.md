## 1. 内在的自己修正（intrinsic self-correction）の限界

### 1-1. 外部フィードバック無しの自己修正は、測ると性能が下がる

**主張**: 正解ラベル無しで「自分の答えを見直せ」と指示すると、全モデル・全ベンチマークで精度が低下した。

**出典**: *Large Language Models Cannot Self-Correct Reasoning Yet* / Jie Huang, Xinyun Chen, Swaroop Mishra, Huaixiu Steven Zheng, Adams Wei Yu, Xinying Song, Denny Zhou (Google DeepMind / UIUC) / ICLR 2024 / https://arxiv.org/abs/2310.01798

**数値**(Table 3・4、本文 PDF から直接抽出。「標準 → 1巡目 → 2巡目」、呼び出し回数 1→3→5):

| モデル | GSM8K | CommonSenseQA | HotpotQA |
|---|---|---|---|
| GPT-3.5 | 75.9 → 75.1 → **74.7** | 75.8 → 38.1 → **41.8** | 26.0 → 25.0 → **25.0** |
| GPT-4 | 95.5 → 91.5 → **89.0** | 82.0 → 79.5 → **80.0** | 49.0 → 49.0 → **43.0** |
| GPT-4-Turbo | 91.5 → 88.0 → **90.0** | 84.0 → 81.5 → **83.0** | — |
| Llama-2-70b-chat | 62.0 → 43.5 → **36.5** | 64.0 → 37.5 → **36.5** | — |

対照的に、**正解ラベルを与えて停止判断させる(oracle)と上がる**: GPT-3.5 GSM8K 75.9 → 84.3、CommonSenseQA 75.8 → 89.7、HotpotQA 26.0 → 29.0。GPT-4 は 95.5 → 97.5 / 82.0 → 85.5 / 49.0 → 59.0。
著者の指摘は「先行研究の改善は oracle ラベル由来であり、ラベルを外すと消える」。

**答えの変化の内訳**(Figure 1、2巡後):
- GSM8K / GPT-3.5 — 無変化 74.7%、**正→誤 8.8%**、誤→正 7.6%、誤→誤 8.9%(正→誤が誤→正を上回る)
- CommonSenseQA / GPT-3.5 — 無変化 42.8%、**正→誤 39.8%**、誤→正 5.8%、誤→誤 11.6%
- GSM8K / GPT-4-Turbo — 無変化 96.0%(強いモデルほど「動かない」ので害が小さいだけ)

**反証・限界**:
- 著者自身が射程を明記している。「本研究は**推論タスク**の評価に絞る。応答のスタイル変更や安全性の向上など、他領域では自己修正が成功した先行研究がある」。**安全性・文体・毒性除去は本結果の射程外。**
- 3種のフィードバック文面を試した結果(Table 5・6)、下げ幅は文面で変わる。GPT-4-Turbo に「Verify whether your answer is correct」を使うと GSM8K 91.5 → 91.0 → 91.0 でほぼ中立。**「必ず大きく下がる」ではなく「上がらない」が正確。**
- 評価は 2023〜2024 年のモデル。推論特化モデル(o1系以降)は含まれない。

### 1-2. 反対文献(Reflexion / Self-Refine)の主張と、その成立条件

**主張**: 自己修正の肯定的な結果は、(a) 外部の検証器があるか、(b) 初期プロンプトが弱いか、のどちらかに依存している。

**出典**:
- *Reflexion: Language Agents with Verbal Reinforcement Learning* / Noah Shinn, Federico Cassano, Edward Berman, Ashwin Gopinath, Karthik Narasimhan, Shunyu Yao / NeurIPS 2023 / https://arxiv.org/abs/2303.11366
- *SELF-REFINE: Iterative Refinement with Self-Feedback* / Aman Madaan, Niket Tandon, Prakhar Gupta ほか17名 / NeurIPS 2023 / https://arxiv.org/abs/2303.17651

**数値**:
- Reflexion: HumanEval (Python) pass@1 **91.0** vs GPT-4 の 80.1。ただし同じ Table 1 で **MBPP (Python) は 77.1 で、GPT-4 の 80.1 を下回る**(自己修正が害になっている)。また HumanEval の自己生成テストの偽陰性率は **FN 0.40**。
- Self-Refine: 7タスク平均で **約20%(絶対値)** 改善と主張。
- Huang らによる Self-Refine の再現(Table 8、CommonGen-Hard、概念網羅率): 原論文の報告 44.0 → 67.0(7回呼び出し)。再現すると 53.0 → 61.1。**ところが初期プロンプトに「上記の概念を*すべて*含む段落を書け」と明示しただけで 81.8 に達し、その上に自己修正をかけると 75.1 に下がる。**

**反証・限界**: Reflexion の HumanEval は**単体テストという外部検証器**を使っており、内在的自己修正ではない。Self-Refine の利得は初期指示の不備を後段で補っていた分を含む。この2点は Huang et al. と Kamoi et al. の双方が独立に指摘している。

### 1-3. 現時点(2026-09)の総説的な位置づけ

**主張**: 「プロンプトされた LLM のフィードバックだけで、一般タスクの自己修正に成功した先行研究は存在しない」。ボトルネックは修正能力ではなく**フィードバック生成**の側にある。

**出典**: *When Can LLMs Actually Correct Their Own Mistakes? A Critical Survey of Self-Correction of LLMs* / Ryo Kamoi, Yusen Zhang, Nan Zhang, Jiawei Han, Rui Zhang / Transactions of the ACL (TACL), Vol.12, pp.1417–1440, 2024 / https://aclanthology.org/2024.tacl-1.78/

**数値**: 数値なし(総説。個別数値ではなく、先行研究の実験設計上の欠陥4類型を提示)。指摘された欠陥は、(1) oracle 情報の使用(RCI, Reflexion)、(2) 意図的に弱い初期プロンプト(Self-Refine)、(3) 外部知識を修正側にだけ与える非対称な設定、(4) self-consistency 等の強いベースラインとの比較欠如。

**成功が確認されている条件**(同総説): コードインタプリタを伴うコード生成、検索エンジンを伴う QA、分解可能な応答の検証、Game of 24 のような検証可能な出力を持つタスク — いずれも**外部の検証手段がある場合**。

**反証・限界**: 2024年12月時点の総説であり、推論特化モデルの大規模な評価は含まない。後述の RealCritic が o1-mini で唯一の正の自己批評を報告しており、**「モデル世代によって結論が変わりうる」点は未決着**。

## 2. 生成と検証の非対称性(generator–verifier gap)

### 2-1. プロセス監督は結果監督を上回る(ただし別モデルの検証器の話)

**主張**: 独立に訓練した検証器を置くと、多数決や結果監督を上回る。

**出典**: *Let's Verify Step by Step* / Hunter Lightman, Vineet Kosaraju, Yura Burda, Harri Edwards, Bowen Baker, Teddy Lee, Jan Leike, John Schulman, Ilya Sutskever, Karl Cobbe (OpenAI) / 2023 / https://arxiv.org/abs/2305.20050

**数値**(MATH 代表部分集合、Best-of-1860): **PRM(プロセス監督)78.2% / ORM(結果監督)72.4% / 多数決 69.6%**。能動学習でプロセス監督のデータ効率が **2.6倍**。PRM800K(80万件のステップ単位人手ラベル)を公開。

**反証・限界**: これは**人手80万件のラベルで訓練した別個の検証器**であり、「モデルに自分の答えを見直させる」話ではない。自己点検の根拠にはならない。また ORM の訓練セットと PRM の訓練セットが直接比較可能でないことを著者自身が断っている(そのため小規模での対照実験を別途実施)。

### 2-2. 同一モデルは「自分の誤り」を「他モデルの誤り」より捕捉できない ← 最も直接的な証拠

**主張**: 同じモデル・同じタスクで、他モデルの解答を批評させると性能が上がり、自分の解答を批評させると下がる。

**出典**: *RealCritic: Towards Effectiveness-Driven Evaluation of Language Model Critiques* / Zhengyang Tang, Ziniu Li, Zhenyang Xiao, Tian Ding, Ruoyu Sun, Benyou Wang, Dayiheng Liu, Fei Huang, Tianyu Liu, Bowen Yu, Junyang Lin (CUHK深圳 / Qwen Team, Alibaba) / 2025 / https://arxiv.org/abs/2501.14492

**数値**(Figure 1、8つの推論タスク平均、批評前後の変化):

| モデル | 自己批評 | 他者批評 | 差 |
|---|---|---|---|
| LLaMA-3.1-70B-Instruct | **−4.3** | +5.8 | 10.1 |
| Mistral Large-Instruct | **−1.8** | +11.0 | 12.8 |
| Qwen2.5-72B-Math-Instruct | **−5.1** | +8.7 | 13.8 |
| Qwen2.5-72B-Instruct | **−3.0** | +7.2 | 10.2 |
| GPT-4 | **−4.5** | +5.1 | 9.6 |
| o1-mini | **+3.3** | +15.6 | 12.3 |

6モデル中5モデルで自己批評は**マイナス**、他者批評は**全モデルでプラス**。閉ループ評価(批評から生成された修正の質を測る)である点が既存ベンチマークとの違い。

**反証・限界**:
- **o1-mini だけが自己批評でプラス(+3.3)**。推論特化モデルでは自己点検が機能しうるという反証であり、この論文自身が「古典的 LLM と推論ベースモデルの明確な分離」を主要な結論としている。ただし o1-mini でも**他者批評(+15.6)のほうが自己批評(+3.3)より4.7倍大きい**ので、非対称性そのものは o1-mini でも残る。
- 推論タスク8種に限定。規則遵守・方針遵守のタスクではない。

### 2-3. 自分の生成候補の中から良いものを選ぶ能力は、生成能力を上回らない

**主張**: 自己改善が成立するには「自分が生成した選択肢の弁別能力 > 生成能力」が必要だが、これは成り立たない。

**出典**: *SELF-[IN]CORRECT: LLMs Struggle with Discriminating Self-Generated Responses* / Dongwei Jiang, Jingyu Zhang, Orion Weller, Nathaniel Weir, Benjamin Van Durme, Daniel Khashabi (Johns Hopkins) / 2024 / https://arxiv.org/abs/2404.04298

**数値**: Self-Refine の対象タスクで、モデルが自己修正後の生成を修正前より好む割合は **約54%**(偶然の50%をわずかに上回るだけ)。評価対象は Phi-3-mini, LLaMA-2 (7/13/70B, base・chat), LLaMA-3 (8/70B, base・instruct), Mixtral 8×7B, GPT-3.5-turbo, GPT-4-turbo。

**反証・限界**: Flan-T5-XXL と Flan-UL2 では仮説が成立しない(DG-DIFF が有意に高い)。著者は事前学習形式の違い(スパン破損)が原因かもしれないとし、**断定を避けている**。

### 2-4. 自己検証のギャップは数回で枯れる。外部検証器の強さには比例して伸びる

**主張**: 自己改善の余地(GV-Gap)は反復すると2〜3巡で0に飽和する。一方、検証器を別モデルにすると**検証器の能力に比例、生成器の能力に反比例**して利得が伸びる。

**出典**: *Mind the Gap: Examining the Self-Improvement Capabilities of Large Language Models* / Yuda Song, Hanlin Zhang, Carson Eisenach, Sham M. Kakade, Dean Foster, Udaya Ghai (Amazon / CMU / Harvard) / ICLR 2025 / https://arxiv.org/abs/2412.02674

**数値**: 相対 GV-Gap は GSM8K/MATH で概ね **0〜20%** の範囲(モデル系列・検証法による、Figure 1)。反復自己改善では**2〜3巡で0に飽和し、飽和速度はモデル容量に依存しない**。飽和の原因は有効多様性の低下(誤答への収束)。**事実想起タスクでは有意な GV-Gap が出ない**(生成と検証の複雑さが同等のため)。

**反証・限界**: 相対 GV-Gap は事前学習 FLOPs に対して単調増加する(自己改善は大型化で改善しうるという**肯定側の証拠**)。ただし絶対 GV-Gap にはこのスケーリングが見られない。数学・GSM8K が中心で、規則遵守タスクは対象外。

### 2-5. 自己評価は「自分の出力だと認識できる」ほど自分に甘くなる

**主張**: LLM 評価者は自分の生成物を優遇し、その強さは自己認識能力と線形に相関する。

**出典**: *LLM Evaluators Recognize and Favor Their Own Generations* / Arjun Panickssery, Samuel R. Bowman, Shi Feng (MATS / NYU / Anthropic) / NeurIPS 2024 / https://arxiv.org/abs/2404.13076

**数値**:
- GPT-4 の自己認識精度 **73.5%**(他2LLM+人間からの弁別)。ペアワイズ内訳では対人間 **0.71**、対 Llama 0.638、対 GPT-3.5 0.526。
- 500例の fine-tuning で GPT-3.5・Llama-2 とも自己認識 **90%超**。
- 自己認識と自己選好の相関(Kendall's τ、GPT-3.5 XSUM、FT前)**0.41**。FT(500)で 0.74。
- 自己選好の強さは自己認識スコアと**線形相関**(Figure 1)。長さ・可読性・母音数などの交絡を統制しても残る。

**反証・限界**: タスクは**要約2種(XSUM, CNN/DailyMail)のみ**。Llama-2-7b の自己認識は 0.495〜0.502 でほぼ偶然水準(自己認識が無くても自己選好は生じうる、と著者が明記)。また Hoelscher-Obermaier et al. (2023) の寓話タスクでは GPT-3.5 が GPT-4 より正確で、本論文と逆の結果になっている(著者が言及)。

## 3. エージェントの方針遵守 — τ-bench / τ²-bench

### 3-1. pass^k: 同じ課題を繰り返すと信頼性が崩壊する

**主張**: 平均成功率が6割でも、同じ課題を8回連続で成功する確率は25%未満。

**出典**: *τ-bench: A Benchmark for Tool-Agent-User Interaction in Real-World Domains* / Shunyu Yao, Noah Shinn, Pedram Razavi, Karthik Narasimhan (Sierra) / 2024 / https://arxiv.org/abs/2406.12045

**数値**:
- pass^k の定義: **k回のi.i.d.試行が*すべて*成功する確率**(pass@k = 少なくとも1回成功、の逆)。
- gpt-4o(function calling): τ-retail pass^1 **61.2%** / τ-airline pass^1 **35.2%**。**τ-retail の pass^8 は 25%未満**。
- 規模: τ-retail 115課題、τ-airline 50課題。
- 失敗内訳(gpt-4o の τ-retail 失敗36件の手作業分類): 部分的解決 33.3%、誤情報 25.0%、**誤った判断 22.2%**、誤引数 19.4%。
- コスト: エージェント $0.38 / ユーザシミュレータ $0.23 per task。**入力プロンプトが費用の95.9%**(方針文書+関数定義が長いため)。

### 3-2. 方針文書をシステムプロンプトから消しても、ほとんど成績が落ちない ← 本調査で最も重要な数値のひとつ

**主張**: エージェントは「方針文書を読んで従っている」のではなく、多くの場合**常識的にツールを使っているだけ**である。

**出典**: 同上、Table 3

**数値**(方針文書をシステムプロンプトから**削除**した場合の pass^1):

| | τ-retail | τ-airline |
|---|---|---|
| gpt-4o | 61.2 → 56.8(**−4.4**) | 33.2 → 10.8(**−22.4**) |
| gpt-3.5 | 20.0 → 14.5(−5.5) | 10.8 → 9.6(**−1.2**) |

著者の解釈を逐語で: 「τ-retail では規則が単純で常識に近いため、gpt-4o と gpt-3.5-turbo は 4.4% と 5.5% しか劣化しない。これは**成功事例の大半が直感的・常識的なツール使用に由来**しており、**方針文書を可能な限り活用してはいない**ことを示唆する」。

**反証・限界**: 規則が複雑でアドホックな τ-airline では gpt-4o が −22.4 と大きく落ちるので、**「方針文書を全く読んでいない」わけではない**。「規則が常識と一致する範囲では文書が実質的に効いていない」が正確。gpt-3.5 の airline が −1.2 なのは、そもそも複雑な規則を処理する能力が無いためと著者は解釈している。

### 3-3. τ²-bench: ユーザと環境を共有すると更に落ちる

**主張**: 単一制御から二重制御(ユーザも道具を使う)に移ると pass^1 が18〜25ポイント落ちる。

**出典**: *τ²-Bench: Evaluating Conversational Agents in a Dual-Control Environment* / Victor Barres, Honghua Dong, Soham Ray, Xujie Si, Karthik Narasimhan (Sierra / Univ. of Toronto / Vector Institute) / 2025 / https://arxiv.org/abs/2506.07982

**数値**:
- gpt-4.1 pass^1: retail **74%** / airline **56%** / telecom **34%**。claude-3.7-sonnet の telecom は 49%。
- モード別 pass^1(telecom、元の方針文書): gpt-4.1 = default 0.34 / no-user 0.52 / oracle-plan 0.73。o4-mini = 0.42 / 0.67 / 0.96。**no-user → default で gpt-4.1 は18ポイント、o4-mini は25ポイント低下。**
- pass^k の崩壊(telecom、課題種別、k=1→4): o4-mini の mms_issue **0.12 → 0.06 → 0.04 → 0.02**。gpt-4.1 の mms_issue 0.18 → 0.13 → 0.11 → 0.10。最も易しい service_issue でも o4-mini は 0.85 → 0.76。
- 必要行動数が **7を超えると default モードの pass^1 はほぼ0**。

**「手順を具体的に書いた方針文書」の効果**: ワークフロー版の方針文書にすると default / no-user ではわずかに改善する(gpt-4.1 default 0.34 → 0.52、o4-mini 0.42 → 0.59)。**ところが oracle-plan モードでは逆に悪化する**(gpt-4.1 0.73 → 0.57、o4-mini 0.96 → 0.88)。著者の仮説は「正解手順を既に持っているのに手順書を渡すと混乱する」。**指示を増やすことが一様に善ではない実測例。**

**反証・限界**: ユーザシミュレータも LLM であり、その誤りが混入する(著者は telecom で critical error 0件と報告)。pass^k は k=4 まで。

### 3-4. 機械的に検証可能な単純指示ですら、2割強は守られない

**主張**: 「400語以上で書け」のようなプログラムで判定できる指示でも、GPT-4 はプロンプト単位で23%失敗する。

**出典**: *Instruction-Following Evaluation for Large Language Models (IFEval)* / Jeffrey Zhou, Tianjian Lu, Swaroop Mishra, Siddhartha Brahma, Sujoy Basu, Yi Luan, Denny Zhou, Le Hou (Google / Yale) / 2023 / https://arxiv.org/abs/2311.07911

**数値**(Table 3、541プロンプト / 25種の検証可能指示):

| モデル | プロンプト単位 strict | 指示単位 strict | プロンプト単位 loose | 指示単位 loose |
|---|---|---|---|---|
| GPT-4 (2023-11) | **76.89%** | 83.57% | 79.30% | 85.37% |
| PaLM 2 S | 43.07% | 55.76% | 46.95% | 59.11% |

**反証・限界**: 2023年11月の GPT-4。現行モデルでは IFEval は概ね飽和しており(公開リーダーボード上)、**この数値をそのまま2026年の推定に使ってはならない**。ただし「指示がプロンプトにあること」と「指示が守られること」が別物である、という構造的な論点は残る。なお本調査では**2026年時点の最新モデルの IFEval 値を一次資料で確認していない(未確認)**。

## 4. 外部強制(プログラムによる拘束)

### 4-1. 制約付きデコーディング: 構文適合は構成上保証され、下流精度も落ちなかった

**主張**: 文法制約デコーディングはスキーマ適合率を上げ、少なくとも本ベンチマークでは下流タスク精度を下げなかった。

**出典**: *JSONSchemaBench / Generating Structured Outputs from Language Models: Benchmark and Studies* / Saibo Geng ほか / 2025(ICML 2025) / https://arxiv.org/abs/2501.10868

**数値**:
- 実効カバレッジ(GlaiveAI): Guidance 0.96 / Llamacpp 0.95 / Outlines 0.95 vs **LM単体 0.90**。
- 難易度の高い GitHub Hard: Guidance **0.41** vs **LM単体 0.13**(差が大きく開く)。
- 適合率(文法がスキーマを受理する場合): Guidance 0.94〜1.00。
- 下流精度(Llama-3.1-8B-Instruct): GSM8K **80.1% → 83.8%**、Last Letter 50.7% → 54.0%、Shuffle Objects 52.6% → 55.9%。いずれも**制約付きのほうが高い**。
- 速度: 制約付きデコーディングは非制約比で最大50%高速化しうる(TPOT: Guidance 6.37〜9.47ms vs LM単体 15.4〜16.68ms)。ただし Outlines は文法コンパイルに 3.48〜8.05秒。

**反証・限界**:
- 保証されるのは**構文的妥当性だけで、値が正しいかは保証しない**。
- 制約付きデコーディングが意味的品質を劣化させるという逆向きの報告が存在する。検索上、*The Constraint Tax: Measuring Validity-Correctness Tradeoffs in Structured Outputs for Small Language Models* (arXiv 2605.26128) や ExtractBench (arXiv 2602.12247) が妥当性51%→37%といった劣化を報告しているとされるが、**本調査では一次資料を開いて確認していない(未確認)**。この論点は割れている、とだけ言える。

### 4-2. ガードレール(コード側の検査)の測定値 — ただしベンダー公表

**主張**: 入出力をコードで検査する層を足すと、方針違反の検出率が大きく上がる。代償は遅延と処理量。

**出典**: *Measuring the Effectiveness and Performance of AI Guardrails in Generative AI Applications* / NVIDIA Technical Blog(NeMo Guardrails)/ https://developer.nvidia.com/blog/measuring-the-effectiveness-and-performance-of-ai-guardrails-in-generative-ai-applications/

**数値**:
- 方針違反の検出率: **ガードレール無し 75.01% → 全段構成 98.9%**。中間: コンテンツモデレーションのみ 83.0%、+脱獄検知 89.1%。
- 遅延: 平均 0.91秒 → 1.44秒(P95 は 0.97 → 1.66秒)。
- 処理量: 112.9 → 98.70 tokens/sec(約12%低下)。

**反証・限界**: **ベンダー自社製品のベンチマークであり、査読を経ていない。** 「方針違反の検出率」という指標の定義・データセットは記事側の定義に依存する。**外部の独立再現を本調査では確認していない(未確認)。** 効果量としては引用可能だが、独立した効果量の推定としては扱えない。

### 4-3. 「プロンプトに書く」対「コードで強制する」の直接比較は、ほぼ存在しない

**主張**: この対比を**同一条件で測った査読付き研究は、本調査では見つからなかった。**間接的な証拠が3つある。

**間接証拠**:
1. **τ-bench Table 3**(§3-2): 方針文書をプロンプトから削除しても retail では −4.4 しか落ちない = プロンプト内の方針文書は、想定されたほど behavior を規定していない。
2. **Huang et al. Table 8**(§1-2): 要件を初期指示に明記(81.8)> 要件を後段の自己修正で補う(67.0 / 61.1 / 75.1)。**同じ要件でも、置く場所で結果が変わる。**
3. **JSONSchemaBench**(§4-1): 構文制約は構成上保証される一方、プロンプト指示(LM単体)は GitHub Hard で 0.13 に落ちる。

**言えないこと**: 上記はいずれも「プロンプト指示 vs コード強制」を**同一タスク・同一モデル・同一要件で対照した実験ではない**。効果量として引用できる公表値を、本調査では特定できなかった。

## 5. self-consistency / 多標本チェック

**主張**: 多数決は数学系の精度には効き、「議論させる」より強い。ただし規則遵守に効くという証拠は見つからなかった。

**出典**: Huang et al. 2024(前掲)Table 7 / Lightman et al. 2023(前掲)

**数値**(GSM8K、gpt-3.5-turbo-0301、全テストセット):

| 手法 | 応答数 | GSM8K |
|---|---|---|
| 標準プロンプト | 1 | 76.7 |
| Self-Consistency | 3 | 82.5 |
| Multi-Agent Debate(1巡) | 6 | 83.2 |
| **Self-Consistency** | **6** | **85.3** |
| Multi-Agent Debate(2巡) | 9 | 83.0 |
| **Self-Consistency** | **9** | **88.2** |

**同じ応答数で揃えると、multi-agent debate は単純多数決に負ける**(6応答で 83.2 vs 85.3、9応答で 83.0 vs 88.2)。著者の結論は「これは『自己修正』ではなく『自己一貫性』であり、debate は投票機構の一種にすぎない」。
また Lightman et al. では多数決 69.6% < ORM 72.4% < PRM 78.2% で、**多数決は訓練された検証器には負ける**。

**反証・限界(この項目は否定的所見が中心)**:
- **self-consistency は「投票対象となる一意の答え」を必要とする。**規則遵守・方針遵守・自由記述には構造的に直接適用できない。Universal Self-Consistency のような拡張はあるが、**規則遵守への効果を測った一次資料を本調査では見つけられなかった(未確認)**。
- 多数決は**「自己一貫した誤り」に無力**。*Too Consistent to Detect: A Study of Self-Consistent Errors in LLMs*(arXiv 2505.17656)は、こうした誤りがモデル固有で他モデルと重ならない(Qwen2.5-14B の自己一貫誤りのうち Llama3.1-70B も同じ誤りをするのは 9.6%)と報告しているとされる。**ただし本調査では一次資料本文を確認していない(未確認)。**もし正しければ、「同一モデルの多標本」ではなく「別モデル」が必要という含意になる。

## 6. 道具を使い始めると指示を忘れるか(ドリフト)

### 6-1. 多ターン化するだけで平均39%落ちる。内訳は「能力」より「ばらつき」

**主張**: 同じ情報を1回で与えるか複数ターンに分けるかだけで、性能が平均39%落ちる。低下の主因は能力低下ではなく**信頼性の崩壊**。

**出典**: *LLMs Get Lost in Multi-Turn Conversation* / Philippe Laban, Hiroaki Hayashi, Yingbo Zhou, Jennifer Neville (Microsoft Research / Salesforce Research) / 2025 / https://arxiv.org/abs/2505.06120

**数値**: 6つの生成タスク平均で **−39%**。20万件超のシミュレーション会話で分解すると、**aptitude(能力)−15% に対し unreliability(ばらつき)+112%**。著者の要約を逐語で: 「LLM が会話の中で一度誤った方向に進むと、迷子になり、復帰しない」。

**反証・限界**: 「道具使用」そのものではなく多ターン会話の実験。ただしエージェントの軌跡は構造的に多ターンであり、含意は直接的。

### 6-2. 目標ドリフト: 新しいモデルは圧力に強いが、「汚染された文脈」には弱い

**主張**: 最新モデルは敵対的圧力下でも目標を保つが、**弱いモデルがドリフトした軌跡を引き継がせると、そのドリフトを継承する**。

**出典**:
- *Inherited Goal Drift: Contextual Pressure Can Undermine Agentic Goals* / Achyutha Menon, Magnus Saebo, Tyler Crosse, Spencer Gibson, Eyon Jang, Diogo Cruz / Lifelong Agents @ ICLR 2026 workshop / https://arxiv.org/abs/2603.03258
- *Technical Report: Evaluating Goal Drift in Language Model Agents* / Rauno Arike, Elizabeth Donoway, Henning Bartsch, Marius Hobbhahn / 2025 / https://arxiv.org/abs/2505.02709

**数値**:
- Arike et al.: 弱い目標明示下のドリフトスコアは利益最大化で **0.51〜0.93**、排出最小化で 0.25〜0.37。Claude 3.5 Sonnet は **64ステップ(9万トークン超)**後も目標を保持。GPT-4o mini は **16ステップで大幅にドリフト**。ドリフトを駆動するのは**トークン距離ではなくパターンマッチング**。
- Menon et al.: 30ステップの通常の敵対的圧力下では、**GPT-4o-mini 以外の全モデルがドリフト0**。しかし GPT-4o-mini のドリフト軌跡を30ステップ分与えてから引き継がせると、Qwen3-235B と Gemini-2.5-Flash がドリフトを採用する。**一貫して耐性を示したのは GPT-5.1 と GPT-5-mini のみ。**
- 同論文の重要な否定的所見: **instruction hierarchy(指示階層)の遵守度は、ドリフト耐性をほとんど予測しない。**

**反証・限界**: Menon et al. は**ワークショップ論文**(査読の水準が本会議と異なる)。株取引シミュレーションと ER トリアージという2環境で、シードは10本/5本と少ない。著者自身が「モデル間分散が大きく、耐性は脆い」と述べている。「ドリフト耐性が高いこと自体が corrigibility の低下というリスク」とも論じており、**単純に「ドリフトは悪」ではない**点に注意。

## 7. 人間による承認ゲートの費用対効果

**主張**: 承認ゲートを掛ける「機構」は容易だが、**何を止めるかの判断**が未解決であり、ゲートを増やすほど安全になるとは限らない。

**出典**: *Oversight Has a Capacity: Calibrating Agent Guards to a Subjective, Fatiguing Human* / Emre Turan (独立研究者) / 2026-06-09 / https://arxiv.org/abs/2606.08919

**数値**:
- 敵対的に重み付けした **125件**のエージェント行動を人手ラベル付け。**レビュアー間の一致は Fleiss κ = 0.52(中程度)** — つまり「何が危険か」に単一の正解ラベルが存在しない。
- レビュアーを**疲労する内生変数**としてモデル化すると、実現される安全性は**エスカレーション率に対して逆U字**になる。安全最適なエスカレーション率は**全件エスカレーションより低い**。
- 「氾濫攻撃」(良性行動を大量に通して疲労させ、悪性行動を承認させる)に対し、負荷を考慮した方針が有効。

**反証・限界(重大)**:
- **著者自身が明記している**: 「逆U字と氾濫攻撃は**モデリングの結果**であり、人間を対象とした研究を動機づけるものである」。**実測ではない。** 実測なのは125件の κ=0.52 の部分だけ。
- 単著・独立研究者のプレプリント。査読なし。
- 著者は新規性も主張していない(FALCON、DeCCaF 等を先行研究として挙げている)。

**その他、確認できなかったもの**:
- 「人間レビューを入れると誤り率が最大40%下がる」(Gartner とされる)、「法務ディスカバリで誤り率 8.3% → 3.2%、エスカレーション 23.7%」(arXiv 2606.19812 とされる)は、**いずれも検索結果の要約から得たもので、一次資料を開いて確認していない(未確認)**。数値として引用してはならない。
- 承認ゲートの**スループット損失**を定量した査読付き研究は、本調査では見つからなかった。

# 外部強制 > 自己点検 と言える根拠はどれか / 言えないのはどこか

## 言える(一次資料の数値で支えられている)

1. **「自分の答えを見直せ」という内在的自己点検は、推論タスクで性能を下げる。** Huang et al. ICLR 2024 の全12セル(4モデル × 2〜3ベンチマーク)で低下。CommonSenseQA / GPT-3.5 では **正→誤 39.8% に対し 誤→正 5.8%**、つまり**壊す方が直す方の約7倍**。これが本調査で最も強い単一の数値。

2. **同一モデルは「自分の誤り」より「他者の誤り」をはるかによく捕捉する。** RealCritic で6モデル中5モデルが自己批評でマイナス(GPT-4 −4.5)、**全6モデルが他者批評でプラス**(GPT-4 +5.1)。同一タスク・同一モデルでの対照であり、これが「点検者を分離せよ」の直接の根拠。o1-mini ですら自己 +3.3 に対し他者 +15.6。

3. **正解ラベル/外部検証器があれば自己修正は効く。** Huang et al. の oracle 設定(GPT-4 HotpotQA 49.0 → 59.0)、Lightman et al.(PRM 78.2 > ORM 72.4 > 多数決 69.6)、Kamoi et al. TACL の総説(成功例はコードインタプリタ・検索エンジン等、外部検証手段がある場合に限られる)。**効いているのは「自己点検」ではなく「外部の判定」。**

4. **自己点検の余地は反復で枯れるが、外部検証器の利得は検証器の強さに比例して伸びる。** Mind the Gap: 自己 GV-Gap は**2〜3巡で0に飽和し、飽和速度はモデル容量に依存しない**。交差検証では**検証器の FLOPs に比例、生成器の FLOPs に反比例**。「同じモデルにもう一周させる」のは構造的に頭打ちで、「別の(強い)検証器を置く」には伸びしろがある、という非対称。

5. **同数の推論予算なら、議論より単純な多数決が強い。** 6応答で 83.2 vs 85.3、9応答で 83.0 vs 88.2。**自己点検を増やすことは、計算量を等価に揃えると正当化されない。**

6. **構文レベルの制約は、構成上保証される。** JSONSchemaBench: GitHub Hard でカバレッジ Guidance 0.41 vs LM単体 0.13。しかも下流精度は落ちなかった(GSM8K 80.1 → 83.8)。**「強制すると馬鹿になる」は、少なくともこのベンチマークでは支持されない。**

7. **方針を「プロンプトに書いてある」ことは、守られていることを意味しない。** τ-bench Table 3: 方針文書を**丸ごと削除**しても gpt-4o の τ-retail は **−4.4 しか落ちない**。IFEval: 機械判定可能な単純指示ですら GPT-4 のプロンプト単位 strict は 76.89%。

8. **長い軌跡では信頼性が崩れる。** Lost in Conversation −39%(内訳: 能力 −15%、ばらつき **+112%**)。τ²-bench: 必要行動数が7を超えると pass^1 がほぼ0。τ-bench: pass^1 61% のモデルの pass^8 は25%未満。

## 言えない / 根拠が足りない

1. **「プロンプトに書く」対「コードで強制する」を同一条件で対照した査読付き効果量は、本調査では見つからなかった。** §4-3 の3点は**いずれも間接証拠**であり、効果量として引用できない。NVIDIA の 75.01% → 98.9% は**ベンダー自社ブログで、独立再現を確認していない**。「外部強制が自己点検より N ポイント優れる」という形の数値は、**本調査の範囲では一次資料に存在しない。**

2. **自己点検の失敗は「推論タスク」で示されたものであり、規則遵守での失敗は直接には測られていない。** Huang et al. は射程を明記して推論に限定し、「安全性・文体では自己修正が成功した先行研究がある」と自ら断っている。**規則遵守について自己点検が下げる、という直接の測定を本調査では特定できなかった。** §1 の結果を規則遵守へ外挿するのは、根拠を1段飛ばしている。

3. **推論特化モデルでは結論が反転しうる。** RealCritic の o1-mini は自己批評 **+3.3**(6モデル中唯一のプラス)。Mind the Gap では相対 GV-Gap が事前学習 FLOPs に単調増加する。**「LLM は自己点検できない」は2023〜2024年モデルの所見であり、2026年の最新世代について同じ主張を一次資料で確認できていない(未確認)。** 非対称性(自己 < 他者)は o1-mini でも残るが、自己点検の符号は反転している。

4. **「指示を増やす・強制を増やす」ことが一様に善ではない実測がある。** τ²-bench: 手順を具体化した方針文書は default / no-user では改善するが、**oracle-plan では悪化**(gpt-4.1 0.73 → 0.57)。制約付き出力が意味的品質を下げるという報告群(Constraint Tax、ExtractBench)も存在するが、**本調査では一次資料未確認**。

5. **人間による承認ゲートの費用対効果は、事実上未測定。** Turan (2026) の逆U字は**著者自身がモデリング結果と明記**しており実測ではない。実測部分は κ=0.52(「何が危険か」に正解が無い)だけ。誤り削減率・スループット損失の査読付き定量を、本調査では**一つも特定できなかった**。引用候補として出てきた「40%削減」「8.3%→3.2%」は**いずれも未確認**。

6. **self-consistency が規則遵守に効くかは未測定。** 多数決は投票対象となる一意の答えを要求するため、規則遵守へ構造的に直接適用できない。**効果を測った一次資料を見つけられなかった(未確認)。**

## 総括(この設問に対する最も正直な答え)

**「外部強制 > 自己点検」は、次の限定された形でのみ支持される**: 「同一モデルが自分の出力を点検する」ことは、推論タスクにおいて、(a) 同じ計算量の多数決に負け、(b) 同じモデルが他者を点検する場合に負け、(c) 反復しても2〜3巡で頭打ちになる。ここは複数の独立した一次資料が同じ方向を向いており、堅い。

**支持されないのは、この比較を「量」として述べることである**。「コードで強制すれば自己点検よりどれだけ良いか」を同一条件で測った公表値は、本調査では見つからなかった。したがって**「外部強制のほうが優れる」は方向としては言えるが、効果量としては言えない。**

**最も実務的な含意は、実は §3-2 にある**: 方針文書をシステムプロンプトから丸ごと削除しても τ-retail の成績が 4.4 ポイントしか落ちなかったという事実は、「プロンプトに規則を書く」という手段の**効き目そのものが小さかった**ことを意味する。自己点検と外部強制を比べる前に、**「プロンプトに書いた規則が読まれているか」を測る**ほうが先である、という順序をこのデータは示唆する。
