## 解決(2026-09-16 12 時、L-176〜L-177)

**真因は `.claude/settings.json` の上位キー `_停止前の設定`(辞書型の未知キー)。**
2026-09-13 13:55(オーナー「フックを一回とめろ」L-160)に止めた設定を同じファイルの中に退避した瞬間、
Claude Code の設定スキーマ検証が `hooks` を「無かったもの」として読み始めた。信頼の旗は原因ではなかった。

**切り分けの方法**(再現できる): 別プロセス `claude -p "Bash で ls を実行して" --allowedTools Bash --model haiku --settings <コピー>`
を走らせ、PreToolUse 全件に配線された `move_budget.sh` が書く `.claude/state/move_counter` の更新時刻で判定する。

| グループ内の鍵だけ剥がす | 走らない |
| `hooks` + `_停止の記録`(文字列) | 走る |

**この会話のプロセスも拾った**: 直した直後、保護パスへの Write を 1 回目は ③(b) が、ゴールを開いた後の 2 回目は **③(a) が止めた**(この会話で最初の発火)。UserPromptSubmit の `owner_turn_digest.sh` も発火した。出力は `ACTION_LOG` 037。
