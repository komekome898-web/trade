## 4. リードの見立て — 本当の欠陥は 4 点(自己批判)

1. **動機と検定が切り離されていた。** M3 の動機文(§0「利益単位 = 1.2×vola」)は**事実として誤り**
   だったのに、検定は「有効」に回り、棄却まで到達した。**動機が偽でも検定が成立するということは、
   検定が動機から独立に回っていた**ということ。オーナーの「意図を汲み取ってほしかった」に対する
   最も鋭い自己批判はここ。
2. **掃引した軸がすべて「戦略パラメータ」で、「状態(いつ効くか)」の軸がほぼ無かった。**
   パラメータ面はパラメータ 4 軸を全部動かしてもほとんど動かず、一方で唯一の状態軸(嵐)は
   **1 本でパラメータ 4 軸の全レンジの約 2 倍**を動かし、2 系統の測定で符号が再現した。【当時の測定。数値は破棄済み】
   にもかかわらず結論は「方向は正しいが量が足りない」で線を閉じた。
3. **その唯一の効果を検出できる検出力の研究を、一度も設計しなかった。**
   盲検監査 K は L22(嵐後)を **n=15 で t=0.49、MDE 大幅未満 = 再計算不能**と判定している。【事実】
   つまり「量が足りない」は**測定の結論ではなく、検出力不足の言い換え**だった。
   検出力はすべてパラメータ軸(後からほとんど動かないと分かった軸)に注がれた。
4. **棄却の出口に「部品を残す」機構が無い。** Phase-2 の単位はすべて 採用/棄却 で終わり、
   「単体で正だった部品を銀行に入れて次の合成に使う」ループが規約に存在しない。
   第31報 §3 が 4 つの設計事実を対称MM族へ持ち越しているが、**制約(やるな)として**であって
   **部品(使え)として**ではない。

**構造的な既視感**: この 4 点は 2026-09-08 の外部生態系レビュー(`2026-09-08_external_ecosystem.md`)で
オーナーに 2 回差し戻されたときと**同じ形** — リードは「与えられた枠の中の可否」を答え、
「枠そのものが自分の盲点ではないか」を自分で問えていない。§2「状態変数がすべて価格由来の内生量」
という発見と、本件の「掃引軸がすべて戦略パラメータ」は**同一の欠陥の別の顔**である。【推定】

### 10.3 構造的な原因 — 敵対者が片側にしかいない【推定、ただし 10.2 の分布が支持】
本 project の規律(事前登録・封印・盲検監査・best-of-N 帰無・多重性台帳)は**すべて偽陽性を防ぐため**に
設計されている。**偽陰性を防ぐ機構は 1 つも無い。**
結果として、保守的な前提は誰にも攻撃されず、楽観的な前提だけが攻撃される。
**誤差は片方向にだけ蓄積し、その蓄積が「確立済み知識」として次の研究の入口に置かれる**(CLAUDE.md §5)。
10.2 の上位前提が**全部悲観側**なのは偶然ではなく、この非対称の帰結である。

もう一つ: **陽性には前向きゲートがあるが、陰性には無い。** 陽性は OOS・ペーパー・実弾と何度も再審される。
陰性は扉を閉じてそれきりで、二度と検算されない。だから陰性の誤り率だけが**測られないまま**になる。

### 10.4 どう整理すべきか — 5 つの動き(リード案、オーナー討議中)
1. **保存単位を「結論」から「測定」へ。** KNOWLEDGE の各行に 対象 / 前提(コスト・約定・データ・条件付け)/
   **n と MDE** / 監査状態 / 判定日 を必須化。**MDE を書けない主張は陰性として引用できない。**
2. **「陰性」と「不明」を語彙として分離。** 陰性 = 検出できる検出力で不在を測った。不明 = 検出力が足りなかった。
   現状は両者が同じ文で書かれ、同じように扉を閉じている(監査は 10 件を判定不能に格下げした)。
3. **棄却に「射程」を必須化し、射程外の引用を禁止。** 何を測ったかと**何を測っていないか**を併記する。
   規則: **新しい単位は、過去の陰性を根拠に構成要素を族から除外してはならない。**
   除外するなら「本単位では測らない」と書く。「既に棄却済み」は書けない(M2 の vr 削除がこの誤り)。
4. **悲観側の前提にも敵対者を立てる(最重要)。** 事前登録の前提表に**バイアスの向き**(この前提が誤ったとき
   判定はどちらに動くか)を明記し、**棄却方向に効く前提にも一次資料か実測を要求**する。
   現状この要求は採用方向に効く前提にしか掛かっていない。
5. **訂正の前向き伝播。** 前提が覆ったら、その `再判定対象` に載る主張を**機械的に**「確立」から「要再判定」へ
   降格する。現状 L9 は監査で覆ったのに KNOWLEDGE 25 行目は無傷 = 訂正に前向きの経路が無い。

### 10.5 このあと(結論は急がない)
再判定の積み残しは「本題の前の事務作業」ではない。前提レジスタ第 2 位の下流は
**「初期報告 a〜l 経由の全棄却」**であり、実測の約 20 倍のコストで棄却された族がそこに含まれうる。
規模の見積りも、着手順も、まだ決めない。

## 11. 全捨ての実行(2026-09-08、オーナー承認)

### 11.1 オーナーの決定
- 「盲目的に全捨てが妥当。**KNOWLEDGE.md すらも捨てれば**あなたは同じ過ちを繰り返さないでしょう」

  見つけた戦略を、**片っ端から検証し知見を深め、最強の戦略へブラッシュアップしていく**。
  これが本来私がやりたかったこと」
- 順序: **暗号資産 → FX → 株**。
- 分類(合意): 活かす = データ / 戦略案 / 失敗を繰り返さない仕組み / 会話の記録 / 道具・実装 / オーナーの実戦知。
  改良 = 双方向監査 / テスト手法 / プロジェクト体制(**枠組みの監査**を追加)。捨てる = 全検証結果・全分析結果。

### 11.2 リードが撤回した提案
「固い測定は 1 件ずつ再入国させる」案は**撤回**。理由(オーナー指摘 + リード自認):
(a) 選別者がリードになり、壊れた判断を生んだ本人が保存対象を選ぶ制度になる。
(b) 監査の「再現」判定も同じ装置による判定で、無汚染の審判は存在しない。
(c) 再入国の審査コストは再測定とほぼ同じで、間違った事前分布を持ち込むリスクだけが増える。
(d) **保存しようとする衝動そのものが病巣**であり、再入国制度はその衝動が手続きの服を着たものだった。

### 11.3 捨てる境界(リードの裁量が入らない判定基準)
> **その文が「相場はこう振る舞う」という主張を含むか。**
> 含む → 捨てる(数値・法則・機構の説明・棄却・優先順位、例外なし)。
> 含まない → 残る(データ、コード、手順、事故の記録、会話、外部世界の事実)。

### 11.4 例外はひとつだけ
**どのデータ区間をいつ何の選択に使ったかの記録**は残す(`docs/DATA_CONSUMPTION_LOG.md`)。
これは相場の主張ではなく**私たち自身の履歴**であり、**再測定で復元できない唯一のもの**。
捨てると、既に構成を選んだ区間で「新鮮な検証」を行って自分を騙せてしまう。

### 11.5 正直な限界
ファイルを消してもセッション内のリードの頭からは消えず、次のセッションのリードは
**今から書く文書に seed される**。したがって捨てる効果は「何を消したか」ではなく
**「後継の文書に何を書かないか」**で決まる。仕組みでは担保しきれず、規律として残る。

## 12. 規定の採用(2026-09-08、L-020)— 本議論の帰結

オーナーが研究の形を規定として採用した。**判定は途中経過であって出口ではない。**

```
案 → 検証 → なぜそうなるのかの理解 → 改良 → 再検証 → …
```

旧来の形(案 → 検定 → 判定 → 終了)は、本書 §4-1〜§4-4 の 4 つの欠陥を構造的に生む器だった:
機械全体の pass/fail しか返さないから「どこが強いか」が出ず(§4 冒頭)、
出口が判定しかないから部品が残らず(§4-4)、
「なぜ」を問わないから動機と検定が切り離されたまま回り(§4-1)、
理解が無いから次に掃引する軸をパラメータ側に取り違えた(§4-2)。
**ループを既定にすることは、この 4 つを同時に塞ぐ。**

ただしループは放置すれば「通るまで試す」に堕落し、事前登録の意味を消す。
線引きを `research-protocol` §0.3 に置いた: **改良は「なぜ」から導かれること**(機構の説明なしに
水準を動かすのはパラメータ探しであって改良ではない)、1 周 1 機構仮説、周回数は帰無の多重性に算入、
判定は設計ごとに一度だけ、機構仮説が 3 周入れ替わったら止めて理解できていないと報告する。

**これで本議論は終了。** 記録は本書 §1〜§12、台帳は L-017 / L-018 / L-019 / L-020。
