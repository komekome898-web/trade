## 2. オーナーの所感(2026-09-08、要旨)

1. 「未熟なコードをぱっと見で分析させた私が悪かった」
2. **求めていたのは「コード通りに動かしたら利益が出るのか確認して」ではない。**
   「コードから**戦略意図を汲み取り**、その戦略の**強み弱みを分析**し、**現環境に適応した戦略を構築**して欲しい」
3. 結果は「分析したまま(しかも分析も間違い)でバックテストし棄却封印」になった。
4. 「強い部分の利益率をあげ、弱い部分の避け方(嵐察知など)を模索してほしくて、色んなパラメータを
   網羅的にテストさせた。しかしグリッドの選定をあなたに任せたために、効果的なものではなく
   **ただグリッドしやすいパラメータを適当な幅で検証したほぼ意図のないもの**になったのではないか」

## 3. 記録との突き合わせ(リード。反論ではなく事実の整理)

**オーナーの見立てが記録と一致する点**
- 検定の単位を**「機構全体」**に置いたのはリードの設計判断であり、両事前登録の §0 に明記されている
  (M2「30秒スケール・在庫つきの**機械全体**は未検証 — それだけを検定する」、M3「検定対象は
  **v37 の機械全体**であり、部品 single ではない」)。**機械全体の検定は pass/fail しか返さない** —
  「どの部分が強いから伸ばす」という出力が構造的に出ない。【事実】
- 出発点の分類(2026-08-21「核は棄却済み系統、未検証は周辺3要素」)が下流すべてを規定した。
  「この機械の強みは何か」という問いは、**分類の時点で議題から外れていた**。【事実】
- 分析の誤り(`exit_setting` 死にコード)は実在した。ただし §4 参照。

**記録が異なる点(公平のため)**
- M2 は逐語移植ではなく **12 行の現代化写像**(vr レジーム → S7 両側フロー窓、壁手前 → queue-realistic、
  SFD → ベーシス異常ガード、複利 → 分離)。「コード通りに動かした」のは M3(忠実移植)のみ。【事実】
- M4 の 4 軸(按分・嵐・段数・間隔)は**オーナーの指示そのもの**で、リードが選んだ軸ではない
  (第31報 冒頭「オーナー指示への直接回答」)。ただし**各軸の水準と、軸をどう解釈するかは
  リードが決めた** — そこは §4 の批判が当たる。【事実】

## 4. リードの見立て — 本当の欠陥は 4 点(自己批判)

1. **動機と検定が切り離されていた。** M3 の動機文(§0「利益単位 = 1.2×vola」)は**事実として誤り**
   だったのに、検定は「有効」に回り、棄却まで到達した。**動機が偽でも検定が成立するということは、
   検定が動機から独立に回っていた**ということ。オーナーの「意図を汲み取ってほしかった」に対する
   最も鋭い自己批判はここ。
2. **掃引した軸がすべて「戦略パラメータ」で、「状態(いつ効くか)」の軸がほぼ無かった。**
   第31報の 51 セル面は、按分・TP幅・段数・間隔の 4 軸を全部動かして **unit bps が 0.66bps しか
   動かない**。一方で唯一の状態軸(嵐)は **+1.2bps/unit** を 2 系統の測定で再現した
   — **1 本の状態軸が、4 本のパラメータ軸の全レンジの約 2 倍を動かした。**【事実】
   にもかかわらず結論は「方向は正しいが量が足りない」で線を閉じた。
3. **その唯一の効果を検出できる検出力の研究を、一度も設計しなかった。**
   盲検監査 K は L22(嵐後)を **n=15 で t=0.49、MDE 大幅未満 = 再計算不能**と判定している。【事実】
   つまり「量が足りない」は**測定の結論ではなく、検出力不足の言い換え**だった。
   検出力はすべてパラメータ軸(後から 0.66bps しか動かないと分かった軸)に注がれた。
4. **棄却の出口に「部品を残す」機構が無い。** Phase-2 の単位はすべて 採用/棄却 で終わり、
   「単体で正だった部品を銀行に入れて次の合成に使う」ループが規約に存在しない。
   第31報 §3 が 4 つの設計事実を対称MM族へ持ち越しているが、**制約(やるな)として**であって
   **部品(使え)として**ではない。

**構造的な既視感**: この 4 点は 2026-09-08 の外部生態系レビュー(`2026-09-08_external_ecosystem.md`)で
オーナーに 2 回差し戻されたときと**同じ形** — リードは「与えられた枠の中の可否」を答え、
「枠そのものが自分の盲点ではないか」を自分で問えていない。§2「状態変数がすべて価格由来の内生量」
という発見と、本件の「掃引軸がすべて戦略パラメータ」は**同一の欠陥の別の顔**である。【推定】

## 6. リード提案(2026-09-08、オーナー回答待ち)

本書 §4 を踏まえ、リードから 3 案を提示した(詳細は会話。要旨のみ記録)。

- **提案 A: 環境差分の診断単位**。「2019-2020 に実際に稼いだ機械が、なぜ今は負けるのか」を
  機械自身の動作変数(40分ボラ、レンジ幅、vr、2.0×vola 変位後の反転幅)で年次比較する。
  価格由来の変数は Binance / bitbank の 2017〜 で再構成可能【事実】、板由来の変数
  (0.1BTC 壁の頻度・スプレッド)は 2019 年分が存在せず再構成不能【事実】。
  どちらの結果でも決定に効く: 反転幅が減衰していれば「死んだレジームの遺物」という一般法則が
  全族に効き、減衰していなければ**当方のリプレイ/コスト模型を疑う**根拠になる。
- **提案 B: 単位の型を増やす(状態軸単位)**。戦略コアを**棄却済み族から凍結して固定**し、
  掃引するのは**状態変数**にする型を Phase-2 に追加。M3 エンジンは再現ゲート15項目 PASS 済みで
  即使える。トリアージ #70(ポジショニング)は本型の最初の実例になる。
- **提案 C: 規約の修正**。(i) 棄却報告に「部品分解」の節を必須化し、単体で正だった部品を
  部品銀行に登録する。(ii) **パラメータ面が平坦だったこと自体を、状態軸単位へ昇格させる根拠**
  として規約に書く(平坦 = 答えはパラメータではなく条件、というシグナル)。
