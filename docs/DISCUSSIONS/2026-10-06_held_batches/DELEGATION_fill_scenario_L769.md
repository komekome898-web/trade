## 作るもの
1. **約定の決まり**(取引所の模型に、選べる決まりとして足す。今の決まりは変えない: 既存の試験と、オーナーが作った環境の決まりを壊さない):
   - 指値を足が閉じた時刻 T に置いたら、足 [T, T+60) から当てる。
   - その足の 安値 ≤ 指値の値段 ≤ 高値 なら、指値の値段で約定。
   - 約定する向きに範囲の外(買いの指値 > 高値、売りの指値 < 安値)なら、その足の始値で約定(L-770 a)。
   - 約定しない向きに範囲の外なら、約定しない。
   - 良い側・悪い側(道の約定の範囲の楽観側・悲観側)で建ての当て方は同じ。違うのは下の 2 の決済だけ。
2. **建てと一緒に出す決済の指値**(L-770 b): 建ての指値と一緒に決済の指値を出す口(建ての約定で有効になる)。決済の値段は戦略が渡す(合図の足の終値から計算した値)。
   - 良い側: 建てが約定した足と同じ足の中で、決済の値段がその足の範囲に入れば約定(指値の値段で)。
   - 悪い側: 建てが約定した足の次の足から当てる。
   - 建てが一部だけ約定したら、決済の量はその約定した分。建てが約定しないまま取り消されたら、決済も消える。
   - 道の土台(`src/bot/bt/road/strategy.py`)から使える口にする。量の決め方は今の決まりのまま(建ては `size_per_level`、決済は建玉、`reduce_only`)。
3. **道の検査**: 約定の時刻・値段が、この決まりのとおりの足で起きているか(約定させた足の範囲の内側か、始値か)を確かめる。決済が建てと同じ足で約定した行は、楽観側にしか無いことも確かめる。
4. **記録**: 注文の表に、建てと一緒に出した決済の行であること(親の建ての注文の番号)を列で残す。SCHEMA の説明に、この約定の決まりを書く。

## 受け入れの場面(試験にする。期待の数は手計算で書く)
1. 足 t の終わりに買いの指値(値段 = 足 t の終値)を置き、足 t+1 の 安値 ≤ 値段 ≤ 高値 → 足 t+1 で指値の値段で約定。
2. 買いの指値が足 t+1 の高値より上 → 足 t+1 の始値で約定。売りの指値が安値より下 → 始値で約定。
3. 買いの指値が足 t+1 の安値より下 → 足 t+1 では約定しない。
4. 建ての買いと一緒に決済の売りの指値を出し、足 t+1 で建てが約定、足 t+1 の高値 ≥ 決済の値段: 楽観側は足 t+1 で決済が約定、悲観側は足 t+1 では約定せず、足 t+2 の範囲に入れば足 t+2 で約定。
5. 足ごとに置き直す決済の指値(足の終わりに取り消して新しい値段で置く): 次の足の範囲に入れば約定する(今の決まりでは一度も約定しなかった場面)。
6. 既存の `tests/road tests/bt` は全部通る(今の決まりを選んだ走らせの動きは変わらない)。
