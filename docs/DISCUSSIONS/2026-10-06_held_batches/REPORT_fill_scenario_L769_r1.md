### 作ったもの
1. **約定の決まり**: `FillSpec` に欄を 2 つ足しました。`bar_rule="range_open"` と `attached_exit="same_bar"|"next_bar"` です。
   - 2 つは両方置くか両方置かないかで、tier 2 のときだけ使えます。
   - 既定は None で、今の決まりのままです。既存の宣言の走らせの番号も変わりません。
2. **建てと一緒に出す決済の指値**
   - 取引所の模型: extra の鍵 `attached_to` を受けます。決済は建てが約定するまで量 0 で待ちます。
   - 建てが約定しないまま閉じたら、決済も閉じます(理由 `attached_parent_closed`)。
   - 建てが一部だけ約定して閉じたら、決済はその分だけ残ります(理由 `attached_parent_part_filled`)。
   - 建てが取引所に無い・既に約定せずに閉じている・決済の形が違うものは拒否します。
   - `attached_exit` を宣言していない走らせで使うと止まります。
   - 道の土台: `place_with_exit(売買, 値段, 段数, 合図, 決済の値段)` を足しました。決済の量は建ての注文の量で、reduce_only です。
   - close・flatten の「出ている決済の量」は、建ての約定の知らせの和(決済の量まで)から決済の約定を引いた量で数えます。
3. **道の検査 (vii)**(record.json の config.fill でその側が bar_rule を選んだ走らせだけ):
   - 約定した足で、範囲の内なら値段 = 指値、約定する向きの外なら値段 = 始値かを見ます。足の JSON に open が無ければ失敗にします。
   - それより前の当てる足で、約定していたはずの足が無いかを見ます。
   - 建てと同じ足で約定した決済が、楽観側だけにあるかを見ます。
   - (iii) には `attached_to` のつなぎの検査を、(v) には with_entry の量の検査を足しました。
4. **記録**
   - 注文の表に列 `attached_to` を足し、exit_kind に `with_entry` を足しました。SCHEMA の版は road-record-6 です。
