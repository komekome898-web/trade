# v37 の挙動の調べ(L-784「これそれぞれどういう挙動か調べて教えて」)

出所はすべて `docs/legacy/matilda_for_TaroCamp37.py` の行。量の言い方は、L-745・L-746・L-781 の決まりに置き換えたあとの形(sizemin = 1 段の量)。

## 1. ブレイク(break_flg)

- **判定**(v37:930-950。巡回ごと)
  - 上のブレイクの線 = 直近 range_count 本の高値 + 幅 × 0.5(v37:504-505)。
    - この線は、直近 range_count 本の高値が、2 倍の長さ(range_count × 2 本)の高値と違うとき、つまり高値を更新している間とブレイク中だけ、足ごとに書き足す(v37:503)。
    - 判定に使うのは break_delay 本前に書き足した線と、2 倍の長さの高値の、高い方(v37:933-934)。
  - 最良の買い値がこの線を越え、b_signal が −1 でなければ、上へのブレイク(break_flg = 1)。下も同じ形(v37:935・943)。
- **ブレイク中の建て**(v37:1001-1005)
  - レンジの逆張り(線の外で逆向きに建てる)をやめる。
  - ブレイクの向き(上なら買い)に段を積む。
  - ただし次のときは建てない。
    - b_signal がブレイクと逆向き(逆行を確認した)
    - 玉が無く、b_signal = 0
- **ブレイク中の決済**(v37:1027-1036)
  - ブレイクと逆向きの玉: 成行で閉じる。
  - b_signal = 0: 利確の指値。
  - b_signal がブレイクと逆向き: 緩めた利確の指値。
  - 玉が breakexitsize 段以上: 利確の指値。
  - それ未満: 利確の指値を出さない。
  - **ブレイク中は、時間(alert_count)での決済が無い**。時間で決済する枝はブレイクしていないときだけ(v37:1008-1026)。
- **解除**(v37:952-966): 上へのブレイク中に値段が中心より下に来たら、break_flg と b_signal を 0 に戻す。下も同じ形。
- **切る(break_delay = 0)**: 判定がまるごと動かない(v37:932 `if break_delay != 0`)。ずっとレンジの逆張りで、一方向に動くと段数の上限まで逆向きに積む。出るのは次の 3 つだけになる。
  - 利確
  - 緩めた利確
  - 時間(alert_count の 2 倍で成行)か反対の建ての合図による成行

**問題(この調べで見つかったこと)**: 今の仕様のままブレイク中を写すと、次の 2 か所が合わない。どちらもオーナーに聞く。
1. **ブレイク中の建ての値段**
   - 今の仕様は「1 段目 = 中心 ∓ entry_setting × ボラ」(L-771)。
   - ブレイク中の買いは、値段が中心より上(上のブレイクの線の外)にあるときに出る。そこで中心 − entry_setting × ボラ に買いの指値を置くと、今の値段からずっと下に置くことになる。
   - 原典は、今の値段のすぐ下の厚い板(ブレイク中は sizemin より厚い板、v37:831-834)に置いていた。
2. **ブレイク中の利確の値段**
   - 今の仕様は「中心 ± exit_setting × ボラ」(L-782)。
   - ブレイク中の買い玉は中心より上にあるので、売りの利確の線(中心 − exit_setting × ボラ)は建値より下になる。置いたとたんに次の足の始値で約定し(L-770 a)、損で閉じる。
   - 原典は、建値 + ボラ × step_exit ÷ 段数 より上の板に置いていた(v37:903-910)。

## 2. b_signal

- **数え方**(v37:512-534。ブレイク中の足ごと)
  - その足の出来高が、直近の出来高の平均を超えたときだけ数える。
  - ブレイクと逆向きの足は逆行。
    - 例(上へのブレイク中): 上ヒゲが下ヒゲと実体より長い足、または陰線。
    - b_signal を 1 → 0 → −1 と 1 つずつ下げる。
  - ブレイクの向きの足(下ヒゲが長い足、または陽線)は順行。b_signal をブレイクの向き(+1)にする。
  - 出来高が平均を超えない足で、expantion_flg が 0(値段がレンジの中心を逆にまたいだ後)なら、b_signal を 0 に戻す(v37:533-534)。
- **使うと何が起きるか**(原典)
  - 1 回の逆行で b_signal は 0 になり、利確の指値を出す。
  - 2 回続けて逆行すると b_signal は逆向きになり、建てを止め、緩めた利確の指値を出す。
  - 順行が来たら、またブレイクの向きに積む。
  - 原典の説明「**出来高のある逆行を検知して利確指値を出す 二回連続の逆行でポジブン投げ、順行するまで一旦エントリー停止**」(v37:75)。ただし、コードの「ブン投げ」は成行ではなく緩めた利確の指値(v37:1031-1032)。
- **使わない(b_signal をずっと 0 にする)と何が起きるか**
  - 玉が無ければ、ブレイク中は建てない(静観)。
  - 玉があれば、ブレイクの向きに積み続ける(v37:1002 の条件は「b_signal = 0 かつ玉が無い」だけを止める)。
  - ブレイク中の決済は、いつも利確の指値になる(v37:1029-1030 の b_signal = 0 の枝が先に当たる)。そのため breakexitsize は効かない。
  - ブレイクの判定の「b_signal が逆でなければ」はいつも成り立つ。

## 3. breakexitsize

- 効くのは、ブレイク中で b_signal がブレイクの向き(順行を確認した)のときだけ(v37:1033-1036)。
- 玉が breakexitsize 段以上なら利確の指値を出す。それ未満なら利確の指値を出さず、大きく伸びるのを待つ。
  - 原典の説明「**breakexitsizeで指定したポジ数までは利確指値を出さない(たまに数万幅とかとれる)**」(v37:76)。
  - v37:113「**ほんまの大動きのときに大値幅とって損失の補填ができるよ**」。
- breakexitsize が段数の上限より大きいと、順行を確認したブレイク中は利確の指値が一度も出ない。出るのは、逆行(b_signal が変わる)・解除・逆向きの合図の成行のときだけ。上の 1 のとおり、ブレイク中は時間での決済も無い。
- ブレイクを切った走らせ・b_signal を使わない走らせでは効かない。

## 4. step_exit

- L-782 で通常の利確は「中心 ± exit_setting × ボラ」になったので、step_exit が効くのは緩めた利確(exit_flg 2)だけ(L-783 問い 1 (a))。
- 緩めた利確が出るのは次のとき。
  - ブレイクしていない: alert_count 分たった、または建値が中心より悪い(売り玉で建値 < 中心、買い玉で建値 > 中心。v37:1012-1014・1020-1022)。
  - ブレイク中: b_signal が逆向き。
- 値段(v37:881・898・912)
  - x = ボラ × step_exit ÷ 持っている段数。
  - 売り玉の買い戻し = 中心 と 建値 − x の**高い方**。
  - 買い玉の売り = 中心 と 建値 + x の**低い方**。
  - つまり「中心」と「建値から x だけ有利な値段」のうち、建値に近い側(儲けが少ない、または損の側)で出す。
- step_exit を大きくすると、x が大きくなり、中心が選ばれやすくなる。建値が中心より悪いときは、損で中心まで戻ったところで出る(v37:127「**ポジションがレンジ中央値より悪いと、損切指値を出すよ**」)。
- step_exit を小さくすると、x が小さくなり、建値のすぐそば(わずかな儲け)で出やすくなる。
- 段数が増えるほど x は小さくなる。
