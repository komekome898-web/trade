## 1. 意図: マチルダは何をしたい機械か

### 1.1 原典が自分で言っていること

- 【事実】機械の名乗りは「**レンジでナンピンする子 「マチルダ」ちゃん**」「**レンジの上方でS、下方でL、中央付近で決済するよ。**」(v37:19-20、v52:22-23 に同文)。
- 【事実】勝ち負けの自己説明は「**レンジである限り損はしない。損する時はレンジブレイク時と利確指値に届かない長期間のポジ保有時**」(v37:21、v52:24)。
- 【事実】使う場面は「**あくまで裁量してない時 or ポジとりにくいクソレンジ相場で使ってね。**」(v37:22、v52:25)、「**レンジである確度が高いと思った日にこの設定にしてね。**」(v37:107)。
- 【事実】在庫の膨らみが危険の中心だと書いている:「**基本はナンピンBotなのでここの調整ミスると危険だよ。**」(v37:108)。
- 【事実】動きが小さすぎるときは建てない:「**どちらかがこの数値以下の場合エントリーをしなくなるよ。ポジポジ病防止の役目をするよ。**」(v37:131、v52:157)。
- 【事実】儲けの源泉を「入る距離と出る距離の差」と書いている:「**ここをいじる際は必ず entry_setting > exit_setting となるようにしてね。この差分が利益になるからね。**」(v37:139)。
- 【事実】板の厚い所を盾にする:「**このBotは指値を大きめの板の2円前に出すの。**」(v37:159、v52:169)。
- 【事実】ブレイクは「怖いので守る」対象として扱われている:「**この前のサーキットブレイクにビビったので、ブレイクの判定と挙動の変更**」(v37:52)、「**sizemaxに余裕があるならブレイク損切りはいらないのでそういう人は 0 も試してみてね。私はこわくてよーせん）**」(v37:148-149)。
- 【事実】一方で、ブレイク時の大きな値幅で損を埋める狙いもある:「**ほんまの大動きのときに大値幅とって損失の補填ができるよ。**」(v37:113)、「**breakexitsizeで指定したポジ数までは利確指値を出さない（たまに数万幅とかとれる）**」(v37:76)。
- 【事実】v52 では方向の検知をブレイクから vr に替えた:「**41から 不安定なブレイクをやめて、レンジ幅÷ボラ　の数値でトレンド検知するようになりました。**」「**vrが大きくなれば一方的なトレンドって判断します。**」「**例えばデフォルトだと、vr>10のときはヒゲ狙いで逆張り、vr<10のときはレンジ内で細かくポジ取って損切りはしない。って感じ。**」(v52:122-125)、「**ブレイク削除タイプの真性逆張りナンピン仕様**」(v52:86)。
- 【事実】v52 では時刻の偏りも使う:「**time_anomalyを1にすると、時刻トレードの逆ポジはとらず、順ポジをとった場合は時間がくるまで利確・損切りしない**」(v52:88)。

### 1.2 意図のまとめ(上の文と下の動きから)

1. **どんな相場で**: 一撃の大きな動きが無く、価格が直近の高安の間を行き来する相場(v37:19-22)。ただし幅が狭すぎる相場は避ける(v37:131-134、v52:157-158)。v52 ではさらに「レンジか一方的か」を vr で見分け、局面ごとに設定の組を替えようとしていた(v52:122-130, 426-457)。【事実】
2. **何を狙うか**: 直近 `range_count` 本の高安の中心から `vola×entry_setting` 以上離れた側で逆向きに建て、中心寄りで決済する往復(v37:978-980, 995-998、v52:931-934, 1118-1121)。離れるほど段を積み(ナンピン、v37:840-850、v52:752-762)、段数が増えるほど 1 段あたりの利確幅を割って早く逃げる(v37:71, 881、v52:817)。【事実】
3. **何を避けたいか**:
   - 在庫の膨らみ: 段数上限 `order_count` と `sizemax`(v37:835, 843、v52:733, 755)。【事実】
   - 長く捕まること: 側が変わってから `alert_count` 分で決済を緩め、2 倍で成行(v37:1010-1022、v52:946-950)。【事実】
   - 一方的な動き: v37 はブレイク判定で逆側の玉を成行で切り、条件つきでブレイク方向に積む(v37:930-950, 1001-1005, 1027-1036)。v52 は vr で設定の組を替える(v52:426-457)。【事実】
   - 取引所の都合: SFD(先物と現物の乖離料)の境の近くでは建てない(v37:972-973、v52:913-922)、日付またぎ・メンテ前後で寝る(v37:31, 325-338)。SFD の意味は bitFlyer の仕組みについての私の知識で、原典には書かれていない【推定】。
4. **オーナーの言語化(§7)との対応**:
   - §7-1「中心から離れた位置で建て、中心近くで利確」= v37:978-980 の建ての引き金と v37:898, 912 の中心までの緩和、v52:1118-1121 の ssp/lsp/sep/lep。【事実】
   - §7-2「動きが少なすぎるときは待つ」= `range_setting`(v37:976, 993、v52:927)。v37 には `vola_setting` もあったが注釈で消されている(v37:133)。【事実】
   - §7-3「大きく動いた後、新しいレンジ中心に戻ってきたら建て始める。一方的な値動きを静観する」= v37 のブレイク解除 `break_off_judge`(価格が `range_center` を逆にまたぐと `break_flg=0`、v37:952-965)と、`expantion_flg` の解除(価格が中心の逆側に来ると 0、v37:595-596)。ただしコードは静観だけではない: ブレイク中でも `b_signal == break_flg`(出来高のある順行足)なら**ブレイク方向に建てる**(v37:1001-1005)。静観になるのは「玉が無く b_signal=0」のとき(v37:1002-1003)と、逆行足が続いて `break_flg == -b_signal` になったとき。【事実】
   - §7-4「負けはレンジ中の突然の一方向の動き。ヘッジに時間成行・逆転順張り」= 時間成行は `exit_flg=3`(v37:1010, 1018 → 1096-1098)、逆転順張りはブレイク中の `entry_flg = break_flg`(v37:1005)。v52 ではブレイクが消えたので逆転順張りは無い(v52:86)。【事実】

## 5. 分からないこと

コードからもコメントからも決められないもの。推測で埋めない。

1. **v52 の inner/outer の、オーナーが実際に使った値**。出荷値は 2 つの組が同じ(v52:128, 130)で、`vr_setting` はコメントの例(10、v52:125)と値(100、v52:129)が違う。どちらで動かしていたか分からない。
2. **「ヒゲ狙いで逆張り」(v52:125)を組のどの値で表すつもりだったか**(entry_setting を大きくするのか、段数を減らすのか等)。「損切りはしない」を `alert_count` を大きくして表すつもりだったのかも分からない。
