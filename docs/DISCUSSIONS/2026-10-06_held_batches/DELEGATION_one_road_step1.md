## 作るもの
1. **量のツール**: `size_per_level(margin_jpy=200000, use_ratio=0.70, levels, price, quote_ccy, usdjpy_at_entry=None) -> BTC`。円建ては 200000×0.70÷levels÷price、ドル建て(USD・USDT)は 200000×0.70÷levels÷(price×USDJPY)。0.001 BTC 未満は切り捨て。**小数の誤差で落ちないこと**(例: 0.028 が 0.027 にならない。整数か Decimal で計算)。証拠金は引数で受けるが既定は 20 万円で、前の損益を足す口を作らない。
2. **帳簿のツール**: 約定の列(時刻 ns・売買・量・値段・通貨)を受け、`MarginAccount` に通して
   - 約定ごとの表: 時刻・売買・量・値段・その後の建玉・平均の建値・確定損益(円、累計と今回分)
   - 取引ごとの表: 最初の約定の時刻・最後の約定の時刻・段の数(建てる向きの約定の数)・最大の建玉・保有時間(最初の約定から建玉 0 まで)・確定損益(円)・状態(閉じた / 途中)
   - 取引の区切り: 建玉 0 → 0 で 1 取引。ドテン(1 つの約定で向きが変わる)は、閉じた側が 1 取引、新しい側は途中として続く。データの終わりで建玉が 0 でない取引は「途中」とし、閉じた取引の数・損益の合計に入れない(別に出す)。
   - ドル建ては、確定損益を確定時刻の USDJPY で円にする(`FxRates`。USDT は USD とみなす。相場が無ければ止まる。1 とみなさない)。
   - まとめ: 閉じた取引の数・損益の合計(円)・途中の取引の数。
3. **検査のツール**(`scripts/road/check_outputs.py` と、関数として呼べる本体):
   - (a) 走らせの置き場にある約定の列からまとめを帳簿のツールで計算し直し、置き場に書かれたまとめと 1 つでも違えば失敗。
   - (b) 約定ごとに、その分の 1 分足があるか、約定の時刻が属する足の始まりが分の区切りにそろうか、値段がその分の安値以上・高値以下か。足は引数で受ける(データの読み込みはこの段では作らない)。
   - 終了コード 0 / 非 0 と、失敗した行の一覧を出す。

## 受け入れの場面(試験にする。期待の数は口座で計算済み)
1. オーナーの例(L-747): 0.01 BTC ずつ 0:00〜0:04 に 10,200・10,100・10,000・9,900・9,800 円で買い、0:10 に 0.05 を 10,100 円で売る → 平均の建値 10,000 円、確定損益 +5 円、保有 10 分、閉じた取引 1、段の数 5。
2. ドテン: 0:00 に 0.01 を 10,000 円で買い、0:05 に 0.02 を 10,100 円で売る → 閉じた取引 1(+1 円)、途中 1(売り 0.01、建値 10,100)。
3. 一部決済: 0:00 に 0.02 を 10,000 円で買い、0:03 に 0.01 を 10,200 円で売り(+2 円)、0:06 に 0.01 を 9,900 円で売る(−1 円)→ 合計 +1 円、閉じた取引 1、保有 6 分。
4. 量: 1,500 万円・1 段 → 0.009 BTC。500 万円・5 段 → 0.005 BTC。500 万円・1 段 → 0.028 BTC(誤差で 0.027 にならない)。
5. 終わりで途中: 0:00 に買い 0.01、データがそこで終わる → 閉じた取引 0、途中 1。
6. ドル建て: 0.01 BTC を 30,000 USD で買い(USDJPY 150)、30,100 USD で売る(確定時の USDJPY 151)→ +1 USD = +151 円。USDT 建ても同じ答え。
7. 検査: まとめを 1 円書き換えた置き場は失敗。約定の値段が高値を 1 円超えた置き場は失敗。足の始まりが 20 秒ずれた足に当たる約定は失敗。
