## 損益のまとめ方の確かめ(L-860「**損益のまとめ方を確認するの忘れてたわ それも仕組みの一部やんな**」)

まとめ方(`src/bot/bt/simple/run.py` の `summarize` と帳簿のツール `src/bot/bt/road/ledger.py`):
- 走らせの後、約定のファイルを頭から読み、建玉が 0 に戻るまでを 1 つの塊として帳簿のツールに渡し、足し合わせる。
- 帳簿のツールの決まり: 損益は値段の差 × 量だけで手数料は含まない(L-741)。取引は建玉 0 → 0 で 1 回、段を足しても同じ取引(L-749)。ドテンは閉じた側で 1 回(L-750)。建玉が残った取引は「途中」で、閉じた取引の数・損益に入れない。計算は分数で丸めない。
- 出すのは 4 つ: 約定の数・閉じた取引の数・閉じた取引の損益の合計(円)・途中の取引の数。取引ごとの表は残さない(L-854 の案 4。要るときは約定から作る)。

確かめ(約定の記録から、帳簿のツールを使わずに別に計算): 建玉が 0 に戻るまでの塊ごとに 売りの 値段 × 量 の和 − 買いの 値段 × 量 の和 を足す(建玉 0 → 0 の塊では、これが閉じた取引の損益の合計になる)。

| | まとめのファイル | 別の計算 |
|---|---|---|
| 約定の数 | 1,673,906 | 1,673,906 |
| 閉じた取引の数 | 381,510 | 381,510(建玉 0 → 0 の塊 381,510・ドテン 0) |
| 閉じた取引の損益の合計 | −590,751.845 円 | −590,751.845 円 |
| 途中の取引 | 1 | 1(最後の建玉 0.015 BTC) |

4 つとも一致した(事実)。この損益は仕組みの確かめの出力で、測りの結果としては読んでいない。
