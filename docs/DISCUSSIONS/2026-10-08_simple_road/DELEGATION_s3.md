## 変異の表

作業者が作り、報告に付ける。U1〜U12 と H1〜H6 の番号ごとに 1 行以上: 「作った物をわざと壊す変更」と「それで落ちた試験」。U1〜U11 の行は、その番号の場面が落ちる壊し方にする(例: U1 = 新しい取引でも前の取引の量を使う、U2 = 売りの段の距離の向きを買いと同じにする、U3 = 同じ値段でなければ遠ざかる向きでも置き直す、U4 = 旗 3 で成行を出さない、U5 = b_signal の出来高の条件を見ない、U6 = 中心に戻ってもブレイクを解除しない、U7 = 逆向きのブレイクで止める、U8 = 欠けた分で窓を閉じない、U9 = ヒゲの閾値を見ずに切る、U10 = 玉を持って足す回の段を全部 limit で出す、U11 = 交差を見ない)。落ちた試験は `tests/<置き場>/<ファイル>::test_名前` の形で省かずに全部書き、表を回す試験は続けて失敗の文に出た場面の名前を全部書く(例: `tests/simple/test_matilda.py::test_scenes`(場面: 自分の注文の交差(L-816「3.a」): 決済と交差する段だけ出さない))。壊した変更は作業者の scratchpad の写しで当て、本物は壊したまま残さない。写しを当てるときは `PYTHONPATH=<写しの src>` と `-o pythonpath=<写しの src>` の両方を付け、出力の最後の行が `skipped` でないことを見る(付け忘れると試験が飛ばされ、壊していないように読める)。壊した変更で試験が 1 つも落ちなかったら、別の壊し方に差し替えずに、その行の落ちた試験の欄に「落ちなかった」と書き、問いとして返す(その欄には経緯の文を書かない)。H の行は、確かめのコマンドと結果の 1 行の要約。「壊した変更」の欄には、実際に当てた変更をそのまま書く。

形: `| 番号 | 壊した変更 | 落ちた試験 |`
