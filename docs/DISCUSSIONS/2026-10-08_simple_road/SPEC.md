経緯: L-819「**測定方法も残し方も検査もシンプルにできるはず**」、L-821「**1.よい 2.よい**」(`DESIGN.md` の決めること 1・2)。
約定の決まりは、これまでのオーナーの決めだけ(L-769・L-770・L-783・L-781・L-816「1.a」・L-817)。この文書で新しく決める約定の決まりは無い。
下の「リードの決め」は、オーナーの決めを形にするためにリードが決めた細部。

## 1. 足

- 1 分足 = (始まりの時刻, 始値, 高値, 安値, 終値, 出来高)。古い順に 1 本ずつ回す。
- 値段が空の足(その分に約定が無かった。`backtest_data/bitflyer_lightchart_FX_BTC_JPY_1m_20260906/README.md`)は、無い足として飛ばす(リードの決め)。
- run も meta の seal を見て、境以後に始まる足が渡されたら止める(リードの決め。read_bars を通らない足のため)。
- 封印の境 2023-12-17T15:00Z 以後に始まる足の行に届いたら、そこでデータの終わりとする(その行より先は読まない。止めない。リードの決め)。境の年より後の年のファイル(名前の `_YYYY.csv.gz` が 2024 以後)は開かずに止める。
- 安値が高値より高い足は、read_bars でも run でも止める(リードの決め。作り終えた後の批評家 1 回目)。

## 2. 1 本の足でする 3 つ(この順)

1. **約定**: 出ている注文を、この足で約定させる(3 の決まり)。
2. **知らせ**: 約定を戦略に渡す。
3. **判定**: この足が閉じた時点で、戦略は「次の足の間に出しておく注文の全部」を返す(L-821 の 1)。
   - 返した注文のうち、前から出ていて同じ番号のものは、そのまま出ている。同じ番号なら中身(形・売買・量・戦略が出した値段そのもの・根・距離・親)も前と同じでなければならない。違えば走らせを止める(値段を変えるときは新しい番号で出す。リードの決め)。
   - 返さなかった注文は、ここで消える(取り消し)。
   - 番号は 1 回の走らせで 1 つの注文にだけ使う。約定し終えた・消えた注文の番号を、もう一度返したら止める(リードの決め)。
   - 「次の足」は、データにある次の足(値段のある足)。時刻 + 60 秒ではない。

## 3. 注文の形と約定の決まり

注文 = 番号(文字)・形・売買(buy / sell)・量・形ごとの中身。値段は銘柄の刻みに切り捨てる(売りも買いも。L-783 の「小数点以下は切り捨て」を刻みに広げたのはリードの読み。刻み 1 円では同じ)。
切り捨てのやり方は 1 つ: `Decimal(repr(値段)) / Decimal(repr(刻み))` を ROUND_FLOOR で整数にし、`Decimal(repr(刻み))` を掛けて float に戻す(limit・exit・段とも。段の値段は `Decimal(repr(F)) + Decimal(repr(距離))` を同じやり方で切り捨てる)。

| 形 | 中身 | いつから・どう約定するか |
|---|---|---|
| limit(指値) | 値段 | 出た次の足から。範囲の内(安値 ≦ 値段 ≦ 高値)なら値段で、約定する向きに範囲の外(買いは値段 > 高値、売りは値段 < 安値)なら始値で約定する(L-769・L-770)。約定の行の case は range(範囲の内)・open(始値)。 |
| level(段) | 根(同じ売買の limit の番号)・距離(買いは負、売りは正) | 根が最初に約定するまで効かない。根の最初の約定値段を F とすると、段の値段 = `Decimal(repr(F)) + Decimal(repr(距離))` を刻みに切り捨てたもの(L-816「1.a」)。<br>根が約定した足では、段の値段が範囲の内なら段の値段で約定する(case は anchor_bar)。良い側・悪い側とも同じ(L-817)。範囲の外ならその足では約定しない。<br>次の足からは limit と同じ決まり(range・open)。 |
| exit(付けた利確) | 親(limit か level の番号)・値段 | 親が約定するまで効かない。量は親と同じ量で出す(リードの決め)。<br>親が約定した足では、良い側だけ、値段が範囲の内なら値段で約定する(case は entry_bar)。範囲の外ならその足では約定しない(始値でも約定しない)。悪い側は親の足では試さず次の足から(L-769)。<br>次の足からは limit と同じ決まり(range・open)。 |
| market(成行) | なし(量は共通の欄) | 出た次の足の始値で約定する(case は market。リードの決め。前の道の market_ref = next_bar_open と同じ)。 |

- 1 本の足の中で約定させ、約定のファイルに記す順: ① market → ② 親が前の足までに約定した exit → ③ limit → ④ level → ⑤ 親がこの足で約定した exit。同じ組の中では番号を出した順(seq)。② を ③ より先にするのは L-824「**(a)**」(同じ足で、前からの建玉を閉じる利確と新しい 1 段目が両方約定したら、利確を先に記す。帳簿のツールは同じ時刻の約定を並びの順に記すので、取引が閉じるかがこの順で決まる)。オーナーの答えが当たるのはこの場面で、同じ順を、建玉を持ったまま足す指値と利確が同じ足で約定する場面にも当てるのはリードの決め(その場面では取引が閉じるかは順で変わらず、閉じた取引の損益は建玉が 0 に戻るまでの売買の差なので変わらない。変わるのは途中の取引の欄だけ)。建玉の全部を決済する指値は ③ の指値で、新しい指値との順は seq(リードの決め。戦略が先に出す)。④ が ③ の後、⑤ が ③・④ の後なのは、後の形が前の形の約定を使うから(リードの決め)。② は今の足の約定を使わないので、この順にしても約定する注文と値段は変わらない。
- 量は 0 より大きく、0.001 の刻みの上(L-756「**3. 0.001**」)。外れたら止める。
- 止める注文(リードの決め): 知らない形 / 根が出ていなくて約定もしていない level / 親が出ていなくて約定もしていない exit / 根が既に約定した後で初めて出た level(段は根と同じ判定で出す)/ 根が limit でない・売買が違う level / 距離の向きが違う(買いで正、売りで負)level / 親が limit でも level でもない exit / 売買が親と同じ exit / 量が親と違う exit。
- exit が、親が既に約定した後で初めて出たときは、出た次の足からふつうの limit の決まりで約定する(「親が約定した足」の扱いは、その足に exit が出ていたときだけ。リードの決め)。
- 取引所の模型の自分の注文どうしの交差の決まり(self_trade)も、建玉を超える決済を切る決まり(reduce_only)も無い。注文は 1 つずつ足と比べて約定する。交差しない(L-816「3.a」)のは戦略の仕事。建玉を超えて決済しないのも戦略の仕事で、建玉の全部を決済する指値は exit ではなく limit(量 = 建玉)で出す(この 2 つはリードの決め)。
- 量は部分で約定しない。約定は全部の量(リードの決め)。
- 取引の中の段の量をそろえる(L-781)のは戦略の仕事。道は渡された量をそのまま使う(リードの決め)。
- 手数料は 0(A-8・L-048「**当時の手数料は戦略に関係ない**」)。maker・taker の区別は残さない。
- 走らせは良い側(optimistic)と悪い側(pessimistic)の 2 回。違うのは exit の「親が約定した足」の扱いだけ。

## 4. 残すファイル(側ごとの名前。良い側と悪い側を同じディレクトリに書いてよい。足を回しながら書き足す)

run は始めに、その側のファイルを新しく作る(同じディレクトリに前の走らせのファイルがあっても、中身を残さない)。

| ファイル | 列 |
|---|---|
| `orders_<側>.csv` | seq(注文を初めて受けた順の通し番号、0 から), id, form, side, qty, px_calc(戦略が出した値段。level は空), px(切り捨てた値段。level は決まった値段、決まらなければ空), root, offset, parent, from_ts(約定しうる最初の足), to_ts(約定しうる最後の足。約定した注文は約定の足、消えた注文は消える前の最後の足、データの終わりまで出ていた注文は最後の足)。最後の足の判定で出て約定しうる足が無い注文は、from_ts・to_ts とも空 |
| `fills_<側>.csv` | ts(足の始まり), id, side, qty, px, case(range / open / anchor_bar / entry_bar / market) |
| `signals_<側>.csv` | id, kind, direction, start_ts, end_ts, end_reason, value_json(データの終わりまで消えなかった合図は end_ts 空・end_reason「データの終わり」) |
| `run_<側>.json` | 呼ぶ側が meta で渡すもの(戦略の名前と引数 strategy・params、封印の境 seal、足のファイルの名前と sha256 bar_files)に、刻み tick・側 side・コードの git の版 git を足したもの。git の版は、`src/` の下のどこかに未コミットの変更があれば末尾に印を付ける(帳簿のツールが読む包みを並べる形は並べ漏れが起きるので、`src/` 全体。リードの決め) |

- 注文の行は、注文が消えた時か約定した時か、データの終わりに 1 行書き、すぐファイルに出す。
- 走らせは、消えた注文の中身を記憶に持ち続けない(番号の使い回しの検めには番号だけを持つ。リードの決め。DESIGN.md の「全部を記憶には持たない」)。約定した注文は、段・利確の検めに要る中身を持ってよい。
- 数の書き方: 量・値段・距離は Python の `repr(float(x))`(例 `6999800.0`・`-100.0`・`1e-10` は `1e-10`)、seq は整数、時刻は足のファイルの ts の文字列のまま。検査 1 はこの書き方で 1 字違わず比べる。
- 建玉・損益・取引の数・保有時間は、帳簿のツール(`src/bot/bt/road/ledger.py` の `book`)で約定から計算し、`trades_<側>.csv`・`summary_<側>.json` に書く(L-754)。
  - `book` に渡す約定: 約定のファイルの順に {t_ns: 足の始まりの UTC の ns, side, qty, px, ccy: "JPY"}(同じ足の約定は同じ t_ns。`book` は受け付ける)。
  - `trades_<側>.csv` の列は `TRADE_KEYS`(`src/bot/bt/road/ledger.py:87`)、`summary_<側>.json` は `book` の summary から trades の欄を除いたもの(fill_count・closed_trades・pnl_jpy・open_trades)。約定が 0 本なら trades は見出しだけ、summary は 0。

## 5. 検査(L-821 の 2)

1. **約定の作り直し**: 3 の決まりを、別の作業者がもう 1 つ独立に書く。`orders_<側>.csv` と足のファイルと `run_<側>.json` の刻み tick・側 side から約定を計算し直し、`fills_<側>.csv` と 1 字違わず同じか比べる(記す順も比べる)。
   - 注文の行の to_ts は約定した注文では約定の足だが、答えを渡すことにはならない。作り直しは from_ts から to_ts までの足を全部試すので、早すぎる約定(作り直しではその足で約定しない)も、遅すぎる・無い約定(作り直しでは前の足で約定する)も、食い違いになる。
2. **数の作り直し**: `book` で `fills_<側>.csv` から計算し直した数が、`trades_<側>.csv`・`summary_<側>.json` と同じか比べる。
   - fills は見出しの行が決まった列(§4)と 1 字違わず同じで、各行の欄の数が見出しと同じでなければ食い違い。0 バイトのファイルも食い違い。
   - trades は、作り直した表を走らせと同じ書き方(見出しは `TRADE_KEYS`、欄は文字、行の終わりは `\n`)で書いた中身と、ファイル全体を 1 字違わず比べる。
   - summary は 4 つの鍵ちょうどの辞書で、値は作り直した値と Python の型(整数・小数・文字・真偽値)まで同じでなければ食い違い(走らせは件数を整数、損益を文字で書く)。
   - 読めない・形の違う入力は、どんな例外も拾い、例外にせず食い違いの行として返す。
   - 約定が 0 本の走らせ(見出しだけの fills・trades と 0 の summary)は合格。
