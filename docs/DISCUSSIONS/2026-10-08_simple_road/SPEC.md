## 1. 足

- 1 分足 = (始まりの時刻, 始値, 高値, 安値, 終値, 出来高)。古い順に 1 本ずつ回す。
- 値段が空の足(その分に約定が無かった。`backtest_data/bitflyer_lightchart_FX_BTC_JPY_1m_20260906/README.md`)は、無い足として飛ばす(リードの決め)。
- **向きの決まらない足**: 始値 = 終値 で、しかも始値 = 直前の足の終値 の足は、取引が無かったとみなし、値段が空の足と同じく無い足として飛ばす(L-877「**取引がなかったとみなして注文を出さない**」。戦略にも渡さない・約定もさせない、はリードの読み)。直前に回した足がまだ無い間(データの頭)の始値 = 終値 の足も飛ばす(リードの決め。データの頭は 2015-11-28 04:54・05:03・06:16 … と始値 = 終値 の足が続く)。「直前の足」は飛ばさずに回した直前の足(年のファイルをまたいでも続ける)。封印の境までの値段のある足 3,983,130 本のうち、この決まりで飛ばすのは 36,139 本で、そのうち 12,298 本は高値 > 安値(`read_bars` で全部を読んで数えた。事前の批評 1 回目の担当の数と一致。10-08 の初めにリードが書いた 36,122 本は、年のファイルの頭で直前の終値を空に戻した数え方の誤り)。
- 「次の足」は、データにあって飛ばさない次の足(時刻 + 60 秒ではない。1 版目と同じ)。
- run も meta の seal を見て、境以後に始まる足が渡されたら止める(リードの決め。read_bars を通らない足のため)。この検めは、向きの決まらない足を飛ばすより先にする(飛ばす足でも境以後なら止める)。
- 値段が空の足を飛ばすのは read_bars。run に渡す足は値段のある足だけで、run は値段が数でない足で止める(1 版目のまま)。
- 封印の境 2023-12-17T15:00Z 以後に始まる足の行に届いたら、そこでデータの終わりとする(その行より先は読まない。止めない。リードの決め)。境の年より後の年のファイル(名前の `_YYYY.csv.gz` が 2024 以後)は開かずに止める。
- 安値が高値より高い足、始値か終値が安値〜高値の外にある足は、read_bars でも run でも止める(リードの決め)。封印の境までの値段のある足 3,983,130 本に、どちらも 0 本(リードが年ごとに数えた)なので、止めても走らせは止まらない。

## 2. 足の中の道筋と、戦略を呼ぶ口

### 2.1 道筋(L-875・L-876)

足の中で値段は、次の点を順にまっすぐ動いたとみなす。

| 足 | 道筋 |
|---|---|
| 陽線(終値 > 始値) | 始値 → 安値 → 高値 → 終値 |
| 陰線(終値 < 始値) | 始値 → 高値 → 安値 → 終値 |
| 始値 = 終値、始値 > 直前の終値 | 始値 → 高値 → 安値 → 終値(L-876「**直前の足のCとその足のOを比べ、その向きに動くシナリオ**」) |
| 始値 = 終値、始値 < 直前の終値 | 始値 → 安値 → 高値 → 終値 |
| 始値 = 終値 = 直前の終値 | 足ごと飛ばす(§1) |

- 前の足の終値から今の足の始値へは**飛ぶ**(途中の値段を通らない)。飛びの間にある注文・見張る値段は、始値に着いた時点で始値で扱う(§3)。
- 同じ値段の点が続く所(例: 始値 = 安値)は、動きの無い区間として飛ばしてよい。

### 2.2 口(L-882「**口の案はそれでよい**」)

戦略は `decide(ev)` を持ち、3 つの組 `(orders, events, watches)` をこの順で返す。
- `orders`: 辞書 `{番号の文字: 注文}`。注文は辞書で、鍵は `"form"`(`"limit"`・`"stop"`・`"market"`)・`"side"`(`"buy"`・`"sell"`)・`"qty"`(数)・`"px"`(limit と stop だけ。数)・`"tag"`(任意。文字)。ほかの鍵は止める。
- `events`: 合図の出来事の並び(1 版目と同じ形: `{"op": "start", "id", "kind", "direction", "value"}` / `{"op": "end", "id", "reason"}`)。
- `watches`: 見張る値段の数の並び(空でよい)。

`ev` は辞書:

| 鍵 | 中身 |
|---|---|
| `kind` | `"stop"`(足の途中で止まった)か `"close"`(足が閉じた) |
| `ts` | 今の足の始まりの時刻の文字列 |
| `price` | 今いる値段。`"close"` では終値 |
| `fills` | この点で約定した注文の並び。1 つは辞書 `{"id", "side", "qty", "px", "case"}`(番号・売買・量・約定値段・case)。約定させた順。`"close"` では空 |
| `touched` | この点で届いた見張る値段の並び(戦略が返した値そのまま) |
| `bar` | `"close"` のときだけ、今の足 (時刻, 始値, 高値, 安値, 終値, 出来高)。`"stop"` では渡さない(足の途中で、その足の高値・安値・終値を見せない) |

1 本の足での流れ:

1. 道筋を始値から順にたどる。たどりながら、出ている注文の約定(§3)と、見張る値段への到達を探す。
2. 約定か到達が起きた**最初の点**で止まり、その点で起きたことを全部(同じ値段の約定と到達を全部)入れて `decide(ev)`(`kind = "stop"`)を呼ぶ。
3. 戦略が返した注文の全部が、この点から先に出ている注文になる。返さなかった注文はこの点で取り消し(L-821 の 1 と同じ)。見張る値段も、返した並びで置き換える。
4. 返した注文のうち、この点の値段ですぐ約定するもの(§3 の「今いる値段で約定する」)は、この点で約定させ、2 に戻る(同じ点でもう一度呼ぶ)。同じ点で呼ぶのは 100 回までとし、超えたら止める(リードの決め。戦略の作りの誤りで回り続けるのを止める)。
5. 何も起きなくなったら、道筋の続きをたどる(1 に戻る)。
6. 終値まで来たら `decide(ev)`(`kind = "close"`、`bar` つき)を呼ぶ。返した注文と見張る値段が、次の足に持ち越される。ここで返した注文は、ここでは約定させない(次の足の始値から。成行も次の足の始値)。

- 見張る値段は、注文の値段と同じやり方で刻みに切り捨ててから比べる(線の値と、線に置いた limit の値段が同じ点で届くように。リードの決め)。`touched` には戦略が返した値(切り捨てる前)をそのまま入れる。
- 見張る値段は、道筋がその値段に**動いて届いた**とき(動き始めの点を除き、着いた点を含む)に到達とする。戻ってきてまた届けばまた到達。返した時点で今いる値段と同じ見張る値段は、その点では到達にしない(リードの決め)。前の足の終値から始値への飛びの間にある見張る値段は、始値で到達とする。
- 注文の番号の決まり(1 版目から変えない): 返した注文のうち、前から出ていて同じ番号のものは、そのまま出ている。同じ番号なら中身(形・売買・量・戦略が出した値段そのもの・tag)も前と同じでなければならない。違えば止める。番号は 1 回の走らせで 1 つの注文にだけ使う。約定し終えた・消えた注文の番号をもう一度返したら止める。
- 合図の出来事の形は 1 版目と同じ(`signals.csv` の列)。
- **戦略を書く人への注意**: 見張る値段は、道筋が動いて届いたときにしか知らせない。例えば陽線(始値 → 安値 → 高値 → 終値)で、買いの線がちょうど安値なら、1 段目は安値で約定し、そこで返した見張る値段(線)は、道筋が安値から上へ折り返すので届かない(動き始めの点を除くため)。だから戦略は、`"close"` のたびに、合図・ブレイクなどの状態を終値から判断し直す。見張る値段が知らせてくれたことだけに頼らない。

## 3. 注文の形と約定の決まり

注文 = 番号(文字)・形・売買(buy / sell)・量・形ごとの中身・tag(任意の文字。約定のファイルの kind の欄に書く。無ければ形の名前)。値段は銘柄の刻みに切り捨てる(売りも買いも。L-783)。切り捨てのやり方は 1 版目と同じ: `Decimal(repr(値段)) / Decimal(repr(刻み))` を ROUND_FLOOR で整数にし、`Decimal(repr(刻み))` を掛けて float に戻す。

| 形 | 中身 | 約定 |
|---|---|---|
| limit(指値) | 値段 | 買いは道筋の値段が値段以下に、売りは値段以上に届いたら約定。道筋を動いて届いたら**その値段**で(case `path`)。出ている時点ですでに約定する側にいたら**今いる値段**で(始値に飛んだときは始値。case `open`。足の途中で出した時点ですでに約定する側なら、その点の値段。case `now`)(L-770 a・L-879) |
| stop(逆指値) | 値段 | 買いは道筋の値段が値段以上に、売りは値段以下に届いたら約定。動いて届いたら**その値段**で(case `path`)。始値に飛んだ時点ですでに越えていたら**始値**で(case `open`。L-877「**3.b**」)。出した時点ですでに越えていたらその点の値段(case `now`)(L-874「**決済する値段は次の始値ではなくブレイクラインの値段にします。**」) |
| market(成行) | なし | 足の途中で出したら、その点の値段で(case `now`)。足が閉じたとき(`"close"`)に出したら、次の足の始値で(case `market`) |

- 1 つの区間で複数の注文に届くときは、道筋で先に届く値段から順に約定させる。同じ値段で届く注文は、番号を出した順(seq)にまとめて約定させ、まとめて 1 回呼ぶ。
- 届いたかの比べは、ちょうど同じ値段を含む(L-879 の例「安値ちょうどですが、届いたので約定」)。
- 量は 0 より大きく、0.001 の刻みの上(L-756)。外れたら止める。量は部分で約定しない。
- 止める注文: 知らない形 / limit・stop に値段が無い / market に値段がある / 量が刻みの外 / tag が文字でない。
- 自分の注文どうしの交差の決まり(self_trade)も、建玉を超える決済を切る決まり(reduce_only)も無い。注文は 1 つずつ道筋と比べて約定する。交差させない・建玉を超えて決済しないのは戦略の仕事(1 版目から変えない)。
- 段・付けた利確(1 版目の level・exit)の形は無くした。戦略は根の約定を `"stop"` で受け取ってから、段・利確を limit で出す(根の約定値段を戦略が知っているので、道に根と距離の形は要らない。リードの決め)。
- 手数料は 0(A-8・L-048)。
- 走らせは道筋の 1 回だけ(L-876「**2.(a)**」)。

## 4. 残すファイル

L-851「**注文の履歴いらないわ、約定の履歴だけでいい**」・L-852・L-853・L-854。注文の記録・取引の一覧は書かない。run は始めに、ファイルを新しく作る(前の走らせの中身を残さない)。側が無くなったので、名前から側を外す。

| ファイル | 列 |
|---|---|
| `fills.csv` | ts(足の始まり), kind(注文の tag。無ければ形の名前), side, qty, px, case(path / open / now / market)。約定させた順に、回しながら書き足す。マチルダの tag は `entry`(1 段目)・`level`(段)・`exit`(段に付けた利確)・`close`(玉全体を閉じる指値)・`market`(成行)・`break`(ブレイクの逆指値)の 6 つ(L-861 の閉じ方ごとの損益を同じ形で出せるように。リードの決め) |
| `signals.csv` | id, kind, direction, start_ts, end_ts, end_reason(1 版目と同じ) |
| `summary.json` | fill_count・closed_trades・pnl_jpy(文字)・open_trades。走らせの後に約定のファイルを頭から読み、建玉が 0 に戻るまでを 1 つの塊として帳簿のツール(`src/bot/bt/road/ledger.py` の `book`)に渡し、足し合わせる(1 版目と同じ)。塊の切り方は建玉が 0 に戻るかだけで決め、kind(tag)の値に頼らない |
| `run.json` | 呼ぶ側が meta で渡すものに、刻み tick・コードの git の版 git を足したもの |

- 数の書き方・時刻の書き方・圧縮は 1 版目と同じ(整数は小数点なし、ほかは `repr(float(x))`、時刻は足のファイルの ts の文字列のまま、圧縮は呼ぶ側 `scripts/simple/run_one.py`)。
- 記憶: 走らせは消えた注文の中身を持たない(番号の使い回しの検めには番号だけを持つ)。
