# 単純な測りの道の決まり(作る人のための正本)

経緯: L-819「**測定方法も残し方も検査もシンプルにできるはず**」、L-821「**1.よい 2.よい**」(`DESIGN.md` の決めること 1・2)。
約定の決まりは、これまでのオーナーの決めだけ(L-769・L-770・L-783・L-781・L-816「1.a」・L-817)。この文書で新しく決める約定の決まりは無い。
下の「リードの決め」は、オーナーの決めを形にするためにリードが決めた細部。

## 1. 足

- 1 分足 = (始まりの時刻, 始値, 高値, 安値, 終値, 出来高)。古い順に 1 本ずつ回す。
- 値段が空の足(その分に約定が無かった。`backtest_data/bitflyer_lightchart_FX_BTC_JPY_1m_20260906/README.md`)は、無い足として飛ばす(リードの決め)。
- 封印の境 2023-12-17T15:00Z 以後に始まる足は読まない。読みかけたら止める。2024 年以降のファイルは開かない。

## 2. 1 本の足でする 3 つ(この順)

1. **約定**: 出ている注文を、この足で約定させる(3 の決まり)。
2. **知らせ**: 約定を戦略に渡す。
3. **判定**: この足が閉じた時点で、戦略は「次の足の間に出しておく注文の全部」を返す(L-821 の 1)。
   - 返した注文のうち、前から出ていて同じ番号のものは、そのまま出ている。同じ番号なら中身(形・売買・量・値段・根・距離・親)も前と同じでなければならない。違えば走らせを止める(値段を変えるときは新しい番号で出す。リードの決め)。
   - 返さなかった注文は、ここで消える(取り消し)。
   - 約定し終えた注文の番号を、もう一度返したら止める(リードの決め)。
   - 「次の足」は、データにある次の足(値段のある足)。時刻 + 60 秒ではない。

## 3. 注文の形と約定の決まり

注文 = 番号(文字)・形・売買(buy / sell)・量・形ごとの中身。値段は銘柄の刻みに切り捨てる(L-783。売りも買いも)。

| 形 | 中身 | いつから・どう約定するか |
|---|---|---|
| limit(指値) | 値段 | 出た次の足から。範囲の内(安値 ≦ 値段 ≦ 高値)なら値段で、約定する向きに範囲の外(買いは値段 > 高値、売りは値段 < 安値)なら始値で約定する(L-769・L-770)。 |
| level(段) | 根(同じ売買の limit の番号)・距離(買いは負、売りは正) | 根が最初に約定するまで効かない。根の最初の約定値段を F とすると、段の値段 = `Decimal(repr(F)) + Decimal(repr(距離))` を刻みに切り捨てたもの(L-816「1.a」)。<br>根が約定した足では、段の値段が範囲の内なら段の値段で約定する。良い側・悪い側とも同じ(L-817)。<br>次の足からは limit と同じ決まり。 |
| exit(付けた利確) | 親(limit か level の番号)・値段 | 親が約定するまで効かない。量は親の量。<br>親が約定した足では、良い側だけ、値段が範囲の内なら値段で約定する。悪い側は次の足から(L-769)。<br>次の足からは limit と同じ決まり。 |
| market(成行) | なし(量は共通の欄) | 出た次の足の始値で約定する。 |

- 1 本の足の中で約定させる順: market → limit → level → exit(リードの決め。後の形は前の形の約定を使う)。同じ形の中では番号を出した順。
- 量は 0 より大きく、0.001 の刻みの上(L-756「**3. 0.001**」)。外れたら止める。
- 止める注文(リードの決め): 根が出ていなくて約定もしていない level / 親が出ていなくて約定もしていない exit / 根が既に約定した後で初めて出た level(段は根と同じ判定で出す)/ 根が limit でない・売買が違う level / 距離の向きが違う(買いで正、売りで負)level。
- exit が、親が既に約定した後で初めて出たときは、出た次の足からふつうの limit の決まりで約定する(「親が約定した足」の扱いは、その足に exit が出ていたときだけ)。
- 取引所の模型の自分の注文どうしの交差の決まり(self_trade)も、建玉を超える決済を切る決まり(reduce_only)も無い。注文は 1 つずつ足と比べて約定する。交差しない(L-816「3.a」)・建玉を超えて決済しないのは、戦略の仕事。
- 量は部分で約定しない。約定は全部の量。
- 約定はすべて maker とする(L-783「maker」)。手数料は 0(当時の手数料は戦略に関係ない。A-8・L-048「**当時の手数料は戦略に関係ない**」)。
- 走らせは良い側(optimistic)と悪い側(pessimistic)の 2 回。違うのは exit の「親が約定した足」の扱いだけ。

## 4. 残すファイル(1 回の走らせ = 1 つのディレクトリ。足を回しながら書き足す)

| ファイル | 列 |
|---|---|
| `orders_<側>.csv` | id, form, side, qty, px_calc(戦略が出した値段。level は空), px(切り捨てた値段。level は決まった値段、決まらなければ空), root, offset, parent, from_ts(約定しうる最初の足), to_ts(約定しうる最後の足。約定した注文は約定の足、消えた注文は消える前の最後の足、データの終わりまで出ていた注文は最後の足) |
| `fills_<側>.csv` | ts(足の始まり), id, side, qty, px, case(range / open / anchor_bar / entry_bar / market) |
| `signals_<側>.csv` | id, kind, direction, start_ts, end_ts, end_reason, value_json |
| `run.json` | 戦略の名前と引数、足のファイルの名前と sha256、封印の境、刻み、側、コードの git の版 |

- 注文の行は、注文が消えた時か約定した時か、データの終わりに 1 行書く。
- 建玉・損益・取引の数・保有時間は、帳簿のツール(`src/bot/bt/road/ledger.py` の `book`)で約定から計算し、`trades_<側>.csv`・`summary_<側>.json` に書く(L-754)。

## 5. 検査(L-821 の 2)

1. **約定の作り直し**: 3 の決まりを、別の作業者がもう 1 つ独立に書く。`orders_<側>.csv` と足のファイルから約定を計算し直し、`fills_<側>.csv` と 1 字違わず同じか比べる。
   - 注文の行の to_ts は約定した注文では約定の足だが、答えを渡すことにはならない。作り直しは from_ts から to_ts までの足を全部試すので、早すぎる約定(作り直しではその足で約定しない)も、遅すぎる・無い約定(作り直しでは前の足で約定する)も、食い違いになる。
2. **数の作り直し**: `book` で `fills_<側>.csv` から計算し直した数が、`trades_<側>.csv`・`summary_<側>.json` と同じか比べる。
