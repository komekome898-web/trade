## 2. 根本原因(リードの読み)

**設計の向きが逆だった。**3 周とも作業者は「送り手の物のうち、そのまま渡してよい物の一覧」を書き、一覧の外を断った。一覧に載せた物が本当に不変かは、載せた時点で誰も確かめていない(`Fraction` は「不変の値」として一覧に入ったが、Python の不変は慣習で、機構ではない)。**一覧を広げる直しは、一覧の穴を 1 つずつ批評家に見つけてもらう構造**であり、周を重ねても収束しない。第 5 周の直しはこの形をむしろ固定した(`_SCALARS` の新設)。

同じ構造の穴が第 6→7 周の i0-r6-01→i0-r7-01(答えの外の名指し)にもある: 「境界 `b >= 0` だけ検める」「答えの事実 1 つで種類を決める」という**扱う場合の一覧**を書き、一覧の外(負の境界、後ろ向きの答え)を批評家が突いた。作業者の神託の試験は 21,888 の名指しを列べたが、負の境界は列に入れていなかった = **試験の入力の空間を、実装が扱う場合の一覧から作っていた**(批評家の指摘のとおり「実装の規則を写している」)。

## 3. 設計の直し(第 8 周の作業者への指示。`lead_notes` で渡す)

### 3.1 路を渡る物: 「保つ物の一覧」を捨て、「核が作り直した物しか渡らない」にする

- 受け手に届く物は**核が自分で構築した新しい物**だけ。送り手の物の同一性(`is`)を保って渡す道を 1 つも残さない。組み込みの型の値も例外にせず、`int(x)`・`float(x)`・`str(x)`・`bytes(x)`・`complex(x)`・`Decimal(str(x))`・`Fraction(x.numerator, x.denominator)` の形で**作り直す**(`None`・`True`・`False` だけは唯一物)。
- 「正確に組み込みの型なら保つ」の分岐(`_plain_scalar` の `t in _SCALARS: return value`)を消す。一覧 `_SCALARS` は「受け付ける型」の一覧としてだけ残してよいが、**同一性を保つ根拠には使わない**。
- 不変条件を機械で測る試験を作業者が持つ(批評家の probe を写す): **送り手の敵対者** = 送った後に、送った物から到達できる全てのオブジェクト(`__dict__`・`__slots__` の私的な属性・list/dict の中身・`__class__` の差し替え)を書き換え、受け手が読む値が送った時の写しと一致することを、受け付ける全ての型 × 全ての運び手(`PATH_CARRIERS`)× 全ての欄について列べて確かめる。加えて、届いた物のグラフと送った物のグラフに `is` で同じ物が無いこと(`None`/`True`/`False` と小さい整数・短い文字列の interned を除く)を確かめる。
- 「なぜ第 5 周で見つけられなかったか」を ROOTCAUSE に書く。答えは上の §2 と一致するはず(一覧の外を試す試験が無かった)。

### 3.2 答えの外の名指し: 扱う場合を列べず、全ての名指しを 1 つの座標に戻す

- 添字・区間の境界(正・負・None・歩幅の符号)を、**切り詰める前に**配達の列の座標に戻し、その座標で「届いた / まだ / 何も無い / 落とした」を決める。`tuple` の切り詰めは、判定が済んだ後にだけ使う。
- 神託の試験の入力は**実装の場合分けから作らない**。答えの形(前向き・後ろ向き・歩幅つき・`until_ns`・`n`・`history_limit`)× 添字と境界を **[-len-3, len+3] の全格子**で列べ、入力だけから決めた神託と比べる。「独立の神託 6 種で 21,888」のように数を書くときは、**何を列に入れなかったか**を併記する(A-10)。
