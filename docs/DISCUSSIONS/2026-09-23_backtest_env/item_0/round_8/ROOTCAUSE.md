## A. i0-r7-01 後ろ向きの答えの負の区間の境界が、まだ届いていない位置だけを名指しても空を返す

### なぜ起きたか(根本原因)

1. **「外か」と「何の誤りか」を別の座標で決めていた。**第 7 周で答えは自分の場所(`AnswerPlace`)を持ち、「何の誤りか」は名指した位置を読み出しの列の座標に戻して決めるようになった。しかし「その境界が答えの外を名指すか」は、今も答えの座標の**符号**で決めていた: `window.py` の `_check_bounds`(178-185 行)は `b >= 0` の境界だけを見て上の限りを検め、負の境界は検めずに `tuple.__getitem__`(169 行)に渡して切り詰めさせた。切り詰めてよい理由として書いた「切り詰めは答えの中にしか届かない」(40-43 行、`contract.py` 45-47 行)は、答えの向きが配達の向きと同じときにしか成り立たない前提だった。後ろ向きの答え(`place.step < 0`)では負の境界は最も古い側から数える位置で、答えの前(= 位置 -1, -2, …)は最新より新しい側、まだ届いていない事象を名指す。
2. **規則が「上の限りの一覧」だった。**`POSITION_RULE` は役ごとの「名指せる最大の位置」だけを持ち、下の限り(位置 0 より前)は役ごとに決めていなかった。下の限りを持たない表では、負の境界を切り詰めるほかに扱いようがなく、これが 1 の前提を固定した。
3. **試験の入力の空間を、実装の場合分けから作っていた(リードの §2 の読みと同じ)。**`tests/bt/item_0/test_bt0_future_position.py` の神託 `_outside_positions`(155-189 行)は「Negative slice bounds are cut (as for any tuple) and name nothing outside」と、実装と同じ除外を書いていた。エンジンを通す神託 `_run_every_naming` は添字だけを [-len-3, len+3] で名指し、区間の境界は固定の 5 つ(`_SLICES`)しか使わず、答えの外を名指す区間は「別の所で確かめる」として飛ばしていた(`_apply` の `return None`)。負の区間の境界を名指す列が 1 つも無かったので、「独立の神託 21,888 通りで誤り 0 件」は負の境界について何も言っていなかった。

   - 添字・区間の始まり(前向きも後ろ向きも): `0 ≤ c ≤ len-1`(そこに事象が要る)。
   - 前向きの区間の終わり: `0 ≤ c ≤ len`(`len` は「届いた所の終わりまで」)。
