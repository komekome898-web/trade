## B. i0-r8-02 `DeliveredList` が「変更を断る」と契約に書いたのに、`__init__` と `dropped` の代入を断っていない

### なぜ起きたか(根本原因)

1. **断る方法を、断りたい方法の一覧(`append`・`extend`・…、`history.py` 71-72 行)で書いた。**一覧の外の変え方(`__init__` をもう一度呼ぶ、`__slots__` の `dropped` への代入、`__class__` の代入、属性の削除)が残った。第 7 周のリードの読み(一覧を書くと一覧の外が残る)と同じ形。
2. **核がこの列の `dropped` と長さを読み返していた**(A-3 の 4 つ目)。そのため列が変えられると、核が作る窓の件数と列が食い違い、`visible_events()` が短い答えを黙って返した。

### どの構造を変えるか

1. **変える口を一覧ではなく入口で閉じる**: `DeliveredList` は属性の代入・削除(`__setattr__`・`__delattr__`)をすべて断り、`__init__` は作られた後にはすべて断る。列の中身を変える `list` の方法は全部(`list` の方法を機械で列べ、読むだけの方法以外を全部)断る。核は作るときにだけ `list` の方法と `object.__setattr__` で書く。`dropped` は読むだけの性質にする。
2. A-4 のとおり、核はこの列から何も読み返さない。基の型の方法(`list.__init__(lst, …)`・`object.__setattr__`)で変えた場合(契約の範囲の外)でも、変わるのは戦略自身がその列から読む物だけになる。
3. **試験**: `list` の全ての方法(`dir(list)` から機械で列べる)と属性の代入・削除・`__init__` の呼び直しを列べ、変える物は全部断られ、断られない物は中身を変えないことを確かめる。
