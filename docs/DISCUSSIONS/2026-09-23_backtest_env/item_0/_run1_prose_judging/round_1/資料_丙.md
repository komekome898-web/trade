# 比較資料(観点別、雛形統一)

固定した 6 観点(V1〜V6)ごとに 1 節、各節「何ができるか / 既定で何が起きるか / 根拠」の 3 行。

## V1(時刻表現の一貫性)

- 何ができるか: 時刻は入力に含まれる索引値をそのまま使うだけで、単一の型への統一や単位の検証を行う機構を持たない。
- 既定で何が起きるか: 秒・ミリ秒・マイクロ秒などの単位が混在していても検出されず、そのまま処理が進む。
- 根拠: 単位や型の検証に相当する語が該当箇所に一件も現れないことをコマンドで実測(該当検索の一致 0 件)。

## V2(事象型の網羅性)

- 何ができるか: 出来事は単一の種類(足)しか扱えず、他の種類に対応する型は存在しない。
- 既定で何が起きるか: 足以外の種類の情報(約定・板・清算など)は構造上そもそも扱えない。
- 根拠: 受け手に渡される引数の型定義を実測し、単一種類のみであることを確認。

## V3(ルックアヘッド不能性)

- 何ができるか: 唯一存在するその一種類については、渡す範囲を区切って先頭から現在までに絞る構造がある。
- 既定で何が起きるか: その一種類に限れば将来分は渡らないが、種類が複数になったときに同じ強制が効くかはこの実装からは判定できない(現状は一種類しかないため測る対象が無い)。
- 根拠: 範囲を区切る記述を該当箇所で実測。

## V4(決定的な事象順序)

- 何ができるか: 複数種類の出来事が同時刻に並ぶ場面自体が無いため、順序を決める規則が存在しない。
- 既定で何が起きるか: 単一の逐次処理が進むだけで、規則を書く対象そのものが無い。
- 根拠: 処理の繰り返し構造を実測し、単一の逐次的な繰り返しのみであることを確認。

## V5(戦略 API の疎結合性)

- 何ができるか: 受け手は一つの呼び出し窓口だけを持ち、残高・発注・取消には直接触れない方針が文書コメントで明記されている。
- 既定で何が起きるか: ただし窓口は種類ごとに分かれておらず、一つの戻り値だけで意思を表現する形になっている。
- 根拠: 方針を述べた記述と、窓口が実質一つであることの両方を該当箇所で実測。

## V6(拡張点の分離)

- 何ができるか: 費用・約定判定・口座の状態を、独立した差し替え可能な窓口として外に出す機構を持たない。
- 既定で何が起きるか: 差し替えるには実行本体そのものを書き換える必要があり、遅延に相当する機構は存在しない。
- 根拠: 費用の定義・約定判定の分岐・口座の状態変数がすべて実行本体の中に直接書かれていることを実測し、遅延に相当する語が該当箇所に一件も現れないことをコマンドで確認(一致 0 件)。
