# 比較資料(観点別、雛形統一)

固定した 6 観点(V1〜V6)ごとに 1 節、各節「何ができるか / 既定で何が起きるか / 根拠」の 3 行。

## V1(時刻表現の一貫性)

- 何ができるか: 時刻を単一の検証済み整数型に統一し、単位ラベル付きの変換窓口を通したものしか受け付けない。
- 既定で何が起きるか: 変換後の値が妥当な範囲から外れる(単位の取り違えなど)場合は例外で拒否され、そのまま処理が進むことはない。
- 根拠: 単位関連の検査一式を実行し全件成功(実行コマンドと出力: 該当検査を収集・実行し、失敗 0 件)。

## V2(事象型の網羅性)

- 何ができるか: 起こりうる出来事の種類ごとに、専用の型を 1 対 1 で用意して列挙している。
- 既定で何が起きるか: 列挙にない種類の出来事は生成できず、型システムが構造で強制する。
- 根拠: 列挙数と専用型の数が一致することを確認する検査を実行し成功(実行コマンドと出力あり)。

## V3(ルックアヘッド不能性)

- 何ができるか: 出来事の受け手に渡す範囲を「現在までに受け取った分」だけに構造で絞り込む仕組みを持つ。
- 既定で何が起きるか: 渡す範囲そのものが先に確定してから受け手が呼ばれるため、将来分が混ざる経路が最初から存在しない。
- 根拠: 将来分を含む経路が無いことを確かめる検査一式を実行し全件成功。

## V4(決定的な事象順序)

- 何ができるか: 同時刻に複数種類の出来事が並ぶときの順序を、種類ごとの優先順位と一意な通し番号で完全に確定させる。
- 既定で何が起きるか: 同じ入力を何度流しても常に同じ順序になり、順序の決め手が欠けて比較が引き分けになる場面が無い。
- 既定で何が起きるか(補足)/ 根拠: 全種類に優先順位が定義されていることを構造で強制する検査と、順序の再現性を確かめる検査の両方が成功。

## V5(戦略 API の疎結合性)

- 何ができるか: 出来事の受け手が触れられる窓口を、出来事の通知・発注・取消など数個の決められた口だけに絞る。
- 既定で何が起きるか: それ以外の内部状態(残高・建玉・発注簿など)に触れる経路が公開面に一つも無い。
- 根拠: 公開面を機械的に数え上げる検査を実行し、想定した窓口の数とだけ一致することを確認。

## V6(拡張点の分離)

- 何ができるか: 約定・遅延・費用・口座それぞれの機構を、核の中身を書き換えずに外側から差し替えられる独立した窓口として持つ。
- 既定で何が起きるか: どれも未指定のときは「何もしない」代替が使われ、効果ゼロのまま実行は止まらずに進む(効果ゼロである点は隠されていない)。
- 根拠: 核の外側で作った代替の実装を差し込んで動かす検査を実行し成功。
