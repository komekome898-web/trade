## 1. i4-r2-02(時間切れの足で範囲の逆指値を始値の時間切れより先に取る)

- **なぜ起きたか**: 第 2 周で足の処理を「始値の段 → 範囲の段」の時の順に分けたとき、時間切れ(R-H1)だけは旧の計算の場所(範囲の出口 0.5 のあとの 0.7)に残し、R-H3 を「範囲の逆指値を時間切れより先に見る」と読んで `time_due` のときに範囲の段を先に回した(`barmodel.py` 0.45 の `not time_due` と 0.5 → 0.7 の順)。R-H3 の文をそのまま写し、R-O1 の原則(始値は範囲より先)と照らさなかった。場面集の正解も同じ読みで固まっていたので、場面集の試験では捕まらなかった。
- **変える構造**: `BarRules` に `time_exit_at_open`(spec = True、legacy = False)を足し、spec では時間切れを**始値の段**(構造的な逆指値の次、待っている taker の合図の前)で取る。時間切れは待っている合図(taker・maker の両方)を捨てる(R-H2)。範囲の段は、始値を越えて建玉が生きるときだけ回るので、時間切れの足では範囲の逆指値・利確は起きない。legacy の順(0.5 → 0.7)は変えない(旧とのバイト一致)。作業者の写し `bar_rules.py` も同じ形に直す(時間切れの足の R-H3 の分岐を消す)。
- **同じ根の全箇所**: (1) 時間切れの足に待っている決済の合図(taker)= 始値で時間切れが取り、合図は捨てる(値は同じ始値)。(2) maker の執行で時間切れの足に待っている指値 = 捨てる、取り逃しに数えない(R-M5)。(3) 構造的な逆指値と時間切れが同じ足 = 構造的な逆指値が先(R-O1 ①)。(4) `tp_before_time_exit` の欄は spec では時間切れの足で範囲の段が回らないので効かなくなる(欄は legacy の値を表すために残す)。
- **先に書く試験**: `tests/bt/item_4/test_i4_r3_time_exit_at_open_grid.py`。格子 = 建玉の向き {買い・売り} × 時間切れの足の始値の位置 {水準の間・逆指値の外} × 範囲が届くもの {無し・逆指値・利確・両方} × 待っているもの {無し・同じ向きの合図・決済の合図} × 執行 {taker・maker}。期待は R-O1 の文から式で書く。

## 2. i4-r2-03(出所の判定が再圧縮・展開・切り出しで破れる)

- **なぜ起きたか**: 第 2 周は出所を「置き場所」か「ファイルのバイトの一致(大きさと sha256)」で決めた。どちらもファイルの**入れ物**の同一性で、データの**中身**(行)の同一性ではない。入れ物は研究者が普通にする操作(再圧縮・展開・切り出し)で変わる。加えて、ファイルなら何でも「合成」と宣言できる口が残っていた(合成の出どころが宣言だけ)。
- **変える構造**: (a) ファイルの出所は、データ層の read で読んだ行(正規化された (時刻, 値) の記録)を、この環境の市場データのフォルダのファイルを**同じ宣言(spec)で**データ層の read を通して読んだ行と照らして決める。1 行でも一致すれば実データ(一致した市場のファイル・一致した行の数を記録する)。封印のあるファイルはデータ層が断るので照らさない(記録する)。(b) **合成は種つきの生成器からだけ作る**: データセットの宣言に `generator`(名前・種・引数)を置く口を足し、生成器の名前・版・種を実行記録に残す。ファイルのデータセットは「合成」と宣言できない(断る)。(c) 行が一致しないファイルは、出所の分からない実データとして扱う(§4 の実データの規則が掛かる)。**この (c) は原文に無い決め**で、リードに聞く(返り値の (d))。
- **同じ根の全箇所**: (1) `market_evidence`(位置・バイト)を消す。(2) 作業者の格子 `test_i4_r2_origin_from_data_grid.py` の「合成のファイル」の升は生成器の口に移す。(3) `test_i4_pipeline.py` の格子の origin 軸も同じ。(4) 場面集の統合の場面の宣言(場面係の持ち物)は、ファイルを「合成」と宣言していない(DEFINITIONS の「宣言は real」)ことを確かめる。
- **先に書く試験**: `tests/bt/item_4/test_i4_r3_origin_by_rows_grid.py`。格子 = 市場のファイル {FX のティック・TOPIX 先物の 1 分足} × 変え方 {そのまま・再圧縮(ヘッダの時刻違い)・展開・先頭の切り出し・途中の切り出し・1 行の値を 1 バイト変える・全行の値を変える・列の並びを変える} × 宣言 {real・synthetic}。期待: 宣言 synthetic は全部断る。宣言 real は、全行を変えたもの以外は証拠 = 行の一致(市場のファイル名)。全行を変えたものは「一致なし・出所の分からない実データ」。

## 3. i4-r2-05(研究の実行が 64 桁の文字列で作れる)

- **なぜ起きたか**: 統合の口に `prereg_sha256`(文字列)の入口を足し、形(64 桁の 16 進)だけを検めた。項目 3 の実行記録の口(`repro/runner.py:plan_run`)がファイルだけを受けることと照らさなかった。
- **変える構造**: `prereg_sha256` の入口を消す(引数として渡されたら断る。型の誤りではなく PipelineError で理由を書く)。事前登録は root の下の**ファイル**として受け、その sha256 を計算して実行記録に残す。空のファイルは断る。

## 4. i4-r2-06(統合の口が項目 2 の執行の模型を繋いでいない)

- **なぜ起きたか**: 第 1 周で統合の口を作ったとき、「1 本の約定の決まり」(最初に観測した値)を統合の口の中に書き、項目 2 の差し込み口(`SimVenue`・`LatencyModel`・`ScheduleCostModel`・`MarginAccount`)を使わなかった。統合の要件(I4-5「部品が 1 本のパイプラインとして繋がっているか」)を「核に通る」ことで満たしたと読み、項目 2 の模型が通ることを確かめる試験が無かった。
- **変える構造**: `pipeline.py` の自前の `FirstObservedFill`・`_Latency`・`_Fee`・`NullAccount` を消し、銘柄ごとに `SimVenue`(約定・注文の規則)・`LatencyModel`(4 つの遅延の分布)・`ScheduleCostModel`(費用の宣言 `CostSchedule`)・`MarginAccount`(証拠金・評価)を宣言から作って核に差す。約定の宣言は `FillRange`(楽観・悲観の 2 つの `FillSpec`)で受け、実行は**両側を回して**両方を記録・書き出しに出す(片側だけの入口は無い)。遅延は分布ごと(Constant / Empirical / SeededUniform、種つき)に宣言し、実行記録に分布と引いた回数・和を出す。口座は通貨・元本・レバレッジ・評価の規則・清算の規則を宣言し、実行記録に証拠金の結果(建玉・実現・評価・資産・清算の時刻)を出す。
- **同じ根の全箇所**: (1) 宣言の `fill`・`costs` の形が変わる(旧の形は断る)。(2) `test_i4_pipeline.py`・`test_i4_real_data_smoke.py`・`test_i4_r2_origin_from_data_grid.py`・`i4w_drive.py` の宣言。(3) 場面集の adapter の `_pipeline` と統合の場面の宣言(場面係の持ち物。返り値に書く)。
- **先に書く試験**: `tests/bt/item_4/test_i4_r3_pipeline_sockets.py`。(a) 自前の 4 つの名が `pipeline.py` に無い、(b) 核に差さった模型の型が項目 2 の 4 つである(実行記録の components)、(c) 楽観・悲観の両側が記録と書き出しに出る、(d) 遅延の分布(種つき)が記録に出て同じ種で同じ、(e) 証拠金の結果が記録に出る、(f) 片側だけの約定の宣言・旧の形の宣言を断る。

## 5. i4-r2-08 の spec の側(maker の 2 値)

- **なぜ起きたか**: maker の合図の受け付け(`BarVenue.on_order`)は旧エンジンの計算(置いてから約定の時にマスクを見る・同じ向きでも置き直す)をそのまま spec にも使った。規則の文に無い所を旧の計算で埋め、規則の文として決めることをリードに上げなかった。
- **変える構造**: `BarRules` に `maker_mask_at_signal`(spec = True: マスク False の建ての合図は指値を置かない・取り逃しに数えない)と `maker_same_side_keeps`(spec = True: 待っている指値と同じ向きの合図は置き直さない)を足す。legacy は両方 False(旧の計算のまま)。作業者の写し `bar_rules.py` も同じに直す。
- **同じ根の全箇所**: 建ての向きの制限(R-E1、long / short)で建てられない合図の指値も、同じ「建てない合図」だが、リードの決めの文はマスクだけを書く。この段では文のとおりマスクだけにし、R-E1 を同じにするかはリードに聞く(返り値の (d))。
- **先に書く試験**: `tests/bt/item_4/test_i4_r3_maker_two_values_grid.py`。格子 = マスク {True・False} × 待っている指値 {無し・同じ向き・反対の向き} × 次の足 {厳密に通過・通過しない} × 寿命 {1・3}。

## 6. 直している途中で決めたこと・見つけたこと(原文に無い判断を含む。返り値の (d) に同じものを書く)

1. **行が一致しないファイルの出所**(§2 (c)): 「実データ(出所の分からないもの)」とした。理由: 合成を生成器だけに限ると、ファイルは合成になれない。一致しないファイルを合成とすると、全行を書き換えたファイルで §4 の規則を迂回できる(第 2 周と同じ形の穴)。**原文に無い決め**。
2. **書き出しの見出しの数は悲観側**: 指標の書き出しの既存の欄(by_instrument・trades・pnl など)は悲観側で計算し、両側は `metrics["range"]`、約定・往復・注文の行は全部 `range` の欄で側を名乗る。ダッシュボードの既存の読み口を変えないための決め。**原文に無い決め**。
3. **滑りの欄を消した**: 項目 2 の費用の宣言(`CostSchedule`)に滑りが無い(価格への影響は tier 6 の影響関数)。統合の口の旧の `slippage_pct` は受けない。
4. 提出前の吟味 (4) で「厳しい批評家なら止める」と列べたもの: 統合の口が項目 2 の tier 6(影響関数)と資金調達の費用を宣言できない = 部品を狭めて繋いでいる → 両方を宣言できるようにした(`fill.<side>.impact`・`costs.funding`)。宣言できないまま残るもの(書く): L3 の列の模型(1 注文ごとの供給)・故障の注入(FaultPlan は空)・FX の換算表(銘柄の値の通貨 = 口座の通貨に限る)・スワップ・手数料表。
5. 順序の違反: 統合の口の格子 3 本は直したあとに書いた(materials/worker/README.md に開示)。
