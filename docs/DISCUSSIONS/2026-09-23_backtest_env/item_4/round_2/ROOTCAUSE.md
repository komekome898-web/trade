## 1. i4-r1-01 [止める](spec の模型が、前の足の合図の始値の決済より、その足の範囲の逆指値・利確を先に取る)

- **なぜ起きたか**: 第 1 周の足の模型 `src/bot/bt/compat/barmodel.py` は、旧エンジンの 1 本の繰り返し(`src/bot/backtest/engine.py` の 0 → 0.4 → 0.5 → 0.7 → 1 の順)を核の上に写し、そこから「spec が旧と違う点」を `BarRules` の欄(4 つ)として足す作り方をした。欄にしたのは、第 1 周に誰かが「違う」と挙げたものだけで、**「足の中の時の順(始値 → 範囲)」は欄になかった**。そのため spec は旧の順(範囲の出口が先、待っていた合図は捨てる)をそのまま引き継いだ。規則の参照 `bar_rules.py` も同じ作業者が同じ前提で書き、行 22-26 で「旧の振る舞いを借りた」と書いている(i4-r1-03 の実害)。根は「spec = 旧 − 挙げた違い」という作り方で、spec を規則の文(R-T1 の「足 i+1 の始値」)から導いていないこと。
- **変える構造**: 足 j の処理を**足の中の時の順**で 2 段に分ける: (段 A)始値で起きること = 足 j より前の情報で決まる出口(構造的な逆指値 R-W3・時間切れ R-H1。どちらも待っていた合図を捨てる R-H2・R-W3)と、待っていた taker の合図(R-T1)/ (段 B)範囲で起きること = 率の逆指値・利確・maker の利確(R-P3・R-P4・R-X1)と maker の指値(R-M1)。`BarRules` に欄 `signal_at_open`(spec = True: 段 A で合図を先に約定し、建玉が始値で閉じた・始値で建てたなら段 B の出口は無い / legacy = False: 旧の順)を足す。規則の参照 `bar_rules.py` にも同じ段の分け方を入れる。
- **同じ根の全箇所**: (1) 始値で窓を空けて水準の外で始まる足(逆指値の値が始値になる)と待っていた合図: どちらも始値の taker で同じ値・同じ損益。段 A の合図が先なので理由は「signal」。(2) 時間切れの足の R-H3(逆指値だけを時間切れより先に見る)は場面係の規則の文どおり残す(段の分け方と食い違うが、規則の文の持ち主は場面係。§6 の問い)。(3) maker の執行(合図が指値を置く)は、指値も逆指値も足 j の範囲の中で、どちらが先かは足からは分からない。規則の文も決めていないので、今の順(範囲の出口が先、指値は捨てる = 旧と同じ)を残し、格子の外として試験のファイルに名指し、リードに聞く(§6)。
- **先に書く試験**: `tests/bt/item_4/test_i4_r2_signal_at_open_grid.py`。規則の入力の空間(建玉の向き × 待っている合図 {無し・同じ向き・反対・CLOSE} × 足 j の始値の位置 {水準の間・逆指値の外・利確の外} × 範囲が届くもの {無し・逆指値・利確・両方} × 出口の組 × 時間切れの有無 × 費用)を全格子で列べ、規則の文から書いた判定(足 j の 1 本だけの答え)と spec の本体・規則の参照の両方を突き合わせる。legacy は同じ格子で旧エンジンとバイト単位で一致することを見る。

## 2. i4-r1-03 [止める] + 監査役の同じ点(I4-1 の参照が独立でない)

## 3. i4-r1-04 [止める] + 監査役の同じ点(実データの規則が呼び手の `origin` の一語に依る)
