# 全件監査計画(2026-09) — 既存の全分析結果を、盲検再実装で網羅的にやり直す

背景: `POSTMORTEM_2026-09-04_tp_precursor.md`。リードの分析の前提条件・データ選定の信頼性が失われたため、
**通過・棄却・法則の全てを同じ手続きで再検証し、その後に初めて順位をつけ直す**。監査中は新規戦略研究を凍結し、
実弾は一切乗せない(フォワード記録・データ収集のみ継続)。

## 2. 監査の手続き(「合格しやすい」余地を潰す設計)

1. **盲検再実装**: 監査者は原スクリプト・原報告・リードの説明文を**見ない**。渡すのは (a) 主張の逐語文
   (法則/棄却行/PREREG の判定基準)、(b) データ・スナップショットの場所と列定義、(c) コスト定数の出所。
   監査者は主張の数値を**自分の実装で再計算**する。原実装と数値が食い違えばそれ自体が所見。
2. **分母監査**: 主張の全ての率に母集団を明記し、(i) 運用時の母集団、(ii) 全時刻無作為対照、(iii) 状態内無作為対照
   の3通りで再計算する。差の向きと大きさを記録。
3. **検出力監査(棄却側の救済)**: 棄却された主張ごとに、その n で検出できた最小効果(MDE)を計算し、
   もっともらしい効果量(同種の文献値・本プロジェクトの通過例)が MDE 未満なら、棄却を**「判定不能」に格下げ**する。
   「効果なし」と「検出できず」を区別する。
4. **前提監査(棄却側の救済)**: 棄却の根拠がコスト・執行前提(例: taker 5.8bps、maker 逆選択、手数料)に依存する
   場合、**現在の前提**(SOR 手数料0・板寄せ執行・マイクロ先物 0.35bps 等)で再計算する。前提が変わって
   結論が変わるなら「再研究待ち」に移す。
5. **対照監査**: 対照は仮説の反事実か。イベント定義が命中・空振りの数え方に暗黙の除外を持ち込んでいないか。
6. **単純説明の攻撃**: 生き残る効果ごとに、最も単純な既知の説明(ボラ持続・時刻・出来高・価格水準・生存バイアス)
   で同じ数値が出ないかを計算する。
7. **データ妥当性**: 極端値・ギャップ・メンテナンス窓・再接続直後・分割/配当調整を除外前後で比較。
8. **判定の4区分**: 再現(結論維持) / 数値差異(結論維持) / **結論変更**(救済 or 棄却) / **再計算不能**
   (データ消失。結論は「未検証」に格下げし、法則からも外す)。
9. **二重監査**: 「結論変更」と、全ての通過側(ON1・ONR・S12 設計・法則)は、**別の監査者が独立に再実装**して
   一致を確認する。不一致は第3者が裁定。
10. **審査官による順位付け**: 全パケット完了後、リードではなく独立の審査官エージェントが、所見だけから
    生存主張の順位表を作る。リードはそれを**そのまま**提示し、異論があれば別欄に書く。

監査の境界: 監査は「元の検定の誤り(分母・対照・コスト・検出力・データ品質)」を正すもので、**新しいパラメータ探索は
しない**。救済がパラメータ変更を要する場合は「再研究待ち(要 PREREG)」に分類する。監査のためにデータを使うことは
選択でも過学習でもない(オーナー指示)。

## 4. 進め方(2案)

- **A. 一括**: 45 パケットを 3 セッションに分けて連続実行。順位は最後にだけ出す。
- **B. 校正波 + 一括**(推奨): 最初の 6 パケット(通過2・棄却2・法則2、種類の代表)で監査手続き自体の
  取りこぼしを測り、手続きを修正してから残り 39 を一括で回す。順位は最後にだけ出す。校正波の選定基準は
  「金が乗る順」ではなく「監査手続きの穴が見つかりやすい種類の代表」。
